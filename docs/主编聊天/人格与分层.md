# 主编人格和聊天提示词分层

2026-10-24 作者想给主编加一个能换的人格（比如主编是女仆、叫他主人），图个开心；更看重的是提示词怎么拼更合理、回答质量更好。作者在提示词页看到「主编人设」写着「主编每次调用的系统提示」，觉得耦合太高。

草稿在 `docs/codex任务/主编口吻和分层/提示词/`（任务包里，Codex 照它搬进 `backend/app/prompts`）。拿一条真实请求拼出来的完整样子在 `docs/主编聊天/示例：改后主编收到的一整份.md`。

## 一、现在的毛病

1. **一份人设两种活**。`persona(role)`＝人设＋通用规则，聊天（群聊、私聊、拆的书的群聊）和十几样写书的活（开书各步、规划、补漏、方案卡、分流、看稿意见要不要记、整理要求）共用。口吻写进人设，就会漏进说明、方案卡和记忆。
2. **聊天规矩抄了两份**。「聊天：自己查、自己动手」和「聊天回答」里的四件事、另外几件事几乎一字不差，改一份得记着改另一份。
3. **同一个意思说了两遍**。人设里「有主见……该拿主意的时候就推荐一个」，聊天第二件又写「要看作者口味的，说清几种走法各会怎样，让他来定」；两处分开说，后一句成了口子。10-24 上午那句话，第一次回答摆了三套、第二次摆了三组六个点子让作者挑（llm_calls 3165、3166）。
4. **两句旧话**。聊天最后那句「照你的角色说话：你管剧情、节奏和方向」，是以前按关键词分人时留下的；现在不点名都是主编答，这句把她框窄了。通用规则里「不要替其他角色做工作」，和主编现在在聊天里设定、大纲都管打架。

## 二、分层

按多久变一次排：不变的在前，变的在后；每层只管一件事，只写在一处。

| 层 | 提示词（提示词页上的名字） | 谁用 | 放哪 |
|---|---|---|---|
| ① 专业 | `persona_chief`「主编人设」：她懂什么、怎么判断、用什么标准 | 写书、聊天都用 | 系统提示 |
| ② 口吻 | `voice_chief`「主编口吻」（新）：身份、称呼、性格；作者改它就是换人格 | 只在跟主编聊天时用 | 系统提示 |
| ②′ 口吻的边界 | `chat_voice`「口吻怎么用」（新）：口吻只管怎么说，谁说了算 | 跟在②后面 | 系统提示 |
| ③ 聊天的做法 | `chat_manner`「聊天的做法」（新）：四件事、另外几件事 | 自己的书的群聊、私聊共用一份 | 系统提示 |
| ④ 这条路能做什么 | `chat_agent`／`chat_reply`／`chat_teardown`：只留各自的开场一句和规矩 | 各走各的 | 系统提示 |
| ⑤ 通用规则 | `rules` | 都用 | 系统提示最后 |
| ⑥ 资料和对话 | `chat_material`「聊天带的资料」（新）：书的资料、之前聊过、最近的对话、作者这次说的 | 所有聊天共用一份 | 用户提示 |

为什么这样排：
- 一件事只在一处说：同一个意思写两遍，模型会加倍照做；两处说法有出入，它就两头都想照顾。
- 专业、口吻、规矩分开：换人格不碰专业，调专业不碰口吻。
- 不变的在前：模型对开头和结尾最上心，开头立住「我是谁、怎么做事」，结尾是这次要接的话，中间是翻查的资料。开头一模一样的部分，模型那边还能缓存（官方 DeepSeek、Gemini 会自动缓存，中转站看它支不支持）。拿 3164 那条算：每句话都不变的开头从 1864 字变成 5238 字，总长只多了口吻那几百字。
- 写明口吻不改判断：女仆这类人设天生爱顺着说，不写明会变成夸夸机。
- 知识用到再翻：手册、拆过的书、联网、大书只给目录，照旧；以后加知识加手册，不往人设里塞。

## 三、每条路怎么拼

系统提示各段之间空一行；口吻那两段只有主编有，设定师、写手、审稿没有。

- **群聊，能用工具**（`chat_agent.answer_note` → `drive`）
  - 系统提示：人设（不带通用规则）→ 口吻怎么用（填主编口吻）→ `chat_agent`（`act_rule` 照旧填 `ACT_RULE`／`ASK_RULE`）→ 聊天的做法 → 通用规则
  - 用户提示：聊天带的资料
- **只说话不动手**（私聊、重新回答、不能调工具时的群聊；`chat.answer` → `stream_reply`）
  - 系统提示：人设 → 口吻怎么用 → `chat_reply`（`where`、`how_to_apply` 照旧）→ 聊天的做法 → 通用规则
  - 用户提示：聊天带的资料
- **拆的书的群聊**（能调工具和不能调的两条都算）
  - 系统提示：人设 → 口吻怎么用 → `chat_teardown`（`lookup` 照旧）→ 通用规则；没有聊天的做法
  - 用户提示：聊天带的资料

写书的活一律不变：系统提示照旧是 `persona(role)`（人设＋通用规则），不带口吻。方案卡、对话摘要、群聊分流、看稿意见要不要记、整理要求也不带口吻。

**聊天带的资料怎么填**：可有可无的块由程序包好标签（`tagged`）再填，没有就填空串，`render` 会把多出来的空行并掉。

| 变量 | 自己的书 | 拆的书 |
|---|---|---|
| `material_note` | 照旧（书大了说只列目录） | 照旧 |
| `book` | `<简介>`＋`ctx.concept`（私聊原来叫 `<定调>`，统一成简介） | `<这本书>`＋`book_info` |
| `library`／`outline` | 照旧 | 前面加原来那行「（从原文拆出来的）」「（从原文倒推的）」 |
| `progress`／`memory` | `<写到哪了>`、`<记忆>` 包好 | 空 |
| `viewing` | 群聊包成 `<作者正在看的那一页>`；私聊空 | 包好 |
| `related` | 私聊和重新回答包成 `<和这次的话有关的资料>`；群聊空 | 照旧（不能调工具时才有） |
| `extras` | 私聊照旧（已经是包好的块）；群聊空 | 空 |
| `pending`／`working`／`quote`／`retry` | 照旧 | `quote`、`retry` 照旧，其余空 |

**程序里跟着改的字**：
- `ROLE_FOCUS`（`chat_context.py`、`teardown_chat.py`）：现在填进 `{{role_focus}}` 的是整句。主编填空串；别的角色填「照你的角色说话：」加原来那句。
- `teardown_chat.py` 的 `LOOKUP_TOOLS`、`LOOKUP_PLAIN` 里的「上面」改掉（它们现在在系统提示里，资料在后面）：
  - `LOOKUP_TOOLS`：「资料里的设定和大纲只是目录，或者还没拆出来，原文一章都没贴。要细节、要核对，用工具查：某一章的原文和摘要、在原文里搜一个词、设定卡全文、大纲上的一段、伏笔。问「第一次出场」「在哪几章」的，先在原文里搜。能一起查的一次调几个工具；资料里已经有的不要再查。」
  - `LOOKUP_PLAIN`：「你这次没法用工具查。资料里的 <和这次的话有关的资料> 是程序按作者这句话找出来的：提到的几章、设定，还有作者用引号标出的词在原文里的位置。那里没有的就说没找到，不要猜；作者要找某个词在哪几章，告诉他在正文页目录的搜索框里搜原文。」
- 提示词页：「主编人设」的说明改成「主编的专业底子：写书、聊天都带」；新的四份进目录（「主编口吻」放「角色与规矩」，挨着「主编人设」；另外三份放「聊天」）；新变量 `voice`、`book` 补中文名。

## 四、人格

- 提示词页「角色与规矩」里的「主编口吻」，默认就是现在这位老主编。作者改成什么样她就是什么样，改坏了点「恢复默认」。所有书共用。
- 只有主编有口吻；设定师、写手、审稿要换口吻，照样加一份 `voice_<角色>` 就行，这次不做。
- 界面上她还叫「主编」；程序自己发的几句固定话（比如「做好了：……」）照旧。

女仆示例（作者自己贴进「主编口吻」，不随程序发）：

```
你是主人的专属女仆，也替主人打理这间编辑部。叫作者「主人」，自称「我」。

你温柔、细心，说话恭敬又亲近，偶尔带点小俏皮。主人卡文、泄气的时候，先体贴他一句，再陪他把问题理清楚。

你对主人忠心，所以不哄他：书哪里不行，你会恭恭敬敬、但一针见血地说出来。主人的书写好了，比他一时听着舒服要紧。
```
