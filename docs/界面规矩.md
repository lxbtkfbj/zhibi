# 界面规矩

2026-10-18 起，执笔的界面照这份来。改界面、给 Codex 写界面任务之前，先对一遍。

## 跟谁学

| 学谁 | 是什么 | 学它哪一点 |
|---|---|---|
| Linear | 任务管理软件，界面公认干净 | 一屏只有一个显眼的按钮；其余多是图标，鼠标停上去才有说明；页面上几乎没有「教你怎么用」的句子 |
| Notion | 笔记和资料库 | 字本身就能改；空着的项不显示，点「＋ 添加」再拿出来；行上的小按钮鼠标移过去才出现 |
| Novelcrafter 的 Codex、Sudowrite 的 Story Bible | 写小说的 AI 工具，和执笔最像 | 左边目录、中间一页；每块只放一个「生成」按钮，不堆功能 |
| Ant Design、TDesign 的文案规范 | 阿里、腾讯的设计规范 | 按钮用动词，两到四个字 |
| 《Refactoring UI》 | 讲界面设计的书 | 靠字的粗细和深浅分主次，少用边框、少用颜色；空页面也要认真设计 |

## 十条规矩

1. **按钮两到四个字，动词开头**：新建、补全、检查、锁住、删除、采纳、忽略。要解释的话放进鼠标停留时的提示里。
2. **一块地方只有一个主按钮**（深色实心）。其他用描边或纯文字，再次要的收进「⋯」。
3. **能用图标说清的就不写字**：搜索、锁、历史、更多、关闭、展开。图标按钮一定要有提示。
4. **教人怎么用的句子，一屏最多一句**，最好只在空着的时候出现。
5. **不显示「（空）」**：空着的项不占地方，点「＋ 添加」再拿出来。
6. **颜色各管一件事**：红＝等你决定；蓝＝选中、链接；绿＝完成；黄底＝AI 刚改过或有意见。数字角标只给要你处理的事，不拿来报总数。
7. **分组靠留白，不靠一层套一层的框**。虚线框只给「AI 建议、还没留下」的东西。
8. **字号只用五档**：12 辅助、13 标签、15 正文、18 小标题、28 大标题（标题用宋体）。
9. **同一件事全站一个叫法**：补全（让 AI 写空着的、缺的）、检查（让审稿看）、采纳／忽略（对建议）、锁住、新建。
10. **空页面要说清三件事：这里将来有什么、什么时候有、谁来写**。把将来会有的几类像目录一样列出来，每类一句话，点哪类就从哪类开始；最上面一句话按进度说清谁来写；大按钮只给真正的下一步，不叫作者去干编辑部的活。别做成「一个图标＋一句话＋一个按钮」漂在大片空白中间，那像出错页。

## 叫法对照

| 以前 | 现在 |
|---|---|
| 让 AI 补上缺的、让 AI 补漏、让 AI 先补一批、把空着的都写上、让 AI 先填一版 | 补全 |
| 全部查一遍、查一查、让审稿看看这一条 | 检查 |
| 照这个改／不用（设定卡上的意见） | 采纳／忽略 |
| 留下这一条 | 留下 |
| 还可以写：＋外貌 ＋身世…… | ＋ 添加 |
| 回到正在进行的：第 2 卷卷纲 | 回到进行中 |
| 自建类别 | 新类别 |
