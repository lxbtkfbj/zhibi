# 执笔 · 设计说明

> 多 Agent 长篇小说创作平台。本文是项目的设计依据，功能与架构变更时同步更新。

## 1. 定位

- 一个由 AI「编辑部」协作写长篇小说的工具：作者给出点子（或导入已有小说），编辑部分工完成设定、大纲、正文与审稿，作者只在关键节点拍板。
- 「设定库」是地基：人物、关系、世界观、伏笔、时间线随写作自动维护，保证长篇前后一致。
- 作者角色：**甩手掌柜**。支持从零开新书与续写已有小说两种入口。

## 2. 编辑部角色

| 角色 | 职责 |
|---|---|
| 主编 | 定方向与卖点、写大纲与细纲、分派工作、处理作者意见、最终把关 |
| 设定师 | 建立与维护设定库；为写手准备本章资料；检查新章节与设定的矛盾 |
| 写手 | 按细纲与资料写正文，遵守文风参考 |
| 审稿 | 站在读者角度挑刺：节奏、冲突、人物是否崩坏、钩子、逻辑漏洞 |

拆分角色的理由：每个角色上下文只含自己所需资料，职责单一；审稿与写手上下文隔离，避免被写手的思路带偏；问题可按环节定位。

## 3. 核心流程

### 3.1 开新书
> 第一包任务 1 数据底座已实现（2026-10-16）；当前默认仍是「一口气出方案」（`oneshot`），任务 2 也保持此默认，任务 3 完成后才改为「逐块确认」。本节描述当前保留的流程，第 11 节其余产品规则按任务继续实施。

作者输入点子（可附文风参考）→（可选）主编先问作者几个关键问题：篇幅固定要问，其余按点子挑选，如主角名字、金手指方向、开局、感情线、结局倾向；每题给出选项和推荐，作者不答的交给编辑部决定 → 主编定书的概念（类型、卖点、主角钩子、基调、篇幅）→ 设定师建世界观与主要人物 → 主编定主线骨架（核心矛盾、主角成长弧、开篇、结局、6-12 个全书关键转折，标明所在卷）→ 主编做**线索规划**（4-10 条线：主线、每位女主一条感情线、反派阶梯、谜团线、成长线；每条线拆成落在各卷的节拍）→ 主编写**全书总纲**（每卷一张卡片：舞台、概要、卷末目标、高潮、主要对手、主角实力区间、推进哪些线、新登场人物、预计章数；另列跨卷的长线伏笔，带计划埋下与回收的卷）→ 主编拆**第一卷卷纲**（剧情单元，每单元写清推进的线索与伏笔动作、用到的套路和破局手法，另新埋本卷的短线、中线伏笔）→ 审稿挑刺（除逻辑外，查线索是否断线、感情线是否雷同、反派是否降智、破局是否重复、是否违反题材打法的防重复规则、伏笔是否只埋在前期）→ 必要时自动修改一轮 → **作者拍板**（批准 / 提意见；提意见后主编判断需要改哪些部分，交给对应角色修改，再次拍板）。

**分层滚动规划**：一次调用规划不了上千章，所以分四层、写到哪规划到哪——开书时只定总纲；每卷写到之前拆卷纲并请作者拍板；每个剧情单元写到之前出章纲；然后逐章写。每次规划都能拿到「实际已经写成什么样」作为前情，可以随时调整。

**题材打法库**：`backend/app/prompts/playbooks/` 下每种题材一份 Markdown，目前有「后宫玄幻爽文」和通用版，按概念的类型与标签选用（类型像玄幻、修仙、仙侠，标签又有后宫、爽文、无敌之类时用后宫玄幻爽文，否则用通用版）。内容分节：总则、线索（女主登场节奏、确认关系的方式、反派阶梯、金手指节奏）、分卷（换地图、卷末大场面分配、每卷先抑的方式）、单元（欲扬先抑的骨架、强度阶梯）、章节（打脸三拍、扮猪吃虎的暗示）、套路库（退婚打脸、扮猪吃虎、拍卖会、秘境、宗门大比、修罗场、女主登场……每个写清用在哪、节拍、怎么出新、全书最多几次）、破局手法（算计设局、底牌显露、临阵突破、长辈出手、双修解困……各自的上限）、防重复规则。线索规划、总纲、卷纲、章纲、审稿各取用得上的几节；章纲只带本单元用到的套路。每个剧情单元标出套路与破局手法，程序据此统计全书用了几次（「套路使用情况」）并检查超限与连续使用。

**伏笔台账**：每条伏笔有书内编号（F1、F2……）、跨度（短：单元内收；中：卷内收；长：跨卷）、计划埋下与回收的卷、状态（未埋 / 已埋 / 已收 / 放弃）以及实际埋下、提醒、回收的章节。卷纲与章纲用编号安排动作，章节定稿后设定师把正文里实际发生的动作记回台账。

**插话**：编辑部工作时作者随时可以插话。插话不打断正在进行的那一步；每一步做完后主编先读新的插话，判断已完成的部分是否需要改（需要改就排进计划，并按 `cascade` 联动下游），还没做的部分直接按插话写。作者对提问的回答、插话和拍板时的修改意见都作为「作者的要求」带进之后每个角色的提示词，后面的要求与前面冲突时以后面的为准。方案交给作者拍板后，插话改走「提修改意见」。

### 3.2 写书主循环（第 2 步）
作者选这一轮写多少（写 N 章 / 写完这一卷 / 一直写到完本）后，编辑部循环执行；每一轮先按**数据库里的进度**决定下一步，所以断点续跑、换一个任务接着写都能接上：

1. 当前这一卷还只有总纲卡片 → 拆卷纲（上下文：本卷卡片、前后卷、线索节拍、前情摘要、前面用过的高潮与破局方式、套路使用情况、人物当前状态、相关伏笔、题材打法）：
   - **比稿**：主编按力度先想 1-4 个有实质差别的方向（均衡默认 2 个，原来为 3 个）（主打的套路、对手的谋划、几条线的比重不同），每个方向并行各拆一份完整卷纲（LangGraph `Send` 扇出，任一份失败时其余的结果保留在检查点里）→ 审稿按爽点、线索交织、反派智商、新意各打 1-10 分，选出最好的一份；别的方案有明显更好的单元或设计时给出融合建议，主编据此融合。只有一个方向时跳过比稿。
   - **专项审稿**：审稿只查四件事——反派是否降智、爽点节奏、伏笔排期、和前面单元是否套路重复。其中套路或破局手法超过打法库上限、连着用同一种、台账里计划在本卷埋下或回收的伏笔没排进单元、新伏笔的埋收位置不合理，由程序直接查出并交给审稿参考；有 high / medium 问题（程序查出的一律算）就由主编自动修改一轮，参照开书流程的 critique。
   - 存库（章数对齐、新伏笔编号并写进单元）→ **作者拍板**；程序还能查出的遗留问题随拍板一起列给作者。提意见则主编按意见修改后再拍板，意见记入作者要求。
   - 会议室依次出现：方向卡片、各份方案、比稿打分表、专项审稿结论、定稿卷纲。
2. 下一个剧情单元还没有章纲 → 主编出这个单元每一章的章纲（目标、2-4 个场景、冲突、爽点、结尾钩子、出场人物、伏笔动作），建成章节行。
3. 有章纲、未定稿的章：
   - **设定师备资料**：设定师读章纲，从人物名单、设定条目目录、前文目录（最近 60 章的标题和摘要，加上本章伏笔埋下、提醒过的章节）里挑出这一章用得上的人物、设定条目、要回顾的前文（最多 5 章）和写手最容易写错的提醒（伤势、谁知道什么秘密、力量体系的代价……），存进章节的 `materials`。程序只保留设定库里真有的人物和条目、已经写过的章节；章纲点名的人物和主角总会带上。设定条目不多（12 条以内）时全给。退稿重写和作者重写时沿用同一份资料。
   - **写手写正文**（流式；上下文：章纲、所在单元、设定师挑的人物完整资料与设定、设定师的提醒、**本章要处理的伏笔**、分层前情提要、设定师挑出的前文摘要、上一章结尾、文风参考、作者要求）。写的过程中每多写约 200 字（或隔 0.6 秒）把这一章到目前为止的全文推到 Redis（`draft` 事件，不进数据库），网页的阅读页和会议室实时显示。
   - **伏笔回收带原文**：章纲里要「提醒」或「回收」某条伏笔时，从台账查出埋下的那一章（回收时再加最近一次提醒的那一章），按伏笔描述在原文里找最相关的句子（按两字词重合打分），向前后扩到约 300 字，连同回收方式一起交给写手。
   - **字数与结尾检查**（程序判断，不靠模型）：字数不到目标的七成就让写手从最后一句接着写，补上章纲里没写足的场景（最多两次）；最后一段出现「一切才刚刚开始」「新的征程」「暗暗发誓」这类总结式说法，就让写手只重写结尾（取最后 1-3 段，约 150 字以上），停在章纲的钩子上（一次）。续写和改结尾也是流式、也会实时推送。
   - 审稿与设定师查矛盾**并行** → 不合格（审稿判退且有中等以上问题，或设定检查发现严重矛盾）退回重写，最多两次 → 仍不合格**交给作者**（直接定稿或给出修改意见）→ 定稿：设定师输出本章摘要、人物状态变化、新人物、伏笔动作，程序校验（只认已有人物与台账编号）后与定稿一起提交，并把每处改动的改前、改后值记进章节的 `bible_changes`。
4. **长篇记忆**：一个剧情单元写完，设定师按各章摘要写单元回顾（300-500 字：实际发生了什么、人物变化、留下的悬念和没收的伏笔）；一卷写完，按各单元回顾写卷回顾（500-800 字），存在 `plot_units.recap` / `volumes.recap`。写正文、查矛盾、出章纲、拆卷纲时带**分层的前情提要**：前面各卷的卷回顾（总长约 3000 字）→ 本卷前面各单元的回顾（约 2400 字）→ 最近几章的摘要（写正文 3 章，出章纲、拆卷纲 5 章）；超长时从最早的开始压缩到 100 字，再不够就略去最早的，最近的一条不压缩。还没有回顾的老数据用卷纲概要或单元结果代替并标明。这一轮的章数写够了，也先把该写的回顾写完再停；早先写完、没有卷回顾的卷会补写。
5. 新书写完前 3 章 → **作者试读**，意见记入作者要求，之后每一章都遵守。
6. 一卷写完进入下一卷；写够本轮章数、写完这一卷（按作者选择）或全书完结就停。

**作者重写已定稿的章节**：阅读页「按我的意见重写」→ 后台任务 `rewrite_chapter`（一张小图）：先撤销这一章原来记进设定库和伏笔台账的变化（只改回「现在还是这一章改成的样子」的字段；这一章新建的人物在后面没有定稿章节时才删；去掉台账里这一章的提醒记录），章节回到写作中，所在单元和卷的回顾作废 → 写手按作者意见重写（作者意见在之后每次退稿重写时都保留），同样经过续写、改结尾、审稿与查矛盾 → 设定师重新提取并定稿 → 单元、卷已经写完的重写回顾。默认只重写最新的已定稿章节；后面还有定稿章节时，接口要求作者确认「后面的章节不会跟着改」，会议室也会提醒；重新提取时，后面章节改过的人物状态不会被这一章的旧状态盖掉。

**导出**：正文目录「导出 TXT」，把已定稿的章节按卷、按章导出（书名、简介、「第N卷 卷名」「第N章 章名」，段首空两格，UTF-8 带 BOM）。

作者在写作中途插话：每写完一步读到，记入这本书的作者要求，之后的卷纲、章纲和正文都要落实。

### 3.3 导入旧书（第 3 步实现）
导入 TXT → 自动分章 → 后台多批并行通读，建立设定库与前情摘要 → 作者选定续写起点 → 进入写章节流程，写手学习原著文风。

### 3.4 拍板点
> 逐块确认模式下，开书拍板拆成五次逐块确认（第 11.3 节），卷纲拍板时还会一并确认对暂定节点的调整（第 11.11 节）。

0. （可选）动笔前回答主编的几个关键问题
1. 开书方案（含第一卷卷纲）与之后每一卷的卷纲（重大转折包含在卷纲的剧情单元中）
2. 新书写完前 3 章试读一次（校准文风与节奏，意见被编辑部记住）
3. 兜底：单章审稿两轮仍不合格时
作者可随时对任意章节提意见，或在连写过程中插话。

## 4. 架构

```
网页（React）          Claude / Cursor（MCP，第 5 步）
        \                 /
     后端服务（Python + FastAPI，SSE 推送会议室）
                 |
     AI 编辑部（LangGraph 编排，运行在 Celery worker）
                 |
 PostgreSQL（业务数据 + 设定库 + LangGraph 检查点）
 Redis（任务队列 + 会议室消息流）   Milvus（原文混合检索，第 3 步）
```

- **LangGraph**：编辑部流程是一张图；`interrupt` 实现拍板暂停，`AsyncPostgresSaver` 检查点实现断点续跑。
- **Celery + Redis**：开书、连写、通读旧书等长任务在后台 worker 执行；worker 崩溃后任务重新投递，从检查点继续。
- **会议室消息**：worker 把每条发言写入 PostgreSQL（可回放）并推送到 Redis Stream；后端通过 SSE 推给网页，断线后按消息 ID 补齐。
- **模型**：OpenAI 兼容接口（DeepSeek / GLM 等），每个角色可分配不同模型配置；API Key 加密存储。内置「演示模式」模型，无 Key 也能跑通全流程。
- **结构化输出**：各角色的产出（概念、设定、大纲、审稿意见、设定变化）均为 Pydantic 模型，经校验后入库。
- **向量检索（第 3 步）**：本地 bge-m3 向量化；Milvus 稠密向量 + BM25 混合检索，RRF 融合，再重排。
- **可观测（第 4 步）**：Langfuse 记录每次调用的耗时与 token；业务侧另记 `llm_calls` 用于界面展示。

## 5. 数据模型（第 1 步）

- `books`：书（来源 new/imported、点子、文风参考、概念 JSON、主线骨架 JSON、作者要求列表、是否已试读、状态 setting_up / awaiting_approval / ready / writing / completed）
- `story_threads`：线索（类型、概要、核心人物、各卷节拍）
- `volumes` / `plot_units`：分卷卡片（舞台、概要、卷末目标、高潮、对手、实力区间、推进线索、新登场人物、预计章数、卷回顾、状态 planned / detailed / approved / done）与剧情单元（目标、冲突、高潮、结果、关键事件、推进线索、伏笔动作、套路、破局手法、单元回顾、状态 planned / outlined / done）
- `characters` / `relationships` / `world_entries` / `foreshadowings`：设定库；伏笔即台账（编号、跨度、计划埋/收的卷、状态、埋下 / 提醒 / 回收的章节）
- `chapters`：章节（全书章号、章纲 JSON、正文、字数、摘要、最近一次审稿结果、重写次数、设定师备的资料 `materials`、定稿时对设定库的改动记录 `bible_changes`、状态 planned / drafting / final）
- `draft_versions`：开书方案各轮版本（AI 生成 / 作者修改）
- `jobs`：后台任务（类型 book_setup / write_book / rewrite_chapter、状态、LangGraph thread_id、等待作者处理的内容：动笔前的提问或待拍板的方案、错误）
- `meeting_messages`：会议室发言（角色、类型、内容、附带数据）；作者插话的类型为 `note`，流程按消息 ID 记录读到哪一条
- `llm_profiles` / `role_assignments`：模型配置与角色分配
- `llm_calls`：每次模型调用的耗时与 token

### 5.1 第一包数据底座（任务 1，已实现）

- `story_nodes` 是关键节点唯一事实来源，含顺序、开篇／中间节点／结局、名称、事件、前提、后果、卷号、铁钉／暂定／留空、来源、编辑批注与技巧；`books.spine` 只存核心矛盾、主题、主角成长弧。增删重排后顺序连续，开篇在首、结局在尾，作者接口不能删除两端节点；作者新增中间节点默认铁钉，改文字不隐式钉死，留空仅限 `setting_up`。
- `node_anchors` 关联书、节点、人物，类型为登场／确认关系／翻脸／高光／退场／其他；节点或人物删除时级联删除。保存时无法匹配人物或节点的锚点丢弃并返回数量。
- `secrets` 存 S 编号、短名、真相、知情人（姓名／章节／如何得知）、读者知不知道、揭开计划与节点、隐藏／公开状态、创建章节。人物卡旧 `secrets` 列已删除；人物改名同步更新知情人，旧数据读者认知为空，显示未标注。
- `foreshadowings` 增加伏笔／期待类型和节点引用；F7、E8 共用同一个书内编号空间，沿用既有埋下／提醒／回收存储动作。方案往返按长／非长、伏笔／期待分成四组。期待状态格式化为未立／已立／已兑现／放弃。

`POST /books/{id}/notes` 接受可选 `to=chief|lorekeeper|writer|reviewer`：
- `book_setup`／`write_book` 的 queued/running 或动笔前提问：记录当前任务 note，点名时 payload 为 `{thread: role}`；现有 intake/dispatch 在步骤边界读取。提示词标「（作者对设定师说）」；写作要求记为「对设定师：……」。处理后由被点名角色在私聊确认。

### 10.2 设置与作者要求的数据边界

- `books.settings` 存书名风格、自定义书名、人称、亲密戏、自定义边界、章字数、其他规矩、打法、力度预设和四个强度参数、卷纲拍板、试读开关。
- `app_settings[new_book_defaults]` 只在新书建立时复制；旧书迁移用新默认但书名风格为交给主编。已有内容不重命名、不重写。
- `author_requirements` 是唯一事实来源。`source` 为 `answer`、`note`、`private:角色`、`trial`、`volume:N`、`manual`、`legacy`。原文去重，旧数据时间用书的更新时间；删除旧 JSONB 列。兼容属性只从关系表读取，不能成为另一份存储。
- 每步从数据库重读要求和设置，不从检查点的旧 brief/notes 复活已删除内容。待处理的旧插话只导入一次；删除后尚未 intake 的要求同样不恢复。
- 即改即存不走 ensure_idle。开书设置修改记入该任务 note（设置变更不作为永久作者要求）；写作设置修改发系统群聊消息。当前已发出的请求不撤回，下一步起生效。

`compile_rules(settings)` 输出定稿的「这本书的写作规矩」，无内容省略、全部空则返回空字符串，置于「作者的要求」块之前。作者填写的其他规矩逐行保留原文。`chapter_words` 同时覆盖写作目标和补写判断；指定打法优先于按类型／标签匹配。

### 10.3 力度真实驱动流程

省时：1 次重写、1 个方案、无专项审稿、宽松；均衡默认：2 次、2 个、开启、标准；精品：3 次、3 个、开启、严格。自定义范围重写 0–5、方案 1–4。**默认比稿由 3 改为 2**，不是只换界面文案。

零重写第一次不合格即交作者；单方案不比稿；关闭专项审稿跳过节点；关闭卷纲拍板自动批准但仍贴卷纲及「按设置自动批准」；关闭试读跳过前 3 章暂停。设置在节点边界重读。

审稿松紧仅由 `review_chapter` 的 `strictness` 占位发给审稿。宽松：审稿 high 和设定 high 拦截；标准保持旧规则；严格：审稿与设定 high/medium 都拦截且不依赖审稿 verdict。

### 10.4 提示词覆盖与完整调用记录

提示词目录保留所有模板的角色、时机、变量中文名与最近调用。CodeMirror 6 replacement decorations + atomic ranges 把占位符作为不可拆的中文变量块；原始存储仍为 `{{name}}`。默认只读，显式自定义后编辑。服务端校验默认变量集合完全一致及打法真实 parse 成功，不依赖前端校验保证安全。

`prompt_overrides(name PK, content, updated_at)` 是全局覆盖；名称使用 `playbooks.harem_xuanhuan` 等安全路径。恢复默认删除行。只缓存发布的默认文件，每次 render／打法读取查已提交覆盖，因此 API 和常驻 worker 不依赖同进程 cache 清除或重启。

`llm_calls.request` 保存 system、user、schema_name、schema、method 及实际包含的模板名；`response` 保存原始 JSON／工具参数或流式全文。重试每次独立行，失败也保留请求、原始或部分输出和错误，演示亦记录。每书最近 2000 条保留正文，旧记录仅清空这两列，统计永久保留；同书并发调用串行化短暂清理事务。

`/prompts` 双页签：左侧 170px 分组目录，30px 行、自定义朱砂圆点；右侧标题／操作、元数据、插变量与编辑区。调用记录按书／角色筛选并游标加载，详情右侧抽屉按系统提示、用户提示、折叠结构、原样回复、错误展示。所有表格数字右对齐及等宽数字。

### 10.5 未读语义与验证

私聊未读只看 `payload.thread === role` 且非作者本人，群聊未读不含任何 thread 消息。「显示他在群里的发言」仅控制呈现，不影响未读或该私聊已读位置。测试包含角色群聊发言、不同发送者同 thread 和作者消息排除。

迁移为 0007（设置／作者要求）、0008（提示词与原始调用）、0009（可空用量）；自动化覆盖原文编译、力度路由、唯一要求表、实时设置 note intake、提示词校验及跨进程热更新、失败重试原文和 2000 条裁剪。浏览器验收使用独立 PostgreSQL／Redis、演示模式与 4332 预览端口，九项清单保留截图及实际结果，不以单元测试代替可视确认。


### 10.6 兼容与边界补充

旧开书任务可能仅在 LangGraph 检查点保存回答与已消费插话、尚未写入旧书列。首次恢复会一次性导入要求表并记迁移标记；编辑／删除标记优先，防止旧检查点和旧待处理 note 复活已经删掉的要求。作者派生修改指令跟踪来源，删除来源时去掉相应指令，保留审稿自己的修改意见。

原始供应商用量缺失时写 NULL，调用和汇总显示 `—`，不根据文本估算；演示明确为 0，历史 0 不做推断式迁移。流式输出遇 `finish_reason=length` 按失败记录并保留全文，避免把截断误认作成功。

提示词未保存草稿使用当前浏览器会话存储，并有内存降级；切模板、切标签、导航及刷新保留，成功保存／恢复只清除对应版本，异步响应不能抹掉较新的草稿。调用抽屉具名、管理焦点与滚动，Escape 关闭后回到触发按钮。

修改设置不主动唤醒已经等待作者决定的 worker；下一步恢复执行才应用关闭的门控。已完成书稿、既有聊天和历史调用不因删除要求而反向改写。


## 11. 开书拼图、关键节点与全书地图（第一包，设计稿）

> 状态：任务 1「数据底座」已实现（2026-10-16），对应内容已并入第 3.1、5.1、9.5 节；任务 2—5 尚未实现。本节保留第一包完整产品规则供后续实施，其中默认逐块确认在任务 3 才启用，当前仍为 oneshot。验收见 `docs/第一包验收.md`。

### 11.1 为什么改

原开书流程里作者只在两处说话：开头回答 3-5 个问题、最后对整套方案拍板。中间概念 → 设定 → 主线 → 线索 → 总纲 → 第一卷六层连做，每一层都建在上一层的猜测上。作者最后面对六份互相咬合的大文件；提意见后 `cascade` 把下游全部重写，又会改到作者原本满意的地方。

改法有三条：

- 先钉关键节点，再填中间（写作课里叫 tentpole）。
- 按依赖关系切成五块，逐块确认并锁定。
- 全书、卷、单元每一层都用同一个方法：从上一个节点走到下一个节点。

### 11.2 两种模式

| 模式 | 说明 |
|---|---|
| 逐块确认（默认，`puzzle`） | 五块各停一次，等作者确认；确认即锁定 |
| 一口气出方案（`oneshot`） | 原流程：五块连做，最后整体拍板；可选「先问我几个问题」 |

- 两种模式是同一张图，差别只在每块做完后是否 `interrupt`。
- 模式存在 `books.settings.setup_mode`。新书默认取自「新书默认」，首页创建时可改；开书任务开始后不再切换，模式写进 `jobs.params.mode`。
- 旧任务的检查点里没有 mode，一律按 `oneshot` 继续。

### 11.3 五块拼图

内部步骤的顺序改为 concept → spine → lore → outline → threads → first_volume，节点提前到设定之前。

| 块（piece） | 内部步骤 | 产出 | 作者操作 |
|---|---|---|---|
| ① 定调 `concept` | directions → 作者选 → concept | 先出 3 个方向；选定后定稿概念（新增舞台阶梯、目标读者） | 选方向、选篇幅、写混搭要求；确认概念 |
| ② 关键节点 `nodes` | spine | 开篇、结局和中间 6-12 个节点，每个都写「之前得先有」和「之后变成」 | 逐个钉死、修改、删除、插入、调顺序、换候选、留空 |
| ③ 人物上轴 `cast` | lore | 世界观、人物、关系、人物锚点（谁在哪个节点登场、确认关系、翻脸、退场）、信息差表 | 确认或修改 |
| ④ 填中间 `fill` | outline → threads | 分卷卡片（每卷标明走向哪个节点、多少章）、长线伏笔（从节点前提倒推）、长线期待、线索节拍 | 主要看节奏：哪段写长、哪段写短 |
| ⑤ 第一卷 `first_volume` | first_volume → critique | 第一卷的剧情单元；跨块审稿 | 确认即开书完成 |

每块产出时附上「编辑部替你做的决定」：最多 3 个，每个带 1-3 个可换的选项和一句理由。作者换掉其中任何一个，主编就按新的选择改这一块。

逐块模式下，开头那轮统一提问取消：篇幅在选方向时一起选，其余问题变成各块里「替你做的决定」。

每块做完、交给作者之前，有三层检查：

- **程序检查**：结果作为「提醒」显示在待确认条上，同时交给审稿参考。
- **单块审稿**：专项审稿开启时，②在交给作者前先过一遍审稿（只审已完成的部分），有 high/medium 问题自动改一轮。③④只做程序检查。
- **跨块审稿**：⑤之后一定会跑。针对⑤的问题自动改一轮；针对已锁定块的问题作为「建议」，随⑤一起交给作者，每条带「解锁并修改」。

### 11.4 关键节点

节点存在 `story_nodes`，是唯一事实来源；`books.spine` 只保留核心矛盾、主题、主角成长弧。

**字段**：顺序 `position`、类型（开篇 / 节点 / 结局）、名称、发生什么、之前得先有（`prerequisite`）、之后变成（`consequence`）、约第几卷、状态、来源（ai / author）、编辑批注、技巧。开篇恒为第一个，结局恒为最后一个。

**三种状态**：

- 铁钉 `pinned`：作者确认过的硬约束。AI 改写、审稿、插话分析、写作中的卷纲规划都不能改它；审稿只能提建议。
- 暂定 `pencil`：AI 提的。写作中拆到相关的卷时，主编可以按已经写出来的内容提议调整，随卷纲一起请作者批准。
- 留空 `empty`：只在②等确认时存在。作者确认（或点「交给编辑部定」）时，编辑部把空位补成暂定节点。

**谁定状态**：作者亲手新增的节点默认是铁钉。作者改了暂定节点的文字，它仍是暂定；要钉死需要明确点一下。

**节点操作**：

- 钉死 / 改回暂定、编辑、删除（开篇和结局不能删）、在某处插入、上移下移。
- 「给我 3 个候选」「补上这个空位」。
- 「我自己写一句」：作者只写名称或一句话，主编补全其余字段，名称尽量保留作者的说法。

**提示词里的编号**：节点一律按当前顺序编号为「节点 1…k」，模型用序号引用；程序用渲染提示词时的同一份顺序快照，把序号映射回节点 ID。改写节点时，模型用 `ref` 指明改的是哪个原节点。铁钉节点由程序按数据库原样放回，模型漏掉了也补回原来的位置。

**程序检查**：

- 有且只有一个开篇、一个结局。
- 中间节点 6-12 个（超出范围只提醒）。
- 「之前得先有」和「之后变成」不能为空。
- 约第几卷不倒退，不超过计划卷数。
- 连续 3 卷以上没有节点时提醒。
- 还有留空的节点时提醒。

### 11.5 锁定与解锁

- 逐块模式下，「确认这一块」就是锁定，状态写进 `books.setup_progress`。
- 锁定的块，审稿、插话分析、作者意见分派都不能给它写修改要求。确实需要改时，产出「解锁请求」（哪一块、为什么），界面让作者点「解锁并修改」。
- 解锁某一块时，它和它后面已确认的块一起回到待确认。这一块按要求修改，后面的块按同步要求逐块重新检查、逐块再确认；铁钉节点原样保留。
- 一口气模式下没有块锁定，但铁钉节点照样生效：作者在最后拍板前可以在拼图板上钉节点，提意见后的修改不会动铁钉。
- 开书完成后，块锁定失效；设定和大纲仍可以在页面上手改，规则同现在。节点的铁钉 / 暂定状态延续到写作阶段。

### 11.6 期待感台账

伏笔是暗的，读者不知道它重要；期待是明的，读者知道、一直在等，比如三年之约、大比将至、谁要被打脸、何时找到母亲。读者追更靠的就是期待。

**存储**：沿用伏笔台账 `foreshadowings`，新增 `kind`（伏笔 / 期待）和可选的 `node_id`。

- 编号和伏笔共用一个序号空间，只是显示前缀不同：伏笔是 F7，期待是 E8。
- 动作沿用「埋下 / 提醒 / 回收」。对期待来说含义是「立下 / 提醒 / 兑现」，界面显示后者。

**跨度**：

- 短：几章内兑现，一般由章末钩子承担，不进台账。
- 中：单元或卷内兑现。拆卷纲时每卷新立 1-3 条。
- 长：跨卷兑现。④产出 2-6 条。

**要求**：每个剧情单元至少立下、提醒或兑现一条期待；兑现要超出读者预期——比读者以为的更大、更快，或者换个角度。

**程序检查**：

- 拆卷纲时，计划在本卷立下或兑现的期待要排进单元。
- 出章纲时，已立下、未兑现的期待，中线超过 20 章、长线超过 50 章没被提起的，要在本单元安排一次提醒。
- 本单元开始时如果没有任何开着的中长线期待，提醒主编新立一条。

**写正文时**：期待任务和伏笔任务一起交给写手；提醒和兑现同样附上立下那一章的原文片段。

### 11.7 情绪曲线

**章纲新增两项**：

- `emotion`：-2 憋屈压抑、-1 偏压、0 平稳或悬着、1 偏扬、2 爆发爽快。
- `mood`：爽、燃、甜、虐、悬、笑、暖、惊。

**节奏底线**（按打法给数值，「后宫玄幻爽文 / 通用」）：

- 连续压抑（情绪 ≤ -1）最多 3 / 5 章。
- 一个单元里压抑的章不超过三分之一 / 二分之一。
- 同一种主情绪不连续 4 章。
- 单元里情绪最高的一章放在最后两章内。

这些底线以文字形式交给出章纲的主编。

**检查与重出**：出章纲后程序按底线检查。不合格时，把问题作为修改要求让主编重出一次（只重出一次）。再不合格就照常建章，问题记在单元上，卷页给出提示。

**用法**：写手和审稿看到的章纲都包含这两项。写手据此写足情绪；审稿据此判断「计划是爆发，写出来爽不爽」。卷页每个单元显示一条按章纲画的情绪小曲线。

### 11.8 信息差表

扮猪吃虎、身份揭晓、打脸的爽感都来自信息差；长篇里「不该知道的人知道了」也是最常见的穿帮。

**存储**：新表 `secrets`。字段有编号 S1…、短名、真相、知情人（姓名、从第几章知道、怎么知道）、读者知不知道（知道 / 不知道 / 部分，旧数据可为空）、计划怎么揭开、揭开节点（可选）、状态（隐藏 / 公开）。人物卡原来的 `secrets` 文本迁移成表里的行，然后删除这一列。

**谁来写**：

- ③由设定师建 4-10 条。
- 拆卷纲、出章纲时可以安排「揭晓」：哪个秘密、揭给谁（某人 / 读者 / 众人）、怎么揭。
- 每章定稿后，设定师记下这一章谁新知道了什么、秘密有没有公开、有没有新的关键秘密。程序只认已有的人物和编号，改动写进 `bible_changes`，重写这一章时撤销。

**谁来用**：

- 写手：拿到本章出场人物相关的信息差——谁知道、谁不知道、读者知不知道、本章要揭的是什么。
- 查矛盾：对照它找「不该知道却知道了」。
- 拆卷纲、出章纲：用它安排揭晓和扮猪吃虎。

### 11.9 编辑批注与术语表

- 方向、节点、分卷卡片、剧情单元都带 `editor_note`（这里用了什么技巧、想让读者有什么感受，一两句白话）和 `techniques`（最多 3 个技巧名）。
- 技巧名只能取自术语表 `backend/app/prompts/glossary.md`（格式为 `## 术语` 加白话解释），程序会丢掉表外的名称。术语表在提示词页可以改，归入「角色与规矩」组；界面通过 `GET /glossary` 读取解释。
- 界面上，技巧显示为小标签，点开看解释；批注显示在卡片底部，字号同辅助说明。

### 11.10 界面

三栏不变，改动集中在右栏稿件和左栏目录。

- **拼图进度条**：开书期间固定在稿件栏顶部，一行五块，状态为已确认（打勾）/ 正在做 / 等你确认（高亮）/ 未开始；②显示「节点 6/9」（已钉 / 总数）。点击进入那一块的页面。窄屏时缩成一行「② 节点 6/9」。
- **左栏**：开书期间，书稿目录最上面一组是「开书拼图」，列出五块和各自状态；开书完成后这一组收起。「主线骨架」入口改名「全书地图」。
- **选方向**：放在概览页。竖排 3 张方向卡，每张显示名称、一句话故事、主角、金手指、开局、卖点、舞台阶梯、基调、读者、与其他方向的区别、批注，各带一个「选这个」。卡片上方选篇幅（沿用原来的篇幅选项和推荐），下方一个「想混搭就写在这里」输入框；另有「都不满意，重新出」。
- **拼图板**：原主线骨架页 `/spine` 升级而来，是一条竖向时间轴。
  - 节点卡按状态显示：实心（铁钉）、虚线（暂定）、点线空卡（留空）。
  - 卡内：名称、发生什么、之前、之后、人物锚点小标签、批注和技巧。
  - 卡上按钮：钉死 / 改暂定、改、删、换候选、在下面插入、上移下移。留空卡上：给我 3 个候选、我自己写一句。
  - ④之后，节点之间显示分段带，如「第 3-4 卷 · 约 110 章」，可以展开看卷卡片。
  - 顶部统计，如「9 个节点 · 5 铁钉 · 3 暂定 · 1 留空」。
- **待确认条**：沿用拍板条的位置，文字如「待你确认：关键节点（还有 1 个空位）」，按钮为「确认这一块」「交给编辑部定」，下方列出程序提醒和审稿建议（⑤）。已确认块的页面顶部有「重新打开这一块」；点击后的确认框说明后面已确认的块也会重新检查。
- **替你做的决定**：显示在块页面顶部。每个决定可以单选换成其他选项；有改动时出现「按我选的改」。
- **卡片和对话联动**：卡片上点「改」，切到群聊，输入框预填「关于节点 3「飞升神界」：」，发出后作为这一块的修改意见（带节点 ID）。等待确认期间在对话框里打的字，一律作为当前这一块的修改意见。
- **候选**：点「给我 3 个候选」后，三张候选卡显示在该节点下方。「用这个」直接替换内容（仍为暂定），「都不要」关闭候选。
- **全书地图**：开写之后，概览页的主线骨架区块换成横向迷你地图——节点圆点、已写部分着色、「写到这里」标记，以及「第 3 卷 42/60 章 · 离「飞升神界」还有 18 章」。拼图板同样标出当前写作位置，已经走过的节点打勾。
- **卷页**：卷卡片显示本卷走向的节点和批注；单元卡显示情绪小曲线、期待动作（E）、揭晓（S）、批注和技巧；有节奏问题的单元显示提示。
- **设定库**：「伏笔」页改为「伏笔与期待」，可按类型筛选；新增「信息差」页，每个秘密一行，显示知情人、读者知不知道、计划怎么揭、状态。

### 11.11 写作阶段

- **卷与节点**：分卷卡片带 `target_node_id`（本卷走向的节点）和 `reaches_node`（节点就发生在本卷）。拆卷纲时交给主编的是：本卷走向的节点（名称、发生什么、之前得先有、铁钉 / 暂定）和再下一个节点。本卷结束时要让节点的前提成立；`reaches_node` 为真的卷，以这个节点为卷末高潮。
- **调整暂定节点**：节点是暂定的、且按前文已经不自然时，卷纲里可以提议调整，写成结构化的新名称、发生什么、之前、之后。提议随卷纲拍板一起显示，批准就应用；关闭卷纲拍板时自动应用。
- **铁钉节点有冲突**：铁钉节点不能调整，主编只能在 `node_conflict` 里说明冲突，交给作者处理。
- **卷纲专项审稿**：从四项变为五项，新增「期待感」——每个单元有没有立下、提醒或兑现期待，兑现是否超出预期，有没有长时间没有期待的空档。
- **其余接入**：出章纲时带情绪、期待、揭晓（见 11.6-11.8）；备资料、写正文、查矛盾、定稿提取都接入信息差表。

### 11.12 数据与兼容

**新表**：`story_nodes`、`node_anchors`（节点、人物、类型、说明，随节点或人物删除而级联删除）、`secrets`。

**新列**：

- `foreshadowings.kind / node_id`
- `volumes.target_node_id / reaches_node / editor_note / techniques`
- `plot_units.reveals / editor_note / techniques / plan_issues`
- `books.setup_progress`
- `books.settings.setup_mode`（JSON 字段，不是表列）
- `story_nodes.updated_by_volume`（迁移 0012：暂定节点被第几卷的卷纲调整过）

**删除**：`characters.secrets`。

**迁移（0011）**：

- 旧书 `spine` 里的开篇、关键转折、结局转成节点，全部为暂定、来源 ai；`spine` 只留核心矛盾、主题、成长弧。
- 按节点的「约第几卷」给已有分卷补 `target_node_id`（取第一个「约第几卷 ≥ 本卷」的节点）和 `reaches_node`。
- 人物的 `secrets` 每条转成一条信息差：知情人为该人物，「读者知不知道」为空。
- 台账里已有的条目全部标为伏笔。
- 已开完书的 `setup_progress` 记为一口气模式、五块全部已确认。

**其他兼容**：

- 章纲 JSON 新增的字段不迁移；旧章纲没有情绪数据时，曲线留空。
- 提示词覆盖：默认模板的变量集合变了以后，已有的自定义版本仍按原样渲染，但用不到新功能。提示词页对这类模板标「默认版本已更新」，显示新增的变量，作者可以恢复默认或自行合并。
- 演示模式要补齐所有新增的结构化产出，保证没有 Key 也能跑通两种开书模式和写作。

### 11.13 不在第一包

实力尺（境界结构化）、AI 味统计、手机阅读指标、范文与人物声口、开篇专项、章纲先查的其余项、追读分、毒点清单、局部修改、包装，分在第二、三包。
