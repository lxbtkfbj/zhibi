# 执笔 · 设计说明

> 多 Agent 长篇小说创作平台。本文是项目的设计依据，功能与架构变更时同步更新。

## 1. 定位

- 一个由 AI「编辑部」协作写长篇小说的工具：作者给出点子（或导入已有小说），编辑部分工完成设定、大纲、正文与审稿，作者只在关键节点拍板。
- 「设定库」是地基：人物、关系、世界观、伏笔、时间线随写作自动维护，保证长篇前后一致。
- 作者角色：**甩手掌柜**。支持从零开新书与续写已有小说两种入口。

## 2. 编辑部角色

| 角色 | 职责 |
|---|---|
| 主编 | 定方向与卖点、写大纲与细纲、分派工作、处理作者意见、最终把关 |
| 设定师 | 建立与维护设定库；为写手准备本章资料；检查新章节与设定的矛盾 |
| 写手 | 按细纲与资料写正文，遵守文风参考 |
| 审稿 | 站在读者角度挑刺：节奏、冲突、人物是否崩坏、钩子、逻辑漏洞 |

拆分角色的理由：每个角色上下文只含自己所需资料，职责单一；审稿与写手上下文隔离，避免被写手的思路带偏；问题可按环节定位。

## 3. 核心流程

### 3.1 开新书
作者输入点子（可附文风参考）→（可选）主编先问作者几个关键问题：篇幅固定要问，其余按点子挑选，如主角名字、金手指方向、开局、感情线、结局倾向；每题给出选项和推荐，作者不答的交给编辑部决定 → 主编定书的概念（类型、卖点、主角钩子、基调、篇幅）→ 设定师建世界观与主要人物 → 主编定主线骨架（核心矛盾、主角成长弧、开篇、结局、6-12 个全书关键转折，标明所在卷）→ 主编做**线索规划**（4-10 条线：主线、每位女主一条感情线、反派阶梯、谜团线、成长线；每条线拆成落在各卷的节拍）→ 主编写**全书总纲**（每卷一张卡片：舞台、概要、卷末目标、高潮、主要对手、主角实力区间、推进哪些线、新登场人物、预计章数；另列跨卷的长线伏笔，带计划埋下与回收的卷）→ 主编拆**第一卷卷纲**（剧情单元，每单元写清推进的线索与伏笔动作，另新埋本卷的短线、中线伏笔）→ 审稿挑刺（除逻辑外，查线索是否断线、感情线是否雷同、反派是否降智、破局是否重复、伏笔是否只埋在前期）→ 必要时自动修改一轮 → **作者拍板**（批准 / 提意见；提意见后主编判断需要改哪些部分，交给对应角色修改，再次拍板）。

**分层滚动规划**：一次调用规划不了上千章，所以分四层、写到哪规划到哪——开书时只定总纲；每卷写到之前拆卷纲并请作者拍板；每个剧情单元写到之前出章纲；然后逐章写。每次规划都能拿到「实际已经写成什么样」作为前情，可以随时调整。

**伏笔台账**：每条伏笔有书内编号（F1、F2……）、跨度（短：单元内收；中：卷内收；长：跨卷）、计划埋下与回收的卷、状态（未埋 / 已埋 / 已收 / 放弃）以及实际埋下、提醒、回收的章节。卷纲与章纲用编号安排动作，章节定稿后设定师把正文里实际发生的动作记回台账。

**插话**：编辑部工作时作者随时可以插话。插话不打断正在进行的那一步；每一步做完后主编先读新的插话，判断已完成的部分是否需要改（需要改就排进计划，并按 `cascade` 联动下游），还没做的部分直接按插话写。作者对提问的回答、插话和拍板时的修改意见都作为「作者的要求」带进之后每个角色的提示词，后面的要求与前面冲突时以后面的为准。方案交给作者拍板后，插话改走「提修改意见」。

### 3.2 写书主循环（第 2 步）
作者选这一轮写多少（写 N 章 / 写完这一卷 / 一直写到完本）后，编辑部循环执行；每一轮先按**数据库里的进度**决定下一步，所以断点续跑、换一个任务接着写都能接上：

1. 当前这一卷还只有总纲卡片 → 主编拆卷纲（上下文：本卷卡片、前后卷、线索节拍、前情摘要、前面用过的高潮与破局方式、人物当前状态、相关伏笔）→ **作者拍板**（提意见则主编按意见修改后再拍板，意见记入作者要求）。
2. 下一个剧情单元还没有章纲 → 主编出这个单元每一章的章纲（目标、2-4 个场景、冲突、爽点、结尾钩子、出场人物、伏笔动作），建成章节行。
3. 有章纲、未定稿的章 → 写手按章纲写正文（流式；上下文：章纲、所在单元、出场人物完整资料、相关设定、最近 3 章摘要、上一章结尾、文风参考、作者要求）→ 审稿与设定师查矛盾**并行** → 不合格（审稿判退且有中等以上问题，或设定检查发现严重矛盾）退回重写，最多两次 → 仍不合格**交给作者**（直接定稿或给出修改意见）→ 定稿：设定师输出本章摘要、人物状态变化、新人物、伏笔动作，程序校验（只认已有人物与台账编号）后与定稿一起提交。
4. 新书写完前 3 章 → **作者试读**，意见记入作者要求，之后每一章都遵守。
5. 一卷写完进入下一卷；写够本轮章数、写完这一卷（按作者选择）或全书完结就停。

作者在写作中途插话：每写完一步读到，记入这本书的作者要求，之后的卷纲、章纲和正文都要落实。

### 3.3 导入旧书（第 3 步实现）
导入 TXT → 自动分章 → 后台多批并行通读，建立设定库与前情摘要 → 作者选定续写起点 → 进入写章节流程，写手学习原著文风。

### 3.4 拍板点
0. （可选）动笔前回答主编的几个关键问题
1. 开书方案（含第一卷卷纲）与之后每一卷的卷纲（重大转折包含在卷纲的剧情单元中）
2. 新书写完前 3 章试读一次（校准文风与节奏，意见被编辑部记住）
3. 兜底：单章审稿两轮仍不合格时
作者可随时对任意章节提意见，或在连写过程中插话。

## 4. 架构

```
网页（React）          Claude / Cursor（MCP，第 5 步）
        \                 /
     后端服务（Python + FastAPI，SSE 推送会议室）
                 |
     AI 编辑部（LangGraph 编排，运行在 Celery worker）
                 |
 PostgreSQL（业务数据 + 设定库 + LangGraph 检查点）
 Redis（任务队列 + 会议室消息流）   Milvus（原文混合检索，第 3 步）
```

- **LangGraph**：编辑部流程是一张图；`interrupt` 实现拍板暂停，`AsyncPostgresSaver` 检查点实现断点续跑。
- **Celery + Redis**：开书、连写、通读旧书等长任务在后台 worker 执行；worker 崩溃后任务重新投递，从检查点继续。
- **会议室消息**：worker 把每条发言写入 PostgreSQL（可回放）并推送到 Redis Stream；后端通过 SSE 推给网页，断线后按消息 ID 补齐。
- **模型**：OpenAI 兼容接口（DeepSeek / GLM 等），每个角色可分配不同模型配置；API Key 加密存储。内置「演示模式」模型，无 Key 也能跑通全流程。
- **结构化输出**：各角色的产出（概念、设定、大纲、审稿意见、设定变化）均为 Pydantic 模型，经校验后入库。
- **向量检索（第 3 步）**：本地 bge-m3 向量化；Milvus 稠密向量 + BM25 混合检索，RRF 融合，再重排。
- **可观测（第 4 步）**：Langfuse 记录每次调用的耗时与 token；业务侧另记 `llm_calls` 用于界面展示。

## 5. 数据模型（第 1 步）

- `books`：书（来源 new/imported、点子、文风参考、概念 JSON、主线骨架 JSON、作者要求列表、是否已试读、状态 setting_up / awaiting_approval / ready / writing / completed）
- `story_threads`：线索（类型、概要、核心人物、各卷节拍）
- `volumes` / `plot_units`：分卷卡片（舞台、概要、卷末目标、高潮、对手、实力区间、推进线索、新登场人物、预计章数、状态 planned / detailed / approved / done）与剧情单元（目标、冲突、高潮、结果、关键事件、推进线索、伏笔动作、状态 planned / outlined / done）
- `characters` / `relationships` / `world_entries` / `foreshadowings`：设定库；伏笔即台账（编号、跨度、计划埋/收的卷、状态、埋下 / 提醒 / 回收的章节）
- `chapters`：章节（全书章号、章纲 JSON、正文、字数、摘要、最近一次审稿结果、重写次数、状态 planned / drafting / final）
- `draft_versions`：开书方案各轮版本（AI 生成 / 作者修改）
- `jobs`：后台任务（类型、状态、LangGraph thread_id、等待作者处理的内容：动笔前的提问或待拍板的方案、错误）
- `meeting_messages`：会议室发言（角色、类型、内容、附带数据）；作者插话的类型为 `note`，流程按消息 ID 记录读到哪一条
- `llm_profiles` / `role_assignments`：模型配置与角色分配
- `llm_calls`：每次模型调用的耗时与 token

## 6. 技术栈

Python 3.12 · FastAPI · Pydantic v2 · SQLAlchemy 2（async，psycopg3）· Alembic · LangGraph · LangChain OpenAI · Celery · Redis · PostgreSQL · Milvus · React + TypeScript + Vite · Tailwind CSS · TanStack Query · Docker Compose · pytest · ruff

## 7. 分步计划

1. **地基 + 开新书**：项目骨架、模型配置、开书流程（LangGraph + 拍板 + 断点续跑 + 会议室）、设定库与大纲的查看编辑
2. **编辑部写章节**（主体已完成）：分层滚动规划、章节流程、并行审稿查矛盾、退稿循环、试读拍板、连写 N 章、中途插话、设定库与伏笔台账自动更新；之后提质：题材打法库、多方案比稿、专项审稿
3. **旧书导入 + 原文检索**：TXT 分章、并行通读、Milvus 混合检索、带出处的设定问答
4. **评测 + Langfuse**：设定问答评测集、矛盾检测评测集（埋点矛盾，计算查出率与误报率），跑 → 分析 → 改进 → 再跑
5. **MCP 服务**：查设定、问剧情、看进度、触发写作、读章节
6. **上线收尾**：部署演示站（免注册）、README 与架构图

## 8. 暂不做

读者段评、配音、插图、多用户登录、手机端；QLoRA 微调列为可选。
