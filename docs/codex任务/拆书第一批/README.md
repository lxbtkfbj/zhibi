# 拆书第一批：导入、分章、能读

产品规则以 `docs/设计说明.md` 第 14 节为准（体检和取舍见 `docs/拆书/架构体检.md`，分章试出来的坑见 `docs/拆书/试验记录.md`）。本目录是交给 Codex 的实施任务：按顺序做，一次一个任务，前一个做完并提交后再开下一个。

一句话概括这一批：作者能在书房里「拆一本书」——选一个 TXT，程序分好卷和章，确认页看一眼就导入；导入的书出现在书房新的一栏「拆的书」，用新书页的四页打开，像看小说一样读原文、搜原文、在群聊里问这本书。**这一批不调模型拆书**，还没有章纲、单元、设定（第二、三批做）；编辑部在拆的书里只回答问题，不改书。

## 共同约定（每个任务都适用）

1. **先读后做**：先读 `docs/设计说明.md` 第 14 节、本文件和任务文件。任务文件和设计说明有冲突时，以任务文件为准（任务文件是照第 14 节细化的，第 14 节里第二、三批的内容这次不做），并在完成说明里指出冲突。
2. **开工前工作区要干净**：另一个对话改过新书页和群聊（Workspace.tsx、Chat.tsx、ChatConvs.tsx、Saves.tsx、Inbox.tsx、BookDesk.tsx、chat_agent.py、chat_context.py、group_notes.py、设计说明……）。`git status` 不干净就停下来问作者，不要动别人没提交的改动，也不要替它提交。
3. **语言**：界面文字、提示词一律用简体中文。界面上的说法照任务文件写的抄，不要自己换词。
4. **提示词由设计方提供**：本目录 `提示词/` 下是写好的模板，任务里写明哪些要用 `git mv -f` 搬进 `backend/app/prompts/`。不要改措辞；新模板的变量登记到 `app/prompts/catalog.py`。由程序拼出来再填进模板的文字，逐字照抄任务文件。
5. **自己的书不受影响**：凡是加了「是不是拆的书」判断的地方，作者自己的书走原来的路，行为不变。界面上该不该显示什么，一律看「是不是拆的书」（`book.source == "teardown"`），不看书的状态。
6. **不调模型**：这一批没有新的模型调用。群聊照常用作者配的模型；测试和验收用演示模式（`app/llm/demo.py`），群聊新模板要在演示模式下能出回答。
7. **不碰作者的服务和书库**：不要升级、重启或改动作者日常的 8000／4320 服务和书库，不要运行 `start.ps1`。验收一律用独立的数据库、Redis 库和端口。
8. **检查命令**：开发中只跑相关测试；提交前跑一次全量，全部通过才算完成。
   - 后端（`backend/`）：`uv run ruff check . && uv run ruff format --check . && uv run pytest -q`
   - 前端（`frontend/`）：`npx tsc -b && npm run lint && npm run build && npm run test:workspace`
9. **验收**：照任务文件最后一节做，结果写进 `docs/拆书第一批验收.md` 对应小节，截图放 `docs/拆书第一批验收/`（截图少而准，每项一两张）。导入真书用作者桌面上的两本 TXT（只读，不要改、不要挪）：`C:\Users\cxc\Desktop\逆天邪神(1-500章).txt`、`C:\Users\cxc\Desktop\都重生了谁考公务员啊.txt`。
10. **文档同步**：任务完成后，在设计说明第 14 节开头的状态行写明哪些已实现；实现时和第 14 节说法不一样的地方（接口名、字段名），在第 14.4 节后面补一小段「第一批实现」。
11. **分支与提交**：仓库没有远程，直接在当前分支（feat/setup-interview-spine）上做。提交信息以「拆书第一批任务 N：」开头。
12. **完成说明**：做完后用一段中文告诉作者：改了什么、迁移做了什么；搬了哪些提示词；跑了哪些检查、结果如何；验收写在哪里；有没有没做完、做不到、或和设计说明对不上的地方。

## 名词对照（写代码时用）

| 界面上的叫法 | 代码里 |
|---|---|
| 拆的书 | `books.source = "teardown"`（原来的 `imported` 留给以后导入自己的书接着写，这次不用） |
| 拆书信息 | `books.teardown`（JSONB）：拆到哪一步、原书作者、原书简介、分章情况 |
| 还没确认分章 | `books.teardown.stage = "confirming"`：刚上传，确认页还没点「导入」 |
| 还没开拆 | `books.teardown.stage = "imported"`：导入了，只有原文（第二批再加「排队中」「在拆」「停了」「拆完了」） |
| 上传的原文件 | 新表 `teardown_sources`：只在「还没确认分章」时存在，导入后删掉 |
| 章上的拆书信息 | `chapters.teardown`（JSONB）：原书标题、原书章号、标记；第二批在这里加逐章记的记录 |
| 还没归单元 | 大纲树接口里虚的单元，不在库里 |
| 不像正文 | 分章标的 `不像正文`、`空的`，默认不导入，确认页能勾回来 |
