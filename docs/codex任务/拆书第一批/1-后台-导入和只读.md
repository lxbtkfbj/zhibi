# 任务 1：后台——导入和只读

对应设计说明第 14.2 节第 1–3 条、14.4 节，第 14.5 节第 1 批的后台部分。这个任务只做后台，不改页面。

## 1. 数据（迁移 0023）

1. `books.teardown`：JSONB，默认 `{}`（`server_default='{}'`）。拆的书的拆书信息都在这里，作者自己的书永远是 `{}`。第一批的结构：

   ```json
   {
     "stage": "confirming",
     "author": "火星引力",
     "intro": "原书简介……",
     "file": {"name": "逆天邪神(1-500章).txt", "size": 5301234, "encoding": "utf-8"},
     "split": {"chapters": 499, "volumes": 5, "chars": 1720000, "ads_removed": 6, "duplicates_removed": 0, "by_length": false},
     "excluded": [{"title": "上架感言", "chars": 812, "reason": "不像正文"}],
     "number_issues": [{"index": 414, "title": "……", "number": 415, "expected": 414, "kind": "跳了"}],
     "open_volume_id": null,
     "imported_at": "2026-10-20T10:00:00+08:00"
   }
   ```

   - `stage`：`confirming`（刚上传，确认页还没点「导入」）、`imported`（导入了，还没开拆）。第二批再加别的值，代码里别的值一律当「还没开拆」处理。
   - `split`、`excluded`、`number_issues`、`imported_at`、`open_volume_id` 在导入时写；`confirming` 时只有 `author`、`intro`、`file`。
   - `open_volume_id`：原书没有卷时，导入建的那一卷的 id（第二批的「还没收尾」那一卷）；原书有卷时为 `null`。
2. `chapters.teardown`：JSONB，默认 `{}`。拆的书每章写 `{"raw_title": "第一章 陨落的天才", "number": 1, "flags": ["太短"]}`：`raw_title` 是原书那一行标题原样，`number` 是原书标题里的章号（序章、楔子、按字数切的为 `null`），`flags` 是分章的标记（`番外`、`太短`、`按字数切的`，勾回来的再加上它原来的 `不像正文` 或 `空的`）。第二批在这里加逐章记的记录，这次不加。
3. 新表 `teardown_sources`：`book_id`（主键，外键 books.id，删书跟着删）、`filename`、`size`、`data`（bytea，上传的原文件原样）、`encoding`（作者在确认页选的编码，空字符串表示自动认）、`preview`（JSONB，最近一次分章的确认页数据，见第 3 节）、`created_at`。只在「还没确认分章」时存在，导入时删掉这一行。**不进存档**（不加进 `book_saves.TABLES`）。
4. `books.source` 新加一个值 `teardown`，列不用改。`books.status` 用一本开完书、正在写的书用的值，让新书页直接打开四页、不走开书流程；在完成说明里写用的是哪个值。
5. 迁移不改已有数据，作者自己的书 `teardown` 都是 `{}`。

## 2. 分章

照 `docs/拆书/分章试验/split_txt.py` 写进 `app/services/teardown_split.py`（规则照搬，命名可以改成项目的风格），测试照 `docs/拆书/分章试验/try_split.py` 的十种样子写成 pytest。在试验版上加下面几条：

1. **「第X卷完结」不当新卷**：卷标题的卷名部分以「完结」「完」「终」「结束」开头（例「【第一卷完结。】」），这一行不是卷标题，当普通的一行留在正文里，不新开一卷。
2. **「第X卷“名字”开启」只取引号里的名字**：卷名部分里有成对的引号（“”、「」、『』、""），卷名只取第一对引号里的字（例「【第二卷“苍风烟云”开启……关键字：……】」→ 卷名「苍风烟云」）。没有引号的照旧。
3. **原书章号**：认成「章」「回」「节」的标题，把标题里的数字解析成整数（阿拉伯数字、全角数字、中文数字，含「零」「千零」「两」「百十」这些写法），记在每章上；序章、楔子这类特殊章、按字数切的，章号为空。
4. **章号对不上的地方**：按导入后的顺序，一章一章看有章号的章，和上一个有章号的章比（序章、楔子、番外不参与）：
   - 比上一章大 1：正常，不记；
   - 新的一卷第一章是 1：原书每卷重新编号，正常，不记；
   - 比上一章大 2 以上：`kind` 记「跳了」，`expected` 是上一章加 1（例：第 413 章后面是第 415 章）；
   - 和上一章一样：记「重了」；
   - 比上一章小（又不是新卷从 1 开始）：记「倒回去了」（例：第 363 章后面是「第36章」，下一章又是第 365 章——这时第 365 章比上一章 36 大很多，**不要再记一条「跳了」**：一章的章号要是比前一章、后一章都对不上，而前后两章对得上，只记这一章一条，`kind` 写「打错了」，`expected` 写前一章加 1）。
   - 每条写 `index`（导入后的顺序号）、`title`（原书那一行标题）、`number`、`expected`、`kind`。最多记 50 条，多了只记前 50 条，另给总数 `number_issue_total`（放进 preview 和 `books.teardown.split`）。
5. **编码**：`split` 加一个参数，能指定编码（`utf-8`、`gb18030`、`utf-16`、`big5`）；指定的编码读不出来（解码出错）时报错，不要静默换成别的编码。不指定时照试验版自动认。
6. **书名**：文件开头认出了书名就用它；没有就用文件名：去掉扩展名、书名号《》，再去掉末尾括号里带数字或「章」「完」「全本」「精校」「txt」的部分（例「逆天邪神(1-500章)」→「逆天邪神」、「【精校】某某书（全本）」→「某某书」）。

分章要快：50MB 的文件在网页后端里几秒内分完（放进线程池跑，别挡住事件循环）。

## 3. 接口

都挂在网页后端，前端任务 2 照这些做。错误一律用 `HTTPException`，`detail` 写给作者看的中文。

### 3.1 上传：`POST /api/teardown`

- multipart，字段 `file`。只收 `.txt`（看扩展名，不分大小写），否则 422「只能导入 TXT 文件」；超过 50MB（52,428,800 字节）413「文件超过 50MB」；分完一个字都没有 422「文件里没有文字」。
- 认编码、分章，建一本书：`source="teardown"`，书名照第 2 节第 6 条，`teardown={"stage":"confirming","author":…,"intro":…,"file":{…}}`；存 `teardown_sources`（含 `preview`）。不建卷、不建章。
- 返回确认页数据（第 3.2 节），HTTP 201。

### 3.2 确认页数据：`GET /api/teardown/{book_id}/preview`

- 只有 `stage == "confirming"` 的书能取，导入过的 409「这本书已经导入了」；不是拆的书 404。
- 返回（就是 `teardown_sources.preview`，外加书名、作者取书上现在的值）：

  ```json
  {
    "book_id": "…",
    "title": "逆天邪神",
    "author": "火星引力",
    "intro": "……",
    "file": {"name": "…", "size": 5301234},
    "encoding": "utf-8",
    "encoding_auto": true,
    "chars": 1720000,
    "chapter_count": 499,
    "volumes": [{"index": 1, "title": "……", "chapters": 101}],
    "first": {"index": 1, "title": "序章"},
    "last": {"index": 499, "title": "……"},
    "opening": "开头几行原文",
    "excluded": [{"order": 54, "title": "上架感言", "chars": 812, "reason": "不像正文", "head": "正文前 60 字"}],
    "number_issues": [{"index": 414, "title": "……", "number": 415, "expected": 414, "kind": "跳了"}],
    "number_issue_total": 2,
    "ads_removed": 6,
    "duplicates_removed": 0,
    "by_length": false
  }
  ```

  - `chapter_count`、`chars`、`first`、`last`、`volumes[].chapters`、`number_issues` 都按「不像正文、空的都不算」算（默认导入的样子）；勾回来以后由前端自己加，不用再请求。
  - `excluded[].order` 是这一章在分章结果里的位置（从 0 起，包括被排除的），导入时用它说勾回了哪几章。`reason` 是「不像正文」或「空的」。
  - `opening`：第一章正文的前 300 个字（看得出是不是乱码）。
  - `by_length`：一个标题都没认出、按字数切的。

### 3.3 换编码：`POST /api/teardown/{book_id}/encoding`

- body `{"encoding": "gb18030"}`，值只能是 `auto`、`utf-8`、`gb18030`、`utf-16`、`big5`；`auto` 表示回到自动认。
- 用存着的原文件重新分章，更新 `teardown_sources.encoding`、`preview`；书名、作者、简介如果作者还没在确认页改过，跟着新的分章结果换（作者改过的不动：前端改书名走 `PATCH /api/books/{id}`，后端在 `books.teardown` 里记 `title_edited: true`）。
- 读不出来 422「用 GB18030 读不出来，换一种试试」（编码名照界面上的写法：UTF-8、GB18030、UTF-16、BIG5）。返回新的确认页数据。

### 3.4 导入：`POST /api/teardown/{book_id}/import`

- body `{"title": "逆天邪神", "author": "火星引力", "include": [54]}`：`title`、`author` 可以不给（不给就用书上现在的）；`include` 是确认页勾回来的 `excluded[].order`。
- 只有 `confirming` 的书能导入，否则 409「这本书已经导入了」。
- 用存着的原文件和编码重新分章（和确认页看到的一样），写库，**一个事务里做完**：
  - **卷**：原书分了卷，照原书一卷一行 `volumes`（`index` 从 1 起，`title` 是卷名，`chapter_count` 是这一卷导入的章数）；原书没分卷（包括按字数切的），建一卷，标题「还没分卷」，`books.teardown.open_volume_id` 记它的 id。卷的状态用写完的值，让大纲树把它算成写完。
  - **章**：只写导入的（默认的加上勾回来的），`index` 从 1 起按顺序编；`title` 是去掉章号以后的章名（「第一章 陨落的天才」→「陨落的天才」，标题里只有章号的就是空字符串，界面显示「第 N 章」）；`content` 是正文；字数照项目里现成的算法；`status="final"`、`source="imported"`、`volume_id` 是它那一卷、`unit_id` 为空、`outline={}`；`chapters.teardown` 照第 1 节第 2 条。一千多章要批量插入，50MB 的书导入几秒内做完。
  - **书**：`books.teardown` 补上 `stage="imported"` 和第 1 节第 1 条的其余字段（`number_issues` 按导入后的顺序号重新算）；书名、作者用 body 里的。
  - 删掉 `teardown_sources` 这一行。
  - 事务提交以后，照现有的自动存档办法存一档，说明写「导入原文」。
- 返回 `GET /api/books/{id}` 的结果。

### 3.5 不导入了

确认页的「不导入了」直接调现有的 `DELETE /api/books/{id}`，删书时 `teardown_sources` 跟着删。不用新接口。

### 3.6 书的接口带上拆书信息

`GET /api/books`（书房列表）和 `GET /api/books/{id}` 多两个字段：`source`，和 `teardown`（拆的书才有，作者自己的书是 `null`）：

```json
{"stage": "imported", "author": "火星引力", "intro": "……", "chars": 1720000, "chapters": 499, "volumes": 5, "number_issue_total": 2, "excluded_count": 1, "open_volume_id": null}
```

`confirming` 时 `chars`、`chapters` 用 preview 里的数。

## 4. 大纲树：虚的「还没归单元」

`GET /api/books/{id}/outline-tree` 只对拆的书改：

1. 每一卷里，`unit_id` 为空的章，装进这一卷 `units` 最后一个虚的单元：

   ```json
   {"id": "unassigned-<volume_id>", "virtual": true, "index": null, "title": "还没归单元", "summary": "", "chapter_count": 312, "status": "done", "locked": true,
    "chapters": [{"index": 1, "title": "序章", "status": "final", "word_count": 3120}]}
   ```

   没有这样的章就不加。真的单元照旧，多一个 `"virtual": false`。
2. 拆的书每章多给 `word_count`（大纲页章那一页要写「正文 · 3,120 字 · 去读」）。
3. 卷多一个 `"open": true/false`：是 `books.teardown.open_volume_id` 那一卷为 true（界面在卷名旁标「还没收尾」）。
4. 作者自己的书输出不变（可以都带上 `virtual: false`、`open: false`，前端不靠它们判断自己的书）。

「还没归篇」这一批用不上（拆的书这一批没有篇），第二批再做。

## 5. 不读正文

下面几处读章节时不要把 `content` 读出来（用 `defer` 或只选要的列），作者自己的书也一样：

- 大纲树（`outline_tree`）；
- 章节目录 `GET /api/books/{id}/chapters`（包括带章纲的那种）；
- 群聊备资料里列全书章节的地方（`chat_context` 里查章节列表的，`chat_agent.agent_values` 已经 defer 了，照它的样子）。

要用正文的地方（读一章、搜原文、群聊里引一章原文）照旧。改完各量一次 670 章那本书的耗时，写进验收。

## 6. 搜原文：`GET /api/books/{id}/search?q=天毒珠`

- 所有书都能用（自己的书搜写出来的正文）。`q` 去掉首尾空白后 1–30 个字，否则 422「要搜的词 1 到 30 个字」。
- 返回 `{"word": "天毒珠", "chapters": 37, "results": [{"index": 12, "title": "……", "times": 3, "near": "……前后各 60 字……"}]}`：按章号排，最多 200 条；`near` 是这一章第一次出现的位置前后各 60 字，换行换成空格。
- 和群聊工具 `search_text`（`app/services/chat_tools.py`）用同一个查法，抽成一个函数两边共用。群聊工具在拆的书里没搜到时说「原文里没有「天毒珠」。」，自己的书照旧说「写出来的正文里没有……」。

## 7. 拆的书里后台挡住写书和改结构

加一个检查（例如 `ensure_not_teardown(book, "开写")`），拆的书调到下面这些接口时报 409，`detail` 写：

`拆的书里不能{做什么}：原文和大纲结构照原书来，编辑部只回答问题。`

| 接口 | {做什么} |
|---|---|
| `POST /books/{id}/write` | 开写 |
| `POST /books/{id}/chapters/{index}/rewrite` | 重写 |
| `POST /books/{id}/plan-segment` | 定下一篇 |
| `PATCH /books/{id}/chapters/{index}` 改了 `content` | 改原文 |
| `DELETE /books/{id}/chapters/{index}`、`POST /units/{id}/chapters` | 改大纲结构 |
| `POST /books/{id}/volumes`、`DELETE /volumes/{id}`、`POST /volumes/{id}/units`、`POST /volumes/{id}/units/order`、`DELETE /units/{id}` | 改大纲结构 |
| `POST /books/{id}/arcs`、`DELETE /arcs/{id}`、`POST /books/{id}/nodes`、`DELETE /nodes/{id}`、`POST /books/{id}/nodes/order` | 改大纲结构 |
| `POST /books/{id}/outline/split`（及 `/undo`、`/accept`）、`/outline/move`、`/outline/restore`、`/outline/write` | 改大纲结构 |
| `PATCH /volumes/{id}`、`PATCH /units/{id}` 里改了文字以外的栏（章数、顺序、锁住这些） | 改大纲结构 |
| `POST /units/{id}/expand`、`POST /volumes/{id}/expand` | 让编辑部改书 |
| `POST /books/{id}/drafts`、`POST /books/{id}/fill-entry` | 让编辑部改书 |
| `POST /books/{id}/library/check`、`/fill-gaps`、`/review`、`/rewrite` | 让编辑部改书 |
| `POST /plans/{id}/apply`、`POST /suggestions/{id}/run-chat` | 让编辑部改书 |
| `PATCH /books/{id}/settings` | 改本书设置 |
| `POST /books/{id}/requirements`、`/requirements/apply`、`/requirements/tidy` | 加写作要求 |

上表是照现在的路由列的；做的时候再搜一遍，新出现的写书、改结构、让编辑部动手的接口也要挡住，并写进完成说明。

**照常能用的**：读的接口；改书名（`PATCH /books/{id}`）；手改章纲、章名、卷和单元的文字；设定（角色、条目、伏笔、关系、秘密、类别、卡片栏目）的增删改；存档、回到某一档、删书；群聊（只回答，第 8 节）。

写一个测试：建一本拆的书，上表每个接口调一次都是 409；同样的调用在作者自己的书上不报这个错（现有测试已经覆盖的不用重写）。

## 8. 群聊：拆的书里只回答

### 8.1 新提示词

把 `docs/codex任务/拆书第一批/提示词/chat_teardown.md` 用 `git mv -f` 搬进 `backend/app/prompts/chat_teardown.md`，措辞不要改；变量登记到 `catalog.py`（说明写「拆的书里群聊回答用」）。变量：`material_note`、`book_info`、`library`、`outline`、`viewing`、`related`、`summary`、`recent`、`quote`、`retry`、`note`、`lookup`、`role_focus`。

### 8.2 两条路都换成它

拆的书里，作者在群聊或私聊说的每一句都**当成提问**：

1. **模型会调工具**（现在走 `chat_agent` 的那条路）：工具一律只给查的（`tool_specs(read_only=True)`，`make_changes` 不给），用 `chat_teardown` 代替 `chat_agent`。
2. **模型不会调工具**（现在退回 `group_notes` 分流的那条路）：**不做分流判断、不落地任何修改、不出方案卡**，直接用 `chat_teardown` 回答（不带工具）。作者现在默认的模型只能用 JSON 模式，多半走这一条，要和第 1 条一样好用。

两条路的人设（system）照旧用这个角色平时的人设。

### 8.3 填进模板的文字（逐字照抄）

- `material_note`、`library`、`viewing`、`summary`、`recent`、`quote`、`retry`、`note`：和 `chat_agent` 的取法一样。`library` 为空时写「（还没拆出设定）」。
- `outline`：书里有单元时和 `chat_agent` 的取法一样；还没有单元时（这一批都是这样），每卷一行：

  `第 {卷序号} 卷「{卷名}」：第 {起} 到 {止} 章，还没拆出章纲。`

- `book_info`（三行）：

  ```
  书名：《{书名}》{作者}
  导入了 {章数} 章，{字数}；{分卷}。
  {进度}
  ```

  - `{作者}`：有作者写「（原作者：{作者}）」，没有写「（原作者没写）」；
  - `{字数}`：一万字以上写「共 {四舍五入的万数} 万字」，不到一万写「共 {字数} 字」；
  - `{分卷}`：原书分了卷写「原书分了 {卷数} 卷」，没分写「原书没有分卷」；
  - `{进度}`：这一批固定写「还没开拆：只有原文，章纲、单元、设定都还没有。」
- `lookup`：
  - 会调工具：「上面的设定和大纲只是目录，或者还没拆出来，原文一章都没贴。要细节、要核对，用工具查：某一章的原文和摘要、在原文里搜一个词、设定卡全文、大纲上的一段、伏笔。问「第一次出场」「在哪几章」的，先在原文里搜。能一起查的一次调几个工具；上面已经有的不要再查。」
  - 不会调工具：「你这次查不了资料，上面「和这次的话有关的资料」是程序按作者这句话找出来的：提到的几章、设定，还有作者用引号标出的词在原文里的位置。那里没有的就说没找到，不要猜；作者要找某个词在哪几章，告诉他在正文页目录的搜索框里搜原文。」
- `related`：
  - 会调工具：空字符串。
  - 不会调工具：`【和这次的话有关的资料】` 换行，接上程序找到的资料；什么都没找到写「（没找到）」。资料是：现有的 `related_of` 找到的（提到的设定、第几章、第几卷）；再加作者这句话里用「」“”『』"" 括起来的词（最多 3 个，每个 1–30 字），每个词照第 6 节的查法搜一遍，写成和群聊工具 `search_text` 一样的那几行。
- `role_focus`：拆的书换一套（`chief`、`lorekeeper`、`writer`、`reviewer`）：
  - 主编：「你管剧情、节奏和结构：原书为什么这样安排，钩子和爽点是怎么做出来的，一个单元怎么起、怎么收。」
  - 设定师：「你管设定和前后一致：查清楚再答，说明出处（哪一条设定、第几章原文）。」
  - 写手：「你管怎么写：文风、场面、对话；拿原文的句子说它好在哪。」
  - 审稿：「你管读者感受：站在付费读者的角度，说清哪里让人想追、哪里容易弃书，按影响大小排。」

### 8.4 别的

- 拆的书里不出方案卡、不记写作要求、不放待处理建议；「重说一遍」「停」照常。
- 演示模式（`app/llm/demo.py`）要能答 `chat_teardown`（两条路都要）。

## 9. 不做

- 拆书本身（逐章记、往上归、进度、停下接着拆、拆书队列和工作进程、模型分工「拆书」）、确认页的「开始拆」：第二批。
- 「还没归篇」、设定、「这本书好在哪」：第二、三批。
- 拆的时候挡住手改（`ensure_idle` 那句话）：第二批有拆书任务了再做。

## 10. 验收

1. **测试**：分章（试验版十种样子；第 2 节第 1–6 条各一个例子，「第 363 章、第36章、第 365 章」只记一条「打错了」）；上传、确认页、换编码、导入、不导入了（删书）；导入后卷、章、`books.teardown`、`chapters.teardown` 对得上，`teardown_sources` 删掉了；大纲树虚的单元；搜原文；第 7 节的 409；群聊两条路在拆的书里都用 `chat_teardown`、不给 `make_changes`、不分流、不出方案卡，作者自己的书照旧。
