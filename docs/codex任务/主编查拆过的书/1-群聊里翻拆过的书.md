# 主编查拆过的书 任务 1：群聊里翻拆过的书

共同约定照本目录的 `README.md`。

## 为什么做

作者拆过三本别人写的书，拿来学人家怎么写：《逆天邪神》（676f45b1，2200 章）、《惊悚乐园》（3861c412，1520 章）、《我有一座冒险屋》（6872d11c，1210 章）。三本都拆完了，精髓、设定、读者在等的事都在库里。可作者在自己的书里和编辑部聊天时，编辑部看不到这些，只能凭印象说。

2026-10-23 在《佔位》（413c96ac）的开书聊天里就出了这几件事：

- 作者自己推出了「女神凭什么跟主角，主角得有一技之长（医术）」「开局最好是个废物」。《逆天邪神》精髓「设定设计」一节里早就有「爽点倒推设定：按核心爽戏定制能力与门槛」「极限残局开局：用假废材与多重危机压出反弹力」，后一条还写着第 7 章才揭开主角的玄脉是被外力毁的，正好答了作者问的「本来就废还是后来变废」。主编看不到，没能说。
- 主编说错了事实：它说大婚下毒的是「情敌萧狂云的人」。读者在等的事里 E2 是「萧澈向萧玉龙清算下毒陷害之仇」，第 2 章立下，第 35 章兑现。
- 作者说「逆天邪神也是三年之约（我没记错的话）」。E13「萧澈三年内重回流云城萧门雪耻」，第 37 章立下，第 327 章兑现。主编本来能告诉他没记错。
- 萧玉龙、萧狂云在《逆天邪神》里都没有角色卡（拆书的毛病，不在本任务），只有搜原文才找得到。

作者 2026-10-23 定的三条：

1. 四样都能翻：精髓（拆出来的写法，还有人物的人设模板）、设定、读者在等的事、原文。
2. 拆完的书都能翻，不加「对标」设置。作者想让一本书对标哪本，在聊天里说一句，编辑部照现在的规矩记进记忆（「聊天时记得」），不用改程序。
3. 作者提到这几本书时翻；他在想的事正好是哪本书用过的一招时也翻。只借道理，不搬人家的人名和情节，不沾边就别硬扯。说到拆过的书带书名和章号；没拆过的书照旧说是印象。

做法和手册一样：书目和每本精髓的目录写在工具说明里，模型看得到；细节用工具去翻。

设计方 2026-10-23 实测过（只读，没写库、没改配置）：用作者主编现在配的「【Alicia】gemini-3.8-flash」，《佔位》真实的群聊提示词（3b2e302 的 `chat_agent`，插上第 5 节那一条），群聊真用的那些工具，再加上照第 2 节拼的 `look_up_teardown`（说明 4219 字，带三本书的目录）。

- 说明这么长，接口照收：每次都正常调工具，没有一次被拒。
- 问「逆天邪神里大婚那天下毒的是谁」：`look` 的说明里没写「先查读者在等的事」时，两次都去搜原文，搜了四轮还没找到；加上以后，三次都先查读者在等的事，查到 E2，再看第 2、35 章，答对了是萧玉龙、弑心散、第 35 章报的仇。
- 问「主角本来就是废物还是后来变的，逆天邪神怎么处理的」：直接翻精髓「极限残局开局」「开篇」，答出了第 7 章才揭开玄脉是被外力毁的。
- 问「设定库里有哪些人物」「斗破苍穹开局怎么写的」：都没去翻拆过的书（斗破没拆过）。
- 还剩的毛病：模型会顺口补没查过的细节，比如说萧玉龙是「大长老的孙子」，原文第 4 章写的是门主萧云海的独子。提示词里写了「查到哪说到哪」，管不全，这次不再加规矩。

## 1. 哪些书列进来

- `books.source = 'teardown'`，并且精髓整理过：`teardown.essence.overview.points` 不空。拆到一半、停下了没整理精髓的不列。
- 同名的只列一本：章数多的那本；章数也一样，列后导入的。现在库里还有一本 498 章、拆到第 100 章停下的旧《逆天邪神》，没有精髓，本来就不列。
- 按导入先后排（`created_at`）。
- 一本都没有：不给这个工具。
- 只读 `books.teardown` 里要用的那几块（精髓、读者在等的事的计数），用 JSON 路径取。不要每次把整个 `teardown` 列读出来：《逆天邪神》那一列将近 50 万字。
- 每句话开始答的时候读一次（书目、书名对哪本书），这句话答完之前不变。

## 2. 工具 `look_up_teardown`

### 2.1 给谁

- 新书的群聊（`chat_agent` 那条路）给。只问不改（ask_only）也给，因为它只查不改。
- 拆的书自己的群聊不给，做法和 `read_skill` 一样，在 `Turn` 上加一个开关。万一还是调了，交回「拆的书群聊不能查别的拆过的书。」
- 私聊、不能调工具的模型走的老路（分流、`chat_reply`）都不动。

### 2.2 定义

照下面这个样子。`description` 是第一段固定文字，加上「\n拆过的书和它们精髓的目录：\n」，再加程序拼的书目（2.3）。`book` 的 `enum` 是书目里的书名（不带书名号），先后和书目一样。

```json
{
  "type": "function",
  "function": {
    "name": "look_up_teardown",
    "description": "查作者拆过的书。这些是别人写好的小说，作者导入后拆过，拿来学人家怎么写，不是作者正在写的这本。能查四样：精髓（拆出来的写法，还有人物的人设模板）；设定（人物、金手指、等级、地方、势力、物品、秘密的卡片）；读者在等的事（书里立下、兑现的期待和伏笔，带章号：结下的仇谁报了、立下的约兑现没有、埋的秘密哪章揭开，都记在这里）；原文（搜一个词在哪几章出现，或者看第几章写了什么）。\n拆过的书和它们精髓的目录：\n《惊悚乐园》1520 章。……",
    "parameters": {
      "type": "object",
      "properties": {
        "book": {"type": "string", "enum": ["惊悚乐园", "我有一座冒险屋", "逆天邪神"], "description": "哪本书，照上面的书名写，不带书名号"},
        "look": {"type": "string", "enum": ["精髓", "设定", "读者在等的事", "原文"], "description": "查哪一样。问书里谁做了什么、结的仇报了没有、立的约兑现没有、秘密在哪章揭开，先查「读者在等的事」，比搜原文准；要找原话，或者某个词在哪几章，再搜「原文」。"},
        "words": {
          "type": "array",
          "items": {"type": "string"},
          "description": "查什么，一次最多 5 个。精髓：写目录里的节名（整节都给你），或者一条的招式名（冒号前面那几个字），或者人物名（看他的人设模板）；不写就给核心要点。设定：写名字。读者在等的事：写关键词，比如「下毒」「三年」，或者编号，比如「E2」；不写就列出到最后还吊着的。原文：写要搜的词，越短越准；要看第几章写了什么，写「第 35 章」。"
        }
      },
      "required": ["book", "look"]
    }
  }
}
```

### 2.3 书目

每本书先一行，再每一节一行：

- 第一行：`《书名》N 章。{精髓 overview.genre}`。精髓整理到的章（`essence.upto`）比总章数少时，「N 章」后面加「，精髓只整理到第 M 章」。
- 「- 核心要点：」后面接核心要点每一条的标题，每条用「」括起来，紧挨着写。
- 十二节照精髓页的先后（`teardown_essence.SECTIONS`）：每节一行「- 节名：」后面接这一节每一条的标题，写法同上。一条都没有的节不写。
- 「配角与对手」先列人物「名字（人设模板）」，用「、」连，再写「；」，再接这一节的条。

## 3. 查到的交回给模型的字

### 3.0 通用

- `book` 先照书名精确找，再去掉书名号和空格找。找不到交回：「没有这本拆过的书：「{book}」。拆过的有：《惊悚乐园》《我有一座冒险屋》《逆天邪神》，book 照工具说明里的书名写。」
- `words` 每个去掉前后空格和「」《》，空的扔掉，只用前 5 个。模型有时把 `words` 给成一个字符串（实测 3.8f 给过 `"words": "开篇"`），也认，当成一个词；给成 JSON 字符串的照 `Lenient` 现在的办法还原。
- 交回的字：第一行是这一样的开头（下面各节写了），然后每个词一段，段和段之间空一行。
- 每个词那一段截一次（截法同 `chat_tools.clip`）：精髓截到 3000 字，另外三样截到 2000 字。

### 3.1 精髓

开头：「《逆天邪神》精髓：拆书时从前 {essence.upto} 章整理的，章号是原书的。」

`words` 空就当成写了「核心要点」。每个词照下面的先后找，哪一步找到了就停在那一步：

1. 「核心要点」：给核心要点。
2. 十二节的节名之一（名字同精髓页：情节怎么想、剧情骨架、剧情衔接、保持新鲜、长线布局、设定设计、爽点类型、爽点戏怎么写、主角、配角与对手、节奏与钩子、开篇）：给整节。照精髓页上的先后排；「配角与对手」先给人物再给条。这一节 `missing` 不空时，最后加一行「这一节拆书时没看出来的：……」（几项用「；」连）。
3. 标题里含这个词的条（核心要点和十二节都找）：给这些条，照精髓页上的先后排。标题和步骤都一样的只留一条。
4. 「配角与对手」里名字或人设模板含这个词的人物：给这些人。
5. 都没有：「精髓里没有「{词}」：写目录里的节名、招式名，或者人物名。」

一条的写法（`note` 空时不写「要注意」那一行）：

```text
【设定设计】极限残局开局：用假废材与多重危机压出反弹力
怎么用：
1. 给主角扣上天生残废与地位卑微的明面耻辱标签
2. 开局当天叠加死局：仇家毒杀、强敌抢妻、宗族排挤连环爆发
3. 让主角保留高阶灵魂记忆或专属金手指，完成第一轮绝境自救
4. 在残局深处埋入非同寻常的血脉身世，作为引爆下一级地图的长线暗火
书里的证据：第1章吞珠跳崖，第2章玄脉残废且成婚晨遭弑心散毒杀，……
要注意：开局被压不能超过三章不反击；第一波反击必须立刻踩死直接下毒的仇人。
见第 1、2、3、7、21、31、37、38 章
```

人物的写法（`arc` 空时不写「怎么变」那一行）：

```text
【配角与对手】茉莉：傲娇毒舌师尊
怎么立起来：红发萝莉外形配狠绝杀戮战力；……
在剧情里起什么作用：充当随身最高战力与眼界天花板，……
怎么变：从冷漠吸血寄居（第12章）到毒舌师徒（第44章），……
见第 12、41、44、53、55、806、1260、1343 章
```

核心要点的写法：先两行，再每一条照「一条」的写法，【】里写「核心要点」。

```text
【核心要点】
这是一本什么书：{overview.genre}
靠什么让人一直追：{overview.engine}

【核心要点】因果接力：旧账兑现前必先立新因，全程无断档
怎么用：
……
```

### 3.2 设定

开头：「《逆天邪神》设定：拆书时从原文整理的卡片。」

每个词在那本书的设定库里找，找法和 `look_up_settings` 一样（名字、别称、名字里含这个词）：

- 找到：交回的全文和 `look_up_settings` 一样。如果是人物，而且「配角与对手」里有这个人（人物名字等于卡上的名字或者别称之一），最后加一行「精髓里的人设模板：傲娇毒舌师尊（怎么立起来，查精髓「茉莉」）」。
- 没找到：「设定里没有「{词}」：拆书时不是每个人、每样东西都写了卡，可以到原文里搜。」
- `words` 空：「没说要查谁。」

### 3.3 读者在等的事

开头：「《逆天邪神》读者在等的事：拆书时整理到第 {waits.upto} 章，一共 {waits.total} 件。」还没整理过（`teardown.waits` 没有），整个只交回一句「《逆天邪神》还没整理读者在等的事。」

每个词：

- 像编号（E 或 F 加数字，大小写都认）：给那一件。没有：「没有「{词}」这一件。」
- 别的：说明、立下、兑现三栏（`description`、`plant_plan`、`payoff_plan`）里含这个词的，按编号先后给前 8 件。多出来的在最后加一行「还有 {N} 件也提到「{词}」：E48、E52……（要细节写编号再查）」，编号全列。没有：「没有提到「{词}」的：换个说法，或者到原文里搜。」
- 每一件写一行，写法和现在查伏笔（`format_foreshadowing`）一样，比如：

```text
- E2［期待·中·已兑现·第1卷立、第1卷兑现］读者在等：萧澈向萧玉龙清算下毒陷害之仇（立：第 2 章；兑现：第 35 章：萧澈潜入萧玉龙房中废其玄心，斩断四肢筋脉并阉割刺瞎。）
```

- `words` 空：「到最后还吊着的：」加还开着的（`planned`、`planted`）前 20 件，多的同样加「还有 N 件……」那一行；一件都没有就「没有还吊着的。」

### 3.4 原文

开头：「《逆天邪神》原文：一共 {章数} 章。」

每个词：

- 「第 N 章」（「第」「章」和数字之间有没有空格都认）：

```text
第 35 章《星隐，以血祭恨(下)》
章纲：
发生什么：……
看点：……
结尾钩子：……
摘要：……
```

  章纲各栏和 `read_chapter` 一样，空的不写。不写「已定稿」这种状态：拆的书每章都是 `final`，写出来会被当成作者写完的。没有这一章：「没有第 {N} 章。」
- 别的：在那本书的原文里搜，交回的和 `search_text` 一样（「「萧玉龙」在 32 章里出现过，第一次在第 4 章。」……；没有就「原文里没有「萧玉龙」。」）。
- `words` 空：「没说要搜什么。」

## 4. 回答框和「查了」里的字

| look | 回答框里那一行 | 回答下面「查了：」里那一项 |
|---|---|---|
| 精髓 | 在翻《逆天邪神》的精髓…… | 《逆天邪神》精髓「设定设计」「极限残局开局」 |
| 设定 | 在查《逆天邪神》的设定…… | 《逆天邪神》设定「茉莉」 |
| 读者在等的事 | 在查《逆天邪神》读者在等的事…… | 《逆天邪神》读者在等的事「下毒」 |
| 原文 | 在翻《逆天邪神》的原文…… | 《逆天邪神》原文「萧玉龙」「第 35 章」 |

- 「查了」里那一项：书名后面接每个词，各用「」括起来，紧挨着写。设定找到的写卡上的名字，没找到写原来的词。`words` 空时，精髓写「核心要点」，读者在等的事写「还吊着的」，设定和原文后面什么也不接。
- `book` 对不上：回答框「在查拆过的书……」，「查了」里写「拆过的书「{book}」」。
- 重新回答照旧带上这一轮查到的东西（现成的 `tools_text`，不用改）。
