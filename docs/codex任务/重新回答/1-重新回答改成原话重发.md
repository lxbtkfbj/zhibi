# 重新回答 任务 1：重新回答改成原话重发

共同约定照本目录的 `README.md`。设计在 `docs/设计说明.md` 9.13「重新回答改成原话重发」。

## 为什么做

作者 10-25 在《佔位》群聊里调完主编的提示词，点最新那条回答下面的「重新回答」想看效果，结果什么也测不出（llm_calls 3181）。现在的重新回答只把那段话重写一遍：`POST /books/{id}/chat/replies/{id}/again` → `again_background` → `answer`。它用的是 `chat_reply`，不给工具，只沿用第一次查到的东西（`payload.tools`）：不再查资料、不翻手册、不联网、不动手改书。群聊「自己查、自己动手」那份提示词（`chat_agent`）根本用不上。

作者要的是：重新回答 = 退回到那句话之前，再从输入框把原话发一遍。作者那句话上的「修改」，一个字不改直接发送，已经是这个效果：`/notes` 带 `rewind_from`，后端 `chat_convs.rewind` 把这句和后面的聊天标成 `dropped`，再照常收这一句。只是这个按钮藏在悬停里，名字又叫「修改」，看不出能这么用。这次让「重新回答」直接走这条路。

设计说明 9.13 第三批第 5 条原来定的是：改过书的回答点重新回答，只重写、不重做（不然「写三个反派」会变成六个）。10-25 作者知道会再改一遍，改成先提醒，作者点了才重发。

## 1. 作者看到的样子

只管群聊，也就是新书页编辑部浮窗里的聊天（拆的书的群聊也一样）。

### 1.1 最新一条回答下的「重新回答」

按钮还在原来的地方，还叫「重新回答」，什么时候出现也不变：`Chat.tsx` 里 `Reply` 的 `showAgain`（最新一条回答、答完了或停下了、没在回答）。另外，正在发送、正在「修改」某一句的时候不显示，和作者那句话上的「修改」一样。

悬停提示（`title`）换成：

> 把你那句话原样再发一遍，从头重新答（会重新查资料、翻手册）；你那句和这一条收起来

点了以后：

1. **改过书的先提醒。**处数照 `LiveChat.tsx` 的 `toChat` 里 `changedFrom` 那样算（这句和后面的话改过几处；最新一条回答这里就是这一句）。改过书就先不发，在这条回答下面弹出小框，样子照作者那句话上「修改」的提醒框（`AuthorBubble` 里 `role="alertdialog"` 那个）。字：

   > 这句话改过书（N 处）。重新回答是把这句原样再发一遍，编辑部可能再改一遍；聊天退回这里，书不跟着退：要退书，用那几处下面的「换回原来的」，或者去「存档」。

   两个按钮：「算了」「重新回答」。点「算了」收起小框，什么都不发；点「重新回答」才往下走。没改过书的不弹，直接往下走。

2. **把那句话原样再发一遍**：`POST /books/{id}/notes`，请求体：
   - `content`：原话，就是那条作者消息的 `content`；
   - `ask`：原来点的名（`payload.ask`），没有就不带；
   - `quote`：原来带的引用（`payload.quote`），没有就不带。输入框下面另外挂着的新引用不带，留给下一问（和「修改」一样）；
   - `viewing`：原来那句当时正在看的那一页（`payload.viewing`），没有就不带。不取现在正在看的；
   - `conv`：原来那句的 `payload.conv`；
   - `rewind_from`：原来那句的 id。

   发送和「修改」重发用同一套：同一个 `sending` 状态，同一个 `sendChatFirst`。等拍板时被 409 `use_feedback` 挡回来，照现在的样子转成修改意见，不另做。发不出去（比如 409「编辑部还在照这几句话办，办完再重来」）就在输入框下面报错，聊天不动。

3. **发出去以后**：原来那句和这条回答收起来（后端标 `dropped`，前端本来就不显示收起来的），原话和新回答出现在最下面。回到底、回答跟到底，和现在点「重新回答」一样：`Chat.tsx` 里 `authorChat.again` 先调 `followLatest()` 的那套。`tests/chat-improvements.browser.mjs` 里「上翻超过48px后重新回答原生click立即回底、回答继续跟到底」照样要过。

### 1.2 照旧只重写的几种

下面这几种，「重新回答」还是照现在的走 `/chat/replies/{id}/again`，只重写那段话：
- 一条回答答了不止一句（`payload.reply_to` 不止一个 id）。作者库里现有 70 条回答都只答一句，新书页回答时又不能发话，基本碰不到。
- 那句话没有 `payload.conv`（分段以前的老消息），或者不是作者在聊天里说的话（`kind` 不是 `note`）。
- 原型页（`WorkspacePrototype.tsx` 用的 `chatSim.ts`）：不动。

### 1.3 「重试」不变

没答上来（`failed`）时的「重试」照旧走 `/again`，自己动手的那一轮接着做没做完的。不要改成重发：做了一半的改动会再做一遍。

### 1.4 「修改」的两处字

作者那句话上「修改」按钮的悬停提示（`Chat.tsx` 第 90 行的 `title`）换成：

> 改这句话再发，不改直接发也行：这句和后面的聊天收起来，从这句重新回答；书里改过的不跟着退

编辑框下面那行小字（`Chat.tsx` 第 318 行）换成：

> 改好了点发送，不改直接发就是原话重来：这句和后面的聊天会收起来，从这句重新回答；书里改过的不跟着退

## 2. 后端不动

「从这里重来」本来就是这次要的样子，代码在 `chat_convs.rewind` 和 `group_notes.receive_note` 里 `rewind_from` 那一段：
- 不删消息，这句和后面的聊天标 `dropped`；
- 没照办的方案卡作废；
- 摘要里折进了收起来的话，摘要作废；
- 还在回答、编辑部还在照这几句话办的时候回 409。

`/chat/replies/{id}/again` 不改，留给「重试」和 1.2 那几种。没有迁移，不改提示词。

## 3. 可以这样做（实现细节自己定）

- `toChat`（`LiveChat.tsx`）给回答加一个字段，比如 `resend: { warn?: string }`。只有 1.1 那种回答才有：答一句、那句是 `note` 而且有 `conv`。`warn` 用那句的处数照 1.1 的字拼，没改过书就不带。
- `ChatControl`（`chatModel.ts`）加一个可选的 `resend(replyId)`，由 `LiveChat` 实现：从 `shown` 里找到这条回答和那句原话，拼 1.1 的请求体，和 `send` 共用发送那一套。`chatSim` 不用实现。
- `Reply`（`Chat.tsx`）：有 `message.resend`、`chat.resend` 也在，就照 1.1 做（有 `warn` 先弹小框，确认后 `followLatest()` 再 `chat.resend`）；不然照旧 `onAgain`。

## 4. 这次不做

- 不留旧回答的几个版本（像有些聊天软件那样「< 1/2 >」翻看）。旧的收起来就不显示了，和「修改」一样。
- 不自动撤销那一轮记下的记忆、改过的书。记忆的回执跟着那句话收起来，记忆本身还在「记忆」里。
- 不给更早的回答加「重新回答」。更早的那句用「修改」，不改直接发。
- 不动后端，不动私聊（新书页没有私聊）。

## 5. 测试

**单元测试**（`node --test`；`tests/chat-outcome.test.mjs` 已经会编译 `LiveChat.tsx` 拿 `toChat`，可以照它写）：
- 群聊里只答一句的回答，`toChat` 带上 1.1 要的东西；那句改过书时，提醒的字逐字照 1.1（N 换成处数）。
- 答两句的、那句没有 `conv` 的、那句不是 `note` 的，都不带，走旧路。

**浏览器测试**（独立后端加演示模型）。下面这几条原来认「重新回答只重写、不再查」，照新样子改断言，改完都要跑过：

  - 原来那句和那条回答从页面上消失，最下面出现原话和新回答；
  - 「上翻超过48px后……立即回底、回答继续跟到底」照样断言。
