# 小修 1：书架上拆书状态的说法、没整理时的设定页

作者用真书试用时看到两处字和样子不对，这次只改这两处，加上相关的测试。不动别的界面，不改提示词。

## 1. 书架卡片上的拆书状态

现在 `frontend/src/pages/Home.tsx` 拆的书卡片底下那行，停下的时候直接显示后台存的 `stop_note`，界面上就成了「拆到第 100 章了（你定的）。」：像聊天里的一句话，和同一行其他状态（「正在拆」「拆完了 · 498 章」）不是一个说法。

改成和书页顶栏一个说法，只写状态，不写句子、不带句号：

| 情况 | 卡片上写 |
|---|---|
| 还没确认分章 | 还没确认分章（不变） |
| 排队中 | 排队中 |
| 正在拆 | 正在拆 · 已拆 {read} / {chapters} 章 |
| 停下了（stop_reason 是 upto 或 author） | 已拆 {read} / {chapters} 章 |
| 停下了（stop_reason 是 model 或 error） | 已拆 {read} / {chapters} 章 · 出错停了（鼠标停上去的提示是 stop_note 全文） |
| 拆完了 | 拆完了 · {chapters} 章（不变） |
| 导入了还没开拆 | 已导入 {chapters} 章 · 还没开拆（不变） |

`read` 是读过的章数，和书页顶栏「已拆 N / M 章」的 N 一个算法（`chapters.teardown.read_version` 不为空的章数）。书列表接口现在没有这个数：在 `TeardownSummary`（后端 schema 和 `frontend/src/api/types.ts`）加 `read: int`，`list_books` 用一次分组计数查出来，不要一本书查一次；`detail` 也带上。`/` 两边各一个空格，和顶栏一致。

## 2. stop_note 的措辞

stop_note 现在只在出错提示和拆书聊天里出现，但措辞也一起改正式一点（`backend/app/services/teardown_runner.py`）：

- upto：`拆到第 {N} 章了（你定的）。` 改成 `已按开拆时定的范围拆到第 {N} 章。`
- author（三处）：`你点了停下，停在第 {N} 章。` 改成 `已手动停下，停在第 {N} 章。`

出错的那几句不改。库里已经存着的旧句子不用迁移（书架不再显示它）。相关测试里的旧句子跟着改。

## 3. 设定页：还没整理时只写一行

现在拆的书设定还没整理（`book.teardown.settings.upto` 为空）时，设定总览（`frontend/src/pages/workspace/desk-v2/SettingsPages.tsx` 的 `SettingsOverview`）照样画八个「0 条」的空框，违反装修定的「空的不画框，只写一行现状」。

拆的书、`settings.upto` 为空、并且所有类别都没有条目时：标题「设定」和下面的分隔线照旧，**八个框都不画**，meta 那一行按情况写：

| 情况 | 写 |
|---|---|
| 正在整理设定（顶栏是「设定师在整理设定」） | 设定师在整理设定，整理完这里就有了 |
| 正在拆（还在读原文、归单元、归卷） | 拆书收尾时会整理设定，到时这里就有了 |
| 停下了或排队中，读过的章大于 0 | 设定还没整理：点右上角「接着拆」，拆到第 {最后读过的章} 章不变，只整理设定，不重读原文 |
| 一章都没读过 | 还没开拆，拆过的章会整理成角色卡和设定 |

只是 meta 那一行换字，样式不新造。整理完（`settings.upto` 有值）或者有任何条目时，照现在的样子画，一点不变。作者自己写的书（不是拆的书）也不变。
