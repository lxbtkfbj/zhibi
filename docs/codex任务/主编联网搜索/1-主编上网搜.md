# 主编联网搜索 任务 1：主编上网搜

共同约定照本目录的 `README.md`。

## 为什么做

作者 2026-10-21 担心编辑部说别的书的设定时凭感觉瞎说。「主编查拆过的书」（f84302d）解决了拆过的三本；没拆过的书、书以外的事（现实里的知识、最近流行什么、有没有撞梗），编辑部还是只能凭印象，提示词里写的是「没拆过的书只凭印象，记不准的说清是印象。」

作者 2026-10-24 定的两条：

1. 搜索用 DeepSeek 官方的网页搜索（Search）和网页抓取（Fetch）。
2. 搜不搜、搜什么，让编辑部自己决定。

作者同意的几处：

- 编辑部能做两件事：上网搜，看前 5 条的摘要；摘要不够时，打开某个网页读全文。
- 拆过的书先翻拆书（有章号，比网上准）；拆书里没有的、书以外的事，再上网搜。
- 回答时说清是网上搜到的、出自哪个网站；「查了」那一行和查拆书一样，点开看得到搜到的原文。
- 群聊都能搜，拆的书的群聊也算；私聊不能。
- 密钥用系统设置里「官方DeepSeek」那一套的，不另外注册、不另外填。

DeepSeek 这两个接口（10-18 上线，官方说明 https://api-docs.deepseek.com/zh-cn/guides/search/ ）：

- 搜索：`POST https://api.deepseek.com/v1/tools/search`，请求头 `Authorization: Bearer <DeepSeek API Key>`、`Content-Type: application/json`。请求体：`query`（必填，1～128 字）、`count`（1～50，默认 10，不影响价钱）、`ori_question`（选填，1～128 字，用户原来的问题，帮它理解要搜什么）、`need_content`（默认 false）。`query` 里能写 `site:`、`-site:`、`"..."`、`lang:`、`after:`／`before:`。返回 `results`，每条有 `title`、`url`、`snippet`（100～200 字）、`summary`（600～800 字，给模型读的）、`content`、`site_name`、`site_icon`、`date`（RFC 3339，可能是 null）、`authority`、`rerank_score`；没结果时 `results` 是空数组。
- 抓取：`POST https://api.deepseek.com/v1/tools/fetch`，请求体 `url`（http／https，最长 8192）。返回 `title` 和 `content`（Markdown）。
- 价钱：各 5 元／千次成功请求，搜到结果、抓到正文才算，失败、没结果、超时不收。官方写的「11 月 1 日前不收」只针对在 DeepSeek Harness、Claude Code、Codex 里用的，执笔自己调要收钱。
- 限流按账号：搜索 100 QPS、抓取 25 QPS，超了回 429；抓取对目标网站另有限流，也回 429。402 是余额不足。

设计方 2026-10-24 实测过（用作者「官方DeepSeek」的密钥真搜，只读）：

- 8 个网文问题都搜到了用得上的东西。书里的事基本是百度百科词条，答案就在 `summary` 里：斗破苍穹「异火榜」（23 种异火和收服者的表）、逆天邪神「萧玉龙」（萧云海独子、大婚当日下毒，和拆书记的一样）、凡人修仙传「墨居仁」（为夺舍收韩立）。问趋势搜到 10-14 北京青年报的网文榜、10-18 起点强推的数据；问写法（黄金三章、退婚流）是头条、公众号、知乎的经验帖，好坏不一。
- 有重复：同一个词条出现两次，标题不一样（「三千焱炎火」和「三千焱炎火（天蚕土豆所著玄幻小说《斗破苍穹》中的异火）_百度百科」）。
- 前 5 条 `summary` 加起来 3～5 千字，10 条 5～11 千字。
- 搜一次 0.5～1 秒；抓一页约 6 秒（百度百科「异火榜」5863 字），正文里带 `\#`、`\[1\-2\]`、`\,` 这种转义。

设计方又用作者的「【Alicia】gemini-3.8-flash」试过编辑部（只读，没写库、没改配置）：用《佔位》真实的群聊提示词（换上第 6 节那一行）、群聊真用的那些工具，加上照第 2 节拼的两个工具，搜索照第 3 节的格式真搜。

- 挑工具（每道题两次）：问「斗破苍穹里萧炎一共收了哪几种异火」，两次都上网搜，有一次自己加了 `site:baike.baidu.com`；问「逆天邪神里大婚那天下毒的是谁」，两次都去查拆过的书，没上网；问设定库里有哪些人物、主角的医术要不要设限制，都没上网；问最近起点什么题材火，先翻手册再上网搜；问宋朝知州和通判的区别，凭自己知道的答了，没搜。拆的书的群聊：问作者还写过什么书，上网搜；问萧玉龙的结局，到原文里搜，没上网。
- 它不知道今天几号：问最近流行什么，搜的是「起点 2024 畅销榜」。工具说明最后加上今天的日期以后，搜的是「2025 2026」。
- 说出处：搜到的结果后面没有那句提醒时，两次完整回答一次没说是网上搜到的，一次说成「查了百度百科和原著设定」（并没有看原著）；加上 3.1 最后那句提醒以后，四次里三次说了出处，说的网站都在搜到的结果里。
- 还剩的毛病和查拆过的书一样：会顺口补几句搜到的结果里没有的细节。这次不再加规矩。

## 1. 用哪把密钥

- 每句话开始答的时候找一次，这句话答完之前不变（和拆过的书的书目一样）：模型配置里 `provider` 是 `openai_compatible`、接口地址的主机是 `api.deepseek.com`、填了密钥的，取最早建的那一套（按 `created_at`，一样再按 `id`）。作者库里现在就是「官方DeepSeek」那一套。
- 密钥解不开（`SecretError`）当成没有，记一行日志。
- 没有：这句话不给 `search_web`、`read_webpage`，别的照旧。
- 接口地址写成配置，默认 `https://api.deepseek.com`（比如 `Settings.web_search_base_url`，环境变量 `ZHIBI_WEB_SEARCH_BASE_URL`），测试和验收指到本机的假服务。挑哪把密钥照上面的规矩，跟这个配置无关。
- 网络设置和调模型一样（同 `router._HttpClients.for_profile`）：接口地址不是本机，`httpx` 用 `trust_env=True` 走系统代理设置；是本机（测试的假服务）用 `trust_env=False`。超时 30 秒。
- 408、429、5xx、超时、连不上：等 1 秒重试一次，还不行照 3.3 交回。

## 2. 两个工具

### 2.1 给谁

- 新书的群聊（`chat_agent` 那条路）给，只问不改也给。
- 拆的书的群聊（`chat_teardown`）也给。
- 私聊、不能调工具的模型走的老路（分流、`chat_reply`）都不动。
- 没有密钥（第 1 节）不给。

### 2.2 定义

照下面逐字写，两个工具排在现有工具后面。`search_web` 的 `description` 最后一句「今天是 2026 年 10 月 24 日。」是程序拼的：这句话开始答的时候，机器上的日期，月和日不补零。

```json
[
  {
    "type": "function",
    "function": {
      "name": "search_web",
      "description": "上网搜。拆过的书先用 look_up_teardown 查，那里有章号，比网上准。没拆过的书（情节、人物、设定、原话）、书以外的事（现实里的历史地理和各行各业的知识、最近流行什么题材、书名人名有没有被用过），你拿不准就搜；凭常识就能说清的，或者跟作者问的事关系不大的，不用搜。一次搜一件事。交回前 5 条：网站、标题、日期、链接和一段摘要。今天是 2026 年 10 月 24 日。",
      "parameters": {
        "type": "object",
        "properties": {
          "query": {"type": "string", "description": "搜什么：几个关键词，用空格隔开，比如「斗破苍穹 萧炎 异火」，越短越准。只想看某个网站，加上 site:网址，比如「萧炎 site:baike.baidu.com」。"},
          "question": {"type": "string", "description": "想弄清的是什么，一句话，比如「斗破苍穹里萧炎收了哪几种异火」。"}
        },
        "required": ["query"]
      }
    }
  },
  {
    "type": "function",
    "function": {
      "name": "read_webpage",
      "description": "打开一个网页读正文：搜到的摘要不够用时，或者作者给了链接让你看。一次给 6000 字，长的可以往后翻。",
      "parameters": {
        "type": "object",
        "properties": {
          "url": {"type": "string", "description": "网页链接，照搜到的或者作者给的原样写。"},
          "start": {"type": "integer", "description": "从第几个字开始读，往后翻时用；第一次读不用写。"}
        },
        "required": ["url"]
      }
    }
  }
]
```

参数照 `Lenient` 的办法收：`question` 没给当空的；`start` 给成字符串的数字也认，认不出当 0。

### 2.3 一句话里最多

- `search_web` 最多 5 次。第 6 次起不去搜，交回「这句话已经搜了 5 次，不能再搜了。用搜到的回答，还缺什么跟作者说清。」
- `read_webpage` 最多读 3 个网页；同一个网页往后翻不算新的一个。第 4 个起不去抓，交回「这句话已经读了 3 个网页，不能再读了。用读到的回答。」
- 被拦下的不记进「查了」，回答框那一行也不变。

## 3. 交回给模型的字

### 3.1 search_web

- `query` 去掉前后空白，超过 128 字截到 128 字。空的不去搜，交回「没说要搜什么。」，不算次数。
- 请求体 `{"query": query, "count": 10}`；`question` 去掉前后空白后不空，加上 `"ori_question"`（同样截到 128 字）。`need_content` 不写。
- 结果按返回的先后，挑前 5 条：
  - `summary` 和 `snippet` 都空的不要；
  - `url` 和前面挑中的某条一样的不要；网站名加标题和前面挑中的某条一样的也不要；
  - 网站名用 `site_name`；空的，或者超过 20 个字的（实测有时候是一整个网页标题），用链接的主机名。标题空的写「（没有标题）」；
  - 摘要用 `summary`，空的用 `snippet`：先去掉反斜杠转义（同 3.2），连着的空白和换行压成一个空格，超过 800 字截到 800 字再加「……」；
  - `date` 不空，取前 10 个字（年月日）写在括号里；空的不写括号。
- 交回（不到 5 条照实写「前 N 条」）：

```text
网上搜「斗破苍穹 萧炎 异火」，前 5 条：

1. 百度百科《异火榜》（2026-07-27）
https://baike.baidu.com/item/...
# 异火榜 天蚕土豆所著玄幻小说《斗破苍穹》中的灵物 ... 异火榜，天蚕土豆所著玄幻小说《斗破苍穹》及其衍生作品中的榜单 [1]，共有二十三种异火位列其上。……

2. 百度百科《三千焱炎火（天蚕土豆所著玄幻小说《斗破苍穹》中的异火）_百度百科》（2026-08-03）
https://baike.baidu.com/item/...
……

这些是网上的说法，不一定准：跟作者说的时候讲明是网上搜到的、出自哪个网站；几处说法对不上的，照实说。
```

- 最后那一行是固定的，前面空一行。设计方实测过，有这一行，模型说出处说得准些（见「为什么做」）。
- 一条都没有：「网上没搜到「{query}」。换几个短一点的词再搜。」

### 3.2 read_webpage

- `url` 去掉前后空白；不是 http／https 开头，或者没有主机名：「链接不对：「{url}」。照搜到的链接原样写。」不去抓，不算个数。
- 抓到的正文：去掉 Markdown 的反斜杠转义（反斜杠后面跟着 `` \ ` * _ { } [ ] ( ) # + - . ! | , ~ < > : `` 其中一个时，去掉反斜杠、留下那个字符）；连着三个以上的换行压成两个；去掉前后空白。
- 同一句话里同一个链接只抓一次，往后翻用抓到的那份。
- `start` 小于 0 当 0，超过全文字数当全文字数。一次给 6000 字：

```text
网页《异火榜》（全文 5863 字，这是第 1～5863 字）
https://baike.baidu.com/item/...
天蚕土豆所著玄幻小说《斗破苍穹》中的灵物
……
```

  后面还有，最后加一行「……后面还有；要接着读，start 填 {这一页最后一个字的位置}」（同 `read_chapter`）。
- 标题空的，第一行写「网页（没有标题）」接括号。
- 抓不到（404、403、正文是空的）：「这个网页打不开（网站拦着，或者没有能读的正文）：{url}。换一条搜到的链接试试。」这也算读过一个。

### 3.3 出错

两个工具一样：

- 401，或者搜索回 403：「联网搜索用不了：DeepSeek 不认这把密钥。请作者在系统设置里检查「{配置名}」的 API Key。」
- 402：「联网搜索用不了：DeepSeek 账户余额不足，请作者去 DeepSeek 开放平台充值。」
- 重试过还是 408、429、5xx、超时、连不上：「网上搜索这会儿没响应。先用手头的资料回答，跟作者说一声没搜成。」
- 别的 4xx：「网上搜索没成：DeepSeek 回了 {状态码}。」
- 抓取回 403、404 照 3.2「打不开」那句。

出错也算次数。出错的照常记进「查了」，点开看得到交回的那句。

## 4. 回答框和「查了」里的字

| 工具 | 回答框里那一行 | 回答下面「查了：」里那一项 |
|---|---|---|
| search_web | 在上网搜「斗破苍穹 萧炎 异火」…… | 网上搜「斗破苍穹 萧炎 异火」 |
| read_webpage | 在读网页 baike.baidu.com…… | 网页《异火榜》 |

- 「……」照现在的 `set_doing` 默认加上：`doing_of` 返回的字不带「……」。`chat_agent.py` 里 `set_doing(..., ellipsis=...)` 那一行不要动（「拆书调提示词」那一包要改它）。
- 搜索的词用清理后的 `query`，超过 30 字截到 30 字。
- 读网页：回答框写主机名；「查了」写抓到的标题，没读成写「网页 {主机名}」。
- 重新回答照旧带上这一轮查到的东西（现成的 `tools_text`，不用改）。
- 前端「查了」那一行和点开看的框都是现成的，不用改。

## 5. 系统设置里标出来

- 返回模型配置的地方（`GET /api/llm/profiles` 列表，新建、修改返回的那一套）多一个 `web_search`：照第 1 节挑中的那一套是 `true`，别的是 `false`。
- 系统设置里模型配置那一行的说明，后面加「 · 联网搜索用它的密钥」。作者那一行会是「deepseek-flash · 已保存密钥 · 联网搜索用它的密钥」。
- 别的不加：没有开关，没有单独填密钥的地方。

## 7. 演示模型

`demo.tool_turn` 新书那一段加一条规则，放在 `look_up_teardown` 那条前面。`FAKE_TOOLS` 默认仍是 `False`。

- 条件：作者这句话里有「上网搜」，工具里有 `search_web`，这一轮还没调过它。
- 做法：调 `search_web`，`query` 是「上网搜」后面、到这句话第一个「。？！?!」或换行之前的字，去掉前后空白和「」，最多 30 字；是空的就用这句话的前 30 字。拿到结果后照旧往下走，最后那段话里带上「上网搜了「{query}」。」
- 拆的书那一段不加。

## 8. 这次不做

- 私聊、不能调工具的老路不搜。
- 排大纲、写正文、拆书这些步骤不联网，只在群聊里。
- 不加开关、不加单独填密钥的地方；没有密钥时提示词不跟着变（没有这两个工具，模型也调不了）。
- 不按 `authority`、`rerank_score` 筛，不让模型选条数。
- 不存搜索结果，下一句话要用再搜；同一句话里同一个网页只抓一次（3.2）。

## 9. 测试

1. 密钥：主机是 `api.deepseek.com`、有密钥的才算；几套里取最早建的；地址带不带 `/v1` 都算；没有、解不开都不给两个工具。
2. 工具：新书群聊、只问不改、拆的书群聊都有两个工具，定义和 2.2 逐字一样（直接从任务文件 2.2 的 JSON 取来比，日期固定成 2026-10-24 再比；换一天，最后那句跟着变）；没有密钥时没有。
3. 搜索：请求地址、请求头、请求体（`count` 是 10，`question` 有才带 `ori_question`，`query` 截到 128 字）；去重、跳过空摘要、只要前 5 条、摘要的清理和截断、日期的写法、网站名（空的、太长的）和标题的替补、最后那一行提醒；没结果、`query` 空交回的字。
4. 读网页：链接不对不去抓；正文的清理；6000 字一页和往后翻的那一行；同一个链接只抓一次；抓不到交回的字。
5. 出错：401、402、429（重试一次以后）、500、超时、别的 4xx，各交回 3.3 的字；重试一次成功了照常交回。
6. 次数：第 6 次搜、第 4 个网页交回 2.3 的字，不发请求、不进「查了」；同一个网页往后翻不算。
7. 回答框、「查了」的字照第 4 节，两个工具各一条，再加读网页没读成那一条。
8. 设置：列表里只有挑中的那一套 `web_search` 是 `true`；页面上那一行带「 · 联网搜索用它的密钥」，别的行没有。
9. 提示词：两份各只换了那一行，换了新指纹。
