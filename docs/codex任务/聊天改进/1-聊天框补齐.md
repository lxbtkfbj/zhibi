# 聊天改进 任务 1：聊天框补齐

共同约定照本目录的 `README.md`。只改前端，外加后台一句话（第 5 节）。

## 为什么做

作者试用新书页编辑部的聊天，说太简陋：没有复制，也不能修改消息。设计方查下来：

- 修改消息其实有，叫「从这里重来」，作者没认出来。
- 复制确实没有。
- 底下输入框里没发出去的字会丢：编辑部收成小球、浮窗和侧栏互换时，聊天组件被卸掉，`Composer` 里的 `text` 是组件自己的 state。
- 往上翻着看的时候来了新回答，现在不会把作者拽到底下，但也没有任何提示。
- 作者那句话下面「只是聊天，没有记 · 其实要记下」说不清楚。这里的「记」其实指记成写作要求，作者觉得鸡肋，要去掉。以后要不要记，由编辑部自己判断，存进记忆（任务 2）；这次先把旧的去掉，不做记忆。

代码在：

- `frontend/src/pages/workspace/Chat.tsx`：`AuthorBubble`、`Reply`、`Composer`、`EditorialChat`
- `frontend/src/pages/workspace/LiveChat.tsx`
- `frontend/src/lib/chat.ts`：`outcomeCopy`
- `frontend/src/pages/book/ChatActions.tsx`：`ChatOutcome`

新书页和拆的书的聊天用的是同一套，都照改。

## 1. 复制

- **作者的话**：鼠标移上去，左边（现在「从这里重来」的位置）出两个小按钮「修改」「复制」。
- **编辑部的回答**：气泡下面一行小按钮「复制」；最新一条在它后面接着现有的「重新回答」。
  - 最新一条这一行一直显示；别的回答要鼠标移到这条上才显出来，淡入方式和作者那边一样。
  - 还在想、还在写的回答，不出「复制」；失败了没有字的，也不出。
- 复制的是纯文字。作者的话不带前面的「@主编」；回答就是气泡里的全文。
- 点了以后，按钮上的字变成「已复制」，2 秒后变回来。
- 复制失败（浏览器不让写剪贴板）时，变成「没复制上，选中文字手动复制」，3 秒后变回来。
- 先用 `navigator.clipboard.writeText`，不行再退到隐藏的 textarea 加 `document.execCommand('copy')`。
- 图标用 lucide 的 `Copy`，已复制时换 `Check`。大小、颜色、字号照「重新回答」那个按钮。
- 方案卡这次不加复制。

## 2. 修改：「从这里重来」改名，改成在原地改

- 「从这里重来」改名「修改」，图标照旧用 `PencilLine`。
- 悬停提示：「改这句话再发：这句和后面的聊天收起来，从改过的这句重新回答；书里改过的不跟着退」。

### 点了「修改」以后

1. 这句和后面的话改过书时（就是现在的 `warn`），先在这句下面出现现有的那个确认框：
   - 文字换成第 5 节的新字；
   - 按钮是「算了」「接着改」（原来叫「接着来」）。
   - 点「接着改」才往下走。
2. 这句话的气泡原地变成输入框：
   - 框里是原话，不带「@主编」。
   - 原来点过名的，在框上方照底下输入框的样子显示「问主编」那个名牌，能点 × 去掉。
   - 样子照底下输入框（白底、细框、圆角）。宽度用作者那一侧的最大宽度（85%），不随原话长短变。最高和底下输入框一样，超出就在框里滚。
   - 框下面左边一行小字：「改好了点发送：这句和后面的聊天会收起来，从这句重新回答；书里改过的不跟着退」；右边两个按钮「取消」「发送」。
3. 按键：Enter 发送，Shift+Enter 换行，Esc 取消。输入法正在打字时（isComposing）按 Enter 不发送。
4. 正在改的时候：
   - 这句后面的聊天照现在一样变淡（opacity 35%），正在改的这句不变淡；
   - 别的话上不出「修改」。
5. 发送：
   - 照现在「从这里重来」的那条路发（`chat.send` 带上 rewind id）。
   - 点名照原来的；改过的话开头打了「@设定师」这类，照底下输入框的规矩认成点名。
   - 发送出错（`chat.send` 返回 `false`）时，留在编辑状态，字不丢。

### 底下的输入框

- 去掉现在那条横幅「从这句重来：改好了再发……」和它的「算了」。
- 点「修改」不再把原话塞进底下输入框，底下原来打的字不动。
- 正在改上面某一句时，底下输入框照常能打字，但发送键变灰，悬停提示「先发出或取消上面正在改的那句」。

后台不用改，`rewind_from` 那条路照旧。

## 3. 草稿不丢

- 底下输入框里没发出去的字，和点了谁（@），都存在浏览器里，每本书各存一份，key 用 `zhibi.chat-draft.<bookId>`。
- 以下情况都还在：编辑部收成小球再打开、浮窗和侧栏互换、换书页（简介、设定、大纲、正文）、刷新页面、关了浏览器再开。
- 发送成功就清掉；字删光了也清掉。
- 读写 localStorage 都包 try/catch，读不到就当没有，不报错。
- 引用（选中书页文字放进来的那一块）这次不存。

## 4. 回到最新

- 聊天列表往上翻了（离底部超过 48px，也就是现在不会自动跟到底的时候），列表底部正中、输入框上方浮一个小圆钮：只有一个向下箭头（lucide `ArrowDown`），悬停提示「回到最新」。
- 往上翻着的时候下面来了新东西（新的一条，或者正在写的回答又多了字），这个钮变成带字的「↓ 有新回答」。
- 点了就平滑滚到最底，之后照现在的规矩跟到底，钮消失。
- 样子：`bg-card`、`border-line`、`shadow-[var(--shadow-lift)]`、`text-ink-2`、字号 13px、全圆角。
- 浮窗、侧栏、拆的书的聊天都有。

## 5. 回答下面的小字

两条规矩：

- **手动「记下」的按钮一律去掉**：要不要记，以后由编辑部自己判断（任务 2 的记忆）。作者不再在每句话下面点按钮。
- **「记」这个字留给以后的记忆**：写作要求那边一律说「加了一条写作要求」，不说「记成了」「已记成」。

`frontend/src/lib/chat.ts` 的 `outcomeCopy` 和 `ChatOutcome` 照下表改，别的情况不动：

| 情况 | 现在 | 改成 |
|---|---|---|
| 只是聊天（`kind=chat`） | 「只是聊天，没有记」＋按钮「其实要记下」 | 什么都不显示（整行不渲染，不留空白） |
| 没判断出来（`kind=failed`，不是「再改一版」那种） | 「没判断出来（{原因}），这句话没有记，也没有改。」＋按钮「其实要记下」 | 「没判断出这句话要做什么（{原因}），书没改。换个说法再说一次试试。」，**没有按钮** |
| 加了写作要求（`kind=requirement`） | 「已记成要求：「{要求}」（{范围}）」＋按钮「改一下」 | 「加了一条写作要求：「{要求}」（{范围}）」＋按钮「改一下」（照旧，改的是这条要求） |
| 等拍板时（`kind=too_late`） | 「编辑部这时在等你拍板，这句话没有记，也没有改。要改的话，在拍板的地方提意见，或者让我总结成方案。」 | 「编辑部在等你拍板，这句话没改书。要改，就在拍板的地方提意见，或者说「总结一下」整理成方案。」 |

- 「其实要记下」这个动作整个去掉：`outcomeCopy` 不再给它，`ChatOutcome` 的 `act` 里也删掉它那一支。写作要求的框（`RequirementDialog`）只剩「改一下」打开。
- `ChatOutcome` 里有前后对照的那种显示，现在写「记成了写作要求」「交给了编辑部：记成写作要求」，改成「加了一条写作要求」「交给了编辑部：加一条写作要求」。
- `ChatOutcome`：文字是空的、没有按钮、也不是「在看」「在做」的时候，返回 `null`，不留空的一行。
- 后台 `backend/app/api/book_settings.py` 在聊天里发的那句「已记成要求：「…」（…）」，改成「加了一条写作要求：「{要求}」（{范围}）」。
- 修改的确认框（`LiveChat.tsx` 里的 `warn`）改成：「这句和后面的话改过书（{n} 处）。改了重发，聊天退回这里，书不跟着退：要退书，用那几处下面的「换回原来的」，或者去「存档」。」

## 6. 不做

- 不加删除单条消息，不做分支，不给方案卡加复制。
- 不碰「以前的对话」列表。
- 不改提示词。

## 7. 测试

1. **单元测试**：`outcomeCopy` 上面四种情况的新字；`kind=chat` 时 `ChatOutcome` 不渲染。
2. **浏览器测试**：真鼠标、真键盘、演示模型。新书页跑全，拆的书的聊天里能跑的也跑一遍。
   - **复制**：作者的话、最新的回答、较早的回答各点一次，剪贴板里是纯文字；按钮变成「已复制」再变回来；还在写的回答没有「复制」。
   - **修改**：
     - 点「修改」，原地出输入框，里面是原话；
     - 按 Esc、点「取消」，都不改任何东西；
     - 改了按 Enter 发出：后面的聊天收起来，按改过的话重新回答；
     - 改过书的那句先出确认框，点「算了」不进编辑；
     - 正在改时，底下发送键是灰的，底下原来打的字还在。
   - **草稿**：打一段字并点名，然后收成小球再打开、浮窗换侧栏、换书页、刷新，字和名牌都还在；发出后清空；两本书的草稿互不串。
   - **回到最新**：回答正在写的时候往上翻，出现「有新回答」；点了回到底部，钮消失。
   - **小字**：`kind=chat` 那句话下面没有那一行；`kind=failed` 显示新字、没有按钮；加了写作要求的那句显示「加了一条写作要求：……」，点「改一下」能改这条要求。界面上任何地方都找不到「其实要记下」。
3. 旧测试里认旧字的（「从这里重来」「只是聊天，没有记」「其实要记下」「已记成要求」「记成了写作要求」等），照新字改；测「其实要记下」能存成要求的旧用例，改成测这个按钮不存在了。
4. 精髓 28 组、装修 16 组照跑。
