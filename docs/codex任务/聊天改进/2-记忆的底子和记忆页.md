# 聊天改进 任务 2：记忆的底子和「记忆」那一页

共同约定照本目录的 `README.md`。设计依据是 `docs/主编聊天/记忆系统.md`（第三版，下面叫「设计稿」）；本文件和设计稿说法不一样的，照本文件。

这次做记忆本身：怎么存、写书怎么用、搬原来的写作要求、原来加写作要求的几个地方改成记记忆、存档不管记忆、编辑部窗口里的「记忆」那一页、聊天里「记住了」那一行。

编辑部在聊天里自己记（任务 3）、看稿意见交给主编判断（任务 4），这次不做。**这次不改任何提示词。**

## 为什么做

作者要编辑部记住事情：点了「新对话」也记得作者的喜好、否掉过的方向，不用再说一遍。设计稿定了：

- 记忆分两种：「写书时照做」「聊天时记得」；
- 分两个库：「全局」「这本书」；
- 原来的「写作要求」并进来，就是「写书时照做」那一种；本书设置里的「写作要求」那一节去掉。

作者所有书现在都是 0 条写作要求，但迁移照样要写对。

## 1. 每条记忆存什么

- **编号**：全程序统一递增的整数，显示成「记N」，不分全局和哪本书。删掉的号不再给别的用。
- **库**：全局（不属于哪本书），或者某一本书。
- **种类**：「写书时照做」或「聊天时记得」。
- **简述**：一句话。
- **详细内容**：可以多行。
- **管多久**：只有写书时照做才有。规矩照现在写作要求的那套（`services/requirements.py` 的 `SCOPE_INPUTS`、`set_scope`、`requirement_states`）：选的是一直有效、只管下一章、只管这一卷、只管下一卷，存的时候换算成「只管第 N 章」「只管第 N 卷」，那一章定稿、那一卷写完就算过期。全局的只能一直有效。
- **从哪来**：聊天里记的、你加的、方案卡、开书时答的、看稿时说的。界面上就显示这几个字。
- 哪天记的、最后改的时间；从群聊哪句话记的（可空）。
- **删掉的不真删**：留着，好「撤销」找回来，编号不变；列表、写书、聊天都当它不存在。

另外：

- 删一本书，这本书的记忆跟着真删；全局的不动。
- 拆的书没有记忆，接口不收拆的书的「这本书」。
- 同一个库、同一种里，新记的简述和已有的一条一字不差：不重记，就是那一条（来源、时间照新的）。

## 2. 搬原来的写作要求

新加一个迁移：

- 每条写作要求搬成那本书的「写书时照做」：
  - 简述＝原文，超过 40 字取前 40 字加「……」；
  - 详细内容＝原文；
  - 管多久、记的时间、message_id 照旧；
  - 编号按原来的 `seq` 先后排。
- 从哪来按原来的 `source` 换：

| 原来的 source | 从哪来 |
|---|---|
| `manual`、`legacy`，以及下面没列到的 | 你加的 |
| `note`、`private:*`、`chat:*` | 聊天里记的 |
| `plan` | 方案卡 |
| `answer` | 开书时答的 |
| `trial`、`volume:*`、`unit:*`、`segment:*` | 看稿时说的 |

- 搬完旧表不再读写。删不删由你定；删的话，存档、旧检查点导入这些用到它的地方都要处理干净。在完成说明里写清。

## 3. 写书怎么用「写书时照做」

- 现在所有带「作者的要求」的地方，改成带「写书时照做」的记忆，全局＋这本书，过期的不带。
  - 用 `active_requirements`、`requirement_text`、`format_requirements` 的地方都算：开书、排大纲、拆卷、出章纲、写正文、审稿、帮写设定、帮写大纲……
  - 开书流程里的 `live_requirements` 也算。
- 每条一行：
  - 只管某章、某卷的，前面照旧带「（只管第 N 章）」「（只管第 N 卷）」；
  - 后面是详细内容，里面的换行换成一个空格。
- 全局的排前面，这本书的排后面，各自按编号从小到大。
- 「作者的要求（必须落实；后面的要求与前面冲突时以后面的为准）」那一块的标题和拼法都不动，写书的提示词一个字不改。
- 编辑部正在写的时候加、改、删的写书时照做，从下一步起照办，不进待处理。和现在一样。
- 聊天提示词里现在的 `{{requirements}}`（chat_agent、chat_reply）这次照旧是那一块，内容换成上面这份写书时照做的清单。任务 3 再换成记忆目录。

## 4. 原来加写作要求的地方，改成记记忆

下面这些都记成这本书的「写书时照做」：

| 入口 | 简述 | 详细内容 | 从哪来 |
|---|---|---|---|
| 群聊分流认出的（`group_notes`，包括编辑部正在写时交给编辑部的） | 分流整理好的那句要求 | 作者原话 | 聊天里记的 |
| 方案卡里「写作要求」那一类，点「按这个来」时 | 卡上那一条 | 卡上那一条 | 方案卡 |
| 能调工具的群聊用 make_changes「写作要求」那一类（这次照旧能用，任务 3 换成 remember） | 那句要求 | 那句要求 | 聊天里记的 |
| 开书时：回答「动笔前提问」；挑故事方向时选了哪个、写多少万字、书名 | 原话，超过 40 字截断（同第 2 节） | 原话 | 开书时答的 |
| 看稿时写的意见、点的「改成……」：开书的各步、试读、篇、卷纲、章纲 | 原话，截断同上 | 原话 | 看稿时说的 |
| 新建书时，新书默认里的「其他规矩」 | 原话，截断同上 | 原话 | 你加的 |

- 看稿那一行是过渡：这次照现在一样自动记，任务 4 再改成交给主编判断。
- 写书流程里认作者插话的旧兼容代码，照现在的效果改成读写记忆：`_new_notes`、`active_notes`、`ingest_notes`、`import_legacy_checkpoint`、tombstone 那些。能证明走不到的，可以删，删了在完成说明里列出来。
- 待处理里点「同意」交给编辑部、结果是记了一条记忆的，照样算办成了（`api/chat.py` 里认「做成了」的那几种）。
- 程序里交回给模型的那几句（`done_text` 的「记成了写作要求」、make_changes 回的「做成了：……」、编辑部正在干活时的那句），这次都不动，任务 3 再改。

## 5. 存档不管记忆

- 存档里不再存记忆。「回到这一档」时记忆不动。「和现在比」里去掉「写作要求」那一组。
- 以前的存档里带着的写作要求，和本书设置里的「其他规矩」，回到那一档时都不管：不挪进记忆，也不恢复。
- 记忆加、改、删不触发自动存档。原来改写作要求会触发。

## 6. 编辑部窗口里的「记忆」那一页

照「待处理」的做法做：`Inbox.tsx` 的 `PendingButton`、`PendingList`，以及 `BookDesk.tsx` 里怎么接的。

**顶上的按钮**

- 在「待处理」右边，叫「记忆」，图标用 lucide `NotebookPen`。窄的时候只剩图标，和待处理一样。
- 悬停提示：没打开时「记忆：编辑部记着的规矩和你的喜好」；打开时「回到聊天」。
- 点了，整个窗口换成记忆那一页；再点，或点「回到聊天」，换回来。记忆和待处理同时只开一个。
- 拆的书没有这个按钮。

**那一页**

- 左上「回到聊天」，右边标题「记忆」。
- 下面切换两页：「这本书」「全局」，默认「这本书」。
- 每页分两组，组名下面一行淡字说明：
  - 「写书时照做」：「编辑部写设定、排大纲、写正文时，每次都守着。」
  - 「聊天时记得」：「只在和你聊天时用，比如你的口味、你说话的意思。」
- 每条：
  - 第一行是简述；
  - 下面淡字：管多久（只有写书时照做才有）· 哪天记的 · 从哪来。日期写成「10月22日」，不是今年的带上年份。
  - 点这一条展开：详细内容（保留换行），下面「改」「删」。
- 组里按编号从小到大排。
- 过期的：排在「写书时照做」那组最后，整条变淡，淡字开头是「已过期 · 」，能改能删。
- 一组一条都没有：组名下面写「还没有。」。整页两组都没有：只写一句「还没有记忆。在聊天里说「记住……」，编辑部就会记下来。」

**加一条**

- 在两页切换的那一行右边。
- 点了在列表最上面出编辑框，各项和「改」一样，默认值：
  - 种类：「写书时照做」；
  - 放在：正在看的那一页；
  - 管多久：一直有效。
- 保存后出现在对应的组里，从哪来是「你加的」。

**改**

- 原地变成编辑框，各项：
  - 简述（单行）；
  - 详细内容（多行）；
  - 种类：写书时照做／聊天时记得；
  - 放在：这本书／全局；
  - 管多久：只有写书时照做才出，选项照现在的 `ScopeSelect`。放在全局时只能一直有效，下拉变灰。
- 下面「取消」「保存」。
- 简述必填；详细内容空着，就存成和简述一样。
- 换了库或种类，保存后它到对应的页和组里去：那一页自动切过去，并滚到它。

**删**

- 这一条原地变成一行「删掉了：{简述}」，后面「撤销」。点了找回来，编号不变。
- 离开这一页再回来，这一行就没了。

**整理一下**

- 只在「这本书」那页的「写书时照做」组名右边，没过期的到 5 条才出。
- 沿用本书设置里原来那一套，挪过来：`requirements_tidy`，作者勾了才改。
- 交给模型的清单，每行写「{序号}. {详细内容，换行换成空格}（{管多久}；来自{从哪来}）」。
- 改写的那条，简述和详细内容都换成改写后的那句；简述超过 40 字照第 2 节截断。
- 整理的提示词不改。

**从别处跳过来**

- 聊天里那一行、本书设置的「去看看」打开记忆页时，可以指定跳到哪一条：
  - 切到它所在的那一页，展开它，滚到中间，淡淡高亮 2 秒；
  - 指到的那条已经删了：页面顶上出一行「这条已经删了。」。

**跟着变**

- 别处记、改、删的（聊天里、方案卡），开着的记忆页跟着变。照待处理怎么刷新的做。

## 7. 本书设置

- 「写作要求」那一节去掉，换成一行：「写书时照做的规矩，现在放在编辑部的「记忆」里。」后面接「去看看」，点了打开编辑部窗口的记忆页（「这本书」那一页）。
- 书页左下「本书设置」按钮的悬停提示，「这本书怎么写：人称、每章字数、写作要求……」改成「这本书怎么写：人称、每章字数……」。

## 8. 聊天里「记住了」那一行

这次给分流那条路、make_changes 那条路和方案卡用。任务 3 编辑部自己记的时候，也用这同一个。

- 字：「记住了：{简述}」。
- 后面淡字：「{种类} · {全局／这本书}」；写书时照做的再加「 · {管多久}」；编辑部正在写的时候记的写书时照做，再加「 · 正在写的从下一步起照办」。
- 再后面是「撤销」：
  - 点了删掉这条，这一行变成「没记：{简述}」；
  - 这条后来又被改过：「撤销」变灰，悬停提示「这条后来又改过，去「记忆」里改」；
  - 这条后来删掉了（记忆页里删的、整理掉的）：「撤销」变灰，悬停提示「这条后来删掉了」。
- 点这一行的字：打开记忆页，跳到那一条。

「改了一条记忆」「忘掉了」那两种行，任务 3 才有。

用在这几处：

- **分流那条路**：作者那句话下面，原来是「加了一条写作要求：「…」（…）」加「改一下」；编辑部正在写时是「已交给编辑部：做完手头这一步就照办」。两种都换成上面这一行。「改一下」和 `RequirementDialog` 不要了。
- **make_changes 那条路**：作者那句话下面，原来是「加了一条写作要求」「交给了编辑部：加一条写作要求」那种前后对照加「换回原来的」，换成上面这一行。
- **方案卡**：
  - 「写作要求」那一类，卡上显示成「记忆 · 写书时照做 · {管多久}」；
  - 点「按这个来」以后，结果里那一条也是上面这一行。
- **修改的提醒**：数「这句和后面的话改过书（n 处）」时不算记忆，`LiveChat.tsx` 的 `CHANGED` 去掉写作要求那一种。聊天退回去，记忆不跟着退。
- 后台 `book_settings.py` 在聊天里发「加了一条写作要求：…」的那段，随旧接口一起去掉。

## 9. 不做

- 不改提示词：聊天的、写书的、分流的、方案卡的、整理的都不改。
- 编辑部在聊天里自己记（remember 那几个工具），回答下面的「改了一条记忆」「忘掉了」：任务 3。
- 看稿意见交给主编判断：任务 4。
- 记忆不能搜索；「聊天时记得」不会自动过期。
