# 聊天改进 任务 4：看稿时写的意见，交给主编判断要不要记

共同约定照本目录的 `README.md`，在任务 2、3 的基础上做。设计依据是 `docs/主编聊天/记忆系统.md`（第三版，下面叫「设计稿」）第 4、6 节和 9.9；本文件和设计稿说法不一样的，照本文件。

**这次要加一份新提示词**，原文在设计稿 9.9，照着逐字放。

## 为什么做

编辑部会停下来请作者看稿：开书的各步、试读前 3 章、篇、卷纲、章纲。作者在框里写的意见，现在（任务 2 照旧）一律存成一直有效的「写书时照做」。

作者指出这不合理：看这一章时说「打斗多一点」，后面每一章都会拼命多写打斗。

改成：意见只管眼前这一处；里面有没有以后要一直照做的，交给主编判断，有才记。

## 1. 哪些不再自动记

- **看稿时写的意见**：
  - 让改时写的，点确认时顺手写的，都算；
  - 地方包括开书的各步（「三个故事方向」让重出时写的、「先写设定」开始时写的也算）、试读、篇、卷纲、章纲。
- **看稿时点的「改成……」**（flips）：不记，只用来改眼前这一处。
- 现在存这些的地方，都在 `api/jobs.py`（decision、`feedback_to_job`、`choose_pitch`、`decide_segment`、`decide_piece`）、`graphs/write_book.py`（`_requirement` 那几处）、`graphs/book_setup.py`。以任务 2 改完后的代码为准，grep 找全。
- **照旧自动记的**（开书时答的）：回答「动笔前提问」；挑故事方向时选了哪个、写多少万字、书名。
- 改眼前这一处，照旧直接用意见原话（现在就是直接传给改稿那一步的），不靠记忆。
- `book_setup.py` 里跟写作要求 tombstone 联动的那段（`feedback_sources`、`deleted`）：作者在记忆里删一条，不再影响编辑部改眼前这一处，照这个意思简化。

## 2. 主编判断

**提示词**

- 新文件 `backend/app/prompts/feedback_memory.md`，原文照设计稿 9.9 逐字放。
- system 照别的主编提示词，用 persona_chief；用主编的模型配置。
- 提示词页登记（`prompts/catalog.py`）：
  - 名称「看稿意见要不要记」；
  - 分组「聊天」；
  - 调用角色主编；
  - 使用时机「编辑部停下来请作者看稿时，作者写的意见里有没有以后要一直照做的，有才记进记忆」。
- 变量 where、what_happens、feedback、memory 怎么填，模型交回什么，照 9.9。where 用页面上那一步的叫法，比如「试读前 3 章」「第 3 卷的卷纲」「单元「{名称}」的章纲」「第 2 篇」「定调」「设定库」「大纲」「三个故事方向」。

**什么时候判断**

- 作者交了带意见的看稿（让改，或者点确认时写了几句）以后，在后台判断。
- 编辑部照意见改眼前这一处，不等判断；判断失败也不影响改稿。
- 同一段意见只判断一次：重试、页面重复提交，都不重复判断。
- 只点了「改成……」、没写字的，不判断。

**交回以后怎么记**

- 都记成这本书的「写书时照做」，从哪来是「看稿时说的」，管多久照交回的。
- 交回的编号是这本书「写书时照做」里有的（没删、没过期）：改那一条，改之前的样子存着，好撤销。
- 编号留空，或者不是上面那种：新记一条。
- 一条都没交回：不记。

**聊天里看到什么**

- 主编判断交回的 reply，以主编的身份发在群聊里，照试读完主编现在说「意见记下了……」那句的发法发。
- 记了的，每条在 reply 下面出一行：
  - 新记的，出「记住了：……」（任务 2 做的）；
  - 改了已有的，出「改了一条记忆：……」（任务 3 做的）；
  - 都带「撤销」。
- 判断失败：主编在聊天里说「这段意见没来得及判断要不要记（{原因}）。要以后都照做，在聊天里跟我说「记住……」。」

## 3. 改两句现有的字

- 试读时写了意见，页面上回的那句（`liveWriting.ts`）：
  - 现在：「记下了：以后每一章都照这个写（记在写作要求里，随时能改）」
  - 改成：「好，交给主编：要后面每章照着写的，会记进记忆」
  - 原型里（`writingSim.ts`）同一句一起改。
- 试读完，主编在聊天里说的「意见记下了，后面每一章都按这个来写。」（`trial_gate_node`）去掉，换成主编判断交回的 reply。

## 4. 演示模型

`llm/demo.py` 认得 feedback_memory，够测试用就行：

- 意见里有「以后」「每章」「都」的，记一条；
- 别的不记；
- reply 照记没记说一句。

## 5. 不做

- 看稿意见只记成这本书的「写书时照做」：不记全局，不记聊天时记得。
- 别的提示词一个字不改。

## 6. 测试

1. **后端**
   - 第 1 节说的各个看稿入口都不再自动记；开书时答的照旧记。
   - `feedback_memory.md` 和设计稿 9.9 逐字一致，用 sha256 指纹锁住。
   - where 和三种 what_happens 填得对。
   - 判断交回以后：新记、改已有的、编号不对当新记、空的不记都对；记的都是这本书的写书时照做、来源「看稿时说的」。
   - 判断失败时的那句；改稿不等判断；判断失败不影响改稿。
   - 同一段意见不重复判断。
2. **浏览器测试**（演示模型，真鼠标、真键盘）
   - 看卷纲时写「这一卷打斗多一点」让改：卷纲照改，聊天里主编回了话，没有「记住了」。
   - 写「以后每章打斗都多一点」让改：卷纲照改；聊天里出「记住了：…」；记忆页里有这一条，来源「看稿时说的」；能撤销。
   - 试读时写意见：页面上那句新字；聊天里主编的回话。
3. **旧测试**：认旧字的照新的改。
4. **页面比对**：精髓 28 组、装修 16 组照跑。
