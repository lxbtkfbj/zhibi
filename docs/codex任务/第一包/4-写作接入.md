# 任务 4：写作接入（后端）

> 先读 `docs/codex任务/第一包/README.md`、`docs/设计说明.md` 第 3.2 节和第 11.6-11.8、11.11 节，并确认任务 1、2 已完成并提交。

## 目标

写作流程用上第一包的新结构：

- 卷纲以节点为目标，并能调整暂定节点；
- 卷纲专项审稿增加「期待感」；
- 章纲带情绪曲线、期待动作和揭晓，出章纲后由程序检查节奏，不合格重出一次；
- 备资料、写正文、查矛盾、定稿提取都接入信息差表，重写章节时能撤销信息差的变化。

不做：写作阶段的新界面（任务 5）。本任务只对前端做最小改动，保证不坏。

## 2. 节奏底线（新建 `app/agents/rhythm.py`）

```python
RHYTHM = {
    "harem_xuanhuan": {"max_low_streak": 3, "low_share": 1 / 3},
    "general": {"max_low_streak": 5, "low_share": 1 / 2},
}
MOOD_REPEAT = 4          # 同一主情绪最多连续 3 章，第 4 章起算问题
CLIMAX_TAIL = 2          # 单元情绪最高的一章要在最后 2 章内
REMIND_AFTER = {"短": 20, "中": 20, "长": 50}   # 已立下的期待隔多少章没被提起就要提醒
```

- **`rhythm_text(playbook_key)`**：返回下面这段，供提示词的 `{{rhythm}}` 使用；数字按打法替换，未知打法按 general。

  ```
  【这本书的节奏底线】
  - 连续压抑（情绪 ≤ -1）最多 3 章。
  - 一个单元里压抑的章不超过三分之一。
  - 同一种主情绪不要连续 4 章。
  - 单元里情绪最高的一章放在最后 2 章内。
  ```

- **`check_chapter_plan(chapters, playbook_key, prior)`**：返回问题列表。`chapters` 是本单元的章纲，`prior` 是本单元之前最多 5 章的章纲，用来接上跨单元的连续压抑和连续同情绪。
  - 只检查有 `emotion` 的章纲；旧章纲（没有 emotion）不参与计算。
  - 问题的写法要能直接当修改要求用，例如：
    - 「第 12-15 章连续 4 章压抑（底线 3 章），中间安排一次小的扬或爆发」
    - 「本单元 9 章里有 5 章压抑，超过三分之一」
    - 「第 20-23 章主情绪都是「虐」，换一换」
    - 「单元情绪最高的一章在第 18 章，不在最后 2 章内，把高潮往后挪」
- **`overdue_expectations(ledger, unit_first, unit_last, actions)`**：
  - 对象：`kind=期待`、`status=planted` 的条目。
  - 最后一次被提起的章 = `max(planted_chapter, *hint_chapters)`。
  - `unit_last - 最后一次 > REMIND_AFTER[span]`，并且本单元章纲里没有对它的提醒或回收时，算作问题，例如「E3「三年之约」已经 26 章没提了，本单元安排一次提醒或兑现」。

## 3. 卷纲

### 3.1 新变量

- `volume_directions`、`audit_volume` 的 blocks 增加 `target_node`。`volume_blocks` 在任务 2 里已经提供这个变量，这里确认审稿和定方向的调用也传进去。

### 3.2 程序检查（`audit_volume` 的 `found`）

每条前缀「问题：」或「提示：」。只有「问题」按现有规则算作必须修改，「提示」只交给审稿参考。

| 类型 | 条件 | 示例 |
|---|---|---|
| 问题 | 计划在本卷立下或兑现的期待（`plant_volume` 或 `payoff_volume` 等于本卷，且没有回收或放弃），没有排进任何单元 | 「期待 E3「……」计划在本卷兑现，没有排进任何单元」 |
| 问题 | 已立下的期待按 `REMIND_AFTER` 到本卷开头已经超期，本卷没有任何单元提醒或兑现它 | |
| 提示 | 某个单元没有任何期待动作 | 「第 2 个单元没有任何期待动作」 |
| 提示 | 本卷开始时没有开着的中长线期待，本卷也没有新立 | |

### 3.3 节点调整与冲突（`write_book`）

- **`node_update`**：
  - 目标节点是暂定：把提议放进流程状态，并放进 `volume_review` 的 pending：

    ```python
    "node_update": {"node_id": str, "index": int,
                    "current": {"title", "event", "prerequisite", "consequence"},
                    "proposed": {...}, "reason": str}
    ```

    - 作者批准卷纲 → 把提议写进节点：状态仍是暂定，来源 ai；并在节点上记 `updated_by_volume = 本卷号`（新增可空 int 列，迁移 `0012_node_updated_by_volume`；`NodeOut` 也返回这个字段）。主编说一句「暂定节点「X」按这一卷的写法调整了」。
    - 卷纲拍板已关闭 → 自动应用，并发一条系统消息。
    - 作者提修改意见 → 丢弃这次提议；修改后的卷纲可以重新提议。
  - 目标节点是铁钉：忽略提议，在 `node_conflict` 后面补一句「（主编提议调整铁钉节点，已忽略）」。
- **`node_conflict`**：不为空时，放进 `volume_review` pending 的 `issues`，写成「节点冲突：……」；主编在群聊里说明。

## 4. 章纲（`plan_chapters_node`）

### 4.1 新变量（`chapter_plan_blocks`）

- `secrets`：与本单元有关的隐藏秘密，最多 10 条，由 `format_secrets` 生成。满足任一条件即算有关：
  - 知情人里有本单元的人物（`unit.key_events` 和本卷新人物里出现的名字，加上主角）；
  - 被本单元 `reveals` 引用；
  - 揭开节点就是本卷的目标节点。
- `rhythm`：`rhythm_text(打法)`。
- `revision`：第一次为空串。

### 4.2 出章纲后

1. 依次检查：
   - `check_chapter_plan`；
   - `overdue_expectations`；
   - 引用合法性：伏笔、期待编号必须在台账里，揭晓编号必须在信息差表里，不合法的丢掉并记成问题。
2. 有问题且是第一次：用 `format_revision("当前章纲", format_chapter_plan(结果), 问题逐条)` 作为 `revision` 重出一次。`format_chapter_plan` 可以用 `format_chapter_outline` 拼。
3. 重出之后仍有问题：照常建章，把剩下的问题写进 `plot_units.plan_issues`，发一条状态消息「第 N 单元章纲还有 2 处节奏问题，已记在卷页」。

章纲 JSON 保存 `emotion`、`mood`、`reveals`（随 `model_dump` 一起存）。

## 5. 正文链路

### 5.1 备资料（`material_blocks`）

增加 `secrets`：全部隐藏的秘密，最多 20 条。章纲点名人物涉及的排在前面——涉及是指当了知情人，或者出现在真相里。

### 5.2 写正文（`chapter_blocks`）

返回两种信息差文本：

- `secrets`：列表版，`format_secrets`，查矛盾和定稿提取用。
- `secrets_for_writer`：写手版。

写手版的格式：

```
【本章的信息差】
- S2「主角的真实修为」（读者：知道）：知道的人：林岚（开书时）；本章出场但还不知道：赵无极、柳如烟
- 本章揭晓：S5 揭给 柳如烟——在拍卖会上看穿主角的伪装
写的时候，不知道的人不能说出、想到或按这些信息行动；要揭晓的，写清楚是怎么知道的。
```

写手版的取法：

- 本章人物 = 章纲人物 + 设定师挑的人物。
- 选秘密：隐藏状态，并且满足下面任一条——知情人里有本章人物；被本章揭晓引用；真相里出现本章人物的名字。
- 最多 8 条；一条都没有时返回空串。

渲染 `write_chapter` 时用 `{**blocks, "secrets": blocks["secrets_for_writer"]}`。作者重写章节也走这一条。

### 5.3 伏笔与期待任务（`foreshadow_tasks`）

- 标题改为「【本章要处理的伏笔和期待】」。
- 期待条目的动作词用 立下 / 提醒 / 兑现，并分别附上：
  - 立下：「立法：{plant_plan}」，再加一句「写清楚让读者开始期待的那一幕（约定、狠话、倒计时），让读者明确知道接下来在等什么。」
  - 提醒：照原样附上原文片段，再加一句「让角色或旁人自然地提起，让读者想起还在等这件事。」
  - 兑现：附上原文片段，加「兑现方式：{payoff_plan}」，再加一句「兑现要超出读者的预期：比读者以为的更大、更快，或者换个角度。」
- 结尾那句说明改为同时提到伏笔和期待。

### 5.4 查矛盾和定稿提取

`check_consistency`、`digest_chapter` 用列表版 `secrets`，没有条目时为「（暂无）」。

### 5.5 定稿写入（`writing_store.apply_digest`）

- `secret_updates`：
  - 编号必须存在；
  - `learned_by` 里的名字必须是已有人物，已经是知情人的跳过；
  - 新知情人追加 `{"name", "since_chapter": 本章, "how"}`；
  - `public=True` 时状态改为 public。
- `new_secrets`：接着编号，知情人做同样的过滤，`since_chapter` 为本章，`how` 为「本章」，`created_chapter` 为本章。
- `bible_changes` 新增两项：
  - `"secrets": [{"seq", "before": {"knowers", "status"}, "after": {...}}]`
  - `"created_secrets": [seq, ...]`
- 返回的统计里加上信息差的改动条数。

### 5.6 重写撤销（`revert_chapter`）

- 撤销本章追加的知情人：名字相同、`since_chapter` 等于本章、并且现在仍然存在的条目。
- 状态还等于 after 的，改回 before。
- 本章新建的秘密：后面没有定稿章节时删除，规则同人物。

## 8. 测试

1. **`rhythm`**：跨单元连续压抑、压抑占比、连续同情绪、高潮位置、旧章纲没有 emotion 的情况；`rhythm_text` 按打法给出不同数字。
2. **`overdue_expectations`**：中线、长线的阈值；本单元已经安排了提醒时不报问题。
3. **出章纲**：曲线不合格时重出恰好一次，`revision` 里带着问题；重出后仍有问题时写进 `plan_issues`。
4. **卷纲审稿**：「问题」和「提示」分开；只有「问题」会导致自动修改。
5. **`node_update`**：
   - 暂定节点：提议进入 pending；批准后节点被更新；卷纲拍板关闭时自动应用。
   - 铁钉节点：提议被忽略，冲突写进 issues。
6. **信息差**：写手版的选取规则；定稿后知情人、状态、新秘密正确写入；重写章节后撤销；后面有定稿章节时不删除新秘密。
7. **期待**：`foreshadow_tasks` 里三种动作的措辞，以及兑现时附带的原文片段。
8. **回归**：演示模式下写完第一卷，并开始拆第二卷。
