# 任务 2b：铁钉节点按作者点名修改（任务 2 的补丁）

> 先读 `docs/codex任务/第一包/README.md` 和 `docs/设计说明.md` 第 11.4 节「铁钉」那一条（已更新）。任务 2 已完成并提交。

## 背景

任务 2 用程序强制保护铁钉节点，这是对的；但现在连作者自己点名要改铁钉节点，也会被程序改回去，作者的话被悄悄吞掉。设计已经明确：**作者亲口点名时，主编按作者的话改那一个铁钉节点，改完仍是铁钉**；其他来源（AI 自己、审稿、插话里没点名的顺带修改、写作中的卷纲）照旧不能改。

## 要改的地方

1. **schema**（`RevisionTriage` 新增，描述逐字照抄）：

   ```python
   pinned_overrides: list[int] = Field(
       default_factory=list,
       description="作者这次的话明确点名要改的铁钉节点序号（按提示词里的节点序号）；作者没有点名就留空",
   )
   ```

2. **提示词**：用 `git mv -f` 从 `docs/codex任务/第一包/提示词/` 搬进 `backend/app/prompts/`：`setup_triage.md`、`setup_notes.md`、`setup_spine.md`。变量没有变化，措辞不要改。

3. **流程**（`graphs/book_setup.py`，`merge_nodes` 及调用处）：
   - 新增「本轮允许改的铁钉」集合，来源只有两个：
     - 修改动作带 `node_id`（作者在卡片上点「改」）：这个节点放进集合，不论它是铁钉还是暂定。
     - `triage_feedback` / `absorb_notes` 返回的 `pinned_overrides`：按渲染提示词时的节点快照映射成节点 ID 放进集合；序号对不上的丢弃。
   - `merge_nodes` 对集合里的铁钉节点，用模型的新内容；位置、状态（仍为铁钉）、来源保持不变。集合外的铁钉照旧原样恢复。
   - 集合只在这一轮修改里有效，修改完清空，不写进检查点之外的地方。
   - 审稿自动修改（critique）、同步要求（SYNC_INSTRUCTIONS）、写作中的卷纲规划都不产生这个集合。
   - 一口气模式的 `author_gate → triage` 同样适用。

4. **主编回应**：改了铁钉节点时，主编在群聊说明「按你的意思改了铁钉节点 N「标题」，它还是铁钉」。

## 测试

- 卡片「改」带 `node_id` 指向铁钉节点：内容按意见改变，状态仍为 pinned，其他铁钉不变。
- 一般意见里点名铁钉节点：triage 返回 `pinned_overrides`，该节点改变；没点名的铁钉不变。
- 插话里点名铁钉节点：同上，经 `absorb_notes`。
- 审稿自动修改、同步要求：铁钉一律不变（已有测试继续通过）。
- 演示模式：`RevisionTriage` 在意见里出现「节点 N」字样且该节点是铁钉时，返回对应的 `pinned_overrides`，供测试使用。
