# 任务 1：数据底座

> 先读 `docs/codex任务/第一包/README.md`（共同约定）和 `docs/设计说明.md` 第 11 节。

## 目标

- 数据库能承载第一包的所有新概念：关键节点、人物锚点、信息差、期待（台账类型）、编辑批注、开书进度。旧数据迁移完成。
- 提供节点、锚点、信息差、台账类型、术语表的读写接口。
- 提示词上下文的格式化函数改为从新结构读数据。
- 现有的开书和写作流程不改逻辑，但要在新结构上继续能跑（开书仍按现有提示词产出，保存时转换成新结构）。

不做：开书流程图改造（任务 2）、写作流程接入（任务 4）、新界面（任务 3、5）。本任务只对前端做最小改动，保证现有页面不坏。

### 1.3 数据迁移（写在迁移文件里，不 import app 代码）

1. **节点**：对每本书的 `books.spine`：
   - `opening` 非空：建 `kind=opening`，title「开篇」，event 为开篇文字。
   - `milestones` 按 index 排序：每个建 `kind=milestone`，title、event、volume 照搬，`consequence` 取原 `change`。
   - `ending` 非空：建 `kind=ending`，title「结局」，event 为结局文字。
   - 全部 `status=pencil`、`origin=ai`，position 按上面的顺序 1..k。
   - 迁移后从 `spine` JSON 里删掉 `opening`、`ending`、`milestones`，保留 `core_conflict`、`theme`、`protagonist_arc`。
2. **卷走向的节点**：每卷取第一个满足 `node.volume >= 卷号` 的 milestone 或 ending 节点（按 position 顺序；ending 的 volume 为空时视为最后一卷），写入 `target_node_id`；`reaches_node = (node.volume == 卷号)`。没有可用节点时留空。
3. **信息差**：每个人物 `secrets` 列表里的每条非空文字，建一条 `secrets`。
   - seq 按书递增；title 取文字前 12 个字（去掉末尾标点），truth 为全文。
   - knowers 为 `[{"name": 人物名, "since_chapter": null, "how": "开书设定"}]`；reader_knows 为空；status 为 hidden。
   - 然后删除 `characters.secrets` 列。
4. **台账**：所有已有行 `kind='伏笔'`（默认值即可）。
5. **开书进度**：`books.status != 'setting_up'` 的书，写入 `{"mode": "oneshot", "current": null, "pieces": {"concept": "confirmed", "nodes": "confirmed", "cast": "confirmed", "fill": "confirmed", "first_volume": "confirmed"}}`；正在开书的书留空，由任务 2 的流程填写。
6. **downgrade**：尽力还原——节点写回 spine JSON；信息差按知情人写回 `characters.secrets`（加回列）；删除新表新列。

## 3. 开书方案的数据形状（`app/services/setup_store.py`）

任务 2 的流程图在状态里用下面这个形状。`load_setup` 返回它，`save_setup` 接收它。所有「节点序号」都是 1 起、按 `spine.nodes` 当前顺序的序号；保存时按刚保存好的节点顺序映射成节点 ID。

```python
setup = {
    "concept": {...},  # 同 books.concept
    "spine": {
        "core_conflict": str, "theme": str, "protagonist_arc": str,
        "nodes": [  # 按顺序；第 i 个就是「节点 i」
            {"id": str | None, "kind": "opening" | "milestone" | "ending",
             "title": str, "event": str, "prerequisite": str, "consequence": str,
             "volume": int | None, "status": "pinned" | "pencil" | "empty", "origin": "ai" | "author",
             "editor_note": str, "techniques": [str]},
        ],
    },
    "lore": {
        "world_entries": [...], "characters": [...],  # 人物不再有 secrets
        "relationships": [...],
        "anchors": [{"character": 姓名, "node": 节点序号, "kind": "登场", "note": str}],
        "secrets": [{"seq": int | None, "title": str, "truth": str,
                     "knowers": [{"name": str, "since_chapter": int | None, "how": str}],
                     "reader_knows": "知道" | "不知道" | "部分" | None,
                     "reveal_plan": str, "node": 节点序号或 0, "status": "hidden" | "public"}],
    },
    "threads": {"threads": [...]},
    "outline": {
        "volumes": [{...原有字段, "target_node": 节点序号或 0, "reaches_node": bool,
                     "editor_note": str, "techniques": [str]}],
        "foreshadowings": [...],  # 长线伏笔：kind=伏笔、span=长，可带 "node"
        "expectations": [...],    # 长线期待：kind=期待、span=长，字段同伏笔，可带 "node"
    },
    "first_volume": {
        "units": [{...原有字段, "reveals": [...], "editor_note": str, "techniques": [str]}],
        "new_foreshadowings": [...],  # 本卷的短线、中线伏笔
        "new_expectations": [...],    # 本卷的中线期待
    },
}
```

要求：

- **节点**：新增 `load_nodes` / `save_nodes`。
  - 按 `id` 对齐：有 id 的原地更新，没有的新建，列表里没有的删除。
  - 保存后整体重写 position。
  - 开篇必须是第一个、结局必须是最后一个，否则抛 `ValueError`。
- **旧形状兼容**：`spine_from_legacy(spine: dict) -> dict` 把旧形状（`opening` / `milestones` / `ending`）转成新形状，转换规则同迁移 1.3 第 1 条。`save_setup`、`format_spine` 遇到旧形状都先转换——旧检查点和本任务期间仍按旧 schema 产出的开书结果都会走到这里。
- **人物锚点**：按（人物名、节点序号、类型）整体替换。人物名或节点序号对不上的丢弃，并在返回值里带出被丢弃的条数。
- **信息差**：
  - 按 seq 对齐；没有 seq 的，先按 title 匹配已有行，匹配不上的接着编号。
  - knowers 里的名字不在人物表的丢弃。
  - 兼容旧人物数据：人物条目里如果还带 `secrets`（现有提示词仍会产出），按迁移规则转成信息差行，知情人为该人物，再从人物数据里去掉这个字段。
- **台账**：
  - `ledger_of` 合并伏笔与期待，共用编号空间（沿用 `assign_seqs`）。
  - `load_setup` 分组规则：
    - `kind=伏笔` 且 `span=长` → `outline.foreshadowings`
    - `kind=期待` 且 `span=长` → `outline.expectations`
    - `kind=伏笔` 且 `span≠长` → `first_volume.new_foreshadowings`
    - `kind=期待` 且 `span≠长` → `first_volume.new_expectations`
  - `FORESHADOW_FIELDS` 增加 `kind`，`node` 序号与 `node_id` 互相映射。
- **分卷**：`VOLUME_FIELDS` 增加 `reaches_node`、`editor_note`、`techniques`；`target_node` 序号与 `target_node_id` 互相映射。
- **剧情单元**：`UNIT_FIELDS` 增加 `reveals`、`editor_note`、`techniques`。
- **保存顺序**：`save_setup` 按 概念 → 节点 → 人物与世界观 → 锚点与信息差 → 分卷 → 线索 → 第一卷单元 → 台账 的顺序保存。`save_setup(load_setup(...))` 必须是幂等的。
- **按块保存**：新增 `save_piece(session, book_id, piece, setup)`，只保存一块的数据，供任务 2 使用：
  - `concept`：概念
  - `nodes`：spine
  - `cast`：lore（含锚点与信息差）
  - `fill`：outline + threads + 长线台账
  - `first_volume`：第一卷单元 + 短中线台账

  写法可以复用 `save_setup` 的内部函数。

## 4. 上下文格式化（`app/agents/context.py` 等）

- **`format_spine(spine)`**：先输出核心矛盾、主题、主角成长弧，再输出关键节点，格式如下：
  ```
  关键节点：
  节点 1「开篇」· 开篇［暂定｜约第 1 卷］发生：……
    之后变成：……
  节点 2「回幻妖界」［铁钉｜约第 2 卷］发生：……
    之前得先有：……
    之后变成：……
  节点 4「（留空）」［留空｜约第 4 卷］这里还没定
  ```
  状态的中文分别是：铁钉 / 暂定 / 留空。空字段那一行省略。结局写成「· 结局」。
- **`foreshadow_code(f)`**：`kind=期待` 返回 `E{seq}`，否则 `F{seq}`。
- **`format_foreshadowing(f)`**：期待的状态词是 未立 / 已立 / 已兑现 / 放弃；方括号里加类型。示例：
  - 期待：`- E8［期待·中·已立·第2卷立、第3卷兑现］读者在等：……（立：……；兑现：……）`
  - 伏笔：`- F3［伏笔·长·已埋·第1卷埋、第4卷收］……`
- **`format_secrets(secrets)`**（新增）：
  ```
  - S2「主角的真实修为」［隐藏｜读者：知道］真相：……
    知道的人：林岚（开书时）、赵青（第 35 章，偷听）；计划：……
  ```
  没有条目时返回「（暂无）」。
- **`format_lore(lore)`**：人物不再输出秘密；末尾追加「人物锚点：」（按节点分组，如 `- 节点 3「回幻妖界」：林岚 登场——……`）和「信息差：」（`format_secrets`）。
- **`format_volume_card`**：分卷有目标节点时，追加一行「走向：节点 5「飞升神界」」；`reaches_node` 为真时加「（本卷发生）」。`volume_dict` 需要拿到节点序号和名称，可以增加可选参数 `nodes`。
- **`format_unit`**：追加「揭晓：S2 揭给 柳如烟——……」，每条一行。
- **`services/writing_context.format_chapter_outline`**：章纲里有 `emotion` / `mood` 时输出「情绪：+2 爆发爽快（爽）」，数字对应的说法是 -2 憋屈压抑、-1 偏压、0 平稳或悬着、1 偏扬、2 爆发爽快；有 `reveals` 时同样输出揭晓。
- **编号解析**：`planning.REF` 改为 `[FE](\d+)`；`attach_new_foreshadowings` 生成编号时用 `foreshadow_code`，不再写死 F。新增 `secret_seq(ref)`，解析 `S(\d+)`。

## 5. 接口

所有写接口都要先调用 `ensure_idle`，规则同现有的设定、大纲接口。新建 `app/api/story_map.py`（或并入现有路由，按代码习惯定）。

**节点**

| 接口 | 说明 |
|---|---|
| `GET /books/{book_id}/nodes` | 按顺序返回 `NodeOut`：`id, index(1 起), kind, title, event, prerequisite, consequence, volume, status, origin, editor_note, techniques, anchors[]` |
| `POST /books/{book_id}/nodes` | 请求体 `{title, event?, prerequisite?, consequence?, volume?, status?, after_node_id?}`。只能建 milestone；`origin=author`，status 默认 `pinned`；`status=empty` 同样只在书处于 `setting_up` 时允许；不给 `after_node_id` 时插在结局前面 |
| `PATCH /nodes/{node_id}` | 可改 `title, event, prerequisite, consequence, volume, status, editor_note`。`status=empty` 只在书处于 `setting_up` 时允许，否则 422 |
| `DELETE /nodes/{node_id}` | 开篇、结局返回 409「开篇和结局不能删」；锚点级联删除，卷、台账、信息差里的引用置空 |
| `POST /books/{book_id}/nodes/order` | 请求体 `{ids: [...]}`，必须是全部节点的一个排列，开篇在首、结局在尾，否则 422 |

**锚点**

| 接口 | 说明 |
|---|---|
| `POST /books/{book_id}/anchors` | 请求体 `{node_id, character_id, kind, note}` |
| `PATCH /anchors/{id}` | |
| `DELETE /anchors/{id}` | |

`AnchorOut` 带 `character_name`。

**信息差**

| 接口 | 说明 |
|---|---|
| `GET /books/{book_id}/secrets` | |
| `POST /books/{book_id}/secrets` | seq 自动编号 |
| `PATCH /secrets/{id}` | |
| `DELETE /secrets/{id}` | |

`SecretOut` 带 `code`（如「S3」）。`BibleOut` 增加 `secrets`。

**其他**

- **台账**：`ForeshadowingBase/Out/Patch` 增加 `kind`、`node_id`，`Out` 增加 `code`（F3 / E8）。创建时可以指定 kind。
- **人物改名**：`PATCH /characters/{id}` 改了名字时，同步更新本书 `secrets.knowers` 里的同名条目。
- **书的详情**：`BookDetail` 增加 `setup_progress`。
- **术语表**：`GET /glossary` 返回 `{"terms": [{"term": str, "explanation": str}]}`。

## 6. 术语表

- **搬入**：`git mv docs/codex任务/第一包/提示词/glossary.md backend/app/prompts/glossary.md`。
- **加载**：在 `app/prompts/__init__.py` 增加公开的 `load(name)`（读覆盖版本，否则读默认），供不需要变量替换的内容使用，不要直接调用 `_load`。
- **解析**：新建 `app/agents/glossary.py`：
  - `parse(text) -> list[tuple[str, str]]`：按 `^##\s+` 切分；标题是术语，下面的正文是解释；第一个 `##` 之前的内容忽略。
  - `terms()`：读当前版本并解析。
  - `glossary_block()`：返回 `【术语表】可用的技巧名称：欲扬先抑、打脸三拍、……` 一行，供提示词的 `{{glossary}}` 使用（任务 2 开始用）。
  - `clean_techniques(items)`：只保留表里有的名称，去重，最多 3 个。
- **登记**：`catalog.CATALOG` 增加 `("glossary", "术语表", "角色与规矩", "all", "编辑批注里的技巧名称与白话解释")`。`validate_content` 对 glossary 额外校验：至少 5 个术语，且每个都有解释。

## 7. 现有流程的过渡兼容
