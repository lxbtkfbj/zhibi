# 第一包：开书拼图、关键节点、期待感、情绪曲线、信息差、编辑批注

产品规则以 `docs/设计说明.md` 第 11 节为准。本目录是交给 Codex 的实施任务：按顺序做，一次一个任务，前一个做完并提交后再开下一个。

## 任务顺序

| 任务 | 内容 | 依赖 |
|---|---|---|
| [1-数据底座](1-数据底座.md) | 迁移、模型、读写接口、上下文格式化、术语表 | 无 |
| [2-开书拼图流程](2-开书拼图流程.md) | 开书流程图、结构化产出、开书提示词、任务接口、演示模式 | 1 |
| [2b-铁钉按作者意见修改](2b-铁钉按作者意见修改.md) | 任务 2 的补丁：作者点名时可以改铁钉节点 | 2 |
| [3-开书拼图界面](3-开书拼图界面.md) | 首页模式、进度条、拼图板、待确认条、选方向、卡片与对话联动、信息差页、伏笔与期待页、术语标签 | 2 |
| [4-写作接入](4-写作接入.md) | 节点驱动的卷纲、期待、情绪曲线、信息差接入写作流程 | 2 |
| [5-写作阶段界面](5-写作阶段界面.md) | 全书地图条、卷页情绪曲线与动作标签、节点调整提议、章节页情绪 | 3、4 |
| [6-开书方向质量调优](6-开书方向质量调优.md) | 真实模型试用后的调优：对标作品理解、保留作者定下的设定、书名候选、金手指与舞台阶梯的质量、重出时看到上一轮、篇幅五档 | 5 |

任务 3 和任务 4 互不依赖，先做哪个都行，但不要同时做。

每个任务做完，系统都要能正常使用：

- 任务 2 做完后，默认开书方式仍是「一口气出方案」。
- 任务 3 做完时，再把默认改成「逐块确认」。

## 交给 Codex 的方式

每个任务要发给 Codex 的话，已经写好在 [给Codex的话.md](给Codex的话.md)，整段复制即可。

## 共同约定（每个任务都适用）

1. **先读后做**：先读 `docs/设计说明.md` 第 11 节、本文件和任务文件。任务文件和设计说明有冲突时，以设计说明为准，并在完成说明里指出冲突。
2. **语言**：界面文字、提示词、schema 字段描述一律用简体中文。
3. **schema 描述就是提示词**：`app/agents/schemas.py` 里的 `Field(description=...)` 会随 schema 发给模型。任务文件里给出的类和描述要逐字照抄，不要自行改写措辞；字段名可以按代码习惯调整，但要在完成说明里写明。
4. **提示词由设计方提供**：本目录 `提示词/` 下是写好的模板。任务里写明哪些文件要「搬进」`backend/app/prompts/`：用 `git mv -f` 覆盖同名默认模板，搬完后草稿目录里就不再有这几份，避免两份不同步。不要改提示词措辞；代码确实需要不同的变量名时，在完成说明里写明，并同步改提示词里的占位符。
5. **提示词登记**：新增或改动模板的变量，要登记到 `app/prompts/catalog.py`（`CATALOG` 与 `VARIABLE_LABELS`），保证提示词页能显示和校验。`render()` 遇到缺变量会直接报错，所以每个调用点都要提供模板里的全部变量。
6. **不破坏旧书**：已开完书、写到一半的书，迁移后要能照常续写；正在开书的旧任务，从旧检查点要能继续。
7. **演示模式**：`app/llm/demo.py` 要补齐所有新增或变化的结构化产出，保证没有 Key 也能跑通。
8. **检查命令**（全部通过才算完成）：
   - 后端（`backend/`）：`uv run ruff check . && uv run ruff format --check . && uv run pytest -q`。后端测试需要 PostgreSQL（5433）和 Redis（6380），没启动就用 `docker compose up -d` 启动；连不上时停下来说明，不要跳过测试。
   - 前端（`frontend/`）：`npx tsc -b && npm run lint && npm run build && npm run test:workspace`
9. **界面验收**：涉及界面的任务，按任务里的验收清单用演示模式跑一遍并截图，写法参考 `docs/设置改版验收.md`。结果写进 `docs/第一包验收.md` 里对应任务的小节（没有这个文件就新建），截图放在 `docs/第一包验收/`。
10. **文档同步**：每个任务完成后，把 `docs/设计说明.md` 第 11 节里本任务已实现的内容并入对应章节（第 3、5、9 节等），README 的流程介绍也要同步。
11. **分支与提交**：仓库没有远程，直接在当前分支上做。开始前确认工作区是干净的（`git status` 没有改动）；不干净就停下来问作者。一个任务做完提交一次或几次，提交信息以「第一包任务 N：」开头。
12. **完成说明**：做完后用一段中文告诉作者——
    - 改了什么、数据库迁移做了什么；
    - 搬了哪些提示词；
    - 跑了哪些检查、结果如何；
    - 验收结果写在哪里；
    - 有没有没做完、做不到、或和设计说明对不上的地方。
