# 拆书第二批：拆大纲

产品规则以 `docs/设计说明.md` 第 14 节为准（第一批怎么实现的见第 14.4 节后面的「第一批实现」；试拆的脚本和结果见 `docs/拆书/真模型试验/`、`docs/拆书/试验记录.md`）。本目录是交给 Codex 的实施任务：按顺序做，一次一个任务，前一个做完并提交后再开下一个。

一句话概括这一批：拆的书能点「开始拆」了——单独的拆书工作进程一批批读原文，每章倒推出章纲、记下人物和设定的原始记录，攒够了由主编往上归成单元、卷；进度一直显示，能停、能接着拆、能只拆到第几章；系统设置的模型分工多一行「拆书」。**篇、全书结局、整理设定、「这本书好在哪」不在这一批**（第三批）。

> 状态：任务 1「后台——拆大纲」、任务 2「界面——开始拆和进度」已实现；任务 2 含作者明确授权的两处后台接口补缺。检查、验收与截图见 `docs/拆书第二批验收.md`。

## 共同约定（每个任务都适用）

1. **先读后做**：先读 `docs/设计说明.md` 第 14 节、本文件和任务文件。任务文件和设计说明有冲突时，以任务文件为准，并在完成说明里指出冲突。
2. **开工前工作区要干净**：`git status` 不干净就停下来问作者，不要动、也不要替别人提交没提交的改动。
3. **语言**：界面文字、提示词、schema 描述一律用简体中文。界面上的说法照任务文件写的抄，不要自己换词。
4. **提示词由设计方提供**：本目录 `提示词/` 下是写好的模板，用 `git mv -f` 搬进 `backend/app/prompts/`：`persona_teardown`、`teardown_read`、`teardown_units`、`teardown_volumes`、`teardown_volume_text` 是新的，`chat_teardown` 盖掉第一批那份。不要改措辞；变量登记到 `app/prompts/catalog.py`（分组「拆书」，角色 `teardown`）。由程序拼出来再填进模板的文字，逐字照抄任务文件。`docs/拆书/提示词草稿/` 里的是试拆时的旧草稿，不用管。
5. **schema 描述就是提示词**：任务文件里给出的类和 `Field(description=...)` 逐字照抄，字段顺序也照抄，放进 `app/agents/schemas.py`。
6. **自己的书不受影响**：凡是加了「是不是拆的书」判断的地方，作者自己的书走原来的路。思考调低、限流等一等只给拆书的调用。
7. **演示模式**：`app/llm/demo.py` 补齐新 schema，没有 Key 也能把一本书从头拆到尾（单元、卷的章号要对得上，能过程序检查）。
8. **不碰作者的服务和书库**：不要升级、重启或改动作者日常的 8000／4320 服务、日常 worker 和书库，不要对日常环境运行 `start.ps1`／`stop.ps1`。验收一律用独立的数据库、Redis 库、端口和 worker。真模型只在任务文件写明、作者同意的那一处用，只读取作者日常库里的模型配置，不打印密钥；不要用作者的官方 DeepSeek 配置。
9. **检查命令**：开发中只跑相关测试；提交前跑一次全量，全部通过才算完成。
   - 后端（`backend/`）：`uv run ruff check . && uv run ruff format --check . && uv run pytest -q`
   - 前端（`frontend/`）：`npx tsc -b && npm run lint && npm run build && npm run test:workspace`
10. **验收**：照任务文件最后一节做，结果写进 `docs/拆书第二批验收.md` 对应小节，截图放 `docs/拆书第二批验收/`（少而准）。真书用作者桌面上的 TXT（只读）：`C:\Users\cxc\Desktop\逆天邪神(1-500章).txt`、`C:\Users\cxc\Desktop\都重生了谁考公务员啊.txt`。
11. **文档同步**：任务完成后，在设计说明第 14 节开头的状态行写明哪些已实现；实现时和第 14 节说法不一样的地方，在第 14.4 节后面补一小段「第二批实现」。
12. **分支与提交**：直接在当前分支（feat/setup-interview-spine）上做，不推送。提交信息以「拆书第二批任务 N：」开头。
13. **完成说明**：做完后用一段中文告诉作者：改了什么、迁移做了什么；搬了哪些提示词；跑了哪些检查、结果如何；真模型用了多少（几次调用、多少 token）；验收写在哪里；有没有没做完、做不到、或和设计说明对不上的地方。

## 名词对照（写代码时用）

| 界面上的叫法 | 代码里 |
|---|---|
| 拆书（模型分工那一行） | 角色 `teardown` |
| 拆书任务 | `jobs.kind = "teardown"`，celery 队列 `teardown` |
| 排队中／在拆／停了／拆完了 | `books.teardown.stage = queued / running / stopped / done` |
| 拆到第几章 | `books.teardown.upto`（空是全本） |
| 这一章读过了 | `chapters.teardown.read_version` 有值 |
| 没读成 | `chapters.teardown.read_failed` |
| 逐章记 | 提示词 `teardown_read`，schema `TeardownRead` |
| 归单元／归卷／写卷那段话 | `teardown_units` / `teardown_volumes` / `teardown_volume_text` |
| 还没收尾那一卷 | `books.teardown.open_volume_id` 指的那一卷（原书没分卷时） |
| 这一章记下的 | `chapters.teardown.read` |
