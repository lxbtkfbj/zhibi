# 任务 1：后台——拆大纲

对应设计说明第 14.2 节第 4、5 条（篇不做）、14.4 节，第 14.5 节第 2 批的后台部分。这个任务只做后台，不改页面（页面在任务 2）。第一批的实现见第 14.4 节后面的「第一批实现」。

一句话：作者点「开始拆」，单独的拆书工作进程一批批读原文、逐章记下章纲和人物设定的原始记录，攒够了让主编往上归成单元、卷；进度一直推给页面；能停、能接着拆、能只拆到第几章。

## 1. 数据（迁移 0024）

1. **章上的记录**：照旧用 `chapters.teardown`（第一批已有），加这几个键，不用新列：
   - `read`：这一章逐章记的原始记录（第 4 节 schema 里 `goal`、`scenes`、`cool_point`、`hook`、`summary` 以外的栏：`feel`、`people`、`things`、`moments`、`waits`、`tropes`），原样存；
   - `read_version`：记录格式版本，这一批是 `1`；
   - `read_at`：读成的时间；
   - `read_failed`：没读成时写 `{"at": 时间, "error": "一句话原因"}`，读成了删掉这个键。
   - 章纲、摘要照作者自己的书存在现成的栏：`outline.goal`、`outline.scenes`、`outline.cool_point`、`outline.hook`；`summary`；读者感觉折算进 `outline.emotion`（憋屈 -2、平 0、爽 1、大爽 2）。
   - 「这一章读过了」＝ `read_version` 有值。进度、接着拆从哪章读，一律按这个算，不另存。
2. **书上的拆书信息**（`books.teardown`）加：
   - `original_volumes`：原书自己分了卷为 `true`（第一批导入时就知道：建了原书的卷、没建「还没分卷」）。迁移里给已导入的拆的书补上：`open_volume_id` 为空就是 `true`。以后判断「原书分没分卷」只看它，不看 `open_volume_id`（拆到头时 `open_volume_id` 会变空）。
   - `upto`：这次拆到第几章（顺序号）；空是全本。
   - `stage` 多几个值：`queued`（排队中）、`running`（在拆）、`stopped`（停了）、`done`（拆完了：最后一章读过、单元和卷都归完）。
   - `stop_reason`：停了的原因：`author`（作者点了停下）、`upto`（拆到了作者定的那一章）、`model`（模型连着出错）、`error`（别的错）；`stop_note`：给作者看的一句话（第 7 节）。
3. **模型分工**加一个角色 `teardown`（界面上叫「拆书」）。现有角色怎么存、怎么校验，照着加；没配就跟随默认（`LLMRouter.resolve` 现有的退回办法）。
4. 迁移不改作者自己的书。

## 2. 拆书任务和工作进程

1. 新的任务类型 `teardown`（`jobs.kind`），一本书同时只能有一个。**不用 LangGraph**：进度就是哪些章读过了，重启后读库就知道接着读哪章。
2. **单独的队列和工作进程**：celery 新任务（例如 `zhibi.run_teardown`）发到队列 `teardown`；`scripts/start.ps1`／`stop.ps1` 多起、多停一个 worker（`-Q teardown`，Windows 上照样 `-P solo`），日志和现在的 worker 分开。原来的 worker 只听 `zhibi`，开书、开写不受拆书影响。几本书排队拆，一次一本（solo 本来就是一次一个）。
3. 现有的任务锁、心跳、取消标记（`job_runner.execute_job` 那一套）照用：拆书的执行入口也拿任务锁，Redis 重新投递时任务锁会挡住，不用另做「每半小时把自己重新排上」。
4. **worker 起来时捡断掉的活**（`worker/tasks.py` 的 `recover_orphaned_jobs`）：现在不分类型，网页后端里跑的大纲展开（`outline_expand`，没有任务锁、`GRAPHS` 里也没有）会被捡去报 KeyError → 改成每个 worker 只捡自己会跑的类型（`zhibi` 的 worker 捡 `GRAPHS` 里有的，拆书 worker 捡 `teardown`），投到各自的队列。
5. **开始、停下、接着拆**的接口（前端任务 2 照这些做）：
   - `POST /api/teardown/{book_id}/start`，body `{"upto": 300}`（`null` 是全本）：只有拆的书、`stage` 是 `imported` 或 `stopped`、没有在跑的拆书任务时能开始；`upto` 要大于已经读过的最后一章，否则 422「已经拆到第 {N} 章了，要拆得更多才能接着拆」；超过总章数按全本算。开始前照现有的自动存档存一档「开始拆书前」；建任务、`stage=queued`、发到 `teardown` 队列；返回任务（`JobOut`）。`done` 的书要是还有没读成的章（`read_failed`），也能用它重读这几章（「再试一次」）。
   - `POST /api/teardown/{book_id}/stop`：在排队的直接取消（`stage` 回到开始前的值）；在跑的设取消标记，手上这几批读完、存好就停（不再开新批、不再归单元），`stage=stopped`、`stop_reason=author`。返回任务。
   - 确认页一步到位：第一批的 `POST /api/teardown/{id}/import` body 多一个可选的 `"start": {"upto": null}`，带了就导入完马上开始拆（同上）；不带和以前一样「先只导入」。
   - 删书：拆的书在拆的时候删，先停下拆书（取消任务）再删，不用作者自己去停。回到某一档：有拆书任务在跑时照旧挡住。
6. **拆的时候不能手改**：`ensure_idle` 挡住时，在跑的是拆书任务就说「正在拆，点「停下」才能改」，其他照旧「编辑部正在工作，请等这一轮结束再修改」。第一批第 7 节那些 409 照旧。
7. **存档**：开始前存一档「开始拆书前」；停了存一档「停下拆书」；拆完存一档「拆完了」。拆的过程中不一步步存。

## 3. 一次拆书怎么走

目标：读到 `upto`（空就是最后一章）。从前往后：

1. **读原文**（第 4 节）：要读的是 `index ≤ 目标`、还没读过的章（包括以前没读成的），按章号从前往后分批。
2. **归单元**（第 5 节）：每读完一批，看从「最后一个单元的下一章」起，往后连着读过的章（没读成又重试过的也算，见第 5.1 条）够不够 40 章；够了就归一次。读到目标或者最后一章时，剩下的也归一次。
3. **归卷**（第 6 节）：原书分了卷的，一卷的章都归进单元了，写这一卷的那段话；原书没分卷的，「还没收尾」那一卷里的单元攒够 100 章左右，归一次卷。
4. 归单元、归卷**一次只做一件，按章号先后**，和读原文同时进行（读第 300 章时可以在归第 200 章的单元），但归单元总在它要的章都读完以后才做。
5. **收尾**：读到目标、该归的都归完了，就停：
   - 目标是最后一章：最后一件事、最后一卷都要收（第 5、6 节的「全书最后」），`stage=done`；
   - 目标在中间：最后没了结的照旧挂着，`stage=stopped`、`stop_reason=upto`。
   - 收尾、停下、拆完都在群聊里由设定师说一句（第 7 节），**拆的过程中不往群聊发消息**（每条消息都会让新书页整本重拉）。

## 4. 读原文（逐章记）

### 4.1 分批和并发

- 一批最多 4 章、原文合起来 12,000 字以内（一章就超过的单独一批，不拆开一章）。
- 这本书一章都还没读过时，第一批单独先读完，拿到主角和开头几个人；之后最多 4 批同时读。
- 每批读完马上写库（第 1 节第 1 条），写库按章，一批里成功几章写几章。

### 4.2 调模型

- 角色 `teardown`；system 是新人设 `persona_teardown`（照其他人设的拼法带上 `rules`）；user 是 `teardown_read`；schema 见第 4.4 节；`purpose` 写「拆书：读原文」。作者配的模型只能 JSON 模式、只能工具调用的，照 `LLMRouter.structured` 现有的办法走。
- **思考调低**：调用时临时把推理强度设成 `low`（不改作者的模型配置）；模型或中转站报不认这个参数，就去掉再调，这本书这次拆书后面都不再带。只给拆书的调用这样做，写书不变。
- **被限流（429）**：先等 5 秒再试，再被限等 10 秒、20 秒、40 秒（最多试 6 次）；一分钟里被限两次以上，同时读的批数减一（最低 1），这次拆书不再加回去。5xx、断线照 `structured` 现有的办法重试。只给拆书的调用加等待，写书不变。
- 一批失败（格式错、输出被截断、漏了章、超时）：漏的章一章一章再读一次；还不行，这一章写 `read_failed`，先跳过。
- **模型不行就停**：这次拆书的前三批里有两批整批失败，就停下：`stop_reason=model`，`stop_note` 照第 7 节。

### 4.3 拼进 `teardown_read` 的字（逐字照抄）

- `title`：书名。`first`、`last`：这一批第一章、最后一章的顺序号。
- `chapters`：每章一段，段和段之间空一行：

  ```
  「第 {顺序号} 章 {章名}」
  {正文}
  ```

  章名空着就是「「第 {顺序号} 章」」。
- `roster`（已经认得的人）：每人一行 `- {名字}｜别称：{别称用「、」连起来，没有写「无」}｜{一句话}`；一个人都没有写「（还没有）」。名单这样算：
  1. **每次从读过的各章记录重新算**，不单独存（回到某一档以后也对得上）：按章号顺序把各章 `people` 并起来——`name` 是名单上的名字或别称的，算同一个人；`was` 有值、又对上了名单上另一个人的，把那个人并过来（他的名字和别称都变成别称）；新人加进名单，一句话取他第一次出场那章的 `shown` 前 50 字；`also_called` 加进别称。几个人共用的叫法（两个人以上都有的别称，或者正好是另一个人的名字）不算谁的别称。逻辑照 `docs/拆书/真模型试验/run_read.py` 的 `Roster`。
  2. **只带这一批出现的人**：拿名单上每个人的名字和别称去这一批的原文里找，找到一个就带上；再加上出场章数最多的 12 个人（按出场章数从多到少，同样多按第一次出场先后）。两部分去重，按第一次出场先后排。
  3. 同时读的几批，各自开读时用当时已经写进库的记录算名单。

### 4.4 schema（类和描述逐字照抄，字段顺序也照抄）

```python
class TeardownPerson(BaseModel):
    name: str = Field(description="认得的人写名单上的名字；新人写原文里最正式的叫法")
    also_called: list[str] = Field(default_factory=list, description="这一章原文里专指这个人的别的叫法：外号、昵称、网名、姓加职务；几个人共用的叫法不写")
    was: str = Field("", description="以前在名单里用别的名字记过、这一章才认出是同一个，写那个旧名字；没有留空")
    shown: str = Field(description="这一章写出了这个人什么：身份、性格、本事、说话的样子、和谁什么关系，一两句")
    change: str = Field("", description="这一章里这个人变了什么：实力与地位、在哪、处境、死了；没变留空")


class TeardownThing(BaseModel):
    kind: Literal["地方", "势力", "物品功法", "金手指", "等级", "规矩", "秘密"]
    name: str = Field(description="照原文的叫法")
    note: str = Field(description="原文说了它什么，一句；人物嘴里说的写明「某某说」")
    belongs: str = Field("", description="属于哪里：地方写在哪座城、哪个国、哪个门派里，势力写归谁管、谁领头；别的留空，原文没说也留空")
    secret: Literal["", "埋下", "揭开"] = Field("", description="秘密写埋下还是揭开，别的留空")


class TeardownMoment(BaseModel):
    who: str = Field(description="谁")
    what: str = Field(description="做了什么")
    shows: str = Field(description="立住了这个人的什么")


class TeardownWait(BaseModel):
    what: str = Field(description="读者在等的那件事")
    action: Literal["立下", "提起", "兑现"]


class TeardownChapter(BaseModel):
    index: int = Field(description="原文标的第几章")
    goal: str = Field(description="一句话，40 字以内：这一章要发生的事")
    scenes: list[str] = Field(description="两到四个场景，按先后，每个 25 字以内")
    cool_point: str = Field(description="看点，40 字以内，写成「哪一种：怎么做出来的」；没有爽点写「铺垫：……」或「情感：……」")
    hook: str = Field(description="结尾钩子，30 字以内，写成「哪一种：读者带着什么问题点下一章」；收得干净写「平收」")
    summary: str = Field(description="100-200 字：这一章发生了什么、结果如何、留下什么悬念")
    feel: Literal["憋屈", "平", "爽", "大爽"] = Field(description="读者读完这一章的感觉")
    people: list[TeardownPerson] = Field(default_factory=list, description="出场的、有名有姓或者以后还会出现的人；路人不记")
    things: list[TeardownThing] = Field(default_factory=list, description="这一章新冒出来、或者头一回说清楚的东西")
    moments: list[TeardownMoment] = Field(default_factory=list, description="名场面：立住某个人的那场戏；没有就空着")
    waits: list[TeardownWait] = Field(default_factory=list, description="读者在等的事：这一章立下、提起还是兑现了哪件；没有就空着")
    tropes: list[str] = Field(default_factory=list, description="用了哪些熟悉的桥段，几个字一个；没有就空着")


class TeardownRead(BaseModel):
    chapters: list[TeardownChapter] = Field(description="每章一条，不漏、不合并、不跳")
```

拿回来以后程序检查：`index` 不在这一批里的扔掉；同一章出现两次取第一条；这一批里没拿到的章算漏了（第 4.2 条）。各栏不截断，原样存。

## 5. 归单元

### 5.1 什么时候归、归哪几章

- 从最后一个单元的下一章（还没有单元就是这一卷第一章）起，往后连着读过的章。中间遇到写着 `read_failed` 的章：它前后的章都读过了，就把它当成读过的一起归（第 5.3 条那一行写「没读成」）；作者「再试一次」读成了，记录补上，单元不重归。
- 够 40 章就归一次；读到目标或最后一章，剩下的不管多少也归一次。一次最多给 60 章（挂着没归的加新读的），超过的留到下一次。
- **原书分了卷的，单元不跨卷**：一次只给同一卷里的章；这一卷的章都读过了，这一卷就是「卷末」（第 5.2 条）。

### 5.2 `tail_rule`（逐字照抄，三选一）

- 这次给的最后一章是全书最后一章：「这是全书最后几章：全部归完，不留 open_from。」
- 原书分了卷、这次给的最后一章是这一卷最后一章：「这几章是原书这一卷的最后几章：全部归完，不留 open_from。」
- 其他：「后面还有没读到的章：最后一件事要是还没了结，就留着不归。」

### 5.3 拼进 `teardown_units` 的字

- `title`：书名。`first`：这次给的第一章。
- `done_units`：这本书最后 5 个单元（原书分了卷的，只取这一卷的），每个一行 `第 {first}–{last} 章「{单元名}」：{那段话}`；没有写「（还没有）」。
- `chapters`：每章一行 `第 {顺序号} 章：{摘要}｜{看点}｜{结尾钩子}`（取章上现在的 `summary`、`outline.cool_point`、`outline.hook`，作者手改过的就用改过的）；没读成的写 `第 {顺序号} 章：（这一章没读成，章名「{章名}」）`。

### 5.4 schema（逐字照抄）

```python
class TeardownUnit(BaseModel):
    first: int = Field(description="第几章起")
    last: int = Field(description="到第几章")
    title: str = Field(description="4-8 个字")
    text: str = Field(description="一段话，100 字以内：什么事找上门；主角怎么应对；读者叫好的那一下；做完拿到什么")


class TeardownUnits(BaseModel):
    units: list[TeardownUnit]
    open_from: int | None = Field(None, description="从第几章起还没收尾；都收完了就不填")
```

角色 `teardown`，system 同第 4.2 条，`purpose`「拆书：归单元」，思考调低、限流同第 4.2 条。

### 5.5 检查和写库

- 程序检查（照 `run_units.py` 的 `check`）：单元从这次第一章起一个挨一个、不重叠、不跳章，`first ≤ last`，最后停在 `open_from` 前一章（没有 `open_from` 就停在这次最后一章）；`tail_rule` 要求全部归完的，`open_from` 必须为空。不对就把问题写进 user 末尾（「【上次归得不对】{问题}。请照要求重新归。」）再归，最多 3 次；还不对就停下：`stop_reason=error`，`stop_note`「主编归第 {a}–{b} 章的单元归了三次都对不上，停下了。点「接着拆」再试一次。」
- 写库：每个单元一行 `plot_units`（`volume_id` 是这些章所在的卷——原书没分卷的就是「还没收尾」那一卷；`index` 接着这一卷已有的排；`title`；那段话写进大纲页显示单元那段话的栏（现在是 `summary`）；`chapter_count`；状态用写完的值），这些章的 `unit_id` 指过去。一次归单元的写库在一个事务里。
- 归好以后推一次刷新（第 8 节）。

## 6. 归卷

### 6.1 原书分了卷：写这一卷的那段话

- 一卷的章都归进单元了，写这一卷的那段话：新提示词 `teardown_volume_text`，schema：

  ```python
  class TeardownVolumeText(BaseModel):
      text: str = Field(description="一段话，120 字以内：这一卷主角想做成什么；被什么挡着；卷末的大高潮；卷末变成什么、留下什么钩子")
  ```

- 拼进去的字：`title` 书名；`index`、`volume_title`、`first`、`last` 是这一卷的；`done_volumes` 是前面最多 3 卷，每卷一行 `第 {卷序号} 卷「{卷名}」（第 {first}–{last} 章）：{那段话}`，没有写「（还没有）」；`units` 是这一卷的单元，每个一行 `第 {first}–{last} 章「{单元名}」：{那段话}`；`tail_rule`：这一卷是文件里最后一卷时写「这是文件里最后一卷，原书可能还没写完：卷末要是没收在一次大高潮上，照读到的写，最后一句写「到第 {last} 章还没收住」。」，否则写空字符串。
- 写进大纲页显示卷那段话的栏（现在是 `summary`），卷名不动。`purpose`「拆书：写卷」。

### 6.2 原书没分卷：从「还没收尾」那一卷里分出卷

- 「还没收尾」那一卷（`open_volume_id`）里的单元，从第一个起攒够 100 章（按单元的章数加），归一次卷；读到目标或者最后一章、单元都归完了，剩下的也归一次。
- 用 `teardown_volumes`（第一批试拆的那份，改了一点），schema：

  ```python
  class TeardownVolume(BaseModel):
      first: int = Field(description="第几章起")
      last: int = Field(description="到第几章")
      title: str = Field(description="4-8 个字")
      text: str = Field(description="一段话，120 字以内：这一卷主角想做成什么；被什么挡着；卷末的大高潮；卷末变成什么、留下什么钩子")


  class TeardownVolumes(BaseModel):
      volumes: list[TeardownVolume]
      open_from: int | None = Field(None, description="从第几章起还没收尾；都收完了就不填")
  ```

- 拼进去的字：`title` 书名；`first` 是「还没收尾」那一卷第一个单元的第一章；`done_volumes` 是已经分出来的最后 3 卷，格式同第 6.1 条；`units` 是「还没收尾」那一卷里的单元，格式同第 6.1 条；`tail_rule`：全书最后一章都归进单元了写「这是全书最后几个单元：全部归完，不留 open_from。」，否则写「后面还有没读到的章：最后几个单元要是还没收在一次大高潮上，就留着不归。」
- 检查：卷一个挨一个、不重叠不跳章，停在 `open_from` 前；**卷的分界只能落在单元的分界上**（照 `run_volumes.py`）。不对照第 5.5 条重来，最多 3 次。
- 写库（一个事务）：分出来的每一卷建一行 `volumes`，排在「还没收尾」那一卷前面（「还没收尾」那一卷和它后面的卷序号跟着往后挪），卷名、那段话、`chapter_count`、状态写完；这几卷里的单元和章的 `volume_id` 改过去；「还没收尾」那一卷的 `chapter_count` 跟着减。全部归完（没有 `open_from`）时：最后一卷就用「还没收尾」那一行改名、写那段话，`open_volume_id` 置空。
- `purpose`「拆书：归卷」。

## 7. 进度、停下的话、群聊里说的话

1. **进度**存在任务的 `pending`（或者别的不会触发整本重拉的地方），每变一次推一次 job 事件（job 事件本来就不触发整本重拉）：

   ```json
   {"teardown": {"doing": "read", "reading": [312, 315], "read": 311, "target": 1280, "total": 1280,
                 "units_upto": 280, "parallel": 4, "eta_seconds": 2400, "failed": [57]}}
   ```

   - `doing`：`read`（读原文）、`units`（归单元，另给 `range: [a, b]`）、`volumes`（归卷）、`closing`（收尾）、`queued`；
   - `read`：目标以内读过的章数；`target`：这次读到第几章；`total`：全书章数；`units_upto`：归进单元的最后一章；`failed`：没读成的章号；
   - `eta_seconds`：读完两批以后才给：最近 5 批「读完的章数 ÷ 用掉的墙钟时间」算速度，乘剩下的章数，再加剩下要归单元、归卷的次数 × 30 秒；之前给 `null`。
2. **停下的话**（`stop_note`，逐字照抄）：
   - `author`：「你点了停下，停在第 {已读最后一章} 章。」
   - `upto`：「拆到第 {upto} 章了（你定的）。」
   - `model`：「开头几批模型连着出错（{第一条错误的一句话}），停下了。可以在系统设置的模型分工里给「拆书」换一个模型，再点「接着拆」。」
   - `error`：照第 5.5 条，或者「拆的时候出错了（{一句话}），停下了。点「接着拆」从停的地方往下拆，读过的不重读。」
3. **群聊里设定师说的话**（只在这几个时候，`speaker=lorekeeper`）：
   - 开始：「开始拆了：读到第 {target} 章{，全本就写「，读到最后」}。读好的章纲随时出现在大纲和正文里。」
   - 停了：`stop_note`，没读成的有几章就加一句「有 {N} 章没读成：第 {…} 章，点「再试一次」重读这几章。」
   - 拆完：「拆完了：{章数} 章都有章纲，归成了 {单元数} 个单元、{卷数} 卷。」加上没读成的那句（有的话）。

## 8. 刷新

- 进度只走 job 事件。
- 大纲、目录的数据：第一批读完推一次「书变了」，之后最多一分钟推一次（这一分钟里有新读完的章才推），每次归好单元、归好卷再推一次。用现有的事件通道发一种新事件（例如 `teardown_saved`），前端任务 2 收到它才重拉；不要借用会话消息。
- 拆书不往群聊发消息（第 7 节那三句除外）。

## 10. 调提示词用的重跑脚本

作者说质量以后再调，所以每一步要能单独重跑（设计说明第 14.4 节「每一步能单独重跑」）。这一批先做成命令行脚本，不上界面：`backend/scripts/teardown_rerun.py`，在 `backend/` 下 `uv run python scripts/teardown_rerun.py <步骤> --book <书 id> [--from N] [--to M]`：

- `read --from N --to M`：重读第 N–M 章（覆盖记录和章纲）；
- `units [--from N]`：删掉第 N 章起的单元（不给就是全部），按第 5 节重归（只看各章现在的记录，不读原文）；
- `volumes`：原书没分卷的，把分出来的卷并回「还没收尾」那一卷，按第 6.2 节重归；原书分了卷的，重写各卷那段话；
- 都用作者配的「拆书」模型，跑之前打印要调几次模型、问一句「继续吗」；有拆书任务在跑时拒绝；跑完存一档「重跑：{步骤}」。
