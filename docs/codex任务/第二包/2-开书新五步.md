## 目标

- 开书流程图改为五步：①定调 → ②主角 → ③世界与人 → ④第一段 → ⑤第一卷。逐块确认和一口气两种模式都按这五步走。

- 卷纲（开书第一卷和写作中每一卷）回答新题：这一卷想做成什么、卷首处境、每个单元的核心循环、开篇落地。
- 正在开书的旧任务改为「按新流程重开」。
- 网页能走完新五步（页面是简版，任务 3 补全）。

不做：按题分组的完整页面（任务 3）、写作中的「定下一段」（任务 4）。

### 3.5 程序整理（`setup_puzzle.py`）

**`normalize_world(world, protagonist) -> (world, notes)`**

- 人物表里 `role_type` 为「主角」的第一位，名字不是主角卡的 `name` 时，改成主角卡的名字（关系里的姓名同步改），记一条说明 `("people", "人物表里的主角已改回主角卡上的名字「X」。")`；人物表里没有主角时，按主角卡补一位（`role_type` 主角，`personality` 取卡的性格，`background` 取起点，`abilities` 取金手指·现在，`goal` 取长线追求，`want` 取开局动机），记 `("people", "人物表里没有主角，已按主角卡补上「X」。")`。
- 主角卡里在乎的人不在人物表里的，补一位（`role_type` 配角，`background` 写成「主角的{关系}：{为什么在乎}」），记 `("people", "已按主角卡补上在乎的人：A、B。")`。
- 设定条目、关系里的姓名校验沿用现有规则（关系两端都要在人物表里）。
- 整理后的 `world` 形状见第 4 节（`first_map` 放进 `maps[0]`；`mystery_answer` 保留当前值）。

**`normalize_secrets(secrets, characters, nodes, existing)`**：从现有的 `normalize_lore` 里拆出信息差部分，规则不变（知情人必须在人物表、节点序号越界置 0、编号沿用或接续），返回丢弃的知情人数。

**`normalize_segment(draft, previous_nodes, characters, previous) -> (segment, notes)`**

- 节点：`merge_nodes` 之后，**第二个节点就是这一段的终点**。第二个节点是结局（开篇后面没有普通节点）时，不加段信息，记 `("end", "开篇后面还没有这一段的终点。")`。
- 终点节点的 `segment` 写成：

  ```python
  {"number": 1, "status": "confirmed", "planned_at": 0, "map": world["maps"][0]["name"],
   "trouble": "", "opponent": "", "goal": ..., "goal_link": ..., "wait": wait.description,
   "reveal": ..., "opening": opening.model_dump(), "carried": "", "pursuit": "",
   "finger_next": "", "answers": "", "finale": False}
  ```

  其他节点的 `segment` 置为 null（开书时只有第一段有段信息）。
- `wait` 变成一条台账：`kind=期待`、`span=长`、`node=终点序号`，其余字段照抄；和当前版本描述相同时沿用原编号（`assign_seqs`）。放进 `segment["expectations"]`。
- 信息差走 `normalize_secrets`；丢弃知情人时记 `("reveal", "已丢弃 N 个不在人物表里的知情人。")`。
- `core_conflict`、`theme`、`protagonist_arc` 照存。

**`normalize_volumes(part, segment, characters, start, end_index=2) -> (part, segment, notes)`**

`end_index` 是终点在 `segment["nodes"]` 里的序号，开书时是 2；任务 4 定下一段时会传别的值。

1. 卷按 `index` 排序后从 `start` 起连续重编号；`techniques` 清洗；`chapter_count` 取非负整数。
2. 每卷 `target_node` 设为终点序号；原来不是的记 `("volumes", "第 N 卷没有走向这一段的终点，已改为节点 M。")`。最后一卷 `reaches_node=True`，其余为 False。
3. 终点节点不是铁钉时，卷号改成最后一卷的卷号；是铁钉且对不上时不改，记 `("volumes", "铁钉节点 M 约第 X 卷，和这一段的最后一卷（第 Y 卷）对不上，没有改动铁钉。")`。
4. 这一段的期待：`plant_volume` 限制在 `[start, 最后一卷]`，`payoff_volume` 不在这个范围时改为最后一卷。
5. 线索：名称去空格、去重；节拍只保留卷号在 `[start, 最后一卷]` 的，按卷号排序；每卷的 `thread_beats` 由程序按线索顺序生成 `[{thread, beat}]`（同现在 `threads_node` 的做法）。
6. 人物锚点：人物要在人物表里、节点序号要有效，不合法的丢弃，记 `("cast", "已丢弃 N 条不合法的人物锚点。")`。

### 3.7 审稿（`piece_check_node`）

- 本块是 `protagonist` 或 `segment`、书的设置 `volume_audit` 为真、这一块还没审过：单块审稿。本块是 `first_volume`：总是审（跨块）。一口气模式的 `critique_node` 用「全套」。
- `critique_setup` 的 `focus` 变量按下面三段原文传（程序拼的，进提示词，逐字照抄）：

  主角（`protagonist`）：

  ```
  【这次审什么】只审「主角卡」，其他部分只作参考，不要对它们提问题。
  重点查：驱动力（开局动机、长线追求、情感根源）够不够具体，长线追求是不是只写了「变强」；驱动力、金手指、核心循环是不是一套；金手指一句话说不说得清，限制能不能逼主角冒险或做选择；起点有没有提前写死境界名称；性格、底线、说话方式能不能让人物立起来。
  题目键（填进 question）：start 起点、drive 驱动力、person 性格底线与说话方式、finger 金手指、flaw_arc 软肋与成长终点、cared 在乎的人、interlock 咬合检查。
  ```

  第一段（`segment`）：

  ```
  【这次审什么】只审「第一段的走向」和「第一段的分卷、线索与人物出场」，其他部分只作参考，不要对它们提问题。
  重点查：开篇是不是从冲突或异常切入，前 3 章有没有小爽点和钩子；这一段的目标具不具体、有没有期限或对手；终点是不是这一段的最高潮，能不能把主角推向下一张地图或下一个追求；第一段有没有兑现定调里的核心卖点，核心循环有没有完整转一圈；读者等的那件事明不明确；分卷和人物出场合不合理。远处只要有方向，不要因为远处没写细就提问题。
  题目键（填进 question）：opening 开篇、goal 这一段的目标、wait 读者等什么、reveal 揭开什么、end 这一段的终点、cast 人物出场、volumes 分卷、direction 全书方向。
  ```

  全套（`first_volume` 和一口气模式）：

  ```
  【这次审什么】审整套开书方案，重点看第一卷卷纲，以及各部分之间对不对得上。
  重点查：第一卷想做成什么是不是第一段目标的一步；卷首处境和卷末高潮；每个剧情单元的核心循环有没有转起来；第一个单元有没有把开篇落地；作者的要求是否全部落实；主角卡、世界与人、第一段之间有没有矛盾。
  题目键（第一卷的问题填进 question）：want 这一卷想做成什么、pressure 卷首处境、climax 卷末高潮与结果、rival 这一卷的对手、units 剧情单元、growth 主角的成长、newcomers 新登场的人、landing 开篇落地。其他部分的问题，question 留空。
  ```

- 单块审稿只把已完成的部分交给审稿，没做的部分传「（还没做）」，同现在。
- 结果处理同现在：本块 high／medium 问题自动改一轮；锁定部分的问题进 `suggestions`。**新增**：本块的 low 级问题，以及本块已经用掉自动修改机会之后剩下的问题，存进 `review_notes`，等确认时交给作者；`question` 是本块的题目键时并进 `flags`，文字写成「审稿：{问题}——{建议}」。

### 3.8 保存与等确认

- **`piece_persist`**：`setup_store.save_piece(piece)` 后从数据库读回本块，存一份 `DraftVersion`（`note=f"piece:{piece}"`），进度改为 `waiting`，主编说「第 N 块「名称」好了……」（同现在）。原来 `fill` 块专门同步节点卷号的代码删掉：卷号已经在 `normalize_volumes` 里改好、随 `segment` 块一起保存。
- **等确认的内容**（`setup_piece`）：在现有字段之外加 `flow: 2`、`flags: {键: [文字]}`、`review: [review_notes]`。`setup_directions`、`setup_questions`、`setup_review` 也加 `flow: 2`。
- **确认、交给编辑部定、修改、重新打开、解锁**：同现在，只是块名换了。
  - 节点操作（候选、补空位、自己写一句、确认时补齐留空）从 `nodes` 块挪到 `segment` 块：`piece == "segment"` 时才可用。
  - 修改带 `node_id` 时，前缀「只改节点 N「标题」：」交给 `segment` 步骤（原来是 `spine`），再按 `cascade` 展开到 `volumes`。
  - 只有替你做的决定（flips）时，交给本块的第一个内部步骤（`segment` 块交给 `segment`，再展开到 `volumes`）。
- **`node_op`**：块名换成 `segment`，其余不变；`fill_all` 之后重新跑 `piece_checks("segment")` 作为提醒。

### 3.9 一口气模式

- 队列是全部六步；跑完照现在的逻辑 `critique`（全套）→ 必要时自动改一轮 → `persist`（整套 `save_setup`）→ `author_gate` → 作者提意见时 `triage`。
- 一口气模式没有块锁定；铁钉保护和作者点名改铁钉同现在。

### 3.10 插话与作者意见

- `triage_feedback`、`absorb_notes` 用新的部分和名称；提示词 `setup_triage`、`setup_notes`（第 9 节）。
- `_unlock_requests`、`_pinned_overrides`、`instruction_sources`／`fallbacks` 等机制不变；原来对 `spine` 的特殊判断（同步要求不授权、删掉作者意见时撤销授权）全部改成 `segment`。

## 4. 开书方案的数据形状（`app/services/setup_store.py`）

`load_setup` 返回、`save_setup` 接收下面的形状。所有「节点序号」都是 1 起、按 `segment.nodes` 当前顺序的序号。

```python
setup = {
    "concept": {...},                     # books.concept
    "protagonist": {...},                 # books.protagonist
    "world": {                            # books.world，加上设定库
        "surface": str, "power": str, "maps": [...], "trouble": str, "opponent": str,
        "far_maps": [...], "shadow": str, "mystery": str, "mystery_answer": str,
        "world_entries": [...], "characters": [...], "relationships": [...],
    },
    "segment": {                          # books.spine 的三项 + 节点 + 信息差 + 长线台账
        "core_conflict": str, "theme": str, "protagonist_arc": str,
        "nodes": [{...节点字段, "segment": dict | None}],
        "secrets": [...],
        "foreshadowings": [...],          # kind=伏笔、span=长（新书一般没有，旧书有）
        "expectations": [...],            # kind=期待、span=长（这一段让读者等的事）
    },
    "volumes": {                          # 分卷卡片、线索、人物锚点
        "volumes": [...], "threads": [...], "anchors": [...],
    },
    "first_volume": {                     # 第一卷卷纲
        "want": str, "pressure": str,     # 存在第 1 卷的卷行上
        "units": [...], "new_foreshadowings": [...], "new_expectations": [...],
    },
}
```

- **保存顺序**：定调 → 主角卡 → 世界（`books.world` 的九个键 + 人物、设定条目、关系）→ 第一段（`books.spine` 三项、节点含 `segment`、信息差、长线台账）→ 分卷（卷、线索、人物锚点）→ 第一卷（单元、第 1 卷的 `want`／`pressure`、短中线台账）。
- **按块保存** `save_piece`：`concept`、`protagonist`、`world` 各存各的；`segment` 块存「第一段」和「分卷」两部分；`first_volume` 同上。
- 台账分组同现在：`span=长` 的进 `segment`，其余进 `first_volume`。`ledger_of` 读 `segment.foreshadowings`、`segment.expectations`、`first_volume.new_*`。
- `remap_node_refs` 的表换成：`segment.secrets.node`、`segment.foreshadowings.node`、`segment.expectations.node`、`volumes.volumes.target_node`、`volumes.anchors.node`、`first_volume.new_foreshadowings.node`、`first_volume.new_expectations.node`。
- `save_setup(load_setup(...))` 必须幂等；作者维护的字段（别名、备注、存活状态、台账进展、节点状态和来源）保留，规则同现在。
- 旧形状（`spine`、`lore`、`outline`、`threads` 键）不再支持：开书只会用新形状；旧任务按第 6 节重开。`spine_from_legacy` 只在读旧会议消息、旧书 `books.spine` 时还会用到的地方保留。

## 5. 卷纲新题（`plan_volume` 两处调用）

`plan_volume.md` 新增变量 `segment`、`protagonist`、`opening`（第 9 节）。两处调用都要提供：

| `protagonist` | `format_protagonist(主角卡, 主角那一条人物)` | `format_protagonist(books.protagonist, 设定库里 role_type 为主角的第一位, hook=概念的 protagonist_hook)` |

## 6. 旧任务：按新流程重开

### 6.1 什么是旧任务

开书任务的 `params` 里没有 `flow` 或 `flow != 2` 的，都是旧流程任务（任务 1 的 `JobOut.setup_flow` 为 1）。本任务起新建的开书任务 `params.flow = 2`。

旧任务不再从旧检查点继续跑：

- `job_runner._run`：开书任务 `flow != 2` 时，不建图、不恢复检查点，直接把任务标为 failed，`error` 写下面这句，并在群聊发一条系统消息（同一句）。原来「等作者拍板、没有新决定就什么都不做」的提前返回保留在它前面。

  ```
  这个开书任务是按旧流程开的，开书流程已经更新。请点「按新流程重开」：保留你的点子、作者要求、已选的方向和已确认的定调，其余按新步骤重做。
  ```

- 接口 `decision`（`setup_review`）、`directions`、`piece`、`answers` 遇到旧任务返回 409，文字同上。

### 6.2 重开接口 `POST /jobs/{job_id}/restart-setup`

1. 锁住任务；必须是开书任务且 `flow != 2`，否则 409「这个任务不需要重开」。状态是 queued 或 running 时 409「编辑部正在工作，先停止再重开」。书的状态必须是 `setting_up` 或 `awaiting_approval`，否则 409「这本书已经开完了，不需要重开」。
2. `keep_concept` = 书的 `setup_progress.pieces.concept == "confirmed"` 且概念有书名。
3. 旧任务改为 cancelled（写 `finished_at`），发布 job 事件。
4. `setup_store.reset_for_restart(session, book_id, keep_concept)`：删除这本书的节点、人物锚点、信息差、人物、关系、设定条目、卷与单元、线索、伏笔与期待；`books.spine`、`protagonist`、`world` 清空；`keep_concept` 为假时 `books.concept` 也清空（`books.title` 不动）；`books.setup_progress` 置为 `{}`。不删作者要求、会议记录、草稿版本、模型调用记录。
5. 新建开书任务：`mode` 取旧任务的 `params.mode`（没有就是 oneshot）；`params` 加 `flow=2`、`restart_from=旧任务 ID`、`keep_concept`。
6. 作者消息「按新流程重开开书。」；系统消息：

   ```
   开书流程更新了：保留你的点子、作者要求、已选的方向和已确认的定调，其余按新的五步重做。
   ```

   `keep_concept` 为假时去掉「和已确认的定调」。
7. 入队，返回新任务。

### 6.3 新任务怎么接上（worker）

`job_runner._run` 判断要用初始状态时，如果 `params.restart_from` 有值：用同一个 `AsyncPostgresSaver` 的 `aget_tuple({"configurable": {"thread_id": 旧任务的 thread_id}})` 读出旧检查点的 `channel_values`（原始字典，不经过新图的状态定义），交给 `book_setup.restart_state(params, old_values, concept)`（`concept` 是数据库里现在的概念）生成初始状态：

- 基础同 `initial_state(idea, style_reference, ask=False, mode)`。
- 旧状态里有 `direction`（作者选过的方向）就带过来。
- `keep_concept` 且概念有 `core_loop`：`concept` 带过来，定调块记为 confirmed，从 `protagonist` 开始（逐块：`queue=["protagonist"]`、`piece="protagonist"`；一口气：`queue` 从 `protagonist` 往后）。
- `keep_concept` 但概念没有 `core_loop`（旧概念）：`concept` 带过来作为当前版本，从 `concept` 开始，`instructions={"concept": LEGACY_CONCEPT}`，作者要再确认一次定调。`LEGACY_CONCEPT` 原文（进提示词，逐字照抄）：

  ```
  这是按旧流程确认过的定调。按新的定调题补上缺的「核心循环」（作者提过对标作品的，再补上「对标」），其余内容保持原样；原来的「主角钩子」不用再写，下一步「主角」会参考它。
  ```

- 只有方向、没有确认的定调：从 `concept` 开始，按带过来的方向重新定调。
- 什么都没有：和新书一样从选方向开始。
- 一口气模式重开时不再问动笔前的问题（回答已经在作者要求里）。

读不到旧检查点（例如已被清理）时，按「什么都没有」处理，不报错。

## 8. 写作的临时保护

任务 4 才接上「定下一段」。在那之前，新流程开的书写完第一段的卷之后不能被标成全书完结：`write_book._next_step` 在所有卷都写完时，如果这本书有任何节点带段信息，而最后一卷的目标节点不是结局，就返回 done，理由：

```
这一段写完了。下一段怎么走，等「定下一段」功能接入后由主编来定，先停在这里。
```

不改书的状态。没有段信息的旧书照旧标为完结。
