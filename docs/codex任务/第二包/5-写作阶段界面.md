# 任务 5：写作阶段界面（前端为主）

> 先读 `docs/codex任务/第二包/README.md`、`docs/设计说明.md` 第 9.6 节和第 12.5—12.7 节，并确认任务 3、4 已完成并提交。视觉规范同任务 3，沿用任务 3 的 `QuestionSection`、`FactTable` 等组件。

## 目标

开写之后，作者一眼能看到：

- 全书分成了几段，每一段写到哪了（已写完、正在写、已规划、写到再定），每一段想做成什么、读者在等什么、揭开什么、在哪张地图；
- 下一段还没定时，可以「现在就规划下一段」；
- 主编定好下一段后，有一页按题分组的确认页，能换掉替你做的决定、直接钉死终点；
- 本书设置里能关掉「每一段开写前先给我确认」、能改全书篇幅；
- 主角此刻想要什么。

## 1. 分段的纯函数（`lib/storyMap.ts`，都要有 node 测试）

### 1.1 `segmentBands(nodes, volumes, chapters)`

只用于分段规划的书（任何节点带 `segment`）；旧书继续用现有的 `segments()`。

```ts
interface SegmentBand {
  number: number | null        // 第几段；还没规划的为 null
  from: StoryNode | null       // 这一段的起点：开篇或上一段的终点
  to: StoryNode                // 这一段的终点
  plan: SegmentPlan | null     // to.segment
  volumes: Volume[]            // 以 to 为目标节点的卷
  chapters: number             // 这些卷的计划章数之和
  status: 'done' | 'writing' | 'planned' | 'later'
  auto: boolean                // plan.status === 'auto'
}
```

- 从开篇开始，相邻两个节点之间是一段，终点是后一个节点。
- `status`：终点有 `segment` 且卷都写完 → `done`；有定稿或正在写的章、还没写完 → `writing`；有 `segment`、还没开写 → `planned`；终点没有 `segment` → `later`（写到再定）。
- `nextUnplanned(bands)`：第一个 `later` 的段；没有就是 null（已经规划到结局）。

### 1.2 写作位置的调整

- **全书总章数**：分段规划的书取「已规划卷的计划章数之和」和「概念的计划总章数」两者的较大值；`ratio` 用它算。
- **没规划的节点在地图上的位置**（`storyMapNodeChapters`）：最后一个已规划终点之后、结局之前的节点，在「已规划章数」和「全书总章数」之间按顺序等分；结局在全书总章数处。旧书不变。
- **文字**（`writingPositionText`、顶栏 `progressText`）：分段规划的书在前面加段号，例如「第 2 段 · 第 3 卷 42/60 章 · 离「寒原追查」还有 18 章」；已规划的卷都写完、还没到结局时「第 2 段写完了 · 下一段写到再定」（任务 4 已有，确认文案一致）；完结仍是「全书完结」。

## 2. 全书地图（`/spine`，开写之后）

分段规划的书，时间轴上的分段带换成段带：

- **段带标题**：「第 2 段 · 第 3-4 卷 · 约 120 章」，后面是状态小标签：已写完（墨绿勾）、正在写（主编色）、已规划（淡墨）、写到再定（虚线）；`auto` 为真时再加一个「自动通过」小标签。
- **展开内容**（已规划、正在写、已写完的段）：
  - 这一段的四项：目标、读者在等、揭开什么、地图，可就地编辑（`PATCH /nodes/{id}` 的 `segment`，编辑部工作时只读）；
  - 定下一段时的四件事（上一段的线头、主角的追求、金手指下一阶段、定下的谜底），只读、默认收起；
  - 这一段的卷卡片（同现在，点击进卷页）；
  - 正在写的段继续显示「正在写：第 3 卷 42/60 章」并高亮。
- **写到再定的段**：虚线、淡色，文字「写到再定 · 写到这里之前，主编会先来定下一段」。
- **现在就规划下一段**：只在 `nextUnplanned` 那一段上显示按钮，条件是编辑部空闲（没有进行中或等待作者的任务）、书的状态是 ready 或 writing。点击弹出确认框：

  ```
  主编会根据已经写出来的内容，规划第 N 段：下一张地图、对手、目标和终点。
  规划好之后会停下来等你确认。规划期间不会写新章节。
  ```

  本书设置关掉了「每一段开写前先给我确认」时，第二行换成「规划好之后按设置直接通过，群聊里会告诉你。」。确认后调用 `POST /books/{id}/plan-segment`，恢复自动跟随。
- 旧书的全书地图不变，也不出现这个按钮。

## 3. 定下一段的确认页（`/books/:bookId/next-segment`）

- `pendingTarget` 的 `segment_review` 改指向这一页（任务 4 指向 `/spine`），标签「第 N 段」；自动跟随会打开它。
- 页头：eyebrow「定下一段」，标题「第 N 段：走到「终点名称」」；下面一行说明：

  ```
  这一段还没写进书里，确认之后才会保存。想改就换掉下面替你做的决定，或者在群聊里说。
  ```

- 「替你做的决定」：同开书时的写法，提交走 `POST /jobs/{id}/segment` 的 `revise` + `flips`。
- 「作者重点看」：主角的追求要不要升级？、这一段主角想做成什么？、这一段走到哪里结束？。
- 十四节，题目和顺序按任务 4 第 3.5 节的表，用 `QuestionSection`，`pending.flags` 标在对应的题下面：
  1. **上一段留下的线头怎么收？**：文字；里面出现的 F／E 编号渲染成小标签，悬停显示台账内容。
  2. **主角的追求要不要升级？**
  3. **金手指下一步解锁什么？**
  4. **快揭晓的谜，谜底是什么？**：空的时候写「还远，写到再定」。
  5. **这一段在哪张地图？**：地图名；有新地图时下面一张 `FactTable`。
  6. **主角和谁打？**：小麻烦、大对手。
  7. **这一段谁登场？**：新人物列表（姓名 · 定位、想要什么、此刻想要）。
  8. **这一段主角想做成什么？**：目标、为什么离长线追求更近。
  9. **这一段让读者等什么？**：期待的一句话、怎么立、怎么兑现、第几卷立下 → 第几卷兑现。
  10. **这一段揭开什么？**：文字，下面列新的信息差。
  11. **这一段走到哪里结束？**：终点卡（名称、发生什么、之前得先有、之后变成、约第几卷），标「沿用远景节点（铁钉／暂定）」或「新起」；下面一个勾选框「确认时把它钉死」。
  12. **人物什么时候登场？**：锚点按节点分组。
  13. **这一段分几卷？**：每卷一张卡（第 K 卷 · 卷名 · 约 X 章 · 想做成 · 卷末结果 · 对手），卡下列出这一卷的线索节拍。
  14. **结局方向要调吗？**：新的结局方向，或「不调」。
- `finale` 为真时，页头下面加一条提示「这是收尾段：开始收线，往结局走。」。
- 页面底部和拍板条都有「确认这一段」「交给编辑部定」：拍板条的确认读取页面上「确认时把它钉死」的勾选状态（放在书的工作台上下文里共享，换书或确认后清掉）。
- 这一页全部只读（还没保存）；在群聊发的话作为修改意见（任务 4 已接）。

## 4. 本书设置

- **每一段开写前先给我确认**：`WritingSettings` 的「编辑部力度」组，在「每卷卷纲都要我拍板」后面加一行开关（`segment_approval`），说明：

  ```
  关掉后，主编定好下一段就直接往下写，群聊里会告诉你；全书地图上会标出新规划的段，节点是暂定的，之后仍然可以改。
  ```

  新书默认（设置窗口）共用这个组件，同样显示。
- **全书篇幅**（只在本书设置页）：「写作偏好」组之后加一组「篇幅」，一行「全书计划写多长」，数字输入（万字，5-1000），旁边小字「按每章约 X 字，约 Y 章」（每章字数取本书设置，没有就取概念的，再没有用 3000）。失焦或回车时 `PATCH /books/{id}` `{concept: {target_length}}`；编辑部正在工作时禁用，说明「编辑部工作时不能改，等这一步做完」。行说明：

  ```
  定下一段时，主编按这个篇幅判断还剩多少、要不要开始收尾；正在写的这一段不变。
  ```

## 5. 此刻想要什么

- **主角页**：「他为什么要往前走？」一节的最上面加一行「此刻想要（写作中设定师每章更新）：……」，取设定库里主角的 `want`；为空不显示；旁边「去人物页」。
- **人物页**：人物卡在「目标」后面显示并可编辑「此刻想要什么」（`want`）。
- 世界与地图页的人物列表任务 3 已显示，确认取的是同一个字段。

## 6. 概览与左栏

- 概览开写后的「全书地图」区块：地图条下面加一行当前这一段的目标「第 2 段 · 想做成：……」（取正在写的那一段；没有就不显示）。
- 等待 `segment_review` 时，左栏书稿目录在「全书地图」下面临时显示一项「定下一段 · 待确认」，链接到确认页。

## 8. 验收（演示模式，浏览器）

每步截图，结果写进 `docs/第二包验收.md` 的「任务 5」小节：

1. 点子带「测试短段」开一本书，写 6 章：自动打开定下一段确认页，十四节、三道重点看、提醒标在题下面。
2. 换掉一个替你做的决定 → 下一段按新选择重出；再在群聊提一次意见 → 重出。
3. 勾选「确认时把它钉死」后在拍板条上点「确认这一段」：全书地图上第 1 段「已写完」、第 2 段「已规划」，终点是铁钉；接着进入第 2 卷卷纲拍板。
4. 第 2 段写到一半时，在第 3 段的「写到再定」段带上点「现在就规划下一段」：确认框文字正确，规划完成后停下等确认，确认后不写新章。
5. 本书设置关掉「每一段开写前先给我确认」，写到下一段边界：不停下，群聊有说明，段带有「自动通过」标签。
6. 本书设置改全书篇幅（例如改小到只够一段）：下一次定下一段的调用记录里，【篇幅】写着「只够一段」，终点是结局。
7. 主角页的「此刻想要」随定稿变化；人物页能改「此刻想要什么」。
8. 一本旧书：全书地图、概览、顶栏和改版前一样，没有段号、没有「现在就规划下一段」。
9. 窄屏（390×844）和暗色模式下，各截全书地图段带、确认页一张。
