# 任务 3：开书界面（前端为主）

> 先读 `docs/codex任务/第二包/README.md`、`docs/设计说明.md` 第 9 节和第 12.4、12.7 节，并确认任务 2 已完成并提交。界面沿用现有的宣纸视觉、组件和动效规范（第 9.4、10.1 节）：辅助字最小 12px，正文类最小 14px，遵守减少动效，暗色模式下颜色正确。

## 目标

作者不是专业写手，开书时要一眼看懂：这一步要回答哪几个问题、哪几道最值得看、哪些现在不用管。

- 五个开书页面按必答题分组，小节标题就是问题本身。
- 每道题标「开写前」或「写到再定」；每一步标出两三道「重点看」。
- 程序检查和审稿发现的问题，标在对应的题下面。
- 修好定调页的排版问题。

不做：写作阶段的全书地图分段状态、定下一段的确认页（任务 5）。

## 1. 必答题表与共用组件

### 1.1 `lib/setupQuestions.ts`

把任务 2 第 2 节的必答题表原样搬成数据：每块一组，每题有 `key`、`title`（问题）、`focus`（重点看）、`rows`（这一节里的各项，每项有名称和 `when`：`before` 开写前／`later` 写到再定）。

- 题目键和问题文字必须和任务 2 第 2 节逐字一致；写一个 node 测试断言五块的键和问题列表。
- 定下一段的题目在任务 5 加。

### 1.2 `QuestionSection`

每道题一节：

- **标题**：问题本身，宋体 18px；节的锚点 id 为 `q-{key}`。
- **什么时候定**：标题右侧一个小标签，「开写前」（主编色细边）或「写到再定」（淡墨虚线边）；一节里各项不一样时，标签放在每一项的名称后面，标题右侧不放。
- **重点看**：`focus` 为真的题，标题前加一个朱砂小圆点和 12px 的「重点看」字样。
- **写到再定的空项**：显示「先空着，写到这里时主编会来问你」，辅助色，不显示编辑入口；有内容（写作中定下的）时正常显示。
- **问题标记**：本块正在等确认时，`pending.flags[key]` 的每一条显示在标题下面，警示色小字，前面加「需要再看看：」；没有就不占位。

### 1.3 页面顶部的「作者重点看」

每个开书页面的页头下面一行：「作者重点看：」加本块 ★ 题的问题文字，每个都是跳到 `#q-{key}` 的链接（点击后平滑滚动并聚焦，遵守减少动效）。下面一行辅助说明：「其余的扫一眼就行，有问题编辑部会标出来。」

### 1.4 「一行一项」紧凑表 `FactTable`

短的事实（题材、标签、篇幅、地图的几项……）用两列小表：左列名称（12px 辅助色，固定 6em），右列内容（可就地编辑），行与行之间一条细线。窄屏（稿件栏小于 480px）时名称在上、内容在下。

### 1.5 可编辑文字的排版修正（`components/Editable.tsx`）

定调页的问题之一是「编辑状态的灰底和铅笔图标贴在栏边」：

- 显示态的悬停底色左右各留 8px（`-mx-2 px-2`，上下 2px），底色不超出所在栏；
- 铅笔图标放进底色里面的右上角（`right-1.5 top-1.5`），文字右侧给它留出位置（`pr-6`），不再伸到文字框外；
- 编辑框和显示态的左边缘对齐，切换时文字不跳动。

这是全站通用组件，改完检查概念页、拼图板、卷页、人物页没有错位。

## 2. ① 定调页（`/concept`）

- 页头：书名（可改）、题材与标签徽章（同现在）。
- 「替你做的决定」、重新打开（`PieceDecisions piece="concept"`，同现在）、「作者重点看」。
- 六节按题排列，一栏到底，不再左右两栏：
  1. **写给谁看？**：`FactTable`——题材、标签、写给谁（`target_reader`）、对标（`benchmark`，空时显示「没有对标作品」）。
  2. **一句话讲什么？**：宋体大字，可改。
  3. **读者会为哪种场面叫好？**：卖点列表，可改。
  4. **主角每个单元反复做什么？**：核心循环，可改。
  5. **读起来什么味道？**：基调与文风，可改；下面一行只读「人称：第三人称（在本书设置里改）」，取本书设置。
  6. **写多长、叫什么？**：`FactTable`——全书篇幅（万字）、粗估卷数、每章字数、书名、备选书名；表下面是舞台阶梯（2.1）；最下面一行程序算出来的说明，辅助色、和可编辑内容分开：「按每章约 3000 字估算，全书约 670 章。」
- 旧书概念里有 `protagonist_hook` 且这本书没有主角卡时，在第 6 节后面加一节只读的「主角钩子（旧版概念）」；新书不显示。
- 作者最初的点子保留在页面最下方（同现在）。

### 2.1 舞台阶梯 `StageLadder`

`stage_ladder` 按「→」（也认「->」「—>」「＞」）切成几层，画成一节节往上的台阶：从左到右，每一层比前一层高一点，第一层标「第一张地图」，其余标「写到再定」（小字）。窄屏改成从下往上的竖列。点「改」时编辑原始文字，保存后重新切分。只有一层或为空时退化为普通文字。

## 3. ② 主角页（`/protagonist`）

替换任务 2 的简版页面。

- 页头 eyebrow「主角卡」，标题是主角姓名（可改）。
- `PieceDecisions piece="protagonist"`、「作者重点看」。
- 七节：
  1. **他从哪里起步？**：起点。
  2. **他为什么要往前走？**：四项——开局动机、长线追求、情感根源（开写前）；怎么升级（写到再定）。
  3. **他是个什么样的人？**：性格、做事风格、底线、说话方式（`FactTable`，说话方式用多行）。
  4. **他凭什么走得动？**：金手指·现在（开写前）；金手指·以后（写到再定）。
  5. **他的软肋是什么，最后变成谁？**：软肋；成长的终点（标「开写前 · 只要方向」）。
  6. **他在乎谁？**：每人一张小卡「姓名 · 关系」和「为什么在乎」，可改、可加、可删（整份列表一起保存）。
  7. **三件套咬得上吗？**：咬合检查；下面用三行小字列出它对照的三样：驱动力（长线追求）、金手指（金手指·现在）、核心循环（定调里的）。
- 编辑：`PATCH /books/{id}`，body `{protagonist: {字段: 值}}`；编辑部工作时只读（`Locked`）。
- 旧书（主角卡为空）：显示「这本书开书时还没有主角卡。」，下面只读显示概念里的主角钩子（有的话）和设定库里主角的简要资料，附「去人物页」链接。

## 4. ③ 世界与地图页（`/world`）

原「世界观」页：上半部分是按题分组的回答，下半部分是原来的设定条目列表。

- 页头：开书期间标题「世界、第一张地图和这里的人」，之后为「世界与地图」；eyebrow「世界与地图」。左栏设定库里的「世界观」改名为「世界与地图」。
- `PieceDecisions piece="world"`、「作者重点看」。
- 六节：
  1. **超凡的力量是明是暗？**：世界的表里。
  2. **升级靠什么？**：力量规则（开写前）；下面一行「往上的层级」标写到再定（写作中追加的内容显示在这里）。
  3. **第一张地图上谁说了算？**：`FactTable`——地图名、谁说了算、天花板、特有的规矩、主角从哪起步、能拿到什么（编辑 `maps[0]`）。写作中换过地图的（`maps` 多于一张），下面列出「后来到过的地图」，每张同样的表，只读。
  4. **主角和谁打？**：开篇的小麻烦、这一段的大对手两段文字，可改；文字里出现的人物姓名渲染成小标签，点击去人物页。
  5. **他身边有谁？**：这一段的人物列表，每人一行：姓名 · 定位、想要什么（`goal`）、此刻想要（`want`）、和主角的张力（取和主角之间的关系说明）；行尾「去人物页编辑」。主角排第一。
  6. **远处还有什么？**：核心谜团的谜面（开写前，可改）；谜底（写到再定）；后面的地图（写到再定，名字和一句话列表，可改）；终极敌人的影子（写到再定，可改）。
- 下面一个分隔标题「设定条目 · 写手写正文时查」，接原来的条目列表和增删改。
- 编辑：`PATCH /books/{id}`，body `{world: {...}}`；`maps`、`far_maps` 改其中一项时整份列表一起保存。
- 旧书（`world` 为空）：不显示上半部分，标题「世界与地图」，只有设定条目（和现在一样）。

## 5. ④ 第一段面板（`/spine` 顶部）

这本书分段规划过（任何节点带 `segment`），或者开书正在做／等待 `segment` 块时，全书地图页的页头下面先显示「第一段怎么走」面板，下面才是原来的节点时间轴。旧书照旧只有时间轴。

- 页头：开书期间标题「第一段怎么走与全书方向」，之后为「从开篇到结局」；统计行保留。
- `PieceDecisions piece="segment"`、「作者重点看」。
- 面板里八节（数据来自第二个节点的 `segment`、节点、台账、信息差、卷、锚点）：
  1. **开篇怎么开？**：五项（第 1 章的切入场面、前 3 章被什么压着、第一个小爽点、金手指露头、第 3 章的钩子），可改（`PATCH /nodes/{id}` 的 `segment.opening`）。
  2. **这一段主角想做成什么？**：目标、为什么离长线追求更近，可改。
  3. **这一段让读者等什么？**：`segment.wait` 可改；下面列出 `node_id` 指向终点的期待（E 编号、内容、「第 X 卷立下 → 第 Y 卷兑现」），点击去「伏笔与期待」页。
  4. **这一段揭开什么？**：`segment.reveal` 可改；下面列出这一段用到的信息差小标签（`S2「主角的真实修为」`），点击去信息差页。
  5. **这一段走到哪里结束？**：终点节点的名称、发生什么、之前得先有、之后变成，可改（节点接口）；铁钉／暂定标记；「在时间轴上看」跳到 `#story-node-{id}`。
  6. **人物什么时候登场？**：锚点按节点分组，「节点 2「外门考核」前后：苏晚晴 登场——……」；点击人物去人物页。
  7. **这一段分几卷？**：每卷一张小卡：第 N 卷 · 卷名 · 约 X 章 · 想做成：……；点击去卷页。
  8. **结局大概往哪去？**：结局方向（结局节点的「发生什么」，可改）；主角最后变成什么样的人（`spine.protagonist_arc`，可改）；核心矛盾、主题（可改）；远景节点列表（第二个节点之后、结局之前的节点，标写到再定），下面一行说明「远景节点只放你已经想到的；在下面的时间轴上点「在下面插入」，就能自己钉一个。」
- **时间轴**：
  - 小标题「节点」，开篇和第一段终点之间的分段带写「第 1 段 · 第 1-2 卷 · 约 61 章」；
  - 第一段终点之后、还没规划的区间显示一条淡色虚线分段带「写到再定 · 写到这里之前，主编会先来定下一段」，不能展开（任务 5 再加状态和按钮）；
  - 候选、补空位、自己写一句、留空只在等待 `segment` 块时出现（任务 2 已改），其余操作不变。
