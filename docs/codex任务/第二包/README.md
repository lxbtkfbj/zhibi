# 第二包：开书流程重整与滚动规划

产品规则以 `docs/设计说明.md` 第 12 节为准（讨论过程见 `docs/开书流程审视.md` v5）。本目录是交给 Codex 的实施任务：按顺序做，一次一个任务，前一个做完并提交后再开下一个。

一句话概括这一包：开书从「先想好整本书」改成「只定到第一段」，按作者要回答的问题分成五步（定调、主角、世界与人、第一段、第一卷）；写作中每一段开写前先「定下一段」。

## 任务顺序

| 任务 | 内容 | 依赖 |
|---|---|---|
| [1-数据底座](1-数据底座.md) | 迁移 0013、模型与接口新字段、上下文格式化、「每一段先给我确认」设置、启动前自动备份 | 无 |
| [2-开书新五步](2-开书新五步.md) | 开书流程图重写、结构化产出、程序检查与单块审稿、一口气模式、旧任务「按新流程重开」、卷纲新题、开书提示词、演示模式、前端最小改动 | 1 |
| [3-开书界面](3-开书界面.md) | 按题分组的五个页面、开写前／写到再定标记、作者重点看、定调页排版、主角页、世界与地图页、第一段面板、重开提示 | 2 |
| [4-定下一段](4-定下一段.md) | 写作中的「定下一段」（自动／手动触发、收尾段、确认或自动通过）、人物「此刻想要什么」、卷纲与章纲提示词更新、前端最小改动 | 2 |
| [5-写作阶段界面](5-写作阶段界面.md) | 全书地图的分段状态、定下一段确认页、「现在就规划下一段」、本书设置新开关与全书篇幅、此刻想要什么的显示 | 3、4 |

任务 3 和任务 4 互不依赖，先做哪个都行，但不要同时做。

每个任务做完，系统都要能正常使用：

- 任务 1 做完后，开书和写作的行为不变（只多了字段和接口）。
- 任务 2 做完后，新书按新五步开书；网页能走完整个开书流程，但页面是简版（任务 3 补全）。第一段写完后先停下，不会误标全书完结（任务 4 接上定下一段）。
- 任务 4 做完后，定下一段能在拍板条上确认；完整的确认页在任务 5。

## 交给 Codex 的方式

每个任务要发给 Codex 的话，已经写好在 [给Codex的话.md](给Codex的话.md)，整段复制即可。

## 共同约定（每个任务都适用）

1. **先读后做**：先读 `docs/设计说明.md` 第 12 节、本文件和任务文件。任务文件和设计说明有冲突时，以设计说明为准，并在完成说明里指出冲突。
2. **语言**：界面文字、提示词、schema 字段描述一律用简体中文。
3. **schema 描述就是提示词**：`app/agents/schemas.py` 里的 `Field(description=...)` 会随 schema 发给模型。任务文件里给出的类和描述要逐字照抄，字段顺序也照抄（模型按顺序填写，顺序是设计过的）。字段名可以按代码习惯调整，但要在完成说明里写明。
4. **提示词由设计方提供**：本目录 `提示词/` 下是写好的模板。任务里写明哪些文件要「搬进」`backend/app/prompts/`：用 `git mv -f` 覆盖同名默认模板，搬完后草稿目录里就不再有这几份，避免两份不同步。不要改提示词措辞；代码确实需要不同的变量名时，在完成说明里写明，并同步改提示词里的占位符。要退役的模板用 `git rm`。
5. **提示词登记**：新增或改动模板的变量，要登记到 `app/prompts/catalog.py`（`CATALOG` 与 `VARIABLE_LABELS`），保证提示词页能显示和校验。`render()` 遇到缺变量会直接报错，所以每个调用点都要提供模板里的全部变量。由程序拼出来、再填进模板的文字（任务文件里写成代码块的那些），也要逐字照抄。
6. **不破坏旧书**：已开完书、写到一半的书，迁移后要能照常续写。正在开书的旧任务不从旧检查点继续跑，而是按任务 2 的「按新流程重开」处理。不要升级、重启或改动作者日常的 8000／4320 服务和书库；验收一律用独立的数据库、Redis 库和端口（写法参考 `scripts/task6-preview.ps1`）。
7. **演示模式**：`app/llm/demo.py` 要补齐所有新增或变化的结构化产出，保证没有 Key 也能跑通。
8. **检查命令**（全部通过才算完成）：
   - 后端（`backend/`）：`uv run ruff check . && uv run ruff format --check . && uv run pytest -q`。后端测试需要 PostgreSQL（5433）和 Redis（6380），没启动就用 `docker compose up -d` 启动；连不上时停下来说明，不要跳过测试。
   - 前端（`frontend/`）：`npx tsc -b && npm run lint && npm run build && npm run test:workspace`
9. **界面验收**：涉及界面的任务，按任务里的验收清单用演示模式在浏览器里跑一遍并截图，写法参考 `docs/第一包验收.md`。结果写进 `docs/第二包验收.md` 里对应任务的小节（没有这个文件就新建），截图放在 `docs/第二包验收/`。
10. **文档同步**：每个任务完成后，把 `docs/设计说明.md` 第 12 节里本任务已实现的内容并入对应章节（第 3、5、9 节等），第 12 节开头的状态行写明哪些任务已实现；根目录 README 的流程介绍也要同步。
11. **分支与提交**：仓库没有远程，直接在当前分支上做。开始前确认工作区是干净的（`git status` 没有改动）；不干净就停下来问作者。一个任务做完提交一次或几次，提交信息以「第二包任务 N：」开头。
12. **完成说明**：做完后用一段中文告诉作者——
    - 改了什么、数据库迁移做了什么；
    - 搬了哪些提示词、退役了哪些；
    - 跑了哪些检查、结果如何；
    - 验收结果写在哪里；
    - 有没有没做完、做不到、或和设计说明对不上的地方。
