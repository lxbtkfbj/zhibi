# 任务 4：写作中的「定下一段」与「此刻想要什么」（后端为主）

> 先读 `docs/codex任务/第二包/README.md`、`docs/设计说明.md` 第 3.2 节和第 12.5、12.6 节，并确认任务 2 已完成并提交（任务 3 做没做都行）。

## 目标

- 写作中，每一段开写前先「定下一段」：自动触发（所有已规划的卷写完、还没到结局时）或作者手动触发；快写完时规划收尾段；默认停下来等作者确认，本书设置可以关。
- 设定师随每章定稿更新人物「此刻想要什么」，写手、章纲、卷纲都用上它。
- 卷纲方向、专项审稿、章纲、定稿提取、写正文五份提示词按第二包的新题更新。

不做：定下一段的完整确认页、全书地图的分段状态、本书设置里的开关（任务 5）。本任务只做能在拍板条上确认的最小界面。

## 2. 什么时候触发

### 2.1 判断（`write_book.decide` / `_next_step`）

- 「分段规划的书」：任何一个节点带 `segment`。旧书没有，照旧按全部卷卡片写到完本，不触发定下一段。
- 「最后一个已规划的终点」：带 `segment` 的节点里位置最靠后的那个。
- **自动**：`_next_step` 里所有卷都写完之后（替换任务 2 第 8 节的临时保护）：
  - 分段规划的书、最后一个已规划的终点不是结局：
    - 这一轮选的是「写完这一卷」、并且这一轮写过卷（有 `start_volume`）→ done，理由 `第{start}卷写完了。下一段还没定，下次开写时主编先来定下一段。`
    - 否则 → 下一步 `plan_segment`。
  - 其余情况照旧：书标为 completed，「全书写完了！」。
  - 「写 N 章」写够了照旧先停（`decide` 现有的判断在前）。
- **手动**：`until == "segment"` 的任务（第 6.2 节）：
  - 已经定好（状态里 `segment_done` 为真）→ done，理由 `下一段定好了，开写时从第{K}卷接着写。`；
  - 最后一个已规划的终点已经是结局 → done，理由 `全书已经规划到结局了。`；
  - 否则 → `plan_segment`。这一判断放在试读之前，手动规划不受试读拦截。
- `UNTIL` 增加 `"segment"`；`initial_state` 照常。

### 2.2 篇幅与收尾

程序先算出下面几个数（`segment_lengths(session, book)`）：

- 全书计划章数 `planned_total` = `planned_chapters(概念)`，每章字数用 `chapter_words(book)`；算不出来为 0。
- 已规划章数 `planned_so_far`：所有卷的计划章数之和（已拆单元的用单元章数之和，否则用卷卡片章数）。
- 已规划段数 `segments`：带 `segment` 的节点数。
- 每段平均章数 `avg` = `planned_so_far / segments`，四舍五入。
- 剩余 `remaining` = `planned_total - planned_so_far`。
- 收尾段 `finale`：`planned_total > 0` 且 `remaining <= 2 * avg`。只剩一段 `last_one`：`planned_total > 0` 且 `remaining <= avg`。

`{{length}}` 的写法（进提示词，固定部分逐字照抄）：

```
全书计划约 200 万字、约 670 章；已经规划了 2 段、4 卷、约 250 章（已定稿 240 章），还剩约 420 章；前面每段平均约 125 章。
篇幅还宽裕，按正常的一段来规划。
```

第二行按情况换成：

- `last_one`：`剩下的篇幅只够一段了：这一段就是最后一段，终点就是结局。`
- `finale`（不是 `last_one`）：`剩下的篇幅只够两段左右：这一段是收尾段——开始收线，揭开核心谜团的谜底，逼近终极敌人，往结局方向走，不要再开大的新坑。`
- `planned_total` 为 0：第一行换成 `这本书没有定全书篇幅。`，第二行 `按正常的一段来规划。`

### 3.3 `plan_segment_node`（主编）

- 状态文字 `主编正在定下一段（第 N 段）：上一段的线头、主角的追求、下一张地图…`；修改时 `主编正在按你的意见修改第 N 段…`。
- 上下文 `segment_blocks(session, book)`（`app/services/writing_context.py`）：

  | 变量 | 内容 |
  |---|---|
  | `concept` | `format_concept`（每章字数用本书设置） |
  | `protagonist` | `format_protagonist(books.protagonist, 主角那一条人物, hook=概念的 protagonist_hook)` |
  | `world` | `format_world(books.world)`（不带设定库列表） |
  | `spine` | `format_spine({books.spine, 全部节点}, books.world)` |
  | `last_segment` | 最后一个已规划终点的 `format_segment_info`，后面加两行：`终点：节点 N「名称」：发生什么`、`这一段写了第 a-b 卷。` |
  | `story_so_far` | `story_so_far(session, book, 下一卷卷号, before_chapter=下一章章号)` |
  | `characters` | `character_states(人物)` |
  | `ledger` | 还开着的（未埋／已埋、未立／已立）伏笔与期待，`format_ledger` |
  | `secrets` | 隐藏状态的信息差，最多 20 条，`format_secrets` |
  | `length` | 第 2.2 节 |
  | `playbook` | `playbook.text("nodes")` |
  | `requirements`、`glossary` | 同现有 |
  | `revision` | 首次为空串；修改时 `format_revision("当前的下一段", format_next_segment(segment_plan), segment_feedback)` |

- 调 `editorial.plan_segment` → `NextSegmentDraft`，程序整理 `normalize_next_segment(...)`：
  - **终点**：`end.ref` 只认两种：最后一个已规划终点后面紧接着的那个节点（远景节点或结局），或者结局。认得上的记为「沿用」，`adopt = {"node_id", "snapshot": {名称, 发生什么, 之前得先有, 之后变成}}`；认不上的（包括 0）记为新节点，ref 不为 0 时记说明 `("end", "终点引用的节点不是紧接着的远景节点，已改为新起一个。")`。
  - `nodes_view`：现有节点列表；新节点插在最后一个已规划终点后面（不写库），`end_index` 是终点在这份列表里的序号。分卷和人物锚点的节点序号都按这份列表。
  - 沿用的是结局，或 `last_one` 为真：`finale = True`；`last_one` 为真但终点不是结局时记 `("end", "篇幅只够一段了，这一段的终点应该是结局。")`。`finale` 为真时同样标记（2.2）。
  - 新人物：和已有人物重名的去掉，记 `("people", "「X」已经在人物表里，没有重复添加。")`。
  - 信息差、期待的整理规则同任务 2（`normalize_secrets`；期待 `kind=期待`、`span=长`、`node=end_index`）。
- 产出卡片 `{"type": "segment_plan", "data": 整理后的下一段}`，标题 `第 N 段：走到「{终点名称}」`；主编发言用 `remark`。

### 3.4 `split_segment_node`（主编）

- 状态文字 `主编正在给第 N 段分卷、排线索…`。
- 提示词 `split_segment`，变量：
  - `concept`、`protagonist`、`world`：同 3.3；`world` 后面接上新人物（`format_character`）和新地图（如果有）。
  - `segment`：`format_spine({books.spine, nodes_view}, world)`，空一行，接 `这一段的规划：` 加 `format_segment_info(按第 3.3 节结果拼成的段信息, world)`。
  - `threads`：`format_threads(现有线索, volume=K)`，K 是这一段的第一卷卷号。
  - `playbook`：`playbook.text("outline")`；`requirements`、`glossary` 同现有。
  - `volume_hint`（逐字照抄，「……」按 2.2 的数填；`planned_total` 为 0 时省略第二句）：

    ```
    卷号从第 5 卷开始（前面已经规划了 4 卷、约 250 章）。全书计划约 200 万字、约 670 章，还剩约 420 章。每卷通常 25-60 万字。
    ```

  - `revision`：首次为空串；修改时 `format_revision("当前的分卷与线索", format_volumes_part(segment_split), segment_feedback)`。
- 程序整理沿用任务 2 的 `normalize_volumes(part, {"nodes": nodes_view, "expectations": [这一段的期待]}, characters, start=K, end_index=end_index)`（人物用已有人物加新人物）。再加两条检查：这一段的章数超过剩余章数时 `("volumes", "这一段约 X 章，超过了剩下的约 Y 章。")`；新人物没有「登场」锚点时 `("cast", "「X」还没写什么时候登场。")`。
- 产出卡片 `{"type": "segment_volumes", "data": ...}`，标题 `第 N 段分 {n} 卷，约 {章数} 章`。

### 3.6 `segment_gate_node`

- 读设置：`segment_approval` 为假 → 不 interrupt，直接按「确认」保存，`status="auto"`，系统消息（kind decision）：

  ```
  第 2 段按设置自动通过：走到「寒原追查」，共 2 卷、约 120 章。全书地图上已经标出来了，节点是暂定的，随时可以改。
  ```

- 否则 interrupt：

  ```python
  {"kind": "segment_review", "flow": 2, "number": N, "round": r,
   "plan": 下一段（给界面显示用，见下）, "split": 分卷,
   "warnings": [...], "flags": {键: [文字]}, "decisions": [两步的决定合并]}
  ```

  `plan` 里带：四件事、地图（含 `new_map`）、对手、新人物（姓名、定位、想要什么、此刻想要）、目标、期待（整条 `ExpectationDraft`）、揭开什么、新信息差（短名、真相、知情人）、终点（名称、发生什么、之前得先有、之后变成、约第几卷、`adopted`、沿用节点现在的状态）、结局方向、`finale`。
- 恢复后：
  - `confirm` / `delegate`：保存（`status="confirmed"`）；`pin_end` 为真时终点保存为铁钉。系统消息 `第 2 段定好了：走到「寒原追查」，共 2 卷、约 120 章。接下来拆第 5 卷卷纲。`（手动规划的任务把最后一句换成 `开写时先拆第 5 卷卷纲。`，并设 `segment_done=True`）。回到 `dispatch`。
  - `revise`：`segment_feedback` = 意见原文，加上每条换掉的决定「把「{topic}」改成「{choice}」」；`segment_round += 1`；回到 `plan_segment`（再到 `split_segment`）。
- 等待期间作者在全书地图上改了节点：保存时以作者当前的版本为准（3.7）。

### 3.7 保存（`writing_store.save_segment`）

一个事务里完成，顺序如下。N 是第几段，K 是这一段第一卷的卷号。

1. **终点节点**：
   - 新节点：插在最后一个已规划终点后面，`kind=milestone`、`status=pencil`、`origin=ai`，内容取 `end`；
   - 沿用节点：锁行复核。节点不在了 → 按新节点插入；现在是铁钉 → 内容不动；是暂定且内容还等于 `adopt.snapshot` → 用 `end` 的内容；是暂定但等待期间被作者改过 → 保留作者的内容，系统消息里加一句「终点节点在等待期间被你改过，保留了你的版本。」；
   - `pin_end` 为真时 `status=pinned`（来源不变）；
   - `segment` 写成 `{"number": N, "status": "confirmed"|"auto", "planned_at": 已定稿章数, "map", "trouble", "opponent", "goal", "goal_link", "wait": 期待的一句话, "reveal", "opening": None, "carried", "pursuit", "finger_next", "answers", "finale"}`。
2. **结局方向**：`ending` 不为空、结局是暂定时，改结局的「发生什么」；是铁钉时不改。
3. **世界**（`books.world`）：有 `new_map` 时追加到 `maps`（同名的替换），并从 `far_maps` 去掉同名的；`power` 不为空时在原文后面另起一行追加 `（第 N 段）……`；`answers` 不为空且核心谜团还没有谜底时写进 `mystery_answer`（已经有谜底时不覆盖，谜底只记在段信息里）。
4. **主角卡**（`books.protagonist`）：`escalation` 另起一行追加 `第 N 段：{pursuit}`；`finger_later` 另起一行追加 `第 N 段：{finger_next}`。
5. **人物**：新人物逐个插入（含 `want`；重名的跳过）；关系两端都要是人物表里的人。
6. **信息差**：新秘密接续 S 编号，知情人过滤同现有规则，`node_id` 指向终点。
7. **期待**：这一段的期待进台账，`kind=期待`、`span=长`、`node_id`=终点，`plant_volume`、`payoff_volume` 限制在这一段的卷号范围内。
8. **卷**：按 `segment_split.volumes` 新建卷行（`status=planned`），`target_node_id`=终点，最后一卷 `reaches_node=True`，`thread_beats` 按线索生成。
9. **线索**：按名称对齐：已有的线把这一段几卷的节拍并进去（同卷号的替换），`summary` 原来为空时才写；新线追加在后面。
10. **人物锚点**：节点序号按 `nodes_view` 映射到真实节点 ID（新终点用刚插入的 ID），人物按姓名。

返回一份统计（卷数、章数、新人物、新秘密），供系统消息使用。

### 3.8 接上拆卷纲

保存后回到 `dispatch`：新卷是 `planned`，照常进入拆卷纲（比稿、专项审稿、卷纲拍板）。段的边界上会连着两次确认，这是设计如此。

## 4. 卷纲、章纲用上新信息

- **卷纲方向、专项审稿**：`volume_directions`、`audit_volume` 新增变量 `segment`（任务 2 的 `volume_blocks` 已经提供）。提示词见第 7 节。
- **专项审稿的程序检查**（`audit_volume` 的 `found`）新增两条「提示」：本卷没写「这一卷想做成什么」；某个单元没写核心循环。只作参考，不触发自动修改。
- **章纲**：`plan_chapters` 新增变量 `opening`：第 1 卷第 1 个单元、且第一段有 `opening` 时为 `format_opening(...)`，其余为空串（`chapter_plan_blocks` 提供）。

## 5. 此刻想要什么

- `writing_store.CHARACTER_STATE` 加 `want`：`apply_digest` 和更新位置、状态、能力一样处理 `want`（非空且和原值不同才写，后面章节改过的不被覆盖），改前改后记进 `bible_changes`；重写撤销自动覆盖这一项。
- 写手、章纲、卷纲拿到的人物资料已经带「此刻想要」（任务 1 的格式化）；提示词里的要求见第 7 节。
- 主角那一行每章都要看一眼：`digest_chapter` 的提示词要求（第 7 节）；程序不强制。

## 6. 接口

### 6.1 确认下一段 `POST /jobs/{job_id}/segment`

- 请求体 `SegmentDecision`：`{action: "confirm" | "delegate" | "revise", feedback?: str, flips?: [ChoiceFlip], pin_end?: bool}`。
- 锁住任务；当前等待的不是 `segment_review` 时 409「当前没有等待你确认的下一段」。`revise` 时 `feedback` 和 `flips` 至少一项，否则 422。
- 作者要求：`feedback` 记一条，来源 `segment:N`；每条 flip 记「「{topic}」改成：{choice}」，来源 `answer`。
- 作者消息：confirm「确认第 N 段，开拆第 K 卷。」（`pin_end` 时加「终点钉死。」）；delegate「第 N 段交给编辑部定。」；revise 为意见原文，只有 flips 时列出改动。
- 入队的恢复值带 `requirement_saved: True`（同现有接口，复用 `_queue_setup_response` 那套写法）。
- `DECISION_KINDS` 加 `segment_review`（等待期间插话返回 409）；`BOOK_STATUS_WHILE_WAITING` 里 `segment_review` → `writing`。

### 6.2 手动规划 `POST /books/{book_id}/plan-segment`

- 书的状态是 `ready` 或 `writing`，否则 409（「开书方案还没定稿」／「全书已经写完了」）。
- 有进行中（含等待作者）的任务 → 409「编辑部手上还有没做完的事，先处理完再规划下一段」。
- 不是分段规划的书 → 409「这本书开书时没有分段规划，不需要定下一段」。最后一个已规划的终点是结局 → 409「全书已经规划到结局了」。
- 新建写作任务，`params={"until": "segment", "count": 1}`；作者消息「现在就规划下一段。」；书的状态改为 `writing`；入队；返回 201 和任务。

## 8. 演示模式

- `NextSegmentDraft`：给出能通过 3.5 检查的第 2 段（例如换到「北境寒原」、终点新起「寒原追查」、新登场一位人物、一条新信息差、一条这一段的期待）；提示词里的【篇幅】写着「只够一段」时，终点 ref 填结局的序号。
- 写作中的 `SegmentVolumesDraft`：卷号从分卷提示里的「第 K 卷」开始，两卷。
- `ChapterDigest`：主角的 `want` 隔几章变一次（例如拿到考核资格后改成「查清师兄的死因」），供测试撤销。
- 触发器（写在点子里，供测试和验收）：
  - 「测试短段」：开书时第一段只有 1 卷 6 章（2 个单元各 3 章），写 6 章就到段的边界；之后每段也是 1 卷 6 章。
  - 「测试收尾」：全书篇幅按 6 章一段只够三段左右，第 2 段的【篇幅】出现「只够两段左右」，第 3 段出现「只够一段」。

## 9. 前端最小改动

- **类型**：`Pending` 加 `segment_review`（字段同 3.6）。
- **拍板条**：等待 `segment_review` 时标题「待你确认：第 N 段」（后面加第一条提醒），按钮「确认这一段」（主按钮）、「交给编辑部定」；提醒可折叠；动作调用 `POST /jobs/{id}/segment`，进行中防重复。
- **对话框**：等待 `segment_review` 时，发送的文字作为 `revise` 提交到同一个接口，占位文字「说说下一段想怎么改…」。
- **跟随**：`pendingTarget` 的 `segment_review` → `/spine`，标签「第 N 段」；`artifactTarget` 的 `segment_plan` → `/spine`「下一段」。
- **会议产出卡片**：`segment_plan` 列出终点、地图、目标、主角的追求；`segment_volumes` 沿用任务 2。
- **写作位置**（`lib/storyMap.ts`）：分段规划的书，只有最后一卷的目标节点是结局、并且写完了，才算全书完结；已规划的卷都写完、还没到结局时，地图文字为「第 N 段写完了 · 下一段写到再定」。
- **作者要求来源**：`segment:N` 显示为「第 N 段规划意见」。

## 10. 测试

1. **触发**：分段规划的书写完最后一个已规划的卷后进入 `plan_segment`；「写完这一卷」先停；「写 N 章」写够先停；旧书照旧完结。
2. **手动**：接口的 409 规则；手动任务只规划不写章，确认后停下；全书已规划到结局时 409。
3. **保存**：确认后终点节点插在正确位置并带 `segment`（第 N 段、`planned_at`）；新卷从第 K 卷起、全部走向终点、最后一卷 `reaches_node`；线索节拍并进已有的线；人物、关系、信息差、期待（E 编号、`node_id`）、锚点正确；世界追加新地图、力量层级、谜底规则；主角卡追加「第 N 段：……」。
4. **沿用远景节点**：铁钉原样；暂定按快照更新；等待期间被作者改过的保留作者版本；ref 指向别的节点时改为新起，并有说明。
5. **收尾**：`length` 的三种写法；只剩一段时终点是结局，写完这一段后书标为 completed。
6. **自动通过**：`segment_approval` 关闭时不停下、`status="auto"`、系统消息正确。
7. **提意见**：意见记成作者要求（来源 `segment:N`）；两步都按修改模式重出，`revision` 里有当前版本和意见；换掉决定同样生效。
8. **此刻想要什么**：定稿后 `want` 更新并记进 `bible_changes`；重写撤销后恢复；后面章节改过的不被前面章节覆盖；写手提示词的人物资料里有「此刻想要」。
9. **章纲**：第 1 卷第 1 单元的 `opening` 有内容，其他单元为空。
10. **提示词**：新模板登记、变量校验通过；schema 描述与本任务代码块逐字一致。
11. **回归**：现有写作测试全部通过（卷纲比稿、专项审稿、节点调整、信息差、重写撤销……）。

## 11. 验收

1. README 第 8 条检查命令全部通过。
2. 演示模式、独立库，点子带「测试短段」：开书 → 写 6 章 → 自动进入定下一段 → 拍板条「待你确认：第 2 段」→ 提一次意见 → 确认 → 拆第 2 卷卷纲 → 批准 → 写一章。截图和调用记录（`plan_segment`、`split_segment` 的提示词）写进 `docs/第二包验收.md` 的「任务 4」小节。
3. 同一本书在第 2 段写完前，用接口手动规划第 3 段，确认后停下，不写章。
4. 把本书设置 `segment_approval` 改为 false（接口改即可），下一段自动通过，系统消息和段信息的 `status` 正确。
5. 「测试收尾」：第 2、3 段的【篇幅】文字正确，第 3 段的终点是结局，写完后全书完结。
6. 主角的「此刻想要」随定稿变化，重写那一章后撤销。
