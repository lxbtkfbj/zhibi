# 任务 1：数据底座

> 先读 `docs/codex任务/第二包/README.md`（共同约定）和 `docs/设计说明.md` 第 12 节（重点是 12.4、12.6、12.8）。

## 目标

- 数据库能承载第二包的新概念：主角卡、世界与地图、段的规划、人物「此刻想要什么」、卷的「这一卷想做成什么」和「卷首处境」、单元的「核心循环」、本书设置「每一段开写前先给我确认」。
- 接口能读写这些字段；提示词上下文的格式化函数能把它们写进提示词。
- 启动脚本升级日常库之前自动备份。

现有的开书流程和写作流程**不改逻辑**，照常能跑；新字段在这一阶段大多是空的，格式化函数遇到空值时输出和现在一样。

不做：开书流程（任务 2）、定下一段（任务 4）、新页面（任务 3、5）。前端只改类型。

## 3. 数据形状

以下是 JSON 列里的键。中文是含义，写进代码注释即可；接口和格式化函数都按这些键读写。

### 3.1 `books.protagonist`（主角卡）

```json
{
  "name": "主角姓名",
  "start": "起点：身份、开局处境、读者为什么会代入",
  "trigger": "驱动力·开局动机",
  "pursuit": "驱动力·长线追求（是个谜的话写谜面）",
  "root": "驱动力·情感根源",
  "escalation": "驱动力·怎么升级（写到再定：写作中每次定下一段时追加一段）",
  "personality": "性格：核心性格加一个反差",
  "style": "做事风格",
  "bottom_line": "底线：绝不做的事",
  "voice": "说话方式",
  "finger": "金手指·现在（没有金手指时写最大的优势）",
  "finger_later": "金手指·以后（写到再定：写作中每次定下一段时追加一段）",
  "flaw": "软肋",
  "arc_end": "成长的终点",
  "cared": [{"name": "姓名", "relation": "和主角的关系", "why": "主角为什么在乎他"}],
  "interlock": "咬合检查：驱动力、金手指、核心循环怎么咬在一起"
}
```

### 3.2 `books.world`（世界与地图）

```json
{
  "surface": "世界的表里",
  "power": "力量规则（写作中定下一段时可以追加往上的层级）",
  "maps": [{"name": "地图名", "powers": "谁说了算、谁和谁有仇", "ceiling": "天花板有多高", "rules": "这里特有的规矩", "start": "主角在这里从哪一层起步", "gains": "这里能拿到什么"}],
  "trouble": "第一段：开篇压着主角的小麻烦",
  "opponent": "第一段：这一段的大对手",
  "far_maps": [{"name": "地图名", "line": "一句话，可以空"}],
  "shadow": "终极敌人的影子",
  "mystery": "核心谜团的谜面",
  "mystery_answer": "核心谜团的谜底（写到再定）"
}
```

- `maps` 是已经写细的地图，第一张就是第一张地图；写作中换到新地图时追加。`far_maps` 是还没写细的远处地图。
- `trouble`、`opponent` 只属于第一段；后面各段的对手记在各自终点节点的 `segment` 里。

### 3.3 `story_nodes.segment`（这一段的规划）

```json
{
  "number": 1,
  "status": "confirmed",
  "planned_at": 0,
  "map": "这一段在哪张地图（地图名）",
  "trouble": "开篇压着主角的小麻烦（第一段为空，读 books.world.trouble）",
  "opponent": "这一段的大对手（第一段为空，读 books.world.opponent）",
  "goal": "这一段的目标",
  "goal_link": "做成它为什么离长线追求更近",
  "wait": "这一段让读者等什么（一句话；台账里对应的期待用 node_id 指向这个节点）",
  "reveal": "这一段揭开什么",
  "opening": {"scene": "第一章的切入场面", "pressure": "前 3 章主角被什么压着", "first_win": "第一个小爽点", "finger": "金手指露头", "hook": "第 3 章结尾的钩子"},
  "carried": "上一段留下的线头",
  "pursuit": "主角的追求（要不要升级或更换）",
  "finger_next": "金手指下一阶段",
  "answers": "定下的谜底",
  "finale": false
}
```

- `number`：第几段。`status`：`confirmed`（作者确认；开书时随开书方案确认）或 `auto`（按设置自动通过）。`planned_at`：规划时已定稿的章数，开书时为 0。`number`、`status`、`planned_at`、`finale` 由程序维护。
- `opening` 只有第一段有，其他段为 null；`carried`、`pursuit`、`finger_next`、`answers` 只有写作中定下的段有。

## 4. 存取（`app/services/setup_store.py` 等，只做加法）

- `CHARACTER_FIELDS` 加 `want`；`VOLUME_FIELDS` 加 `want`、`pressure`；`UNIT_FIELDS` 加 `loop`。现有的整套保存、按块保存、写作卷纲保存都会顺带存取这些字段（字段缺失时不改原值，沿用 `_assign` 的规则）。
- `node_dict` 返回 `segment`；`save_nodes` 在条目里有 `segment` 键时写入（值为 null 表示清空），没有这个键时不动原值。
- `writing_context._char_dict` 加 `want`。
- 开书方案的数据形状（`load_setup` / `save_setup`）这一步不改，任务 2 再改。

## 5. 接口

| 位置 | 改动 |
|---|---|
| `BookDetail` | 新增 `protagonist: dict = {}`、`world: dict = {}` |
| `BookPatch` | 新增 `protagonist`、`world`（可选）：按顶层键合并进现有的值（`{**原值, **传入}`）。只接受 3.1、3.2 里的键，类型照表；不认识的键返回 422「不认识的字段：x」。用两个 `extra="forbid"` 的 Pydantic 模型校验（`cared`、`maps`、`far_maps` 的元素也校验键）。沿用 `ensure_idle` |
| `NodeOut` | 新增 `segment: dict \| None = None` |
| `NodePatch` | 新增 `segment`（可选）：只允许改已经有段信息的节点，节点的 `segment` 为 null 时返回 422「这一段还没规划，写到这里时主编会来定」；按键合并，`opening` 按子键合并。可改的键：`map`、`trouble`、`opponent`、`goal`、`goal_link`、`wait`、`reveal`、`opening`、`carried`、`pursuit`、`finger_next`、`answers`；传 `number`、`status`、`planned_at`、`finale` 或其他键返回 422 |
| `CharacterBase/Out/Patch` | 新增 `want` |
| `VolumeOut` / `VolumePatch` | 新增 `want`、`pressure` |
| `UnitOut` / `UnitPatch` | 新增 `loop` |
| `JobOut` | 新增 `setup_flow: int \| None`：开书任务取 `params.get("flow", 1)`，其他任务为 null。现有任务都是 1；任务 2 起新建的开书任务写 2 |
| 本书设置、新书默认 | 返回和保存 `segment_approval` |

## 6. 上下文格式化（`app/agents/context.py`）

下面代码块里的文字会进提示词，固定部分逐字照抄；「……」是填进去的内容。值为空的行一律省略，除非下面写明「空时写某某」。

### 6.1 已有函数的加法

- `format_character`：「目标」后面加一行 `此刻想要：……`（`want`）。
- `format_character_state`：「目标」后面加 `此刻想要：……`。
- `format_volume_card`：标题行后面、「舞台」前面加两行：`这一卷想做成：……`（`want`）、`卷首处境：……`（`pressure`）。
- `format_unit`：「结果」那一行后面加 `核心循环：……`（`loop`）。
- `format_spine`：
  - 有段信息的节点，在它的「之后变成」后面加一行：`  这是第 N 段的终点：目标：……；读者在等：……；揭开：……；地图：……`（四项里空的省略；第 1 段的地图为空时取 `books.world.maps[0].name`，取不到就省略）。`format_spine` 增加可选参数 `world`。
  - 只要有任何一个节点带段信息（这本书是分段规划的），就给「最后一个有段信息的节点」之后的节点（不含开篇）在方括号里加 `｜这一段写到再定`，例如 `节点 3「北境」［暂定｜约第 4 卷｜这一段写到再定］发生：……`。
  - 没有任何段信息的书（旧书），输出和现在完全一样。

### 6.2 新函数

```
姓名：……

驱动力
- 开局动机：……
- 长线追求：……
- 情感根源：……
- 怎么升级：……
性格：……
做事风格：……
底线：……
说话方式：……

金手指·以后：……
软肋：……
成长的终点：……

```

- 「怎么升级」「金手指·以后」空时写 `写到再定`，不省略。
- `在乎的人` 每人写成 `姓名（关系：为什么在乎）`，用「；」分隔。
- `此刻想要` 取 `character["want"]`（设定库里主角的「此刻想要什么」），没有就省略。
- 卡是空的（旧书）：第一行写 `（这本书开书时还没有主角卡）`；有 `character` 时接着输出 `format_character(character)`；有 `hook` 时再加一行 `主角钩子：……`。

**`format_world(world: dict) -> str`**

```
世界的表里：……
力量规则：……
地图「青石镇」：谁说了算：……；天花板：……；特有的规矩：……；主角从这里起步：……；能拿到：……

第一段·大对手：……

终极敌人的影子：……

```

- `maps` 每张一行，按顺序。
- `后面的地图`：每张写 `名字（一句话）`，一句话为空就只写名字，用 ` → ` 连接；`far_maps` 为空时写 `后面的地图：写到再定`。
- 谜底为空时写 `谜底：写到再定`。
- `world` 里如果还带着设定库的列表（任务 2 开书时会这样传），依次追加，每段之间空一行：`设定条目：` + 每条 `- [类别] 名称：内容`；`人物：` + 每人 `format_character`，人与人之间空一行；`人物关系：` + 每条 `- A 与 B：关系。说明`。
- 完全为空（旧书）时返回 `（这本书开书时还没有「世界与地图」）`。

**`format_segment_info(segment: dict, world: dict | None = None) -> str`**

第一行：

- `number` 为 1 且 `planned_at` 为 0：`第 1 段（开书时规划）`
- 否则：`第 N 段（写到第 M 章时规划，作者确认）`；`status` 为 `auto` 时括号里写 `按设置自动通过`

```
地图：……

大对手：……
这一段的目标：……
为什么离长线追求更近：……

这一段揭开什么：……

主角的追求：……
金手指下一阶段：……
定下的谜底：……

```

- 第 1 段的 `map`、`trouble`、`opponent` 为空时，分别取 `world["maps"][0]["name"]`、`world["trouble"]`、`world["opponent"]`。
- 最后一行只在 `finale` 为真时输出。

## 7. 启动前自动备份

作者用 `启动.cmd` 启动时，`scripts/start.ps1` 会自动 `alembic upgrade head` 升级日常库。这一包有迁移，升级前要先备份。

- 新建 `scripts/backup-db.ps1`：参数 `-Label`（写进文件名）、`-Database`（默认 `zhibi`）。做法：
  1. `docker compose exec -T postgres pg_dump -U zhibi -d <Database> -Fc -f /tmp/zhibi-backup.dump`
  2. `docker compose cp postgres:/tmp/zhibi-backup.dump data/backups/<Database>-<Label>-<yyyyMMdd-HHmm>.dump`
  3. `docker compose exec -T postgres rm -f /tmp/zhibi-backup.dump`
  4. 文件不存在或大小为 0 就报错退出（返回非零）。成功时输出文件路径。

  用容器内文件再拷出来，不要把 `pg_dump` 的输出经 PowerShell 管道重定向到文件（二进制会被编码损坏）。
- `start.ps1` 在 `alembic upgrade head` 之前：用 `alembic current` 和 `alembic heads` 判断有没有待执行的迁移。当前版本不为空、且和最新版本不同时，调用 `backup-db.ps1 -Label before-<最新版本号>`；备份失败就 `Fail '升级前备份失败，没有升级数据库'`，不再往下执行。没有待执行的迁移时不备份。
- 新加的步骤输出一行中文说明，如 `已备份到 data\backups\zhibi-before-0013_segment_planning-20261017-0930.dump`。

## 9. 测试

- **迁移**：在隔离库里跑 upgrade／downgrade／再 upgrade，核对七列、默认值，以及旧数据（节点、人物、卷、单元、正文）不变。
- **接口**：
  - `BookDetail` 返回空的 `protagonist`、`world`；PATCH 按顶层键合并；不认识的键、错的类型返回 422；编辑部工作中返回 409。
  - `NodeOut.segment` 默认为 null；对没有段信息的节点 PATCH `segment` 返回 422；对有段信息的节点（测试里直接写库）合并成功，`opening` 按子键合并；改 `number`、`status`、`planned_at`、`finale` 返回 422。
  - 人物 `want`、卷 `want`／`pressure`、单元 `loop` 的读写。
  - `JobOut.setup_flow`：现有开书任务为 1，写作任务为 null。
  - 本书设置和新书默认里 `segment_approval` 默认为真、可以修改，不出现在「实际发给编辑部的话」里。
- **存取**：`save_setup(load_setup(...))` 仍然幂等；节点带 `segment` 时往返不丢；人物、卷、单元的新字段往返不丢；写作卷纲保存不清空单元的 `loop`。
- **格式化**（快照测试）：
  - `format_protagonist`：完整的卡、「写到再定」两项为空、空卡带人物和主角钩子、空卡什么都没有。
  - `format_world`：完整的、带设定库列表的、`far_maps` 为空的、谜底为空的、完全为空的。
  - `format_segment_info`：第 1 段从 `world` 取地图和对手；第 2 段作者确认；第 3 段自动通过且是收尾段。
  - `format_spine`：分段规划的书（第 1 段终点后面的节点带「这一段写到再定」）；旧书输出与本任务之前逐字相同。
  - `format_opening`、`format_volume_card`、`format_unit`、`format_character`、`format_character_state` 的新行；新字段为空时输出与之前逐字相同。
- **回归**：现有测试全部通过（开书、写作流程不变）。
