# 主编口吻和分层 任务 1：主编口吻和聊天提示词分层

共同约定照本目录的 `README.md`。

## 为什么做

作者 2026-10-24 想给主编加一个能换的人格，比如主编是女仆、叫他「主人」，聊起来开心一点。他更看重的是聊天的提示词怎么拼更合理、回答质量更好。他在提示词页看到「主编人设」写着「主编每次调用的系统提示」，觉得耦合太高。

查下来的毛病（细节在 `docs/主编聊天/人格与分层.md` 第一节）：

1. `editorial.persona(role)`（人设＋通用规则）既是聊天的系统提示，也是开书、规划、方案卡、分流这些写书的活的系统提示。口吻写进人设，就会漏进说明、方案卡和记忆。
2. `chat_agent.md` 和 `chat_reply.md` 里的四件事、另外几件事几乎一字不差，抄了两份。
3. 人设里说「该拿主意的时候就推荐一个」，聊天第二件又说「要看作者口味的，说清几种走法各会怎样，让他来定」，后一句成了口子。10-24 上午同一句话答了两次，两次都摆出三套点子让作者挑（llm_calls 3165、3166）。
4. 聊天最后那句「照你的角色说话：你管剧情、节奏和方向」，是以前按关键词分人时留下的；现在不点名都是主编答，这句把她框窄了。通用规则里「不要替其他角色做工作」，和主编在聊天里什么都管打架。

作者同意的做法：按「多久变一次」分层，每层只管一件事、只写在一处。聊天的规矩都放进系统提示，用户提示只放资料、聊过的和作者这次说的。作者看过九份草稿原文，说没问题。

## 2. 每条路怎么拼

### 2.1 系统提示

新加一个拼聊天系统提示的函数（放哪、叫什么自己定）。下面几段依次用一个空行（`"\n\n"`）接起来：

1. 人设：`render(f"persona_{role}", rules="")`。聊天时人设里不带通用规则，通用规则挪到最后。
2. 只有 `role == "chief"` 才有：`render("chat_voice", voice=render("voice_chief"))`。
3. 这条路的提示词：`chat_agent`、`chat_reply` 或 `chat_teardown`，见下表。
4. 只有自己的书（不是拆的书）才有：`render("chat_manner", role_focus=…)`。
5. `render("rules")`。

| 哪条路 | 第 3 段 | 第 4 段 |
|---|---|---|
| 群聊、能调工具（`chat_agent.answer_note`，书不是拆的） | `render("chat_agent", act_rule=ASK_RULE if read_only else ACT_RULE)` | 有 |
| 只说话不动手（`chat.answer`：私聊、重新回答、不能调工具时的群聊，书不是拆的） | `render("chat_reply", where=…, how_to_apply=…)`，两个值照 `reply_values` 现在的算法 | 有 |
| 拆的书的群聊（能调工具、不能调的都算） | `render("chat_teardown", lookup=LOOKUP_TOOLS 或 LOOKUP_PLAIN, role_focus=…)` | 没有 |

`role_focus` 的值：主编填空串；设定师、写手、审稿填「照你的角色说话：」接上原来 `ROLE_FOCUS` 里那句。自己的书用 `chat_context.ROLE_FOCUS`，拆的书用 `teardown_chat.ROLE_FOCUS`。两份 `ROLE_FOCUS` 里 `chief` 那条都删掉。

### 2.2 用户提示

三条路都改用 `render("chat_material", …)`。可有可无的块，由程序先用 `tagged(名字, 内容)` 包好再填；没有就填空串，`render` 会把多出来的空行并掉。

| 变量 | 群聊（能调工具） | 只说话不动手 | 拆的书 |
|---|---|---|---|
| `material_note` | 照旧 | 空 | 照旧 |
| `book` | `tagged("简介", ctx.concept)` | 同左（原来的标签叫 `<定调>`，统一成简介） | `tagged("这本书", book_info(…))` |
| `library` | 照旧 | 照旧 | 原来的值前面加一行「（从原文拆出来的）」 |
| `outline` | 照旧 | 照旧 | 原来的值前面加一行「（从原文倒推的）」 |
| `progress` | `tagged("写到哪了", …)` | 同左 | 空 |
| `memory` | `tagged("记忆", …)` | 同左 | 空 |
| `viewing` | `tagged("作者正在看的那一页", viewing_full(…))` | 空 | 同群聊 |
| `related` | 空 | `tagged("和这次的话有关的资料", …)`；重新回答时换成那一轮查到的、做了的（现在就是这样） | 照旧（能调工具时为空）；重新回答时，那一轮查到的接进同一个块里，不要接在块后面 |
| `extras` | 空 | 照旧 | 空 |
| `pending` | 照旧 | 照旧 | 空 |
| `working` | 照旧 | 空 | 空 |
| `retry` | 照旧 | 空 | 照旧 |
| `summary`、`recent`、`quote`、`note` | 照旧 | 照旧 | 照旧 |

### 2.3 不变的

- 写书的活照旧用 `persona(role)`，也就是人设＋通用规则，不带口吻、不带聊天的做法。包括 `editorial.py` 里的各个函数、`library_ai.call_model`、`book_setup` 里的分流。
- 总结方案（`chat_plans.make_plan_background`）从 `reply_values` 拿 `concept`、`library`、`outline`、`progress`、`pending`、`summary`、`note` 七样，这七样照旧是原样的字，拼出来的请求一个字不变。
- 对话摘要、看稿意见要不要记、整理要求、群聊分流都不动。
- 工具定义、工具说明、调工具的来回、`MAX_ROUNDS` 这些也都不动。

## 3. 程序里交给模型的字

1. `teardown_chat.LOOKUP_TOOLS` 换成下面这段（它现在在系统提示里，资料排在后面，所以不能再说「上面」）：

   ```text
   资料里的设定和大纲只是目录，或者还没拆出来，原文一章都没贴。要细节、要核对，用工具查：某一章的原文和摘要、在原文里搜一个词、设定卡全文、大纲上的一段、伏笔。问「第一次出场」「在哪几章」的，先在原文里搜。能一起查的一次调几个工具；资料里已经有的不要再查。
   ```

2. `teardown_chat.LOOKUP_PLAIN` 换成：

   ```text
   你这次没法用工具查。资料里的 <和这次的话有关的资料> 是程序按作者这句话找出来的：提到的几章、设定，还有作者用引号标出的词在原文里的位置。那里没有的就说没找到，不要猜；作者要找某个词在哪几章，告诉他在正文页目录的搜索框里搜原文。
   ```

3. `ROLE_FOCUS` 照第 2.1 节改。
4. 这些一个字不改：`ACT_RULE`、`ASK_RULE`、`how_to_apply` 的两段、`retry_note`、「编辑部正在干活」那段、`material_note`。

## 5. 演示模型

`backend/app/llm/demo.py` 第 1056、1172 行，是靠用户提示里的「作者导入的别人已经写好的小说」认出拆的书的。这句现在挪进了系统提示。改成看系统提示，或者看用户提示里有没有 `<这本书>`，演示的回答不变。

别的演示规则能照旧用就不动：
- 认角色看的是系统提示第一行，人设开头没变；
- 找 `<作者这次说的>`、`<记忆>`、`<和这次的话有关的资料>`、`<上次做到一半>`，看的是用户提示，这些块都还在用户提示里。
