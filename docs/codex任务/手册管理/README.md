# 手册管理：共同约定

这一包给编辑部的写书手册（作者叫 skill）做一个管理页：手册能新建、改名、改「什么时候翻」、改正文、开关、删除；每存一次留一版，能退回，能跟程序带的那份比一比。只有一个任务，后台和页面一起做，见 `1-手册管理.md`。

本包照这一份约定，不照别的目录的 README。

1. 先读本文件，再读任务文件。设计在 `docs/设计说明.md` 10.8「手册管理」。
2. 开工前 `git status` 不干净就停下来问，不要动、也不要替别人提交没提交的改动。
3. 改哪些：
   - 后端：手册怎么存、怎么读（`backend/app/prompts/handbooks.py`，加上新的存储和接口）、迁移 `0032`、提示词页不再管手册（`backend/app/prompts/catalog.py`、`backend/app/api/prompt_tools.py` 里跟手册有关的几处）。
   - 前端：新页面 `/handbooks`；系统设置、提示词页、预设管理三处入口。
   - 两本手册的文件 `backend/app/prompts/skills/opening.md`、`standards.md` 一个字都不动；别的提示词、预设的十九块也一个字都不动。
4. 不要升级、重启或改动作者日常的 8000／4320 服务、日常 worker 和书库，不对日常环境运行 `start.ps1`／`stop.ps1`，迁移只在测试库和你自己的独立库上跑。**不调真实模型**：要看效果用演示模型。
5. 什么时候自己定，什么时候停下来问：
   - 自己定，做完在完成说明里单独列出来：
     - 测试里写死的旧指纹、旧文字和开工时 HEAD 对不上，而那份文件本任务没动过（和开工时 HEAD 逐字节一样）：改测试跟上 HEAD。
     - 本任务有意改了的东西，旧测试还认旧的：照任务里写的新样子改测试。有意改的包括：提示词页不再有「手册」那一组，`/api/prompts/skills.*` 没有了；手册改由 `/api/handbooks` 管；系统设置多一张卡；提示词页、预设管理各多一个链接；预设管理选中「工具：翻手册」时多一行小字。任务第 11 节点名的旧测试都属于这一类，照新样子改断言不算「放宽」。
     - 和本任务无关、开工前就坏了的测试：修法是机械的（同第一条），直接修；要改产品代码或者改变行为才能修好的，停下来问。
     - 任务没写到的实现细节：文件放哪、函数叫什么、接口参数和返回的细节、表的列怎么命名、组件怎么拆、「比一比」的段落怎么对齐、测试放哪个文件。
   - 停下来问：
     - 要改两本手册的文件、预设的块，或者别的提示词；
     - 要动任务写死的东西：主编翻到的全文怎么拼、哪种能删哪种不能删、开着的不能重名、关着的可以没写完、迁移怎么搬作者改过的手册、作者看到的字；
     - 任务的要求和现有代码真的打架，两种做法都说得通，而且会影响主编翻到什么，或者作者怎么用；
     - 要删测试、跳过测试，或者放宽和本任务无关的断言才能过；
     - 要动作者日常的服务和书库，或者要调真实模型；
     - git status 不干净（第 2 条）。
6. 检查：开发中只跑相关测试；提交前跑一次全量，全部通过。
   - 后端：`backend` 下后端全量。
   - 前端：`frontend` 下 `npx tsc -b && npm run lint && npm run build && npm run test:workspace`；浏览器测试（独立后端加演示模型）跑任务第 11 节的新测试，以及第 11 节点名的旧测试。没改公共样子，装修、精髓两套页面比对不用跑。
7. 验收写在 `docs/手册管理验收.md`，截图放 `docs/手册管理验收/`。
8. 直接在当前分支上做，不推送。提交信息以「手册管理：」开头，一次提交。
9. 做完用一段中文告诉作者：改了哪些文件、测试结果、验收文档在哪；按第 5 条自己定的事单独列出来。还要告诉作者：这次改了后端、有新迁移，要重启服务才用上，设计方复核完会替作者重启；重启前在提示词页改过的手册，迁移会原样搬进手册管理。

## 先后（给作者和设计方看的，Codex 不用管）

1. 本目录提交了、工作区干净了，就能发。要发给 Codex 的那段话，设计方直接贴在对话里。
2. 提交以后，设计方复核：
   - 两本手册文件逐字节没动；没改过的手册，主编拿到的目录和全文跟今天一样；
   - 迁移把提示词页改过的手册原样搬过来（在测试库上试一遍）；
   - 开关、重名、没写完、删除、保存记录、新版提醒这几条规矩；
   - 截图，再在作者的 4320 上只看不改地点一遍。
   复核通过就重启作者的服务（会自动备份、跑迁移 0032）。
3. 上线以后作者在手册管理里改、开关、新建；改完在群聊里问一句，设计方只读看那次翻到的是不是新的。
