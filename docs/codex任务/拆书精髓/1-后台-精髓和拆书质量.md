# 拆书精髓（任务 1 · 后台）：精髓、合并同一个人、通用版逐章记、提速

## 0. 这次做什么

作者拆书是为了学「一本小说是怎么写出来的」，以后开新书还要把学到的交给帮写书的 AI。现在简介页上的「这本书好在哪」只有六个结构数字题，写得空。这次换成「精髓」：一条条能直接拿来用的知识点，剧情最重要，其次设定、爽点、人物。

提示词和做法都已经拿真模型试过三版（《逆天邪神》前 100 章、《惊悚乐园》前 60 章，【Alicia】gemini-3.8-flash），试验脚本、结果说明在 `docs/拆书/精髓试验/`：

- `analyze.py`：精髓各步的**参考做法**。每一节给模型的材料怎么拼（文字、顺序、截断长度、上限），这里照它逐字照搬，只把数据来源换成库里的。
- `render_page.py`、`make_sample.py`：页面数字（rails）怎么算、样张怎么生成。
- `common.py`：调模型的方式（只用来看，产品里照现有的 `runner.call_user` 调）。

这次一共九件事，都是后台：

1. 逐章记换成通用版提示词（第 3 节）。
2. 写角色卡前先「合并同一个人」（第 4 节）。
3. 拆的书角色卡「成长与结局」改写成「变化」（第 5 节）。
4. 拆的书角色顺序：主角在前，其余按出场（第 6 节）。
5. 收尾加「整理精髓」，取代「这本书好在哪」（第 7 节）。
6. 提速：整理设定和整理精髓 8 个一起跑、读者在等的事边读边记、多开一个拆书工作进程（第 8 节）。
7. 接口（第 9 节）。
8. 编辑部聊天带上精髓（第 10 节）。
9. 重跑脚本（第 11 节）。

页面（精髓页、新简介页、设定页几处小修、编辑部按钮）是任务 2，这次不碰前端；只有第 9 节接口要给任务 2 用。

## 3. 逐章记换成通用版

只换提示词，`TeardownRead` 的字段、`feel` 的四档（憋屈、平、爽、大爽）、`FEEL` 分数都不变。改动在提示词里：

- 看点不只认爽：笑、燃、甜、吓、烧脑都算；
- 读者感觉的定义放宽到别的类型的书；
- 有方向的关系照原文写，转述写成「某某说」，名称照原文；
- 人物关系的变化也记进 `change`；
- 「兑现」只写在那件事本身发生的那一章。

已经读过的章不重读；以后读的章用新提示词。

## 4. 合并同一个人

### 4.1 什么时候

放在 `collect_settings`（整理设定）的最前面，写角色卡之前。重跑脚本也能单独跑（第 11 节）。

### 4.2 材料

先照现有做法算名单：`people_of(reads, names)`，已经套上 `books.teardown["names"]`。

按第一次出场排好，每人一行，照 `analyze.py` 的 `merge_material()` 拼：

```
【名字】出场 N 章（第 a–b 章）；别的叫法：甲、乙（没有写「没有」）；第 a 章：第一次写出来的样子前 60 字；第 b 章：最后一次写出来的样子前 60 字
```

只出场一章的，只写第一句。「别的叫法」用名单里的 aliases。

- 不到 150 人：一次调用，`render("teardown_merge", title=书名, people=全部行)`。
- 150 人以上：按第一次出场的顺序切成每段 150 人、前后两段重叠 30 人，一段一次调用。各段结果合在一起：同一个名字落在两组里的，两组并成一组；`keep` 取先出现的那组的。

schema `TeardownMerge`，见第 12 节。

### 4.3 检查和落库

一组至少两个名字。`keep` 必须是组里的一个名字；组里的名字都要在名单里（不分大小写、去掉首尾空白比较）。不合格的组丢掉，不重来。

全部名单行合起来的 sha1 记成 inputs，和 `books.teardown["merges"]["inputs"]` 一样就不调。

落库在一个事务里，持书锁：

1. `names[名字] = keep`：组里除 `keep` 以外的每个名字都写一条。这就是现有 `people_of` 认的那套映射，并过的人此后读章、写卡都按一个人算。
2. `books.teardown["merges"] = {"inputs", "groups": [{"names", "keep", "why"}], "at"}`。

### 4.4 卡

并完以后，照现有流程写卡：并到 `keep` 上的人，记录变多了，inputs 变了，卡会重写。

被并掉的那个名字原来有自己的卡：

- 作者没改过（照现有的 hash 规矩判断）：删掉这张卡；
- 作者改过：留着不删，在 `merges` 那一组里记 `kept_card: true`。

### 4.5 进度

进度沿用 `settings` 那套，`now` 写「合并同一个人」。

## 5. 角色卡「成长与结局」

只换 `teardown_card` 提示词第 3 条。字段名还是「成长与结局」，存的地方不变；页面上拆的书把这一栏叫「变化」（任务 2）。

旧书的卡不自动重写，作者要的话用重跑脚本 `settings --force`。

## 6. 拆的书角色顺序

整理设定写完卡以后，在同一个事务里给这本书全部角色写 `characters.position`：

- 主角（`people_of` 算出来的 `protagonist`）为 0；
- 其余按出场章数从多到少，一样多的按第一次出场先后，从 1 往后编。

只写卡、只写一句话的人都排进去。作者自己的书不动。

确认书详情接口里角色是按 `position` 出来的；不是就改成按它排（只改拆的书）。

## 7. 整理精髓

### 7.1 放在收尾哪一步

`finish()` 里收尾的顺序改成：

1. 归篇
2. 写全书结局
3. 整理设定（开头先合并同一个人）
4. 整理读者在等的事
5. **整理精髓**

条件和别的几步一样：不是作者停下，且 `reason in (None, "upto")`。

出错只记下来，不影响前面几步，`stop_note` 加「整理精髓没做完（{原因}），」，后面照现有规矩接「点「{按钮}」再试一次。」。

群聊最后那句，在读者在等的事那句后面加：「整理了精髓：{k} 节、{n} 条知识点，在「精髓」那一页。」。k 是有内容的节数（不含核心要点），n 是各节知识点条数加人物条数。

### 7.2 存法

| 存什么 | 存在哪 |
|---|---|
| 每个过瘾的章的爽点类别 | `chapters.teardown["tags"] = {"tags": [...], "crowd": "", "of": sha1}`；`of` 是「feel＋看点＋摘要」的 sha1 |
| 每个单元拆出来的剧情 | 新迁移 `0025`：`plot_units` 加一列 `teardown JSONB NOT NULL DEFAULT '{}'`；存 `{"plot": {...}, "of": sha1}`，`of` 是这个单元材料块的 sha1 |
| 精髓本身 | `books.teardown["essence"]`，见下面 |

```json
{
  "upto": 100,
  "at": "2026-10-21T08:00:00+00:00",
  "inputs": {"source": "sha1", "scene:打脸": "sha1", "overview": "sha1"},
  "sections": {
    "source": {"name": "情节怎么想", "points": [...], "missing": [...], "fixes": [...]},
    "cast": {"name": "配角与对手", "figures": [...], "points": [...], "missing": [...], "fixes": [...]}
  },
  "overview": {"genre": "...", "engine": "...", "points": [...]},
  "rails": {},
  "failed": false
}
```

- 一条知识点：`{"title", "steps": [...], "evidence", "note", "chapters": [...]}`。
- 一个人物：`{"name", "archetype", "build", "role", "arc", "chapters": [...]}`。
- `rails` 是页面右栏和简介页用的数字，第 7.6 节。
- 样张数据 `docs/界面原型/精髓样张-数据.js` 里的 `essence` 就是接口要返回的样子（除了 `inputs`、`fixes`、`failed` 不上接口），字段名照它。

### 7.3 第一步：爽点分类

- 范围：读过的、`feel` 是爽或大爽、还没有 `tags` 或者 `of` 对不上的章。`feel` 不是爽、大爽的章，有 `tags` 的删掉。
- 按章号排好，80 章一批，一批一次调用：`render("teardown_tags", title=书名, chapters=...)`。
- 每章一行，照 `analyze.py`：`第 {n} 章（{feel}）看点：{看点}｜{摘要前 110 字}`。
- schema `TeardownTags`。检查：这一批每章都要有一条，漏了照现有「上次写得不对」的办法重来，最多三次；三次都不行，这一批的章不写，整步记失败。
- 返回的 `tags` 去掉首尾空白、去重、最多留 3 个。

### 7.4 第二步：逐单元拆剧情

- 单元：这本书全部不虚的单元，按章号先后排，编号 n 从 1 起，跨卷连着编。
- 每个单元的材料块照 `analyze.py` 的 `unit_block()` 拼。人名用名单里的；「第一次出场」照名单的第一次出场；「读者在等的事」照 `foreshadowings`。
- 块的 sha1 和 `plot_units.teardown["of"]` 一样就跳过。
- 要做的单元从最前面一个开始，8 个一批，一次调用：`render("teardown_unitplot", title=书名, units=几块用空行隔开)`。
- schema `TeardownUnitPlots`。检查这一批每个 n 都有；回来的 n 对不上的丢掉。
- 落库：`plot_units.teardown = {"plot": 那一条（不含 n）, "of": sha1}`。

### 7.5 第三步：十二节

节名和顺序（键、节名、提示词）：

| 键 | 节名 | 提示词 |
|---|---|---|
| source | 情节怎么想 | essence_source |
| skeleton | 剧情骨架 | essence_skeleton |
| link | 剧情衔接 | essence_link |
| fresh | 保持新鲜 | essence_fresh |
| longline | 长线布局 | essence_longline |
| setting | 设定设计 | essence_setting |
| shuang | 爽点类型 | essence_shuang |
| scene | 爽点戏怎么写 | essence_scene |
| hero | 主角 | essence_hero |
| cast | 配角与对手 | essence_cast |
| rhythm | 节奏与钩子 | essence_rhythm |
| opening | 开篇 | essence_opening |

**材料**：

- 每节照 `analyze.py` 的 `materials(book, key)` 和它用到的 `feel_facts`、`unit_facts`、`wait_facts`、`returns`、`tag_facts`、`tag_examples`、`plot_line` 拼，逐字照搬（标点、截断长度、上限、「（没有）」这些都一样）。
- 数据换成库里的：章的记录（`chapters.teardown["read"]`、`outline`、`summary`）、爽点类别（7.3）、单元剧情（7.4）、读者在等的事（`foreshadowings`：编号用 `foreshadow_code`；`what` 是 description、`planted`、`hints`、`resolved`，`how` 取 payoff_plan 冒号后面）、主角的卡（`characters`）、名单。
- 主角是 `people_of` 的 `protagonist`；人名、出场章数、第一次和最后一次出场，都按名单（已套 names）。

**调用**：

- 每节一次：`render(提示词, materials=材料)`；schema 是 `EssenceSection`，配角与对手是 `EssenceCast`。
- 用户消息的 sha1 和 `essence.inputs[键]` 一样，并且这一节已经有，就不调。
- 爽点戏怎么写不一样：
  - 取出现章数前 3 的爽点类（`top_tags()`），每类一次调用：`render("essence_scene", tag=类名, materials=scene_material(类名))`；
  - inputs 键是「scene:类名」；
  - 三次的结果按类的顺序合成一节：points 接起来，missing 接起来；
  - 原文从 `chapters.content` 取，`scene_material()` 照抄。

**检查**（不过就照「上次写得不对」重来，最多三次）：

- points 不空；
- 每条 `chapters` 里的章号都在已读的章里；
- 人物的 `chapters` 也查。

**核对**：每一节（爽点戏怎么写除外，它引的是原文，核对时看不到）写完马上核对一次：`render("essence_check", title=书名, section_name=节名, section=section_text(这一节), records=引到的章的记录)`。

- `section_text()` 照 `analyze.py` 抄。
- 引到的章：这一节所有 `chapters` 里的，加上正文里「第 N 章」「N 章」「第 a–b 章」写到的（区间只取 a 到 a+3），去重，按章号排，最多 40 章，没读过的去掉。
- 每章一行：

  ```
  第 {n} 章：{摘要}｜看点：{看点}｜读者在等的事：{立下/提起/兑现：那件事；…（没有写「没有」）}｜新冒出来的：{类「名字」、…（最多 6 个，没有写「没有」）}
  ```

  比试验多了后面两样，试验发现只给摘要和看点时，核对会把伏笔、信物这类对的话误删。
- schema `EssenceSectionChecked`，配角与对手是 `EssenceCastChecked`。检查同上。
- 核对后的内容就是这一节存下的内容，`fixes` 一起存。

整节三次都不行：这一节留旧的（有的话），整步记失败，接着做别的节。

### 7.6 第四步：核心要点和数字

**核心要点**：

- 材料每条一行，照 `analyze.py` 拼：`【节名】{title}｜怎么用：{steps 用「；」接}｜证据：{evidence 前 80 字}（第 {章号区间} 章）`。各节按 7.5 的顺序。
- `render("essence_overview", materials=...)`，schema `EssenceOverview`，检查同上。
- inputs 键「overview」；各节都没变就不调。

**rails**：每次整理精髓最后由程序重算，照 `render_page.py` 的 `rail_data()`：

| 键 | 是什么 |
|---|---|
| feel | 四档各几章 |
| strip | 已读各章的 feel，按章号 |
| tags | 各类爽点出现几章，前 8，`[类, 章数]` |
| crowd | 有旁观者的过瘾章数 |
| hooks | 结尾钩子种类前 6 |
| triggers | 单元起因分布 |
| stakes | 赌注变化分布 |
| units | `[{n, first, last, title}]` |
| tail | 没归单元的最后几章 `[a, b]`，没有就 null |
| waits | `{total, open}` |
| open | 还吊着的最近 4 件 `[{at, what}]`，按立下先后 |
| people | 出场最多的 7 人 `[名字, 章数]` |
| things | 各类设定条数 |
| hero | 主角名字 |
| merges | 合并过的 `[{names, keep, why}]` |

数字都按名单、库里的记录算。

**收尾**：最后写 `essence.upto` 为读过的最后一章、`essence.at`、`failed`。

### 7.7 别的

**并发**：第一、二、三步各自最多 8 个调用同时跑；第三步各节之间也最多 8 个。

**进度**：`runner.progress("essence", essence={"done", "total", "now"})`，`now` 写：

- 「爽点分类」
- 「逐单元拆剧情」
- 节名
- 「核对·{节名}」
- 「核心要点」

`total` 开跑时按要调的次数估。

**needs_closing**：加一条，放在第 6 条（arcs.failed）后面：`essence` 没有、或者 `essence.upto < last`、或者 `essence.failed` 为真，就是真。

**teardown_summary**：

- 去掉 `merits`；
- 加 `"essence": {"upto": essence.upto, "points": n} | None`，n 同 7.1。

### 7.8 「这本书好在哪」不要了

- `collect_settings` 不再调「这本书好在哪」；`merits_only`、`estimate_calls` 里的这部分去掉。
- `teardown_merits.md` 和目录删掉；`teardown_facts.build_facts` 没人用了就删。
- 旧书 `books.teardown["merits"]` 留着不动，也不再读。
- 重跑脚本的 `merits` 步骤去掉（第 11 节）。

## 8. 提速（读原文还是 4 个一起跑，不动）

1. **整理设定 8 个一起跑**：`collect_settings` 的并发从 4 改 8。整理精髓见 7.7。
2. **读者在等的事边读边记**：
   - 时机：`Runner.grouping()` 每轮归完单元和卷以后，如果从 `waits.upto` 往后已经有凑满的一段，就记这一段。「凑满」是 `wait_batches` 照现有规矩切出来、不是最后剩下的那一段（满 80 章或者满 150 条），并且这一段最后一章之前的章都读过了。
   - 记法和收尾时一样，直接用 `collect_waits` 那套，分段规矩完全不变，保证边读边记和收尾时记，切出来的段一模一样。
   - 边读时这一段出错：只记日志，不停下读原文，也不再试这一段；收尾时照现有规矩从 `waits.upto` 接着记。
   - 作者点停下照常停。
3. **多开一个拆书工作进程**：
   - `start.ps1`／`stop.ps1` 照现有 `teardown@%h` 再起一个 `teardown2@%h`，同样 `-P solo -Q teardown`，日志 `teardown2.log`、`teardown2.err.log`。
   - 两本书就能同时拆，同一本书照现有任务锁挡住。
   - 两个进程同时起来时，捡断掉的活不能把同一个任务跑两遍：现有任务锁挡得住就写测试证明，挡不住就修。
   - 日常的 start／stop 不要实际执行，照之前的办法在独立资源里验。

## 9. 接口

**`GET /api/books/{id}/teardown/essence`**（放在 `teardown_digest` 一起）：

- 不是拆的书：404，照现有拆书接口的话。
- 返回 `{"essence": null}` 或者 `{"essence": {"upto", "at", "overview", "sections", "rails"}}`。
- `sections` 只放有内容的节，每节 `{name, points, figures?, missing}`，不返回 `fixes`、`inputs`、`failed`。
- 字段和 `docs/界面原型/精髓样张-数据.js` 的 `essence` 完全一样。

**书详情、书架**：`teardown.essence` 见 7.7。

## 12. schema（`app/agents/schemas.py`，字段顺序、描述照抄）

```python
class TeardownMergeGroup(BaseModel):
    names: list[str]
    keep: str
    why: str = Field(description="第几章怎么看出来是同一个人，40 字以内")

class TeardownMerge(BaseModel):
    groups: list[TeardownMergeGroup] = Field(default_factory=list)

class TeardownTag(BaseModel):
    index: int
    tags: list[str] = Field(description="1-3 个爽点类别，最主要的在前")
    crowd: str = Field("", description="被谁的反应放大，没有空着")

class TeardownTags(BaseModel):
    chapters: list[TeardownTag]

class TeardownUnitPlot(BaseModel):
    n: int
    trigger_type: Literal["前事的后果", "早先埋下的事发作", "换了新地方新局面", "有人找上门", "主角自己要做", "意外撞上"]
    trigger: str = Field(description="具体是哪件事引出来的，40 字以内")
    shape: list[str] = Field(description="起承转合 4-6 步，每步 20 字以内")
    payoff: str = Field(description="「哪一种：哪一下」，40 字以内")
    new: list[str] = Field(default_factory=list)
    changed: list[str] = Field(default_factory=list)
    stakes: Literal["更大", "差不多", "更小"]
    stakes_note: str = ""
    hook_out: str = ""
    seeds: str = ""

class TeardownUnitPlots(BaseModel):
    units: list[TeardownUnitPlot]

class EssencePoint(BaseModel):
    title: str = Field(description="「招式名：一句话说清这一招」，30 字以内，不写人名事件")
    steps: list[str] = Field(description="怎么用，2-5 步，每步 25 字以内，能照着做的动作")
    evidence: str = Field(description="这本书里的证据：用了几次＋两三个例子，80 字以内")
    note: str = Field("", description="什么时候用、要注意什么，40 字以内，没有空着")
    chapters: list[int] = Field(description="证据章号，从小到大，3-8 个")

class EssenceSection(BaseModel):
    points: list[EssencePoint]
    missing: list[str] = Field(default_factory=list, description="想写却缺记录、看不出来的")

class EssenceFigure(BaseModel):
    name: str
    archetype: str = Field(description="人设模板，网文读者常说的叫法，2-8 个字")
    build: str = Field(description="作者用哪几招把这个人设立起来，80 字以内")
    role: str = Field(description="在剧情里起什么作用，60 字以内")
    arc: str = Field("", description="自己或者和主角的关系怎么变，没变写空")
    chapters: list[int]

class EssenceCast(BaseModel):
    figures: list[EssenceFigure]
    points: list[EssencePoint]
    missing: list[str] = Field(default_factory=list)

class EssenceSectionChecked(EssenceSection):
    fixes: list[str] = Field(default_factory=list, description="改了什么，一句一条；没改空着")

class EssenceCastChecked(EssenceCast):
    fixes: list[str] = Field(default_factory=list, description="改了什么，一句一条；没改空着")

class EssenceOverview(BaseModel):
    genre: str = Field(description="一句话：这是一本什么书、读者追它主要图什么，40 字以内")
    engine: str = Field(description="一句话：这本书靠什么让人一直追下去，60 字以内")
    points: list[EssencePoint]
```

演示模型（`demo_teardown`）给这些 schema 都要能回合格的结构（只要结构对，内容按记录随便拼）。
