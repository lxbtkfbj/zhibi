# 拆书精髓：精髓、拆书质量、精髓页

产品规则以 `docs/设计说明.md` 第 14 节为准，这一包的概要在第 14.5 节第 6 条。试验脚本和结果在 `docs/拆书/精髓试验/`，样张是 `docs/界面原型/精髓样张.html`。本目录是交给 Codex 的实施任务：按顺序做，一次一个任务，前一个做完并提交后再开下一个。

一句话概括这一包：「这本书好在哪」换成「精髓」，也就是一条条能直接拿来用的知识点，剧情最重要，其次设定、爽点、人物。顺带提高拆书质量（通用版逐章记、写卡前合并同一个人），提速，并新加精髓页、重排拆的书的简介页、修设定页几处小毛病，编辑部按钮换成朱砂印章。

> 状态：任务 1 后台、任务 2 页面均已实现；全量检查、精髓 28 组与装修 16 组比对及交互验收见 `docs/拆书精髓验收.md`（2026-10-21）。

## 共同约定（每个任务都适用）

这一包只照本文件，不再照 `docs/codex任务/新书页装修/README.md`：那份里不改提示词、不调模型、验收文档、提交前缀这些是装修那次专用的。

1. **先读后做**：先读设计说明第 14 节、本文件和任务文件。任务 1 再看 `docs/拆书/精髓试验/`（`analyze.py`、`render_page.py`、`make_sample.py`、`common.py`）；任务 2 再看样张 `docs/界面原型/精髓样张.html`，14 页都在浏览器里点一遍。
2. **冲突怎么办**：
   - 页面的样子以样张为准，其次任务文件；其余以任务文件为准，其次设计说明。冲突在完成说明里指出。
   - 任务文件自己前后打架、和现有代码对不上、跑不通、样张没画到又拿不准：停下来问，不要自己挑。
3. **开工前工作区要干净**：`git status` 不干净就停下来问作者，不要动、也不要替别人提交没提交的改动。
4. **字**：
   - 界面文字、提示词、schema 描述一律用简体中文。
   - 任务文件和样张里写死的字一个不改。
   - 没写到、你自己补的字，列进验收说明。
5. **提示词由设计方提供**：
   - 本目录 `提示词/` 下 20 份，任务 1 用 `git mv -f` 原样搬进 `backend/app/prompts/`，逐字节一致；目录登记照任务 1 第 2 节。
   - 任务 2 不碰 `backend/app/prompts/`。
6. **schema 描述就是提示词**：任务 1 第 12 节的类和 `Field(description=...)` 逐字照抄，字段顺序也照抄。
7. **作者自己的书**：
   - 只改任务文件写明的几处：目录点了能收起、主角排在置顶的后面、编辑部按钮。别的一点不变。
   - 凡是加了「是不是拆的书」判断的地方，作者自己的书走原来的路。
8. **演示模式**：`app/llm/demo.py` 补齐新 schema，没有 Key 也能把一本书从头拆到尾、整理出精髓（章号在读过的范围里，能过程序检查）。
9. **不碰作者的服务和书库**：
   - 不要升级、重启或改动作者日常的 8000／4320 服务、日常 worker 和书库，不要对日常环境运行 `start.ps1`／`stop.ps1`。
   - 验收一律用书库的只读副本和独立的数据库、Redis 库、端口、worker；测试文件（含原文）不进 git。
10. **真模型**：
    - 只在作者在「给Codex的话」里同意的那一处用。任务 1 是【Alicia】gemini-3.8-flash 在《逆天邪神》副本上「只整理」一次，大约 50 次调用，只跑一次。
    - 只读取日常库里的模型配置，不打印密钥；不要用作者的官方 DeepSeek 配置。
    - 任务 2 不调真实模型。
11. **检查命令**：开发中只跑相关测试；提交前跑一次全量，全部通过才算完成。
    - 后端（`backend/`）：`uv run ruff check . && uv run ruff format --check . && uv run pytest -q`
    - 前端（`frontend/`）：`npx tsc -b && npm run lint && npm run build && npm run test:workspace`
12. **页面比对**：
    - 任务 1 不碰前端，不用跑页面比对。去掉「这本书好在哪」以后，旧简介页那一块会空着，等任务 2 换成新简介页。
    - 任务 2 要过两套比对：
      - 精髓样张那套 28 组（任务 2 第 0.4 节）；
      - 装修那套（`frontend/tests/desk-v2-parity.browser.mjs`）。装修这套的 `VIEWS` 去掉「简介」，因为新简介页归精髓样张那套比；其余 8 页 × 两种尺寸照样要过。
    - 装修样张已经由设计方改成新样子：顶栏多了「精髓」、编辑部印章按钮、拆的书角色卡「变化」。所以装修这套不加新的遮挡、不放宽阈值。
13. **验收**：
    - 照任务文件最后一节做，结果写进 `docs/拆书精髓验收.md`：任务 1 先写，任务 2 接在后面。
    - 截图、比对图、导出的精髓放 `docs/拆书精髓验收/`，少而准。
14. **文档同步**：任务完成后，在设计说明第 14 节标题的状态里写明哪些已实现；实现时和设计说明说法不一样的地方，在第 14.5 节第 6 条后面补一小段「精髓实现（任务 N）」。
15. **分支与提交**：直接在当前分支（feat/setup-interview-spine）上做，不推送。提交信息以「拆书精髓：」开头。
16. **完成说明**：做完后用一段中文告诉作者以下几项：
    - 改了什么、迁移做了什么；
