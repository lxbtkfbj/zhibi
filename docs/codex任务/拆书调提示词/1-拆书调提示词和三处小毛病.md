# 拆书调提示词：攒下的毛病一起改，外加三处界面小毛病

## 0. 共同约定

1. 开工先看 `git status`。这个目录别的会话也在用：工作区有不是你改的、还没提交的改动，先停下来问；提交时只提交你自己改的文件。
2. 不碰作者的日常服务和书库：8000、4320 端口的进程，日常 worker，`zhibi-postgres-1` 里的 `zhibi` 库，6380 的 Redis。不运行 `scripts/start.ps1`、`scripts/stop.ps1`。测试用自己起的库和 Redis。
3. 不调真实模型。要模型回话的地方用演示模型或测试替身。
4. 提示词照本目录 `提示词/` 里的 8 份副本，逐字节一致：用 `git mv -f` 盖掉 `backend/app/prompts/` 下的同名文件。别的提示词一个字不改。
5. 第 3 节程序里的字、第 5 节界面上的字，逐字照本文件。
6. 本文件没写到、要你自己定的事，写进验收说明的「自行决定」。会改变作者看到的字、或者要动别的提示词的，先停下来问。
7. 检查：后端全量、前端全量（TypeScript、lint、build、workspace）；精髓 28 组、装修 16 组页面比对，照原样张、原阈值、原遮挡。
8. 验收写在 `docs/拆书调提示词验收.md`；一次提交，提交信息以「拆书调提示词：」开头，不推送。最后给我一段中文完成说明。

## 1. 为什么改

作者已经拆完三本书：《我有一座冒险屋》1210 章、《惊悚乐园》1520 章、《逆天邪神》2200 章。拿书库里的结果对过，攒下的毛病大多还在：

- **别称乱收**，三本都很严重：
  - 收了泛称和头衔：「仙子」挂在四个人身上，「本尊」「老夫」各挂了三四个；
  - 收了亲属称呼：「家父」「二叔」「大哥」；
  - 收了这个人喊别人的叫法：大家喊封不觉「疯兄」，「疯兄」却挂到了另外四个人身上；「小陈」挂到了张雅母亲身上。
- **认人**：
  - 没露名字的人只记成「老者」，几个不同的老人被当成了同一个人；
  - 有名字的人用称号当了名字：「惊雷界王」是称号，他的名字「厉道谙」反倒被当成了别称。
- **金手指混进了别的东西**：
  - 冒险屋 42 条里，真正的外挂只有黑色手机和几样能力，其余是试炼任务、恐怖屋场景，还有一个人（许音）；
  - 惊悚乐园混进了游戏任务目标，比如「杀死灰胡子船长」；
  - 逆天邪神混进了别人的体质血脉，比如夏元霸的霸皇神脉、夏倾月的九玄玲珑体；
  - 冒险屋的「黑色手机」，第一次出现记成了第 904 章。
- **等级**：
  - 逆天邪神一套玄力等级，只有两级写了主角第几章到。原因是交给模型的「主角各章的变化」是从一千多条里均匀挑的 120 条，突破的那几章大多被挑掉了；
  - 有的说明写成了「原文未记载晋升机制」这种讲记录的话，有的写成「凡器之上的玄器品级」这种空话。
- **秘密的揭开章对不上**：逆天邪神里「云澈的亲生父母」「刺杀萧鹰的凶手」都写着「到第 2200 章还没揭开」，可读者在等的事那本账里，第 297 章、第 344 章就记着揭开了。原因是：
  - 埋下和揭开在原文里常常不是一个叫法；
  - 整理秘密时按名字分组、60 样一批，两头对不上。
- **读者在等的事**：
  - 路线变了，事件名没跟着变：「寻找焚魂花为苍万壑解蛊」最后没用焚魂花；
  - 两件事并成了一件：「达君玄境，重塑茉莉肉身」；
  - 大谜团只露了一角，就算成了揭开：冒险屋第 182 章只是给了个提示，「陈歌父母失踪的真相」就被记成兑现了。
- **精髓**：
  - 节奏一节把统计数字写成了铁律：「最长连着憋了 9 章」写成「受压不超九章」，「平均隔 1.8 章」写成「间隔绝不超过两章」；
  - 原文里还出现了「全书模型判憋屈仅 184 章」这样的话；
  - 核心要点第 6 条几乎原样照抄了节奏一节的一条；
  - 「兑现 217 件且全部无缝接力」这种说满了的话，核对那一步没拦住。

## 4. 程序改动

### 4.1 别称过滤

拆的书写角色时，别称再过一遍程序。整理设定写角色的地方、合并同一个人写角色的地方，都要过。不管这一轮有没有重新调模型写卡，整理设定最后都过一遍整本书。去掉三种：

1. 同一本书里两个及以上角色都有的别称：谁都能叫，就不是专指谁；
2. 等于同一本书里另一个角色名字的别称；
3. 下面这张表里的字。这是自称、纯亲属称呼，还有表示「没有」的字，不是谁的别称：
   老夫、老朽、老衲、贫道、本尊、本座、本王、本宫、本少、本公子、本小姐、本姑娘、小王、在下、晚辈、属下、末将、奴婢、朕、哀家、小女子、家父、家母、爸、妈、爹、娘、父亲、母亲、爷爷、奶奶、外公、外婆、儿子、女儿、哥哥、姐姐、弟弟、妹妹、老公、老婆、媳妇、夫君、娘子、相公、无、没有、暂无

作者自己改过、锁住的角色，照现有的保护规矩不动。只管拆的书，作者自己的书不动。拆书读原文时用的名单（`teardown_roster.py`）不在这次改的范围里，照旧。

### 4.2 等级：主角各章的变化怎么挑

`world_context` 里等级那一段，现在从主角所有 change 里均匀挑 120 条。改成：

- 先挑写到实力、等级变化的：change 里出现「突破」「晋升」「升到」「升至」「踏入」「达到」「境」「级」「阶」中任何一个的。这类超过 120 条，就在这类里均匀挑 120 条，首尾保留，用现成的 `evenly`。
- 不到 120 条，就用剩下的 change 均匀补满 120 条。
- 输出照章号从小到大排，开头那行「主角各章的变化：」和每行的格式照旧。

### 4.3 秘密：带上读者在等的事里的伏笔

整理秘密时，`{{context}}` 里带上这本书「读者在等的事」里种类是伏笔的那些：

```
读者在等的事里的伏笔（第几章立下｜第几章揭开｜那件事｜怎么揭开的）：
- 第 3 章立下｜第 344 章揭开｜刺杀萧鹰与毁掉萧澈玄脉的真凶｜云澈告知萧烈当年杀害萧鹰的真凶来自圣地天威剑域
- 第 1 章立下｜还没揭开｜陈歌父母失踪的真相｜
```

- 只列第几章立下不晚于这次整理到的那一章的；揭开晚于这次整理到的那一章，当还没揭开。
- 按立下的章号排。超过 200 件，均匀挑 200 件，首尾保留。
- 「怎么揭开的」用那件事记下的了结那句话，去掉开头的「第 N 章：」。
- 一件都没有，写「读者在等的事里的伏笔：（没有）」。
- 每一批秘密都带上同一份。

## 5. 三处界面小毛病

1. **设定总览窄的时候，卡片标题挤成两行**。浏览器 1024 宽时，冒险屋的「角色列表」被旁边那行「123 人，其中 40 人写了全卡」挤成了两行。
   - 在 `frontend/src/styles/desk-v2-host.css`，把现在只给多套等级那张卡的 `.desk-v2 .tiles .settings-many-ladders .hd > b { flex-shrink: 0; }`，推广到每张卡的标题：标题不缩、不换行；旁边那行字可以换行。
   - `desk-v2.css` 要和精髓样张逐字一致，不能动。
2. **等级体系没写说明时，标题行末尾多一个「·」**（比如「陈家境界 · 0 级 ·」）。在 `frontend/src/pages/workspace/desk-v2/SettingsPages.tsx` 第 161 行：
   - 有说明的照旧，写成「名字 · N 级 · 说明」；
   - 没有说明的写「名字 · N 级」，后面不加「 · 」；
   - 鼠标停上去显示的 title 照旧显示说明。
3. **「在翻《开书》」少了省略号**。回答框里那一行，别的都是「在查陈默……」这样带「……」，只有翻手册的不带。在 `backend/app/services/chat_agent.py` 第 150 行去掉对 `ReadSkill` 的例外，显示「在翻《开书》……」。钉着旧字的测试照新的改。
