# 预设管理 任务 1：后台——预设怎么存、怎么拼，主编群聊改用预设

共同约定照本目录的 `README.md`。设计在 `docs/设计说明.md` 10.7「预设管理」。

## 为什么做

10-27 作者说提示词字写得多、质量低，也不知道这些提示词是哪来的，要一个预设管理系统，照他另一个项目的样子：发给模型的提示词由一块一块的「预设块」组成，块能开关、能排先后、能改；系统自带的预设锁着，要改就复制一份；程序的数据用占位符插进块里。

查了主编在群聊里每回一句要读的说明：五份提示词（主编人设、主编口吻和口吻怎么用、群聊：自己查、自己动手、聊天的做法、通用规则）加两段写死在程序里的话（`ACT_RULE`、`ASK_RULE`），由 `chat_prompts.system_prompt` 拼起来，约 5300 字。其中真正离不开的约 2300 字。作者和设计方逐块定下了默认预设：十九块，见本目录 `系统预设/chief_group/v1/`。

## 1. 这次只管哪一条

只管「主编群聊」：
- 作者自己写的书（`book.source != "teardown"`）；
- 在群聊里；
- 主编来答（`payload.chat_role` 是 `chief` 或者没写）；
- 走 `chat_agent.answer_note` 的那条（能调工具），包括重试（`retry=True`）。

下面这些一个字都不变，照旧用老提示词：拆的书的群聊（`chat_teardown`）、私聊和重新回答只重写（`chat_reply`）、调不了工具时的 `fall_back`、点名设定师写手审稿的、方案卡、分流、对话摘要、写书的各样活。

## 2. 系统预设放在仓库里

- 把本目录 `系统预设/chief_group/` 整个 `git mv` 到 `backend/app/presets/chief_group/`，逐字节一样。每个文件的 sha256 写在本目录 `系统预设/指纹.json`，把这份 json 原样挪到 `backend/tests/preset_hashes.json`，测试照它核。
- 每一版一个目录：`v1/`、以后的 `v2/`……。目录里一份 `preset.json`，每块一个 `<id>.md`。
- `preset.json` 的字段：
  - `kind`：预设种类，这次只有 `chief_group`；`kind_label`：给作者看的名字「主编群聊」。
  - `name`：预设名字；`version`：第几版；`date`：哪天出的；`note`：这一版改了什么、为什么。
  - `blocks`：按发送的先后排，每块：
    - `id`：块的记号（文件名就是 `<id>.md`），复制给作者以后也不变，用来认哪块是系统的、哪块必须；
    - `title`：标题；
    - `role`：`system`、`user` 或 `assistant`；
    - `enabled`：默认开不开；
    - `required`：是不是必须的块；
    - `when`：什么时候发，见第 4 节；
    - `without`：关了这块会怎样，一句话，检查时提醒作者用；
    - `origin`：这块是哪来的；以后的版本这块改了的，另加 `change`：这一版改了什么、为什么。
- 块的内容就是 `<id>.md` 的全文，去掉最后的换行。
- 读法：跟提示词一样用 `importlib.resources` 随程序发布，读出来可以缓存。版本号最大的是「最新版」，旧的版本只读，能看。
- 以后出新版是设计方的事：整份复制成 `v2/`，改要改的块，写 `change`。程序不用为出新版做别的。

## 3. 占位符

块里用 `{{名字}}` 插程序的数据，名字是中文。认法和 `app.prompts.VARIABLE` 一样（`\{\{(\w+)\}\}`）。主编群聊的占位符就这十四个，值就是今天 `agent_values` 加 `material_values(values, template="chat_agent")` 算出来的那些字，一个字都不变，只是换个地方放：

| 占位符 | 给作者看的说明 | 今天从哪来 |
|---|---|---|
| `资料说明` | 书大的时候是一句「（书比较大：设定和大纲只列了目录，要细节用工具查）」，书小的时候是空的 | `material_note` |
| `简介` | 这本书的简介，包在 `<简介>` 里 | `book`（`tagged("简介", concept)`） |
| `设定库` | 设定库：书小给全文，书大只列名字和一句话 | `library` |
| `大纲` | 大纲：书小给全文，书大只给目录 | `outline` |
| `写到哪了` | 写到第几章、在开书还是在写，包在 `<写到哪了>` 里 | `progress` |
| `正在看的那一页` | 作者发话时正在看哪一页，包在 `<作者正在看的那一页>` 里 | `viewing` |
| `等你确认的` | 编辑部停下来等作者拍板的内容；没有就是空的 | `pending` |
| `编辑部正在干活` | 编辑部正在写书时的一段提醒；没在写就是空的 | `working` |
| `记忆` | 记忆目录，包在 `<记忆>` 里 | `memory` |
| `之前聊过` | 太长时缩成的摘要；没有就是「（没有）」 | `summary` |
| `聊天记录` | 摘要以后的聊天原话，一条一行 | `recent` |
| `选中的原文` | 作者选中让主编看的那段原文；没有就是空的 | `quote` |
| `上次做到一半` | 重试时上回已经做完的；不是重试就是空的 | `retry` |
| `作者这次说的` | 作者这次说的那句话 | `note` |

## 4. 什么时候发

块的 `when` 只能是下面几种，由程序每次判断。这几种和 `chat_tools.tool_specs` 给不给那个工具一一对上，免得块里讲了一个这次根本没有的工具：

| when | 给作者看的说法 | 程序怎么判断 |
|---|---|---|
| `always` | 每次都发 | — |
| `can_act` | 能动手时 | 不是只读（`read_only` 为假），有 `make_changes` |
| `ask_only` | 只问不改时 | 只读（作者点了「只问不改」） |
| `skills` | 有手册时 | 给了 `read_skill`（`allow_skills` 而且 `handbooks.tool_spec()` 不是空的） |
| `teardowns` | 有拆过的书时 | 给了 `look_up_teardown`（拆书目录不是空的） |
| `web` | 配了联网时 | 给了 `search_web`（`web` 不是 `None`） |

## 5. 发出去之前怎么拼

1. 取正在用的那份预设（第 6 节）。
2. 按先后取块，跳过关着的，跳过 `when` 这次对不上的。
3. 换占位符：一次替换，值里要是带着 `{{…}}`，不再换第二遍（和 `app.prompts.render` 一样）。不认识的名字原样留着。换完把连着的三个以上换行压成两个，去掉前后空白；换完是空的块不发。
4. 合成消息：
   - 所有 `system` 的块按先后合成一条 system 消息，块和块之间空一行，放在最前面；
   - `user`、`assistant` 的块按先后排，挨着的同一种合成一条，块和块之间空一行。
5. 交给 `router.tool_rounds`：它现在只收 `system`、`user` 两段，改成也能收一串消息（参数叫什么、怎么兼容老的调用，自己定）。工具、来回、最后一来回不许调工具、记用量，这些都不变。
6. 记调用（`llm_calls.request`）：
   - 照旧有 `system`（合好的那条）和 `user`（其余的消息按先后接起来，中间空一行；有 `assistant` 的，在它前面单独一行写「【assistant】」），调用详情页照旧能看；
   - 另加 `messages`：第一来回真正发出去的那一串，每条 `{"role": …, "content": …}`；
   - 另加 `preset`：`{"kind": "chief_group", "source": "system" 或 "mine", "id": 作者预设的 id（系统的不写）, "name": …, "version": 系统预设第几版，或者作者预设第几次保存, "blocks": [这一次真发了的块，每块 {"id", "title", "role"}]}`；
   - `prompt_names`、`prompt_parts` 照现在的算法算，不特意改。

默认预设拼出来的样子：
- system 是块 1～13 里这次该发的，不带默认关着的「怎么想问题」「聊天的四件事」；
- user 是「书的资料」「记忆目录」「聊天记录」「作者这次说的」四块合成的一条。

user 里资料的字和今天 `chat_material` 填进去的是同一些字，只是先后有一处不一样：「记忆」从「写到哪了」后面挪到了「编辑部正在干活」后面。

## 6. 作者的预设、正在用哪一份

**新表**（迁移 `0031_presets`）：
- `presets`：`id`（uuid）、`kind`、`name`、`based_on`（jsonb：从系统预设复制的写 `{"source": "system", "version": 1}`，从作者另一份复制的写 `{"source": "mine", "id": …, "saved": 第几次保存}`，导入的写 `{"source": "import"}`）、`blocks`（jsonb，每块 `{"id", "title", "role", "enabled", "required", "when", "content"}`）、`saved`（保存过几次）、`created_at`、`updated_at`。
- `preset_saves`：`id`、`preset_id`（删预设时一起删）、`saved`（第几次保存，从 1 起）、`name`、`blocks`、`saved_at`。新建、复制、导入也算第 1 次保存。

**复制**：块的全文、`id`、`title`、`role`、`enabled`、`required`、`when` 都带过去。作者自己新加的块，`id` 由程序生成（不跟系统的撞），`required` 是假。

**正在用**：
- 存在 `app_settings`，key 是 `active_preset.chief_group`，值是 `{"source": "system"}` 或 `{"source": "mine", "id": …}`。没有这一行，就是用系统预设。所有书共用这一份。
- 用系统预设时，跟着最新版走：设计方出了 `v2`，就自动用 `v2`。
- 作者的预设不会跟着系统预设变。

**删除**：正在用的那份不让删（409「这份正在用，先换一份再删」）。

## 7. 检查

检查一份预设（块的清单），给出一串问题，每条写清严重不严重、哪一块、怎么回事：

- **不让用**：没有一块开着、又不是只在「只问不改时」发的块里写了 `{{作者这次说的}}`。说法：「没有一块放了 {{作者这次说的}}，主编看不到你这次说的话。」
- **提醒**：
  - 必须的块（`required`）关了或者删了：用那块的 `without` 说，比如「关了『工具：翻手册』：主编不会翻手册，手册放着没用。」
  - 占位符名字不认识：「『{{设定}}』不是占位符，发出去会原样露出来。」
  - 块是空的：「这一块是空的，发不出去。」
  - 开着的块里，`assistant` 排在最后：「最后一条是 assistant，模型可能不接着回；最后一条最好是 user。」

什么时候拦：
- 设为正在用时，有「不让用」就拦下（422，带上问题清单）；只有「提醒」照样能用。
- 保存不拦，没写完的也能存。

## 8. 接口

前缀 `/api/presets`。名字照这个，参数和返回的细节自己定，任务 2 的页面用得上就行：

- `GET /api/presets?kind=chief_group`：种类列表（这次只有主编群聊）、正在用哪份、系统预设的最新版和每一版的号、日期、说明、作者的预设列表（名字、从哪来、几块、开着几块、保存过几次、改的时间）。
- `GET /api/presets/system/chief_group?version=N`：系统预设的某一版（不给就是最新版），每块带全文和 `without`、`origin`；再给每块一份「来历」：从第 1 版到这一版，这块哪几版改过（字变了的那几版），每回的 `change`（第 1 版是 `origin`）。
- `GET /api/presets/mine/{id}`：作者的一份，带块、保存过几次、从哪来；系统预设出了比它所依据的那版更新的版本，就带上 `system_newer`（新版的号、日期、说明）。
- `POST /api/presets/mine`：新建或复制。从系统预设的哪一版、或者作者的哪一份复制；不给就从系统预设最新版复制。名字不给就叫「我的主编群聊 1」「我的主编群聊 2」……挑第一个没被用过的。
- `PUT /api/presets/mine/{id}`：保存名字和块，存一次 `preset_saves`，返回这份预设和检查结果。
- `DELETE /api/presets/mine/{id}`：正在用的不让删。
- `GET /api/presets/mine/{id}/saves`：保存记录；`GET …/saves/{n}`：某一次保存的块；`POST …/saves/{n}/restore`：退回到那一次（退回本身也算一次新的保存）。
- `PUT /api/presets/active`：`{"kind", "source", "id"}`，先检查，有「不让用」就 422。
- `POST /api/presets/check`：传块的清单，回问题清单，页面上改到一半也能查。
- `GET /api/presets/placeholders?kind=chief_group&book_id=…`：占位符清单。每个占位符给名字、说明（第 3 节那一栏），带了 `book_id` 的再给一段「现在大概是什么样」：
  - `简介`、`设定库`、`大纲`、`写到哪了`、`记忆`、`之前聊过`、`聊天记录`（取这本书最近聊的那一段对话），照发的时候的算法算，截前 300 字，后面接「……」；
  - `资料说明`、`等你确认的`、`编辑部正在干活` 照现在的状态算，空的就写「（现在是空的）」；
  - `正在看的那一页`、`选中的原文`、`上次做到一半`、`作者这次说的` 写「发的时候才有」。
- `GET /api/presets/conditions`：第 4 节的几种 `when` 和说法。
- `GET /api/presets/mine/{id}/export`、`GET /api/presets/system/chief_group/export?version=N`：导出成一个 json 文件，文件名用预设名字，内容 `{"format": "zhibi-preset", "format_version": 1, "kind", "name", "blocks"}`。
- `POST /api/presets/import`：传这样一个文件，新建一份作者的预设。种类不对、格式不对、块的 `role` 或 `when` 不认识，回 422，说清哪儿不对。

## 10. 测试

**有意改了、旧测试还认旧样子的**（照 README 第 5 条，照新样子改，不算放宽）：
- 认主编群聊系统提示原文、指纹、手册目录开头的测试，比如 `test_chat_prompt_layers.py`、`test_teardown_lookup_demo.py`（第 3 条的基线）、`test_web_search_demo.py`、`test_handbooks.py`（目录多了「写书的标准」）。主编群聊的系统提示从此由预设拼，改成认预设拼出来的样子。
- `catalog.py` 那几句说明改了，认旧说明的测试跟上。

**新测试**：
1. 系统预设和新手册的文件，sha256 和 `tests/preset_hashes.json` 一样。
2. 用默认预设拼：
   - 能动手、配了联网、有拆过的书的时候，system 里依次是块「角色」到「做完怎么说」，不带「只问不改」和默认关着的两块，块和块之间空一行；
   - user 一条，资料的字和今天 `chat_material` 那几段的字一样，只是记忆挪了位置。
3. 什么时候发：没配联网不发「工具：上网搜」；只问不改时发「只问不改」、不发「动手改书」；没有拆过的书时不发「工具：查拆过的书」；没有手册时不发「工具：翻手册」。每种都对上 `tool_specs` 给不给那个工具。
4. 占位符：一次替换、不认识的原样留、空块不发、连着的空行压成一个、值里的 `{{…}}` 不再换。
5. 作者的预设：复制、保存存一次、看某一次保存、退回、删除（正在用的不让删）、导出再导入一模一样、坏文件 422。
6. 正在用：设为正在用（有「不让用」的拦下）；没有设置时用系统预设最新版；所有书都用这一份。假装出了 `v2`（测试里临时放一个目录），系统预设正在用时自动用 `v2`，作者的那份不变，并且带上 `system_newer`。
7. 检查：第 7 节每一条都有一个测试。
8. 记调用：主编群聊的调用记录里有 `messages`、`preset`，`system`、`user` 照第 5 节第 6 条拼。
9. 别的路一个字不变：拆的书的群聊、私聊、重新回答只重写、`fall_back`、点名设定师，发出去的 system 和 user，和开工时 HEAD 拼出来的逐字比，一样。
10. 演示模型下，主编群聊「自己查、自己动手」照常：查资料、记忆、动手改书、方案卡、重试。
