# 聊天记性 任务 1：整段聊天原文给编辑部

共同约定照本目录的 `README.md`。设计在 `docs/设计说明.md` 9.13「聊天的记性：整段原文给编辑部」。

## 为什么做

10-27 作者问：主编的建议为什么总是不行。查了《佔位》（413c96ac）那段群聊（conv efeebc46，10-24 到 10-27 凌晨），发现编辑部回答时看到的聊天记录剪了三刀，都在 `chat_context.dialogue_text` 和 `chat.merge_summary`：

1. 每条消息只留前 800 字，后面接「……」。主编的回答常常一千多字，后半截往往是它给作者列的几个方案，它自己就看不到了。
2. 最近 20 条加起来最多 6000 字，超了从最早的丢，大约只剩 7 个来回。
3. 再早的要攒够 10 条，才由设定师缩成 300 字的摘要，中间漏一截，两头都没有：llm_calls 3206 里，#587–#594、#607、#608 既不在摘要里，也不在最近的对话里。缩的时候又不分是谁说的：3203 那次把主编 10-24 凌晨自己提的「废除医毒，改为看穿修补功法规则漏洞的一技之长」写成了「已定结论」，作者从没答应过。主编因此一连几轮想办法把医术换掉，作者只好问「当初是为了什么」。

作者说：模型有 1M 的上下文，为什么不用起来；别动不动就截断，这套要重新设计。现在主编回一句，一次请求总共约 1.6 万 token，还不到百分之二。作者库里最长的一段对话（就是上面这段，三天）不算撤回的才 2.2 万字。

作者定的：一段对话的原话全给编辑部，太长了才把最早的缩成摘要；缩的时候分清谁说的、作者答应了没有。

## 1. 新的规矩

作者在界面上看不到变化，变的是编辑部回答时看到什么。

### 1.1 一段对话的原话全给

- 「一段对话」怎么取照旧：`chat_context.dialogue` 不改。群聊是那一段（`conv`），私聊是换个话题以后的；撤回的（`dropped`）、还在写的、没答上来的不算；作者把书换回存档那一行算。
- 每条照旧一行 `名字：内容` 加 `done_note`，内容一个字不剪：去掉 800 字截断和后面的「……」。
- 摘要以后的原话（`id > summarized_until`）全部给，不按条数丢，也不按字数丢。去掉的有：回答的最近 20 条和 6000 字，方案卡的 30 条和 12000 字，分流的最近 6 条。

### 1.2 太长了才缩

两个常量放在 `chat_context.py`，测试里能改：

```python
HISTORY_LIMIT = 150_000  # 摘要以后的原话超过这么多字，才把最早的缩进摘要
HISTORY_KEEP = 100_000  # 缩完以后，原话剩这么多字以内
```

字数用 `len()` 量 `dialogue_text` 拼出来的那段字。

**回答和方案卡**：下面六条路都用同一套，写成一个函数，六条路都调它，函数叫什么、放在哪个文件自己定。
1. 群聊，自己查、自己动手（`chat_agent.answer_note`，拆的书也走这里，经 `agent_values` 到 `teardown_chat.values`）；
2. 群聊调不了工具、改走只说话的那条（`chat_agent.fall_back` 里交给 `chat.answer` 的那段）；
3. 私聊，以及模型调不了工具时的群聊（`chat.reply_background`）；
4. 重新回答只重写、重试（`chat.again_background`）；
5. 拆的书群聊不调工具的那条（`chat.answer` 里 `book.source == "teardown"` 那段）；
6. 方案卡，也就是「总结一下」（`chat_plans.make_plan_background`）。

这几条路里，现在凡是写 `rows[:-20]`、`rows[-20:]`、`rows[-30:]` 的地方，都换成这个函数。

这个函数做的事：
- 摘要以后的原话没超过 `HISTORY_LIMIT`：不缩，也不调设定师。`<之前聊过>` 放现有的摘要，没有就写「（没有）」；`<最近的对话>` 放摘要以后的全部原话。
- 超过了：从最早的一条起，一整条一整条地挪进摘要，挪到剩下的不超过 `HISTORY_KEEP` 为止，最后一条总要留着。挪出来的那几条连同旧摘要交给 `chat_summary`（照现在一样由设定师来缩，`who` 照现在的取法），挪出来的每条也不剪。
  - 缩成了：存新摘要，`summarized_until` 记成挪进去的最后一条的 id。这一次就用新摘要加剩下的原话。
  - 缩失败了：照旧沿用旧摘要，什么也不存；这一次只给剩下的原话，下一次回答再缩。
- 标签名不改：`<之前聊过>` 只放摘要，`<最近的对话>` 放摘要以后的原话（方案卡的 `chat_plan.md` 里也一样）。

**分流**（`group_notes.classify`、开书流程里提意见的 `graphs/book_setup._library_feedback`）：给摘要以后的原话，每条不剪，不调设定师，也不存东西。超过 `HISTORY_KEEP` 时，从最早的整条往后丢，丢到不超过为止，只管这一次。`library_route.md` 没有放摘要的地方，不加。

**照旧的**：
- 「从这里重来」：退回的那句在摘要范围里（`summarized_until >= 那句的 id`），摘要清空、`summarized_until` 归 0。`chat_convs.rewind` 现成就是这样，不改。
- 私聊「换个话题」：`reset_after` 和 `summarized_until` 都记成最新一条，摘要清空。不改。

### 1.3 摘要分清谁说的

- `backend/app/prompts/chat_summary.md` 换成本目录的 `提示词/chat_summary.md`。用 `git mv -f` 覆盖，逐字节一样，sha256 是 `dd337f7be028ef8e1efa559c58df4f0b4b6d6f7d8ad65fefc5302f61001a5bd7`。变量还是 `who`、`summary`、`messages`。
- `backend/app/agents/schemas.py` 里 `ChatSummary.summary` 的 description 换成：

  ```text
  这一段之前聊过的摘要：照要求里的五个小标题分开写，哪句是谁说的、作者答应了没有要分清，3000 字以内
  ```

- 测试跟上，见第 3 节。

### 1.4 旧摘要清掉：迁移 0030

现有的摘要都是照旧剪法缩的。作者库里那段群聊的摘要就把主编的提议写成了已定，留着还会接着误导。

加迁移 `0030_chat_full_history`：
- `chat_conversations`：`summary = ''`，`summarized_until = 0`；
- `chat_threads`：`summary = ''`，`summarized_until = reset_after`。换个话题的分界不动。
- `downgrade` 什么也不做：摘要恢复不了，也不需要恢复。

作者库里最长的一段才 2.2 万字，清掉以后每段都是整段原话，上线后不会马上触发缩。

### 1.5 不改的

- 提示词只改 `chat_summary.md`。`chat_material`、`chat_agent`、`chat_reply`、`chat_teardown`、`chat_plan`、`library_route`、`chat_manner` 一个字都不动，`<最近的对话>` 这个标签名也不改。
- 前端不动。
- 资料、工具、记忆、手册、拆过的书那几块不动。
- 模型装不下的时候（上下文小的模型），照旧报错，这次不做自动少给。作者给编辑部配的模型都装得下。
- 记调用（`llm_calls`）照旧，不改。

## 3. 测试

**本任务有意改了、旧测试还认旧样子的，照新样子改**（照 README 第 5 条，不算放宽）：
- `tests/test_chat_task6.py::test_context_blocks_and_limits` 最后三行：20 条、每条 900 字的话拼出来，一个字不少，没有「……」。
- `tests/test_chat_task6.py` 里摘要失败的那个（断言 `seen == ["旧摘要"]` 那个）：把两个常量调小，造出超过上限的对话。断言摘要失败照旧用旧摘要、回答照常出来；这一次给的原话不超过 `HISTORY_KEEP`；库里的 `summary`、`summarized_until` 没变。
- `tests/test_chat_convs.py::test_summary_belongs_to_the_conversation`：调小上限以后，照旧测摘要记在那一段对话上，不记在 `chat_threads` 上。
- `tests/test_chat_task6.py::test_exact_templates_and_schema_contracts`：
  - `tests/chat_task6_prompt_hashes.json` 里 `chat_summary` 换成新指纹；
  - `tests/later_changes.py` 的 `SCHEMA_CHANGES` 加一条，从第三包任务 6 原文里的旧 description 换成 1.3 的新 description，前面写一行注释「2026-10-27 聊天记性：摘要分清谁说的」。
- `tests/fixtures/` 里拿旧剪法拼出来的快照（比如 `chat_prompt_layers_before.json`），要是因为 `<最近的对话>` 不剪了而对不上，照新样子重新生成，完成说明里列出来。

**新测试**：
1. `dialogue_text` 不剪：一条 5000 字的回答，拼出来原样都在。
2. 没超过上限：不调 `chat_summary`；`<之前聊过>` 是「（没有）」；`<最近的对话>` 里每一条都是全文。
3. 超过上限（测试里调小两个常量）：
   - 只调一次 `chat_summary`，给它的 `messages` 是挪出来那几条的全文；
   - 存下的 `summarized_until` 是挪进去的最后一条；
   - 这一次 `<最近的对话>` 不超过 `HISTORY_KEEP`，从挪完以后那一条开始；
   - 下一次回答没再超，就不再调。
4. 缩失败：沿用旧摘要，什么也不存，这一次原话不超过 `HISTORY_KEEP`。
5. 第 1.2 节那六条路用的是同一套：每条路造一段对话，里面有一条超过 800 字的旧回答，看记下的调用（`llm_calls.request` 的 `user`）里有它的全文。
6. 分流两处：给的是摘要以后的原话，不调 `chat_summary`；超过 `HISTORY_KEEP` 只给最后那些。
7. 迁移 0030：升级以后摘要都清空了，私聊的 `summarized_until` 等于 `reset_after`。
8. 「从这里重来」清摘要照旧：现成的测试过了就行。
