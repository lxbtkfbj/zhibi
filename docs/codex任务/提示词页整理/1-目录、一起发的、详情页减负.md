# 提示词页整理 任务 1：目录、一起发的、详情页减负

共同约定照本目录的 `README.md`。

## 为什么做

作者 2026-10-24 说提示词页「信息不清楚，看起来有点眼花缭乱」。设计方在作者的页面上看过，眼花的地方是这几处：

1. 想改的找不到：78 份排成一长条，作者最常改的「主编口吻」排第 70，前面隔着 29 份拆书。
2. 重复的字太多：拆书那组每份前面都顶着「拆书：」「拆书精髓：」。
3. 看不出谁和谁拼在一起：主编在群聊回一句话，是 7 份提示词拼起来的，分在「角色与规矩」「聊天」两组里，页面上看不出来。「聊天回答」「聊天：自己查、自己动手」的说明还是分层以前的说法。
4. 详情页抢眼的东西多：每份都挂「默认版本」标签；三个按钮里有两个是灰的；还有「可用变量 · 展开查看」。
5. 调用详情的系统提示是一整块字，看不出用了哪几份。调用记录里其实存了 `prompt_names`，只是没显示。

作者同意了三条：目录换个排法、每组能收起；每份写清「一起发的」；详情页减负。

## 2. 目录能收起

改提示词页左边的目录（`frontend/src/pages/PromptsPage.tsx`）。

- 每组的组名变成能点的一行：前面一个小箭头（展开时朝下、收起时朝右），后面淡淡地写这组有几份，比如「拆书 14」。点一下收起或展开，屏幕阅读器读得出是展开还是收起（`aria-expanded`）。
- 默认「拆书」「拆书精髓」两组收着，别的组展开。
- 作者收起、展开过的，记在本机，下次打开照他上次的样子。
- 搜索框里有字时，有匹配的组都展开显示（不改记下的收起状态）；清空搜索后回到记下的样子。
- 选中的那份（地址里带的、从「一起发的」或调用详情里点过来的）所在的组要是收着，自动展开，记进本机，并把那一份滚到看得见的地方。
- 目录顶上「提示词目录 78 项」、搜索框、找不到时的那句话都不改。手机上的「选择提示词」下拉只跟着新的先后和名字，别的不动。

## 3. 一起发的

### 3.1 后台把系统提示、用户提示里各用了哪几份记下来

- `backend/app/prompts/__init__.py` 加一个函数，算出这次请求的系统提示里用了哪几份、用户提示里用了哪几份。认法和 `prompt_names_for` 一样：这次渲染过的提示词，内容出现在哪段字里就算哪段用了。各自按在那段字里**第一次出现的位置**排先后，不重复。
- `backend/app/llm/router.py` 里，两处写 `"prompt_names"` 的地方（`_request` 和 `tool_rounds`），旁边多存一项 `"prompt_parts": {"system": [名字…], "user": [名字…]}`。`prompt_names` 照旧存，目录接口还靠它找「最近一次」。
- 照这个排法，现在主编在群聊里回一句话，系统提示是 `persona_chief`、`chat_voice`、`voice_chief`、`chat_agent`、`chat_manner`、`rules`。「口吻怎么用」的第一句在主编口吻那段字前面，所以排在前面。用户提示是 `chat_material`。出章纲这类写书的活，系统提示是 `persona_chief`、`rules`，用户提示是那份任务提示词，带了题材打法的话还有题材打法。
- 旧的调用记录不补。

### 3.2 接口

- `GET /api/prompts/{name}`：`last_call` 在 `id`、`created_at` 之外多给 `purpose` 和 `used_prompts`。
- `GET /api/llm-calls/{id}`：多给 `used_prompts`。
- `used_prompts` 的样子：
  - `{"parts": {"system": [{"name", "title"}…], "user": [{"name", "title"}…]}, "names": [{"name", "title"}…]}`；
  - `names` 照 `prompt_names`，一直都有；
  - 旧记录没有 `prompt_parts`，`parts` 给 `null`；
  - `title` 照目录里现在的名字（手册照作者改过的名字）；目录里找不到的，`title` 就用 `name`。
- `GET /api/prompts`（整份目录）不改，免得每次都查调用记录。

### 3.3 详情页上那一块

放在标题和说明下面，换掉现在「主编 · 最近调用：…… · 查看这次调用」那一行。拿「聊天的做法」举例，主编在群聊里说过一句以后是这样：

```text
一起发的　最近一次：2026/10/24 12:48:24 · 聊天·主编　查看这次调用
系统提示　主编人设 → 口吻怎么用 → 主编口吻 → 群聊：自己查、自己动手 → 聊天的做法 → 通用规则
用户提示　聊天带的资料
```

- 时间照现在「最近调用」的写法；「聊天·主编」是那次调用的 `purpose`；「查看这次调用」和现在一样，打开调用详情。
- 名字用「 → 」接起来。当前这份字加粗、不能点；别的名字能点，点了就选中那一份（第 2 节：所在的组自动展开、滚到看得见）。
- 系统提示或用户提示里一份都没有，那一行不显示。
- 旧记录（`parts` 是 `null`）：第二行写「用到的　A、B、C（旧记录，分不出系统提示和用户提示）」，名字之间用「、」，名字照样能点；没有第三行。
- 还没用过：只有一行「一起发的　还没用过」。

### 3.4 调用详情里那一块

`frontend/src/pages/PromptCallDetail.tsx`：在最上面那块（用途、书名、时间、角色、模型、Token、耗时）下面、「系统提示」上面加一块，标题「用到的提示词」：

```text
用到的提示词
系统提示　主编人设 → 口吻怎么用 → 主编口吻 → 群聊：自己查、自己动手 → 聊天的做法 → 通用规则
用户提示　聊天带的资料
```

- 名字都能点：点了关掉调用详情，切到「提示词」那一页，选中那一份（第 2 节的展开、滚动照样）。
- 旧记录写「A、B、C（旧记录，分不出系统提示和用户提示）」，名字照样能点。
- `names` 也是空的（更早的记录），这一块不显示。

## 4. 详情页减负

都在 `PromptsPage.tsx` 的详情那一半。

- 标题后面的标签：改过的才挂「改过」（样子照现在的「已自定义」），没改过的什么都不挂。「默认版本」不再出现。
- 说明那一行不改。现在那一行「主编 · 最近调用……」换成第 3.3 节那一块，角色那个小标签不要了。
- 按钮：
  - 看的时候只有一个「修改」（就是现在的「自定义」，改个字）。
  - 点了「修改」以后，从左到右是「恢复默认」「取消」「保存」。「保存」是主按钮，什么时候能点照现在；「恢复默认」只有这份改过（`customized`）才出现，点了照现在先确认、再恢复。
  - 「取消」：内容和存着的不一样，先问「改的还没保存，确定不要了吗？」；点确定，或者本来就没改，就丢掉本机草稿，回到看的样子。
  - 存好、恢复好以后回到看的样子，提示的话照现在。
- 本机草稿照现在：有草稿就直接是修改的样子，下面那句「有未保存的本地草稿……」照旧。
- 「可用变量」只在修改的时候出现，样子和字照现在。
- 正文上面那一行：看的时候只写「提示词正文」，右边那句「只读 · 点「自定义」后可编辑」不要了；修改的时候左边写「正在修改」，右边「保存后对所有书生效」照旧。
- 「默认模板的变量有变化……」那块提醒照旧。
- 目录里改过的那个小圆点照旧，鼠标停上去和读屏读出来的字从「已自定义」改成「改过」；「变量有更新」照旧。
- 「提示词」那一页标题下面那句「查看编辑部的工作指令。自定义内容只在点击保存后生效，适用于所有书。」改成「查看编辑部的工作指令。改了点「保存」才生效，所有书都用同一份。」
