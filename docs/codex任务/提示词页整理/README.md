# 提示词页整理：共同约定

这一包整理「提示词与调用记录」页里的「提示词」那一页（`/prompts`），一共三件事：
- 目录换个排法，每组能收起；
- 每份提示词写清「一起发的」还有哪几份；
- 详情页减负。

只有一个任务。

本包的任务都照这一份约定，不照别的目录的 README。

1. 先读本文件，再读任务文件。
2. 开工前 `git status` 不干净就停下来问，不要动、也不要替别人提交没提交的改动。
3. 界面上的字逐字照任务文件；任务没写到、你自己补的字列进验收说明。**提示词正文一个字不改**：这次只改提示词页的目录（`catalog.py` 里的分组、名字、说明）和页面本身。没有迁移。
4. 不要升级、重启或改动作者日常的 8000／4320 服务、日常 worker 和书库，不对日常环境运行 `start.ps1`／`stop.ps1`。**不调真实模型**：要有调用记录，就用演示模型在独立环境里聊一句。
5. 什么时候自己定，什么时候停下来问：
   - 自己定，做完在完成说明里单独列出来：
     - 测试里写死的旧指纹、旧文字和开工时 HEAD 的提示词或代码对不上，而那份文件本任务没动过（和开工时 HEAD 逐字节一致）：改测试跟上 HEAD，提示词和代码都不动。
     - 本任务有意改了的东西（目录的分组和名字、按钮的字、「恢复默认」什么时候出现），旧测试还认旧的：照任务的新样子改测试。
     - 和本任务无关、开工前就坏了的测试：修法是机械的（同第一条），直接修；要改产品代码或者改变行为才能修好的，停下来问。
     - 任务没写到的实现细节：组件怎么拆、样式类名、收起的箭头用哪个图标、本机存收起状态的键名、后台怎么取最近一次调用。
   - 停下来问：
     - 要改提示词正文，或者要动任务写死的字、排法和行为；
     - 改动会碰到提示词页以外的页面（书页、系统设置、聊天框），或者要改调用记录那张表；
     - 任务的要求和现有代码真的打架，两种做法都说得通，而且会影响作者怎么用；
     - 要放宽断言、删测试或跳过测试才能过；
     - 要动作者日常的服务和书库，或者要调真实模型；
     - git status 不干净（第 2 条）。
6. 检查：开发中只跑相关测试；提交前跑一次全量，全部通过。
   - 后端（`backend/`）：`uv run ruff check . && uv run ruff format --check . && uv run pytest -q`
   - 前端（`frontend/`）：`npx tsc -b && npm run lint && npm run build && npm run test:workspace`
   - 浏览器测试：`tests/prompts-workspace.browser.mjs`、`tests/handbook-task1.browser.mjs` 跟着改完重跑，全过。精髓、装修两套页面比对里没有提示词页，不用跑。
7. 验收写在 `docs/提示词页验收.md`（要写什么见任务第 6 节）。截图四张，放在 `docs/提示词页验收/`，用独立环境截。
8. 直接在当前分支上做，不推送。提交信息以「提示词页：」开头。
9. 做完用一段中文告诉作者：改了哪些文件、测试和全量检查的结果、截图在哪、自己补的字；按第 5 条自己定的事单独列出来；提醒作者升级后要重启服务；还要说明升级前的旧调用记录分不出系统提示和用户提示，聊过一句以后才会显示成两行。
