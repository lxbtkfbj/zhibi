# 任务 5：写作接入

> 先读 `docs/codex任务/第三包/README.md` 和 `docs/设计说明.md` 第 13 节（重点 13.4 的「写作中」、13.5 的「写作中展开」），并确认任务 3、4 已完成并提交。

## 目标

开写以后，写作流程接上新的设定库和大纲树：

- **写作上下文**改读设定库和大纲：主角、金手指、底牌来自设定库；「一句话就好」的惯例每章都给写手；底牌只给规划用，不给写手；
- **开写前补齐**：开书时大纲只出了一段话，开写时主编先把第一篇的线索、人物出场、读者在等的事、信息差，和第 1 卷各单元的细节补上，作者看过的一段话一个字不动；
- **定下一篇**：第二包「定下一段」的十四道题换成「一段话加分卷」；确认放到大纲树上的这个节点；
- **拆卷纲**：每个单元多一段话，作者在大纲里看到、改的就是它；出章纲时以它为准；
- **展开这一个**：大纲树上只有一句话的卷、下一个要出章纲的单元、下一个写到再定的篇，可以提前展开；
- **单元章纲给不给看**：本书设置新开关，默认不给看；
- **设定师每章记新设定**，正文和设定库对不上时提醒；
- **旧书补底牌**：第二包和更早开的书没有底牌的，下一次定下一篇时主编先推一句，让作者确认；
- 后端给作者看的文字里，「段」都改成「篇」。

## 1. 写作上下文（`app/services/writing_context.py`、`app/agents/context.py`）

提示词的变量名**不改**，改的是程序给它们填的内容。下面的规则对所有书都适用：任务 1 已经把旧书的主角卡、世界与地图迁进了设定库，所以不再区分新书旧书，只在下面写明的几处兼容旧数据。

### 1.1 定调 `concept`

`format_concept`：`story` 不空时，「一句话简介」「核心卖点」两行换成一行 `定调：{story}`，其余各行照旧（空的照旧不写）。`story` 空的（旧书）完全照旧。

定调里**不放底牌**，底牌在 1.2。

### 1.2 主角、金手指和底牌 `protagonist`

拆卷纲（`volume_blocks`）、定下一篇和分卷（`segment_blocks`）里的 `protagonist` 改为逐条 `entry_full_text`（任务 2 第 3.3 节），之间空一行：

1. 主角的角色卡片（`role_type = '主角'`）；
2. 带「金手指」标签的条目和角色卡片（是主角卡片本身的不重复写）；
3. 底牌：`concept.secret_entry_id` 指向的条目，没有就取带「底牌」标签的条目。

设定库里没有主角卡片时，第 1 条写「（设定库里还没有主角的角色卡片）」。

### 1.3 设定库 `world`

`segment_blocks` 的 `world` 改为：

```
{设定库目录：任务 2 第 3.2 节的 library}

现在要定的条目：
{逐条 entry_full_text，之间空一行}
```

「现在要定的条目」只列状态是现在要定、不是角色卡片、也没有在 `protagonist` 里写过的条目，类别顺序同目录；一条都没有就不写这一段。

`volume_blocks` 新增 `world`，内容同上（`plan_volume.md` 新加了【设定库】，见第 8 节）。

### 1.4 大纲 `spine`

沿用 `format_spine` 按节点逐个写的格式（定下一篇时模型要靠「节点 N」填 `ref`），改这几处：

- 状态：`铁钉` 改为 `已锁`，`暂定` 改为 `没锁`，`留空` 不变；
- `｜这一段写到再定` 改为 `｜这一篇写到再定`；
- 带 `segment` 的节点下面那一行：`text` 不空的写 `  这是第 {N} 篇「{篇名}」的终点：{text}`；`text` 空的（旧书）照旧写目标、读者在等、揭开、地图，「段」改「篇」；
- 篇号 `N` 按顺序数（第几个带 `segment` 的节点），不读 `segment.number`（开书时出的第一篇没有这个键）；
- 开头的「核心矛盾」「主题」「主角成长弧」空的不写（新书都是空的）。

### 1.5 这一篇 `segment`、上一篇 `last_segment`

`volume_blocks` 的 `segment` 和 `segment_blocks` 的 `last_segment`，按这一篇的 `segment` 写：

- `text` 不空：第一行 `第 {N} 篇「{篇名}」：{text}`；`finale` 为真时再加一行「这是收尾篇：开始收线，揭开底牌，往结局方向走。」；
- `segment` 里还有第二包的旧字段（`goal`、`map`、`wait` 等）：接着写 `format_segment_info` 的内容（作者给旧书的篇写了一段话的，两样都写）；
- `last_segment` 后面照旧接终点和卷的范围，「段」改「篇」：`这一篇写了第 {a}-{b} 卷。`

### 1.6 写手这一边

`chapter_blocks`（写正文、续写、改结尾、审稿、查矛盾共用）和 `material_blocks`（设定师备资料）：

- **底牌不给**：带「底牌」标签的条目，不出现在 `world_text` 里，不出现在 `world_catalog` 里，`clean_materials` 也把它去掉（模型挑了也不要）。
- **惯例每章都给**：`chapter_blocks` 的 `world` 在设定师挑的条目后面空一行，加：

  ```
  这本书的惯例：
  - {名称}：{one_line}
  ```

  列出状态是「一句话就好」、来源不是「写作中记下的」（`source != 'writing'`）、不是底牌、上面没有整条写过的条目，按目录的类别顺序，最多 30 条；一条都没有就不写这一段。写作中记下的条目不进惯例，由设定师按需要挑。
- `world_text`：`content` 空的条目用 `one_line`。
- `world_catalog` 每行改为 `- [{类别}] {名称}：{one_line，空的取 content 前 40 字}`。

### 2.3 确认或自动通过时保存

新写 `writing_store.save_arc`（flow 3 用它；第二包的 `save_segment` 只留给第 2.5 节的旧确认，不再新调用），同一个事务里：

1. **终点**：`ref` 指向已有节点的，锁住的原样用，不改；没锁的按 `end` 更新名称和发生什么（作者在等待期间改过的保留，沿用第二包的快照比对）。`ref = 0`：在最后一个已规划的终点后面插一个新节点（`kind = 'milestone'`，`status = 'pencil'`，`origin = 'ai'`）。`pin_end` 为真时把终点锁住。
2. **篇**：终点节点写 `segment = {"number", "title", "text", "status": "confirmed" 或 "auto", "planned_at", "finale", "split": true}`（`planned_at` 是已定稿章数），记一版。同一个 `number` 已经保存过的，直接返回（第二包的防重复保存照旧）。
3. **分卷、线索、人物锚点**：照第二包的做法建卷（`summary` 是一段话）、线索节拍和人物锚点。
4. **读者在等的事**：`split.wait` 记成一条长线期待（`kind = '期待'`，`span = '长'`，`node_id` 是终点），立下和兑现的卷限在这一篇的卷里（第二包的做法）。
5. **信息差**：`split.secrets` 逐条建（`node_id` 是终点），知情人的获知方式写「定下第 {N} 篇时」。`entry` 对得上「往事与秘密」里的条目、而且那一条还没有 `secret_id` 的，把它的 `secret_id` 指向这条信息差。
6. **以后再说的条目**：`fill_entries` 按名称（和别名）找状态是「以后再说」的条目，写入 `content`，状态改为现在要定，记一版；锁住的不改，改为挂一条建议（`kind = 'fill_gap'`，`op = set_field`，`path = content`，标题「定下第 {N} 篇时，「{名称}」可以写全了：{content 前 30 字}……」）。找不到的跳过。
7. **新设定**：`new_entries` 照任务 3 第 4.3 节的规则建（`source = 'ai'`）；类别是等级体系、名称和已有条目相同的，只把已有条目里没有的级（名称和介绍）接在后面，记一版；那一条锁住的不改，改为挂一条建议（`kind = 'fill_gap'`，`op = note`，标题「第 {N} 篇要用到更高的等级：{级名，用顿号连起来}。「{条目名}」锁住了，解锁后加上。」）。
8. **新人物**：`new_characters` 按姓名和别名找，已有的跳过，其余建角色卡片（`source = 'ai'`，状态照模型给的换成键）。
9. **底牌**：`secret` 不空、而且这本书确实没有底牌时，在「往事与秘密」建「底牌」条目（`content = secret`，`one_line` 取第一句，`tags = ["底牌"]`，`locked = true`，`status = 'must'`，`source = 'ai'`），写 `concept.secret_entry_id`。
10. **结局**：`ending_change` 不空、结局节点没锁时，更新结局的发生什么。

保存后主编在群聊说：`第 {N} 篇「{篇名}」定下来了：分 {K} 卷，新建了 {M} 条设定、{P} 个人物，写全了 {Q} 条以后再说的设定。`；建了底牌时再加一句「这本书原来没有底牌，我推了一句：{secret}，你看看要不要改。」

自动通过（`segment_approval` 关掉）时的系统消息照第二包，文字按第 9 节改。

## 3. 开写前补齐

开书时（任务 3）大纲只出了一段话：第一篇的卷有一段话和章数，第 1 卷的单元有一段话和章数。写作要用的线索、人物出场、读者在等的事、信息差、单元的目标冲突高潮、伏笔和期待都还没有。开写时，写作流程先补上这些，**作者看过的名称、一段话、章数、锁一个都不改**，也不停下来等作者。

### 3.1 补齐这一篇（新节点 `fill_segment`）

**什么时候**：写到某一卷时，它走向的终点节点有 `segment`，但 `segment` 里既没有 `split` 也没有 `number`（开书时出的第一篇）。

**做什么**：调一次 `split_segment`（同第 2.2 节），区别是：

- `segment` 拼法同第 2.2 节，用现有的节点；
- `volume_hint` 写「这一篇的卷已经分好了，卷号照【这一篇已经分好的卷】。」；
- `fixed`：

  ```
  【这一篇已经分好的卷】
  第 {卷号} 卷「{卷名}」约 {章数} 章：{一段话}
  第 {卷号} 卷「{卷名}」约 {章数} 章（已锁）：{一段话}
  ```

**保存**（同一个事务）：

- 卷：模型给的卷按顺序对上这一篇已有的卷（多出来的丢掉，对不上的那几卷照旧）；只写舞台、这一卷想做成什么、卷末结果、高潮、对手、成长、新登场的人、批注、技巧、线索节拍；**卷名、一段话、章数、锁、走向的节点不改**；最后一卷 `reaches_node = true`。
- 线索、人物锚点、读者在等的事、信息差：同第 2.3 节的 3-5 步，知情人的获知方式写「开书设定」。
- 这一篇的 `segment` 加上 `number`（按顺序数）、`planned_at = 0`、`split = true`。
- 群聊（主编）：`开写前，我把第 {N} 篇的线索、人物出场、读者在等的事和信息差排好了：{T} 条线，{S} 条信息差。`；照分卷的样子发一张产出卡片。

### 3.2 补齐卷纲（新节点 `fill_volume`）

**什么时候**：写到某一卷时，这一卷有单元，其中有还没写完、关键事件（`key_events`）是空的单元——开书时出的第 1 卷（任务 3 已把它的状态写成 `approved`），或者作者在大纲里给已经拆好的卷加的单元。

**做什么**：调一次 `plan_volume`（不比稿、不做专项审稿、不停下来拍板），区别是：

- `chapter_count` 用现有单元的章数之和，`unit_hint` 写单元个数；
- `fixed`：

  ```
  【这一卷已经拆好的单元】
  单元 {序号}「{名称}」{章数} 章：{一段话}
  单元 {序号}「{名称}」{章数} 章（已出章纲）：{一段话}
  单元 {序号}「{名称}」{章数} 章（已锁）：{一段话}
  ```

  已经有章节行的单元标「已出章纲」，锁住的标「已锁」，两样都有就依次写在一起。

**保存**：

- 单元按序号对上；只给关键事件是空的那些单元写目标、冲突、高潮、结果、核心循环、关键事件、线索节拍、伏笔动作、揭晓、批注、技巧、套路、破局手法；**名称、一段话、章数、锁、状态不改**，别的单元整个不动；「已出章纲」的单元，伏笔动作和揭晓清空（章纲已经出了，不会照着做）。
- 补完仍然没有关键事件的单元，关键事件填它的一段话（免得写作流程反复补齐）。
- 新埋的伏笔、新立的期待照拆卷纲的做法编号、写进单元（`save_volume_plan`，`replace_new = False`）；埋下（立下）的单元不在这次补的单元里的，丢掉。
- 卷的 `want`、`pressure` 空着的才写；卷的状态是 `planned` 的改成 `approved`，其余不改。
- 群聊（主编）：`开写前，我把第 {N} 卷各单元的细节补上了：新埋伏笔 {F} 条，新立期待 {E} 条。`；照拆卷纲的样子发一张产出卡片。

### 3.3 写作流程怎么判断下一步（`_next_step`）

对每一卷（没写完的），按顺序：

1. 它走向的那一篇要补齐（3.1 的条件）→ `fill_segment`；
2. 没有单元 → `plan_volume`（照旧：比稿、审稿、按设置拍板）；
3. 状态 `detailed` → `volume_gate`（照旧）；
4. 有要补齐的单元（3.2 的条件）→ `fill_volume`；
5. 其余照旧（写正文、出章纲、回顾）。

原来「状态是 `planned` 就拆卷纲」的判断改成「没有单元才拆卷纲」：有单元的卷不再重拆，免得盖掉作者在大纲里看过、改过的单元。有单元、状态还是 `planned` 的卷（旧数据）按 `approved` 处理。

## 5. 展开这一个

大纲树上（任务 4 的大纲页）这三种节点，右边多一个按钮：

| 节点 | 什么时候出现 | 按钮 | 做什么 |
|---|---|---|---|
| 还没有单元的卷 | 这一卷没开写 | 展开这一个 | `POST /volumes/{id}/expand`：在接口里直接跑一次拆卷纲（`plan_volume`，`fixed` 为空，不比稿、不做专项审稿），照拆卷纲的做法存单元、新伏笔和新期待，卷的状态直接改为 `approved`（作者自己点的，写到时不再停下来拍板）；给卷和每个单元记一版；返回这一卷 |
| 下一个要出章纲的单元 | 全书顺序里第一个还没有章节行的单元 | 展开这一个 | `POST /units/{id}/expand`：在接口里直接跑一次出章纲（复用写作流程出章纲的代码，含程序检查和重出一次），建章节行；返回这个单元 |
| 下一个写到再定的篇 | 第二包「现在就规划下一段」的条件（编辑部空闲、书是 ready 或 writing、还没规划到结局） | 现在就规划下一篇 | 调现有的 `POST /books/{id}/plan-segment` |

- 单元只能展开「下一个」：章号要接着前面排，跳着展开会打乱章号。再后面的篇也不出现按钮。
- 前两个接口沿用 `ensure_idle`，编辑部排队或正在工作时返回 409「编辑部正在工作，等这一步做完再展开」；卷已经有单元、单元已经有章节时返回 409「已经展开过了」；不是下一个要出章纲的单元返回 409「先展开前面的单元」；模型出错返回 502「模型出错了：{原因}」。
- 群聊（主编）：`第 {N} 卷提前拆好了：{K} 个单元，新埋伏笔 {F} 条，新立期待 {E} 条。` / `「{单元名}」的章纲提前出好了：第 {a}-{b} 章。`
- 展开以后，新单元照常能改一句、给几个写法、锁住、改章数。

## 11. 验收（演示模式，浏览器）

在独立环境里，每步截图，结果写进 `docs/第三包验收.md` 的「任务 5」小节：

1. 新开一本书走完三步，「确认，开写」：群聊里先出现补齐第一篇、补齐第 1 卷的两条消息，再开始写第 1 章；大纲页「线索」里有线索，设定库下「伏笔与期待」有一条长线期待和几条伏笔，「信息差」有条目，某条「往事与秘密」显示「谁知道」；大纲里卷和单元的一段话和开书时一样，单元的「细节」里有目标、关键事件、伏笔与期待动作；
2. 写到第一篇的卷都写完：自动打开大纲页的「待你确认」节点，显示篇名、一段话、终点、分卷、要新建和写全的设定；勾「确认时把它锁住」，在拍板条上确认；第二篇变成已规划，终点锁住，设定库里多了「青云宗」、「天风国」写全了；
3. 卷纲拍板在大纲页完成；
4. 在下一个要出章纲的单元上「展开这一个」出章纲；后面的单元没有这个按钮；在下一个写到再定的篇上看到「现在就规划下一篇」；
5. 本书设置打开「每个单元的章纲都给我看」，写到下一个单元时停下来，大纲页显示章纲；提一次意见再批准；
6. 写几章后，设定库里出现来源「写作中记下的」条目；点子带「测试冲突」的书，待处理的建议里有一条「第 N 章：……」；
7. 查调用记录：写手的提示词里有「这本书的惯例」，没有底牌；出章纲的提示词里没有底牌；定下一篇、拆卷纲的提示词里有底牌；
8. 一本第二包开的、没有底牌的旧书，定下一篇时主编推了一句底牌，确认后设定库里有锁住的「底牌」；
9. 顶栏、群聊、本书设置里没有「段」，都是「篇」。
