# 任务 6：和编辑部聊天

> 先读 `docs/codex任务/第三包/README.md`、`docs/设计说明.md` 第 13 节（重点 13.2 最后一段）和本文件，并确认任务 5 已完成并提交。

## 目标

现在作者在会议室说的话，只要不是「改设定」，一律记进「作者要求清单」，而这张清单会带进以后每一次规划、写作和审稿：随口问一句「主角是不是太惨了？」，也会变成以后每一章都要遵守的要求。只管下一章的话（「下一章节奏快一点」）也永远有效。私聊对方只会回「记下了」，没法真的商量。等作者拍板时，群聊里问一句话，还会被当成修改意见送去重写。

这个任务做完以后：

- **群聊分三种话**：改设定（照任务 2）；写作要求（自动记下，带有效范围，结果显示在消息下面，能撤销）；提问闲聊（由最合适的角色回答，不记、不改）。
- **私聊只商量**：任何时候都不改东西、不记要求，也不当成修改意见；聊出结论，作者点最新回复下面的「记成要求」或「照这个改」才生效。
- **等作者拍板时也能问**：提问不会被送去重写。
- **回答时看得到这本书**：书的底子每次现查，按名字找相关资料，每个角色再带自己那一行的资料；对话保留最近二十条，更早的折成摘要；可以「换个话题」。
- **作者要求有有效范围**：一直有效、只管某一章、只管某一卷；过期的不再发给编辑部。
- **作者要求清单能「整理一下」**：主编标出像提问、闲聊、重复、过时的条目，作者勾了才改。
- **选中原文「问问主编」**。
- **主编人设换成第三包的说法**（篇、锁住、底牌）。

### 1.3 有效范围

作者和编辑部说的有效范围有四种，存的时候换算成 1.1 的三种：

| 说法 | 存成 | 换算 |
|---|---|---|
| 一直有效（`always`） | `always` | |
| 只管下一章（`next_chapter`） | `chapter` | `chapter_index` = 记下时第一个还没定稿的章；没有这样的章，就是已有最大章号加一 |
| 只管这一卷（`this_volume`） | `volume` | `volume_index` = 记下时第一个没写完（`status` 不是 `done`）的卷；没有卷时是 1；都写完了是最大卷号加一 |
| 只管下一卷（`next_volume`） | `volume` | 上面那一卷再加一 |

- **什么时候过期**：`chapter` 的，那一章定稿以后；`volume` 的，那一卷写完（`status = 'done'`）以后。`always` 不过期。
- 新增 `active_requirements(session, book_id)`：只返回没过期的。**凡是把作者要求发给模型的地方**（`requirements_of`、开书流程拼 `requirements` 的地方、任务 2 设定库操作的 `requirements`）都改用它。
- `format_requirements` 逐条写：`always` 写 `- {text}`；`chapter` 写 `- （只管第 {N} 章）{text}`；`volume` 写 `- （只管第 {N} 卷）{text}`。
- 显示用的说法（接口返回 `label`）：`一直有效`、`只管第 {N} 章`、`只管第 {N} 卷`；过期的是 `已过期 · 只管第 {N} 章`。
- `add_requirement` 增加参数 `scope`（上表四种说法之一，默认 `always`）和 `message_id`。同样文字的要求已经有了，就不重复建，改用新的有效范围。

### 2.2 处理

按书现在的状态分三种：**空闲**（没有排队、进行中或等作者的任务）、**编辑部在工作**（任务排队或进行中）、**等作者拍板**（任务在等作者，`waiting_author`）。

| 种类 | 空闲 | 编辑部在工作 | 等作者拍板 |
|---|---|---|---|
| 改设定 | 照任务 2 第 4.5 节改一处 | **开书中**：照原来的做法交给开书流程（作者的话记成要求，消息带上 `job_id`，由流程在步骤之间消化）。**写作中**：不改，挂一条建议（第 2.4 节），主编回「编辑部正在写，这一处等写完再改。我放进待处理的建议了，写完点「现在改」。」 | 返回 409（第 5 节） |
| 写作要求 | 记成要求（文字用 `requirement`，`requirement` 空的用作者原话；有效范围用 `scope`），主编回 `reply` | 同左；消息照原来的做法带上 `job_id`，流程照旧在下一步回「收到……」 | 返回 409（第 5 节） |
| 提问闲聊 | 由 `who` 在群聊回答（第 4 节） | 同左；消息不带 `job_id`，不进流程 | 同左 |

- 「写作中」指 `write_book`、`rewrite_chapter`；「开书中」指 `book_setup`。
- 除了 409 的情况，作者的消息都照常记进群聊，`payload` 加 `outcome`（第 2.3 节），并且 `requirement_saved = true`（不让流程再记一遍）。
- 判断要调一次模型。判断期间书的状态变了（比如开写了），按判断完以后的状态处理（任务 2 已有这层复核，保留）。

### 2.3 消息下面显示处理结果

作者消息的 `payload.outcome`：

| `kind` | 其余字段 | 消息下面显示 | 按钮 |
|---|---|---|---|
| `requirement` | `requirement_id` | 已记成要求：「{这条要求现在的文字}」（{有效范围}） | 〔撤销〕〔改一下〕 |
| `to_job` | `requirement_id` | 已交给编辑部：做完手头这一步就照办 | 〔撤销〕 |
| `edit` | `target_type`、`target_id`、`target_label`、`mode`，以及 `revert_version_id`（照作者的意思改的）或 `candidate_id`（给几个写法的） | 照作者的意思改的：已改：{target_label}；给几个写法的：给了三个写法：{target_label} | 照作者的意思改的〔去看看〕〔撤销〕；给几个写法的〔去挑〕 |
| `not_found` | `target_name` | （不显示，主编的回复里已经说了） | |
| `later` | `suggestion_id` | 编辑部写完再改：在待处理的建议里 | 〔去看看〕 |
| `chat` | | 只是聊天，没有记 | 〔其实要记下〕 |

- **撤销要求**：调现有的 `DELETE /requirements/{id}`（会留墓碑，旧检查点不会再带回来）。这条要求在清单里已经没有了，就显示「已撤销」。显示用的文字和有效范围从要求清单里取，作者在清单里改过，这里跟着变。
- **改一下**：打开「要记下的要求」小框（第 6.3 节），保存走 `PATCH /requirements/{id}`。
- **撤销改动**：调任务 1 的 `POST /versions/{revert_version_id}/revert`。`revert_version_id` 是这次改完以后、这个目标**倒数第二新**的那一版（也就是改之前的样子；第一次改时是「初版」）。撤销成功后按钮变成「已撤销」；刷新后再点，也只是再退回到改之前那一版，没有坏处。连带建议不跟着撤，作者自己忽略。
- **其实要记下**：打开「要记下的要求」小框，文字先填作者的原话；保存时 `POST /books/{id}/requirements` 带上 `message_id`，服务端把那条消息的 `outcome` 改成 `requirement`。
- **去看看、去挑**：打开那一条（设定库 `library?id=…`，大纲 `outline?node=…`，定调 `concept`）。

## 3. 私聊：只商量

- 带 `to` 的消息（发给某个角色的）一律是聊天：**不判断种类、不记要求、不带 `job_id`、不改任何东西**，书在任何状态都一样。第二包「点名插话记成要求」的做法取消；前端也不再把私聊的话当成修改意见送去重写（第 5 节）。
- 由那个角色回答（第 4 节）。作者消息的 `payload` 加 `outcome = {"kind": "chat"}`，但私聊里不显示「只是聊天，没有记」这一行（私聊本来就是聊天）。
- **聊出结论**：私聊里**最新一条**角色回复下面，有两个小按钮〔记成要求〕〔照这个改〕：
  - 点了以后调 `POST /books/{book_id}/chat/{thread}/conclude`（`{"mode": "requirement"}` 或 `{"mode": "instruction"}`），返回 `ChatConclusion`（第 4.2 节）。
  - `found = false`：提示「这段对话里还没聊出要落实的结论。」
  - 记成要求：打开「要记下的要求」小框，文字和有效范围先填好；保存走 `POST /books/{id}/requirements`（`source = chat:{角色}`），再在私聊里发一条系统消息 `已记成要求：「{文字}」（{有效范围}）`。
  - 照这个改：打开「交给编辑部的话」小框（一个文字框，〔发到群聊〕〔取消〕）；发出去就是作者在群聊说了这句话，照第 2 节处理；再在私聊里发一条系统消息 `已交给编辑部：「{文字}」，去群聊看看。`
- 私聊顶上原来那句「点名插话会记入作者要求，并由编辑部在工作时处理。」改为：「这里只聊天，不会改动书稿，也不会记成要求。聊出结论，点最新回复下面的「记成要求」或「照这个改」。」

## 4. 回答

### 4.1 什么时候回答、怎么回答

- 群聊里的提问闲聊、私聊里的每一条，都要回答。接口先把作者的消息存好、返回，**回答在后台生成**（FastAPI `BackgroundTasks` 或等价做法），不占编辑部的任务、不排队，编辑部正在工作时也能回答。
- 同一个对话（同一本书、同一个 `thread`）同时只生成一条回答（用 Redis 锁）。生成时，把这个对话里还没回答的作者消息都算进来，一起回一条；回答的 `payload.reply_to` 记下回答了哪几条消息的 id。
- 生成期间发事件 `chat_typing`：`{"thread": "…", "speaker": "chief", "on": true}`，结束（成功或失败）时发 `on: false`。前端在那个对话的最下面显示「{角色名}正在想…」。
- 回答发成那个角色的 `speech` 消息：私聊的 `payload` 带 `thread`；群聊的不带 `thread`，说话人是 `who`。
- 模型出错：在这个对话里发一条系统消息「{角色名}这会儿没答上来：{原因}。再问一次试试。」
- 调模型用这个角色的模型（`LLMRouter(sessionmaker, book_id=…)`，用完 `aclose`），调用记录的 `purpose` 写 `聊天·{角色名}`。

`progress`：

```
已定稿 {N} 章，全书计划约 {M} 章。
正在写：第 {篇号} 篇「{篇名}」 · 第 {卷号} 卷「{卷名}」 · 单元「{单元名}」 · 第 {章号} 章《{章名}》

```

- 没定篇幅的，第一行只写 `已定稿 {N} 章。`；不是分篇规划的旧书，「正在写」那一行不写篇。
- 还没开写（没有定稿的章）：只写 `还没开写。`；开书正在进行时再加一行 `开书正在做：{定调／设定库／大纲}`。

### 4.4 和这次的话有关的资料 `related`（程序找，不调模型）

在「作者这次说的」、选中的原文和最近 4 条对话里找，按下面的顺序拼，各块之间空一行；一块都没有写「（没有）」：

1. **设定**：设定库条目和角色卡片的名称或别名出现了的，逐条 `entry_full_text`，按第一次出现的先后，最多 8 条。块首一行 `设定：`。
2. **章节**：出现「第 N 章」（阿拉伯数字或中文数字）的，最多 3 章，每章：

   ```
   第 {N} 章《{标题}》：{已定稿的写摘要；没定稿的写章纲的目标和结尾钩子}
   原文片段：{已定稿的，用 best_excerpt 按作者的话从正文里取约 300 字；没定稿的不写这一行}
   ```

3. **卷**：出现「第 N 卷」的，最多 2 卷，每卷 `第 {N} 卷「{卷名}」：{一段话}`，下面逐个单元 `  单元「{名称}」：{一段话}`。
4. **篇和单元**：篇名或单元名出现了的：`第 {N} 篇「{篇名}」：{一段话或终点的发生什么}`、`单元「{名称}」：{一段话}`。
5. **台账和信息差**：出现台账编号（F3、E2）或信息差编号（S2）的，块首 `台账：` 下面逐条 `format_foreshadowing`；块首 `信息差：` 下面逐条 `format_secrets`。

### 4.5 角色自己的资料 `extras`

| 角色 | 内容 |
|---|---|
| 主编 | `【正在写的这一篇】` 下写这一篇的一段话；`【正在写的这一卷】` 下写这一卷的一段话，再逐个单元 `单元「{名称}」（{已写完／正在写／还没写}）：{一段话}`；`【还开着的期待】` 下写已立下、还没兑现的期待（`format_ledger`）。还没开写时只写 `【还开着的期待】`（没有就整段不写） |
| 设定师 | `【人物现在的状态】`（`character_states`）、`【还藏着的信息差】`（隐藏的，最多 20 条，`format_secrets`）、`【还没收的伏笔】`（最多 20 条，`format_ledger`） |
| 审稿 | `【最近定稿的一章】`：作者点了「第 N 章」的用那一章，否则用最近定稿的一章；写 `第 {N} 章《{标题}》：{摘要}`，下面 `审稿时写得好的：{highlights，用分号连}`、`审稿时的问题：` 逐条 `- [{严重程度}] {问题}——{建议}`（`chapters.review` 里没有的不写）。还没定稿的章就整段不写 |
| 写手 | `【写作规矩】` 下写 `compile_rules` 的内容（空的不写）；`【文风参考】`（`format_style`，空的不写）；`【最近定稿一章的结尾】` 下写那一章最后 1500 字（还没定稿的章就不写） |

没有内容的块整块不写；四个角色都没有内容时 `extras` 为空字符串。

### 4.6 等你确认的内容 `pending`

书在等作者拍板时：

```
【等你确认的内容】
{内容}
```

- 定下一篇（`segment_review`，flow 3）：任务 5 第 2.2 节「当前的下一篇」的格式，后面空一行接分卷（`format_volumes_part`）；
- 三个短版（`setup_pitches`）：逐条 `{序号}. {名称}：{短版}（书名候选：{用顿号连}）`；
- 其他等待：一行 `等你确认：{名称}（内容在上面的资料里）`，名称是：开书的块（定调、设定库、大纲）、`第 {N} 卷卷纲`、`单元「{名称}」的章纲`、`前 3 章试读`、`第 {N} 章（写不过去了）`。

不在等作者时为空字符串。

### 4.7 对话和摘要

- **算进对话的消息**：这个对话里、`reset_after` 之后的消息。私聊：作者的话和这个角色的话。群聊：只算作者的话和聊天回答（`payload` 有 `reply_to` 的），编辑部工作时的发言不算（工作进展在 `progress` 里）。状态、产出卡片、出错的消息都不算。
- **最近的对话 `recent`**：最后 20 条，按时间顺序，每条一行 `作者：{内容}` 或 `{角色名}：{内容}`；一条超过 800 字的只留前 800 字加「……」；合计超过 6000 字时从最早的开始丢。没有写「（没有）」。
- **摘要**：在 20 条之前、`summarized_until` 之后、还没折进摘要的消息满 10 条时，先调一次 `chat_summary`（第 8 节，设定师的模型），把它们和旧摘要合成新摘要，`summarized_until` 记到最后一条。这一步在生成回答之前做，失败了就跳过（用旧摘要），不挡回答。
- **换个话题**：`POST /books/{book_id}/chat/{thread}/reset`：`reset_after` 记成这本书现在最大的消息 id，摘要清空，`summarized_until = reset_after`；在这个对话里发一条系统消息：私聊 `—— 换了个话题，前面的对话不再带给{角色名} ——`，群聊 `—— 换了个话题，前面的对话不再带给编辑部 ——`。每个对话顶上一个〔换个话题〕按钮。

## 5. 等作者拍板时

- **前端**：群聊的话一律先发 `POST /books/{id}/notes`。返回 409、而且 `detail.code` 是 `use_feedback` 时，再按现在 `composerRoute` 的做法，把同一句话当成修改意见交给对应的接口（三个短版重出、块的提意见、定下一篇提意见、拍板提意见）。私聊的话永远只发 `POST /books/{id}/notes`。
- **后端**：等作者拍板时，群聊的话照样先判断：提问闲聊就回答（第 4 节，`pending` 带上等确认的内容）；改设定和写作要求返回 `409`，`detail = {"code": "use_feedback", "message": "等你拍板时请直接提意见"}`，不存作者的消息（交给修改意见的接口去存）。原来在判断之前就返回 409 的那一段去掉。
- 判断时模型出错，返回 502「模型出错了：{原因}」，前端保留作者的草稿并显示错误，不自动当成修改意见。

## 6. 作者要求清单

### 6.1 接口

- `GET /books/{book_id}/requirements`：每条多返回 `scope`、`chapter_index`、`volume_index`、`active`（没过期）、`label`（1.3 节）、`message_id`。没过期的在前，过期的在后。
- `POST /books/{book_id}/requirements`：加 `scope`（`always`、`next_chapter`、`this_volume`、`next_volume`，默认 `always`）、可选 `message_id`（第 2.3 节「其实要记下」）。
- `PATCH /requirements/{id}`：加 `scope`（同上，传了就按现在的进度重新换算）。
- `POST /books/{book_id}/requirements/tidy`：调 `requirements_tidy`（主编，`RequirementsTidy`），只看没过期的要求；返回 `{"items": [{"id", "text", "action", "reason", "rewrite"}]}`，**不改任何东西**。模型漏了的条目按「保留」补上。
- `POST /books/{book_id}/requirements/apply`：`{"delete": [id…], "rewrite": [{"id", "text"}…]}`，一次做完（删除照现有的做法留墓碑），返回最新的清单。

`requirements_tidy` 的变量：`concept`（任务 2 第 3.1 节）、`progress`（4.3 节）、`requirements`：逐条 `{序号}. {text}（{label}；来自{来源}）`。来源的说法：`note` 群聊、`private:{角色}` 私聊{角色名}（旧数据）、`chat:{角色}` 和{角色名}聊天时记下、`answer` 开书时的回答、`volume:{N}` 第 {N} 卷卷纲的意见、`segment:{N}` 定下第 {N} 篇时的意见、`unit:{id}` 单元章纲的意见、`trial` 试读意见、`manual` 手动添加，其余写「其他」。

### 6.2 页面（本书设置的「作者要求清单」）

- 每条后面显示有效范围（`label`）；过期的整行变淡，标「已过期」，仍可改、可删；改有效范围就是〔修改〕里多一个下拉框（一直有效、只管下一章、只管这一卷、只管下一卷）。
- 标题行加〔整理一下〕：调 tidy，列出主编的建议，每条：原文、建议（删掉／改写成「……」）、理由，前面一个勾选框（「删掉」「改写」默认勾上，「保留」的不列出来）；底下〔照勾的改〕〔算了〕。〔照勾的改〕调 apply。全部是保留时提示「看过了，没有要整理的。」

### 6.3 「要记下的要求」小框（会议室里共用）

一个文字框加一个有效范围下拉框（一直有效、只管下一章、只管这一卷、只管下一卷），〔记下〕〔取消〕。第 2.3 节的「改一下」「其实要记下」和第 3 节的「记成要求」都用它。

## 7. 问问主编

- 定调页、设定库、大纲页、正文阅读页选中文字后出现的那一排按钮（任务 4 的「改这一句」所在的那一排；正文阅读页新加这一排，只有这一个按钮）加〔问问主编〕。

- 回答时 `quote` 变量写：

  ```
  【作者选中的原文】（{where}）
  {text，最多 2000 字}
  ```
