# 任务 4：开书界面

> 先读 `docs/codex任务/第三包/README.md` 和 `docs/设计说明.md` 第 13 节（重点 13.2、13.3、13.4、13.5、13.6），并确认任务 3 已完成并提交。视觉沿用现有的书房风格和组件（`components/ui.tsx`、`Editable.tsx`、`TechniqueChip.tsx` 等）。

## 目标

把任务 3 的简版页面换成正式页面，让作者照 13.2 的路径用起来顺手：

- 左边栏按流程排：概览、定调、设定库、大纲、正文；
- **定调页**：挑三个短版；一段话可以选中一句只改这一句；底牌、基本信息；
- **设定库页**：重点和各类别、条目列表、选中一条看详情；三种样式（卡片、阶梯、段落）；改这一句、改这一项、给我几个写法、自己改、历史、锁住；待处理的建议；补漏、全部查一遍；自建类别；
- **大纲页**：树和地图两种看法，线索也放进来；篇、卷、单元、章纲；改这一句、给我几个写法、自己改、锁住、改章数、增删挪动；
- 旧页面改为跳转。

界面上不出现「点杀」「段」这类内部说法：选中文字出现「改这一句」，一项上是「改这一项」，第二包的「段」一律叫「篇」。

## 2. 定调页（`pages/book/sections/StoryPage.tsx`）

### 2.1 挑三个短版（等 `setup_pitches` 时）

- 有 `benchmark` 时，页顶一张卡：「我理解的对标作品：{benchmark}」，下面一行小字「理解得不对？在下面的输入框里告诉主编。」
- 三张卡并排（窄屏竖排）：方向名、短版（正文字号）、书名候选（可点选，选中的书名随「用这个」一起提交）、「用这个」；推荐的那张标「主编推荐」。
- 下面一组篇幅五档（沿用第二包的 `length_question`），默认推荐档。
- 最下面一个输入框，占位文字「都不要？想混搭？直接说，比如：第一个的主角，配第二个的金手指」，旁边「再来三个」（输入框空时提示「先写一句你想怎么改」）。
- 提交走任务 3 的 `POST /jobs/{id}/pitches`。

### 2.2 定调（挑完以后，以及开写以后）

- **一段话**：正文字号，按句子渲染。作者在这段话里**选中一段文字**（鼠标拖选或手机长按），旁边浮出一个小工具条「改这一句」，点开有四项：给我几个写法、照我的意思改（弹出一个输入框）、写细一点、精简一点。调任务 2 的 `POST /books/{id}/library/rewrite`：`target_type = concept`，`path = story@{起}:{止}`（按这段话的字符位置算）。
- 这段话右上角两个按钮：「给我几个写法」（整段，`path = story`）、「自己改」（就地编辑，保存走 `PATCH /books/{id}`）。
- **候选**：出了候选，就在这段话下面显示三种写法（标「稳妥」「大胆」「出格」），每种一个「用这个」，调 `POST /candidates/{id}/choose`；没选的候选一直留着，直到作者选了或者关掉。
- **改动标出来**：AI 换进去的那一段（`applied.after`，或选中的候选），在这段话里标黄，直到作者做下一个操作。
- **底牌**：一行，前面一个锁的图标，「底牌（只有你和编辑部知道）：{内容}」；点它跳到设定库里那一条。`secret_entry_id` 为空时显示「这本书没有底牌」。
- **基本信息**：书名、类型、篇幅（万字）、每章字数、基调与文风、目标读者，紧凑排列，每项可以就地改（篇幅、每章字数改的是本书设置，和设置页一致）。
- 旧书（`concept.story` 为空）：显示「这本书开书时还没有一段话的定调」，下面列旧的一句话故事、核心卖点、核心循环（只读），加一个「让主编按现有内容写一段」按钮（调改一处，`path = story`，`mode = instruction`，`instruction` 为「按书的概念和设定库，写一段话的定调」）。
- **等确认时**（`setup_piece`，块 `concept`）：页底「确认，去建设定」和「提意见」（提意见切到群聊输入框，沿用第二包的做法）；替你做的决定沿用 `PieceDecisions`。

## 3. 设定库页（`pages/book/sections/LibraryPage.tsx`）

数据来自任务 1 的 `GET /library-config`、`GET /books/{id}/library`、`GET /books/{id}/suggestions`。

### 3.1 页面结构

```
┌ 页顶 ─────────────────────────────────────────────────────┐
│ （开书时）一句总结：主编建了 N 条……先看「重点」就行。          │
│ 待处理的建议 K　[全部接受]   ← 有建议时才显示，可以展开         │
│ [重点] [角色卡片 6] [等级体系 1] … [厉鬼 2]  [＋自建类别]       │
│ [只看现在要定] [只看有建议] [搜索…]     [让 AI 补漏] [全部查一遍] │
├ 左：条目列表 ──────────┬ 右：选中的那一条 ────────────────────┤
│ 名称          状态      │ 名称  标签  锁                       │
│ 一句话（一行）          │ 类别 · 状态 · 来源 · 第 N 版          │
│ …                      │ （卡片／阶梯／段落的内容）            │
│ [＋新增一条]            │ 改这一项 ▾  自己改  历史  查一查       │
└────────────────────────┴──────────────────────────────────────┘
```

- 类别按钮显示条数；有现在要定的条目时，条数后面加「· 要定 M」；某一类里有待处理建议的，加一个小圆点。
- 左边列表：按状态（现在要定、一句话就好、以后再说）再按位置排；每条两行：名称和状态、一句话（一行省略）；有待处理建议的条目名称后面一个小圆点。世界与地图按 `parent_id` 缩进成树。
- 一次只展开一条；按钮只出现在右边选中的那一条上。
- 窄屏（≤ 768px）：先显示列表，点一条进详情，详情页顶上「返回列表」。

### 3.2 三种样式的详情

- **卡片**（角色卡片、卡片样式的自建类别）：一行一个字段（字段名在左、内容在右），按 `CHARACTER_CATEGORY.fields` 或自建类别的 `fields` 排；空字段显示淡色「（空）」。角色卡片下面一块「写作中每章更新」：此刻想要、在哪、处境、是否活着（只读，旁边小字「设定师每章写」）。
- **阶梯**（等级体系）：先是总说明；下面一级一级从低到高排，每级一行：级名（加粗）和介绍；介绍空的显示「（还没写介绍）」。底下「＋加一级」。
- **段落**：一句话（小一号，标「一句话」），下面一段话。
- 往事与秘密：有 `secret_id` 的，下面一块「谁知道」：列出那条信息差的知情人和「读者知不知道」；没有的显示「还没关联信息差」和一个选择框（从这本书的信息差里选一条）。
- 世界与地图的地方：「属于哪里」一个选择框（同类别的其他条目）。

### 3.3 改的方式

| 操作 | 在哪 | 做什么 |
|---|---|---|
| 改这一句 | 在一段话、卡片的某个字段、阶梯某一级的介绍里**选中文字**，浮出「改这一句」 | 四项：给我几个写法、照我的意思改、写细一点、精简一点；调改一处，`path` 带 `@起:止` |
| 改这一项 | 详情右上角，或卡片的某一行、阶梯的某一级右边（鼠标停在那一行时出现） | 同样四项；`path` 是这一项（`content`、`fields.<名>`、角色卡片的列、`levels.<i>.text` 或 `levels.<i>.name`） |
| 自己改 | 详情右上角 | 整条进入编辑：每个字段、每一级都能直接改；保存一次 `PATCH` |
| 历史 | 详情右上角 | 列出版本（第几版、来源、为什么改、时间），每版能看内容、能「退回到这一版」 |
| 锁住 | 名称旁边 | 切换 `locked`；锁住的条目，改这一句、改这一项都提示「已锁：AI 不能改这一处，先解锁」，自己改照常 |
| 查一查 | 详情右上角 | 调 `POST /library/check`，结果进待处理的建议，并在这一条下面直接列出来 |
| 状态、标签 | 详情第二行 | 状态是一个小下拉（现在要定、一句话就好、以后再说）；标签可以加减，常用标签（`COMMON_TAGS`）一点就加 |

- 出了候选：在那一处的下面显示三种写法和「用这个」，同定调页。
- AI 换进去的那一处标黄，直到作者做下一个操作。
- 模型在想的时候，那一处显示「主编正在想……」，按钮不能重复点；出错时显示错误原因和「再试一次」。

### 3.4 待处理的建议

- 页顶一条：「待处理的建议 K」，点开是列表，每条：标题、「改」（或接受建议对应的动作名：建、补）、「不用」；`written` 类的展开能看到每章出现的次数和上下文；锁住的目标显示「（已锁）」，点「改」时提示先解锁。
- 「全部接受」：调 `accept-all`，返回里跳过的逐条列出原因。
- 建议涉及的条目，在列表里有小圆点；点建议的标题跳到那一条。

### 3.5 新增、删除、自建类别

- **＋新增一条**：在当前类别下新建，填名称（必填）和状态；建好以后可以「让 AI 先填一版」（调改一处，`path = content` 或第一个字段，`mode = instruction`，`instruction` 为「按定调和这一类该写清的事，写这一条」）。
- **删除**：详情里「更多」菜单里的「删除这一条」，要确认。
- **＋自建类别**：弹窗填名称、选卡片或段落、卡片样式时加减字段名（可调顺序）、一句「这一类该写清什么」。建好以后出现在类别按钮里。自建类别的「更多」菜单里可以改名、改字段、删除（还有条目时提示先删掉或挪走）。

### 3.6 补漏、全部查一遍

页顶两个按钮，调任务 2 的接口；结果进待处理的建议，并在群聊里看得到主编和审稿的话。

### 3.7 等确认时（`setup_piece`，块 `settings`）

页顶显示 `summary`；页底「设定先这样，去出大纲」和「提意见」；替你做的决定沿用 `PieceDecisions`。

## 4. 大纲页（`pages/book/sections/OutlinePage.tsx`）

数据来自任务 1 的 `GET /books/{id}/outline-tree`。

### 4.1 三种看法

页顶切换：**树**（默认）、**地图**、**线索**。

- **地图**：搬现在全书地图页（`SpinePage`）的内容：分段地图、篇带、节点；文字里的「段」都改成「篇」（如「第 2 篇 · 第 3-4 卷 · 约 120 章」「现在就规划下一篇」）。
- **线索**：搬现在线索页（`ThreadsPage`）的内容。

### 4.2 树

- 左边一棵树：全书 → 篇 → 卷 → 单元 → 章纲；每个节点一行：三角（有下一层时）、名称、章数或章号范围、状态小标签（已写完、正在写、已规划、写到再定）、锁的图标（锁住时）。
- 默认只展开正在写的那一篇、那一卷（开书时是第一篇、第 1 卷），正在写的那一行标出来。
- 右边是选中的那个节点：名称、一段话（或一句话）、章数；和设定库一样，选中文字出「改这一句」，右上角「给我几个写法」「自己改」「锁住」「历史」。改一处的 `target_type`：篇 `segment`（`path = text` 或 `title`）、卷 `volume`（`summary`）、单元 `unit`（`summary`）。
- 章纲节点：显示这一章的标题、要完成的剧情、场景、爽点、钩子（只读，来自章纲）；已写的章节加「去看正文」。
- 写到再定的篇：显示「写到再定 · 写到这里之前，主编会先来定下一篇」。
- 终点就是结局、还没规划的那一篇（`end.kind` 是 `ending`、`planned = false`，就是「最后一个篇到结局之间」还没定的那一段）：名称显示「后面的篇」，不编号，不显示它的一段话（那是结局的内容，结局在最后一行单独显示）。其余的篇按顺序编「第 N 篇」。
- 已规划的篇一段话是空的（第二包开的书只有篇名）：显示终点的发生什么（`end.event`）。
- 结局：一行，可以自己改（改的是结局节点的 `event`）。

### 4.3 改结构

只能改还没写的部分（篇、卷、单元下面没有已定稿或正在写的章节）；已写的部分，这几个按钮不出现。

| 操作 | 在哪 | 接口 |
|---|---|---|
| 改章数 | 卷和单元的详情里，一个数字框 | `PATCH /volumes/{id}`、`PATCH /units/{id}` |
| 加一个单元 | 卷的详情里「＋加一个单元」，或单元的「更多」里「在后面加一个单元」；**还没拆成单元的卷不出现这个按钮**，改为一行小字「这一卷还没拆成单元。想要的情节写进这一卷的一段话，写到这一卷时主编会照着拆。」 | 新接口，见第 6 节 |
| 删掉这个单元 | 单元的「更多」菜单，要确认 | 新接口 |
| 上移、下移 | 单元的「更多」菜单 | 新接口 |
| 加一卷、删掉这一卷 | 篇的详情里「＋加一卷」，卷的「更多」菜单 | 新接口 |

### 4.4 等确认时（`setup_piece`，块 `outline`）

页底「确认，开写」和「提意见」。「确认，开写」先确认大纲，等开书任务结束，再自动调 `POST /books/{id}/write`（任务 3 的简版已经这样做，这里沿用）。

## 6. 后端：大纲结构的增删挪动

在 `app/api/books.py` 加：

| 接口 | 说明 |
|---|---|
| `POST /volumes/{volume_id}/units` | `{title, summary, chapter_count, after_unit_id}`：在指定单元后面插入一个单元（`after_unit_id` 为空就放在最前面）；`index` 依次重排。这一卷还没有任何单元时 409「这一卷还没拆成单元，不能单独加」（写到这一卷时主编会整卷拆，单独加的会被覆盖） |
| `DELETE /units/{unit_id}` | 删单元；它下面只有「计划中」的章节（没有定稿或正在写的）时才能删，章节一起删；否则 409「这个单元已经开写了，不能删」 |
| `POST /volumes/{volume_id}/units/order` | `{ids}`：重排单元；已经开写的单元不能挪到没开写的单元后面 |
| `POST /books/{book_id}/volumes` | `{title, summary, chapter_count, target_node_id, after_volume_id}`：插入一卷，`index` 依次重排 |
| `DELETE /volumes/{volume_id}` | 删一卷；卷里有已开写的章节时 409「这一卷已经开写了，不能删」 |

- 改动以后，后面没开写的章节号按单元章数顺延（沿用写作流程算章号的规则）；
- 每个改动都给受影响的卷、单元记一版（任务 1 的版本）。

另外，`GET /books/{book_id}/outline-tree`（`app/api/outline_tree.py`）的每一篇加一个键 `end`：`{"title", "event", "kind"}`，是这一篇终点节点的名称、发生什么和类型（`milestone` 或 `ending`；没分段的旧书「全书」那一篇为 `null`）。其余不变。

在独立环境里，每步截图，结果写进 `docs/第三包验收.md` 的「任务 4」小节：

1. 新建一本书：挑短版（换一个书名候选、改篇幅）；定调页里选中一句「改这一句 → 给我几个写法」，选一个，看到标黄；确认；
2. 设定库：页顶总结和建议；先看「重点」；对等级体系的某一级「改这一项 → 给我几个写法」，选第二项，看到连带建议；在建议里「全部接受」；锁住一条再试改这一项，看到提示；看历史并退回一版；建一个自建类别（卡片，三个字段）并新增一条；确认；
3. 大纲：树默认展开第一篇和第 1 卷；选中一个单元，改一句、改章数；加一个单元再删掉；切到地图和线索；「确认，开写」后写完前 3 章；
4. 开写以后回到定调页改一句，设定库里出现「定调改了」的建议；
5. 旧路由（`/protagonist`、`/spine`、`/world`）跳到新页面；
6. 一本第二包开的旧书：定调页显示旧内容和「让主编按现有内容写一段」；设定库里看到迁移来的条目；大纲树按篇显示；
7. 窄屏（390×844）和暗色模式下，定调页、设定库、大纲各截一张。
