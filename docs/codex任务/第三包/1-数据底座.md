# 任务 1：数据底座

> 先读 `docs/codex任务/第三包/README.md` 和 `docs/设计说明.md` 第 13 节（重点 13.2、13.4、13.5、13.7）。

## 目标

给设定库、定调和大纲树打好数据和接口的底子，旧书迁移过来。这个任务**不改开书和写作的行为**，也不改页面：做完后老流程照常开书、写作，只是多了字段、表、配置和接口。

做完以后：

- 设定库有七个默认类别和自建类别；角色卡片在 `characters`，其余类别在 `world_entries`；
- 条目有样式（卡片、阶梯、段落）、状态、标签、一句话、锁、来源；
- 每一次修改都留版本，能退回；
- 有「候选」和「待处理的建议」两张表，以及按路径把一处文字换进去的通用办法（任务 2 的 AI 操作靠它保证别处不动）；
- 大纲树（篇 → 卷 → 单元 → 章纲）有一个读取接口，篇、卷、单元都能写一段话、能锁住；
- 已有的书迁移进新结构，照常续写。

## 3. 接口

### 3.1 配置

`GET /library-config`：返回 `STATUSES`、`STYLES`、`SOURCES`、`FOCUS_TAGS`、`COMMON_TAGS`、`ROLE_TYPES`、`LEGACY_ROLE_TYPES`、`CHARACTER_CATEGORY`（`fields` 和 `state_fields` 转成 `[{"name", "column"}]`）、`BUILTIN_CATEGORIES`、`GENRE_DEFAULTS`（转成 `{题材: [{"category", "name", "status"}]}`）。前端从这里读，不在前端再抄一份。

### 3.2 设定库

`GET /books/{book_id}/library`：

```json
{
  "categories": [
    {"key": "角色卡片", "name": "角色卡片", "style": "card", "builtin": true, "hint": "…", "count": 6, "must_count": 4},
    {"key": "等级体系", "name": "等级体系", "style": "ladder", "builtin": true, "hint": "…", "count": 1, "must_count": 1},
    "… 其余内置类别 …",
    {"key": "custom:ligui", "name": "厉鬼", "style": "card", "builtin": false, "fields": ["外形", "杀人规律"], "hint": "", "count": 2, "must_count": 1, "id": "…"}
  ],
  "characters": ["CharacterOut，含新字段"],
  "entries": ["WorldEntryOut，含新字段"],
  "focus": {"characters": ["id…"], "entries": ["id…"]},
  "suggestions_pending": 2
}
```

- 顺序：角色卡片、六个内置类别（按 `BUILTIN_CATEGORIES` 顺序）、自建类别（按 `position`）。
- `focus`：定位是主角的角色卡片，加上 `tags` 含 `FOCUS_TAGS` 任一个的角色卡片和条目。
- 条目和角色卡片都按 `status`（现在要定、一句话就好、以后再说）再按 `position` 排。

### 3.3 条目和角色卡片

沿用现有接口，扩展字段：

- `WorldEntryBase`、`WorldEntryPatch` 加上 `style`、`status`、`tags`、`one_line`、`aliases`、`fields`、`levels`、`parent_id`、`secret_id`、`locked`、`position`（`source` 只读，由服务端写）。
- `CharacterBase`、`CharacterPatch` 加上 `one_line`、`relation`、`status`、`tags`、`locked`、`position`。
- 校验：
  - `category` 必须是内置类别或这本书已有的自建类别（`custom:<key>`），旧类别名先过 `normalize_category`；
  - `style` 不传时按 `category_style` 自动定；传了但和类别的样式对不上，返回 422「这个类别用的是{样式}」；
  - `status` 只能是 `STATUSES` 的键；
  - `parent_id` 必须是同一本书里「世界与地图」的条目，不能指向自己或自己的下级；
  - `secret_id` 必须是同一本书的信息差。
- 作者通过接口新建的，`source` 写 `author`；作者修改的，原来是 `author` 的保持不变，其余一律改为 `ai_edited`。锁只拦 AI，不拦作者。
- 每次通过接口新建、修改条目或角色卡片，都按第 4 节记一版。

`BibleOut` 里的人物和设定条目也带上这些新字段，旧页面不受影响。

### 3.4 自建类别

- `GET /books/{book_id}/setting-categories`
- `POST /books/{book_id}/setting-categories`：`{name, style, fields, hint}`。`key` 由服务端按名称生成（拼音或短随机串都行，同一本书里唯一）。`style` 只能是 `card` 或 `paragraph`。
- `PATCH /setting-categories/{id}`：可以改 `name`、`fields`、`hint`、`position`；不能改 `style`（422「类别的样式建好后不能改」）。删掉的字段，条目里对应的值保留在 `fields` 里，不删。
- `DELETE /setting-categories/{id}`：类别下还有条目时返回 409「这个类别下还有 N 条设定，先删掉或挪走」。

### 3.5 版本

- `GET /books/{book_id}/versions?target_type=…&target_id=…`：按 `version` 倒序。
- `POST /versions/{version_id}/revert`：把这一版的 `snapshot` 写回目标，再记一版（`source = 'revert'`，`note = 退回到第 {N} 版`），返回目标的最新内容。

### 3.6 候选

- `GET /books/{book_id}/candidates?target_type=…&target_id=…`
- `POST /candidates/{id}/choose`：`{index}`。按第 5 节把 `options[index].text` 换到 `path`；成功后 `chosen = index`，目标记一版（`source = 'candidate'`）。可以反复换成别的选项（每换一次记一版）。

候选由任务 2 的 AI 操作生成；这个任务只做表、读取和「换进去」。

### 3.7 待处理的建议

- `GET /books/{book_id}/suggestions?status=pending`：按 `created_at` 倒序。
- `POST /suggestions/{id}/accept`：按第 6 节执行 `payload`，`status = 'accepted'`，`resolved_at = now`。
- `POST /suggestions/{id}/ignore`：只改状态。
- `POST /books/{book_id}/suggestions/accept-all`：逐条执行所有待处理的建议，遇到失败的（目标已锁、原文对不上）跳过并在返回里列出原因，其余照常执行。

### 3.8 大纲

扩展现有接口：

- `PATCH /units/{unit_id}`：加 `summary`、`locked`。
- `PATCH /volumes/{volume_id}`：加 `locked`。
- `SegmentPatch` 加 `title`、`text`。
- 这三处每次修改都按第 4 节记一版（`unit`、`volume`、`segment`）。

新接口 `GET /books/{book_id}/outline-tree`：

```json
{
  "arcs": [
    {
      "node_id": "…",
      "title": "青阳城篇",
      "text": "…",
      "status": "writing",
      "locked": false,
      "planned": true,
      "volumes": [
        {
          "id": "…", "index": 1, "title": "废物", "summary": "…", "chapter_count": 60, "status": "writing", "locked": false,
          "units": [
            {"id": "…", "index": 1, "title": "退婚", "summary": "…", "chapter_count": 5, "status": "done", "locked": false,
             "chapters": [{"index": 1, "title": "帝尊陨落", "status": "final"}]}
          ]
        }
      ]
    }
  ],
  "ending": {"node_id": "…", "title": "…", "event": "…"},
  "segmented": true
}
```

- 篇的划分和第二包前端 `segmentBands` 一致：从开篇起，相邻两个节点之间是一篇，终点是后一个节点；终点带 `segment` 的是已规划的篇（`planned = true`，`title`、`text` 取 `segment.title`、`segment.text`）；终点没有 `segment` 的是写到再定的篇（`planned = false`，`title` 取节点标题，`text` 取节点的 `event`）。卷按 `target_node_id` 归到篇。
- `status`：篇和卷按第二包的规则算（`done`、`writing`、`planned`、`later`）；单元和章照数据库里的状态。
- 不是分段规划的旧书（没有任何节点带 `segment`）：`segmented = false`，只返回一个篇，`title` 为「全书」，所有卷都在里面。
- 这个接口只读，不改任何数据。

### 3.9 定调

`books.concept` 是 JSON，不加列。约定三个新键，`BookPatch.concept` 照旧整块写入：

- `story`：一段话（定调）；
- `pitches`：三个短版，`[{"name": "…", "text": "…", "titles": ["…", "…"]}]`；
- `secret_entry_id`：底牌那一条的 id，可空。

通过 `PATCH /books/{id}` 改了 `concept`，按第 4 节记一版（`target_type = 'concept'`，`target_id` 是书的 id）。

## 4. 记版本

新建 `backend/app/services/versions.py`：

- `snapshot_of(target)`：返回目标可编辑部分的字典：
  - 条目：`category`、`name`、`aliases`、`style`、`status`、`tags`、`one_line`、`content`、`fields`、`levels`、`parent_id`、`secret_id`、`locked`、`position`；
  - 角色卡片：`CHARACTER_CATEGORY` 里 `fields` 的全部列，加 `one_line`、`status`、`tags`、`locked`、`position`（不含每章更新的状态）；
  - 定调：整块 `concept`；
  - 篇：节点的 `title`、`event`、`status` 和整块 `segment`；
  - 卷：`title`、`summary`、`chapter_count`、`locked`，以及第二包那些分开的字段；
  - 单元：`title`、`summary`、`chapter_count`、`locked`，以及第二包那些分开的字段。
- `record_version(session, book_id, target_type, target, source, note="")`：
  - 这个目标还没有任何版本时，先把**改之前**的内容记成第 1 版（`source` 取目标原来的 `source`，没有就 `ai`；`note = 初版`），再记改之后的内容；
  - 有版本时，直接记改之后的内容，`version` 加一。
  - 调用方要在修改前先拿一次 `snapshot_of`，传进来作为「改之前」。具体签名按代码习惯定。
- `apply_snapshot(target, snapshot)`：把快照写回目标，供退回用。

## 5. 按路径换进去（保证别处不动）

新建 `backend/app/services/splice.py`。任务 2 的「改这一句／改这一项」和这里的候选、建议，全都靠它把一处文字换进去：AI 只交回那一处的新文字，程序负责换，别的字段、别的句子由程序保证不动。

**路径的写法**：

| 路径 | 指的是 |
|---|---|
| `content`、`one_line`、`name` | 条目的这一列 |
| `fields.<字段名>` | 卡片样式条目的某个字段 |
| `levels.<序号>.name`、`levels.<序号>.text` | 阶梯的某一级（序号从 0 开始） |
| `<列名>` | 角色卡片的某一列，如 `personality`、`background` |
| `story` | 定调的一段话 |
| `text`、`title` | 篇的一段话、篇名 |
| `summary` | 卷或单元的一段话 |
| 以上任一个加 `@<起>:<止>` | 这一处文字里的一段（按字符位置），如 `content@12:40` |

**`splice(target, path, new_text, base=None)`**：

1. 解析路径，取出这一处当前的文字；
2. 带 `@起:止` 的：先看当前文字在这个位置上是不是 `base`；不是的话，在当前文字里找 `base` 第一次出现的位置；找不到就报错「原文已经改过，没法只换这一段」；找到了就只换这一段；
3. 不带位置、但给了 `base` 的：当前文字要等于 `base`，否则同样报错；
4. 写回目标，只动这一处；
5. 返回改之前和改之后的这一处文字，供调用方记版本、给前端标出改动。

`fields.<字段名>` 指向的字段不存在时新建这个字段；`levels.<序号>` 越界时报错。

## 6. 建议的操作（`payload`）

`accept` 时执行，全部由程序完成，不调模型：

| `op` | 字段 | 做什么 |
|---|---|---|
| `replace_text` | `target_type`、`target_id`、`path`、`old`、`new` | 在这一处文字里，把所有 `old` 换成 `new`（用 `splice` 写回） |
| `splice` | `target_type`、`target_id`、`path`、`base`、`new` | 同第 5 节 |
| `create_entry` | `entry`（`category`、`name`、`one_line`、`content`、`status`、`tags`、`style`、`levels`、`fields`） | 新建条目，`source = 'suggestion'` |
| `create_character` | `character`（角色卡片字段） | 新建角色卡片，`source = 'suggestion'` |
| `set_field` | `target_type`、`target_id`、`path`、`value` | 把这一处直接设成 `value` |
| `note` | 无 | 只是提醒（查一遍的结果），接受就是标记已处理 |

- 目标已锁（`locked = true`，或篇的节点是 `pinned`）时，`accept` 返回 409「这一条已锁，先解锁再改」，建议保持待处理。
- 执行成功后，目标按第 4 节记一版（`source = 'suggestion'`，`note` 用建议的 `title`）。
