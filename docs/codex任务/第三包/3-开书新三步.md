# 任务 3：开书新三步

> 先读 `docs/codex任务/第三包/README.md` 和 `docs/设计说明.md` 第 13 节（重点 13.2、13.3、13.4、13.5），并确认任务 1、2 已完成并提交。

## 目标

新书按「定调 → 设定库 → 大纲」开书：

1. **三个短版**：主编按点子给三个短版定调（各一百字左右，加书名候选），作者挑一个，或在输入框里说「都不要」「A 的主角配 B 的金手指」重出；挑的时候一并选篇幅（沿用第二包的五档）。
2. **定调**：主编把挑中的短版展开成一段话，加底牌和基本信息；底牌同时建成设定库「往事与秘密」里锁住的一条。作者确认。
3. **设定库**：先出重点（主角的角色卡片、金手指），再补其余条目；建完自动查一遍，问题进待处理的建议。作者确认。
4. **大纲**：第一篇一段话、结局一句话、中间只列定调里提到的篇；第一篇分卷；第 1 卷拆单元；第一个单元出章纲。作者确认后就能开写。

另外：一口气模式自动挑推荐的短版、不停地做完定调和设定库，停在大纲给作者看；三步不锁，回头改不推倒重来；第二包流程中途的开书任务「按新流程重开」；演示模式跑得通；网页能走完整个开书（页面是简版，任务 4 补全）。

## 2. 三个短版

### 2.1 结构化产出

`app/agents/schemas.py` 新增（逐字照抄，字段顺序照抄）：

```python
class Pitch(Lenient):
    name: str = Field(description="方向名：给这个版本贴的标签，4-8 字，说清主打什么，如「废柴逆袭流」；不是书名")
    text: str = Field(description="短版定调：一百字左右，一段话说清主角是谁、凭什么、想要什么、读者爽在哪")
    titles: list[str] = Field(description="2 个书名候选：一个突出金手指或核心意象，一个突出主角或反差")


class PitchSet(Lenient):
    benchmark: str = Field(
        default="",
        description="作者点名对标某本书时，写出你理解的读者爱那本书什么：核心设定、爽点、主角气质；拿不准的写「不确定」；没有对标就留空",
    )
    pitches: list[Pitch] = Field(
        description="三个短版，彼此在读者享受的东西上有实质差别；作者定下的东西三个都保留"
    )
    recommended: int = Field(ge=1, le=3, description="推荐第几个")
    reply: str = Field(description="主编在群聊里说的话：一两句白话说清推荐哪个、为什么；有对标时顺带请作者看看理解对不对")
```

### 2.2 生成

`pitches` 节点调 `setup_pitches`（主编，`PitchSet`），变量：

- `idea`：作者的点子；
- `style`、`requirements`：和第二包一样（`format_style`、`format_requirements`）；
- `previous`：重出时程序拼的上一轮，第一轮为空字符串：

  ```
  【上一轮的短版】
  1. {名称}：{短版}
  2. {名称}：{短版}
  3. {名称}：{短版}
  【作者的意见】
  {意见}
  ```

  从第二包旧任务重开时（第 6 节），第一轮的 `previous` 是：

  ```
  【之前按旧流程选过的方向】
  {方向名}：{一句话故事}
  （作者之前选过它，三个短版里请保留它的好东西。）
  ```

主编在群聊发 `reply`。不足三个或超过三个时，程序重试一次；还不对就取前三个、不足的报错停下。

### 2.3 等作者挑

`pitches_gate` 中断，`pending`：

```json
{"kind": "setup_pitches", "flow": 3, "round": 1, "benchmark": "…", "pitches": [...], "recommended": 2, "length": {"…": "沿用第二包 length_question 的结构"}}
```

新接口 `POST /jobs/{job_id}/pitches`（第二包的 `/directions` 删掉，旧任务调用返回 409「这个任务用的是旧流程，请按新流程重开」）：

- `{"action": "pick", "index": 1, "length": 200, "title": "逆世帝尊"}`：`index` 从 1 开始；`length` 取五档之一（不传用推荐档）；`title` 可选，作者从书名候选里挑的或自己写的。挑中的短版、对标理解、篇幅、书名写进状态，进入定调。
- `{"action": "redo", "feedback": "A 的主角配 B 的金手指"}`：`feedback` 不能空；记成作者要求（沿用第二包的做法），回到 `pitches` 重出，`round` 加一。

## 3. 定调

### 3.1 结构化产出

```python
class StoryConcept(Lenient):
    story: str = Field(description="定调：一段话，200-400 字，说清这本小说主要讲什么故事")
    secret: str = Field(
        description="底牌：全书最大的秘密，一两句，只有作者和编辑部知道；金手指的来历、幕后的人最好都落在它上面；这本书没有大秘密就写「没有」"
    )
    title: str = Field(description="书名本身（不带书名号、不带备选）")
    alt_titles: list[str] = Field(default_factory=list, description="2-3 个备选书名，风格与书名一致")
    genre: str = Field(description="类型，如「玄幻·修仙」「都市·重生」")
    tags: list[str] = Field(default_factory=list, description="3-6 个标签")
    target_reader: str = Field(default="", description="目标读者：男频还是女频、这类读者爱看什么、最讨厌什么，一句话")
    tone: str = Field(description="基调与文风：轻松还是压抑、幽默还是冷峻、节奏快还是慢，一两句")
    target_length: int = Field(
        default=100,
        ge=5,
        le=1000,
        description="全书计划总字数，单位：万字（200 万字就填 200）。以作者要求为准；作者没说时按类型的主流长度",
    )
    chapter_words: int = Field(ge=1000, le=8000, description="每章目标字数，通常 2000-4000")
    decisions: list[AuthorChoice] = decisions_field()
    remark: str = remark_field("这一段为什么这样写、底牌怎么和金手指连上")
```

`target_length` 沿用第二包 `BookConcept` 的换算校验（`_to_wan`）。

### 3.2 生成和保存

`concept` 节点调 `setup_story`（主编，`StoryConcept`），变量：`idea`、`style`、`requirements`、`revision`（第二包的 `format_revision`，第一轮为空），以及 `pitch`：

```
{名称}：{短版}
书名候选：{候选，用顿号连起来}
对标理解：{benchmark}
```

（`benchmark` 空的不写第三行。）作者在挑的时候选了篇幅或书名的，以作者为准，覆盖模型给的。

保存（`piece_persist`）：

- `books.concept` 合并写入：`story`、`pitches`（三个短版）、`title`、`alt_titles`、`genre`、`tags`、`target_reader`、`tone`、`target_length`、`chapter_words`、`benchmark`；书的 `title`、`genre` 同步。
- `secret` 不是「没有」时：设定库「往事与秘密」里建或更新名为「底牌」的条目：`content = secret`，`one_line` 取第一句，`tags = ["底牌"]`，`locked = true`，`status = 'must'`，`source = 'ai'`；`concept.secret_entry_id` 指向它。这一条已经被作者改过（`source` 不是 `ai`）时不覆盖。`secret` 是「没有」时不建，`secret_entry_id` 为空。
- 记一版（任务 1 的版本，`target_type = 'concept'`）。

### 3.3 程序检查

- `story` 少于 150 字或多于 500 字：自动重写一次，`revision` 写「定调要写成一段话，200-400 字，现在是 {N} 字。」；
- 还不对，或 `secret` 为空：在 `piece_gate` 的 `warnings` 里提醒，不挡确认。

## 4. 设定库

### 4.1 结构化产出

```python
class CharacterCardDraft(Lenient):
    name: str = Field(description="姓名；作者定过的照用")
    aliases: list[str] = Field(default_factory=list, description="别名、外号、化名；没有就留空")
    role_type: Literal["主角", "女主", "男主", "班底", "对手", "导师", "配角"] = Field(description="定位")
    status: Literal["现在要定", "一句话就好", "以后再说"] = Field(
        default="现在要定", description="现在要定的写全；一句话就好、以后再说的只写名字和一句话"
    )
    one_line: str = Field(description="一句话：这个人是谁、在故事里干什么")
    gender: str = Field(default="", description="性别")
    age: str = Field(default="", description="年龄或年龄段")
    appearance: str = Field(default="", description="外貌，一两个记得住的特点")
    personality: str = Field(default="", description="性格与说话方式：2-3 个核心性格加一个反差，再写一两句他会说的话")
    background: str = Field(default="", description="身世：公开的来历；藏着的秘密不要写在这里")
    goal: str = Field(default="", description="想要什么：长远的和眼下的，各一句")
    abilities: str = Field(default="", description="能力：本事、修为、技能，用等级体系里的叫法")
    relation: str = Field(default="", description="和主角的关系，一句话；主角本人留空")
    want: str = Field(default="", description="此刻想要什么：故事开始时最想马上做成的事，一句话")


class FingerDraft(Lenient):
    place: Literal["物品与功法", "特殊规则", "角色卡片"] = Field(
        description="金手指放在哪：是东西放物品与功法，是系统或机制放特殊规则，是主角天生的特质就写在主角的角色卡片里"
    )
    name: str = Field(description="金手指的名称，如「轮回镜」；写在角色卡片里的，填主角的名字")
    one_line: str = Field(description="一句话")
    content: str = Field(
        description="一段话：写成主角在故事里遇到的样子——能做什么、第一阶段有多大本事、限制和代价、谁知道、以后往哪长；来历落在底牌上，但不要直接把底牌写出来"
    )


class LibraryFocus(Lenient):
    protagonist: CharacterCardDraft = Field(description="主角的角色卡片，写全")
    finger: FingerDraft = Field(description="金手指；没有金手指的书，写主角最大的优势，放在角色卡片里")
    decisions: list[AuthorChoice] = decisions_field()
    remark: str = remark_field("主角为什么非往前走不可、金手指怎么和底牌连上")


class LevelDraft(Lenient):
    name: str = Field(description="这一级的名称")
    text: str = Field(default="", description="这一级的介绍，一两句；高阶的可以留空，以后再补")


class EntryDraft(Lenient):
    category: str = Field(
        description="放进哪一类：等级体系、世界与地图、势力划分、物品与功法、往事与秘密、特殊规则；七类放不下、属于建议的自建类别的，写那个自建类别的名字"
    )
    name: str = Field(description="条目名称；世界与地图的第一条叫「世界概况」")
    status: Literal["现在要定", "一句话就好", "以后再说"] = Field(description="现在要定、一句话就好、以后再说")
    one_line: str = Field(description="一句话")
    content: str = Field(
        default="",
        description="一段话（等级体系写总说明：怎么往上升、越级多难、有什么代价）；一句话就好、以后再说的留空",
    )
    levels: list[LevelDraft] = Field(
        default_factory=list,
        description="只有等级体系才写：各级从低到高；没有正式等级的，写一级「没有」，并在总说明里说清怎么看强弱",
    )
    fields: list[FieldValue] = Field(default_factory=list, description="只有卡片样式的自建类别才写：它的字段")
    parent: str = Field(default="", description="只有世界与地图里的地方才写：属于哪里，写上级地方的名称；没有就留空")


class LibraryRest(Lenient):
    characters: list[CharacterCardDraft] = Field(
        default_factory=list,
        description="主角以外的角色卡片：第一卷就登场的写全（班底、女主或男主、导师、开篇的小麻烦、第一个大对手），后面才登场的写「以后再说」；要紧的人物八个以内",
    )
    entries: list[EntryDraft] = Field(description="设定条目：按题材常建的条目起步，用得上的才建，用不上的不建")
    categories: list[NewCategory] = Field(
        default_factory=list,
        description="七个默认类别放不下、又是这本书的核心东西时，建议新建的自建类别，最多 2 个；作者同意才建",
    )
    decisions: list[AuthorChoice] = decisions_field()
    remark: str = remark_field("这本书的设定以什么为主、哪几条最要紧")
```

（`FieldValue`、`NewCategory` 是任务 2 加的。）

### 4.2 先出重点

`settings_focus` 节点调 `library_build_focus`（设定师，`LibraryFocus`），变量：`concept`（任务 2 第 3.1 节的拼法）、`genre_defaults`（任务 2 第 3.7 节）、`requirements`、`revision`。

保存（这一步立刻写库并发消息，不等后面）：

- 主角：按姓名建或更新角色卡片，`role_type = '主角'`，`status` 换成 `must` 这类键，`source = 'ai'`；已经被作者改过的字段（这张卡片 `source` 是 `author` 或 `ai_edited` 时）不覆盖。
- 金手指：`place` 是「物品与功法」「特殊规则」时，在那一类建或更新同名条目，`tags` 含 `金手指`；是「角色卡片」时，`content` 写进主角的 `abilities`（主角的 `abilities` 已有内容就接在后面），主角的 `tags` 加 `金手指`。
- 记版本；群聊（主编）：`重点先出来了：主角「{姓名}」和金手指「{名称}」。其余设定正在补。`
- 发一次进度事件，让页面马上看到这两条。

### 4.3 补齐其余

`settings_rest` 节点调 `library_build_rest`（设定师，`LibraryRest`），变量：`concept`、`genre_defaults`、`requirements`、`revision`，以及：

- `focus`：主角和金手指两条，按任务 2 第 3.3 节的 `entry_full_text` 逐条写，之间空一行；
- `category_hints`：

  ```
  【角色卡片】{CHARACTER_CATEGORY 的 hint}
  【等级体系】{hint}
  【世界与地图】{hint}
  【势力划分】{hint}
  【物品与功法】{hint}
  【往事与秘密】{hint}
  【特殊规则】{hint}
  ```

保存：

- 角色卡片：按姓名建或更新（作者改过的不覆盖，同上），`status` 换成键；
- 条目：类别是内置类别的直接建；类别是 `categories` 里某个建议的自建类别的，**先不建**，收进第 4.5 节的建议；类别对不上任何一个的放进「特殊规则」；
- 等级体系的条目 `style = 'ladder'`，`levels` 照写；
- `parent` 按名称找同一本书「世界与地图」里的条目，找到就挂上，找不到留空；
- 同名、同类别的条目已经存在：被作者改过（`source` 不是 `ai`、`migration`）的不覆盖，其余更新；
- 「世界概况」排在世界与地图第一（`position = 0`），其余按模型给的顺序。

### 4.4 建完自查

补齐以后，先做程序检查，再自动查一遍：

**程序检查**（不通过的，带着问题自动重写 `settings_rest` 一次；还不通过的，进待处理的建议，`op = note`）：

| 检查 | 不通过时的问题（写进 `revision`） |
|---|---|
| 没有「世界概况」 | 世界与地图的第一条要叫「世界概况」。 |
| 状态是现在要定、但一段话（或角色卡片的性格、身世、想要什么）是空的 | 「{名称}」是现在要定的，还没写一段话。 |
| 等级体系的条目没有任何一级 | 「{名称}」还没写各级；没有正式等级就写一级「没有」。 |
| 除主角外，第一卷要登场的角色卡片一张都没有 | 还没写第一卷登场的人物。 |

**自动查一遍**：调任务 2 的 `library_review`（审稿），`scope` 写「这是开书时刚建好的设定库，查整个设定库。」，结果按任务 2 第 4.4 节进待处理的建议。

### 4.5 建议的自建类别

`categories` 的每一项生成一条建议（任务 2 的 `create_category`），`payload.category` 里再带上 `entries`：属于这个类别的条目（第 4.3 节先没建的那些）。接受时先建类别，再把这些条目建进去。标题：`建一个自建类别「{名称}」，放进{N}条设定——{why}`。

### 4.6 页顶总结

`piece_gate` 的 `pending` 里加 `summary`，并由主编在群聊发同样一句：

```
主编建了 {总数} 条：现在要定 {M} 条，一句话 {O} 条，以后再说 {P} 条。先看「重点」就行。
```

（总数含角色卡片；有待处理的建议时，后面加「另外有 {K} 条建议等你看。」）

## 5. 大纲

### 5.1 结构化产出

```python
class ArcDraft(Lenient):
    title: str = Field(description="篇名，如「青阳城篇」「宗门篇」")
    text: str = Field(
        description="第一篇写一段话（在哪个舞台、主角这一篇想做成什么、谁挡路、怎么收尾、读者在等什么和揭开什么、主角从哪儿走到哪儿）；后面的篇只写一句方向"
    )
    planned: bool = Field(description="第一篇填 true；后面的篇填 false（写到再定）")


class VolumeBrief(Lenient):
    title: str = Field(description="卷名本身，不要带「第几卷」")
    summary: str = Field(
        description="第 1 卷写一段话（这一卷想做成什么、卷首处境、卷末的高潮和结果、这一卷的对手、新登场的人）；其余卷写一句话"
    )
    chapter_count: int = Field(ge=1, le=1000, description="这一卷大约多少章")


class UnitBrief(Lenient):
    title: str = Field(description="单元名，2-8 字，如「退婚」「识宝」")
    summary: str = Field(
        description="一段话：什么事找上门；主角怎么应对、用了什么本事；读者叫好的那一下；做完拿到什么、主线往前走了哪一步"
    )
    chapter_count: int = Field(ge=1, le=50, description="这个单元几章")


class NewName(Lenient):
    category: str = Field(description="角色卡片，或设定库的类别名")
    name: str = Field(description="名称")
    one_line: str = Field(description="一句话")


class OutlineDraft(Lenient):
    arcs: list[ArcDraft] = Field(
        description="全书的篇，按顺序：第一篇写细；中间的篇只写定调里提到的或作者自己想到的，没有就不写；不要硬排"
    )
    ending: str = Field(description="结局：一句话，往哪里结束")
    volumes: list[VolumeBrief] = Field(description="第一篇分成的卷，按顺序")
    units: list[UnitBrief] = Field(description="第 1 卷拆成的剧情单元，按顺序；章数加起来等于第 1 卷的章数")
    new_names: list[NewName] = Field(default_factory=list, description="大纲里冒出来、设定库里还没有的人物和地方；没有就留空")
    decisions: list[AuthorChoice] = decisions_field()
    remark: str = remark_field("第一篇怎么兑现卖点、第 1 卷的节奏怎么排")
```

### 5.2 生成

`outline` 节点调 `setup_outline`（主编，`OutlineDraft`），变量：`concept`、`library`（任务 2 第 3.2 节）、`length`（第二包的 `format_length`）、`requirements`、`revision`，以及 `focus`：主角、金手指、底牌三条的 `entry_full_text`，之间空一行（底牌是「没有」的不写）。

### 5.3 保存

- **节点**（`story_nodes`，整本书的节点按这次的大纲重建，锁住的节点保留，见 5.6）：
  1. 开篇节点：`kind = 'opening'`，`title = 开篇`，`event` 取第一个单元的 `summary`；
  2. 每一篇一个终点节点：`kind = 'milestone'`，`title` 取篇名，`event` 取篇的 `text`，`status = 'pencil'`，`origin = 'ai'`；第一篇（`planned = true`）的终点节点写 `segment = {"title": 篇名, "text": 篇的 text}`，其余篇不写 `segment`（写到再定）；
  3. 结局节点：`kind = 'ending'`，`title = 结局`，`event` 取 `ending`。
- **卷**：第一篇的每一卷建一行，`target_node_id` 指向第一篇的终点节点，`summary` 照写，`chapter_count` 照写；第 1 卷的 `chapter_count` 改为它的单元章数之和。
- **单元**：第 1 卷的每个单元建一行，`summary`、`chapter_count` 照写。
- **新名字**：`new_names` 的每一项，设定库里按名称和别名都找不到的，生成一条建议（`kind = 'new_entry'`；角色卡片用 `create_character`，`role_type = '配角'`；其他用 `create_entry`，类别对不上的放进特殊规则；`status = 'one'`）。标题：`大纲里出现了「{名称}」，要给它建一条{类别}吗？`
- 记版本：每一篇、每一卷、每个单元各记一版（`segment`、`volume`、`unit`）。

### 5.4 第一个单元的章纲

`outline_chapters` 节点给第 1 卷的第一个单元出章纲：**直接复用写作流程出章纲的代码**（提示词 `plan_chapters`、产出 `ChapterPlanDraft`、建章节行和章纲的写法都和写作时一样）。写作开始后，写作流程看到第一个单元已经有章节，就不会再出一遍（`write_book` 现在就是这样判断的）。

### 5.5 程序检查

不通过的，带着问题自动重写一次（第一个单元的章纲没出来时只重跑 `outline_chapters`）；还不通过的写进 `warnings`：

| 检查 | 问题 |
|---|---|
| 没有篇，或第一篇的 `text` 是空的 | 第一篇要写一段话。 |
| 第一篇以外有 `planned = true` 的 | 只有第一篇写细，后面的篇写到再定。 |
| 没有卷，或第 1 卷的 `summary` 是空的 | 第 1 卷要写一段话。 |
| 第 1 卷没有单元，或某个单元的 `summary` 是空的 | 第 1 卷要拆成剧情单元，每个单元一段话。 |
| 第一个单元没有章纲 | 第一个单元的章纲还没出来。 |

### 5.6 修改大纲

大纲的 `piece_gate` 收到「提意见」（`revise`）时：重跑 `outline`，`revision` 带上作者的意见，并在后面加一句「下面这些节点作者锁住了，原样保留：{锁住的篇、卷、单元，逐条写名称}」。保存时锁住的节点（篇的节点 `pinned`，卷和单元 `locked`）不覆盖、不删；其余按新结果重建。第一个单元变了（名称或 `summary` 不同），重出它的章纲。

## 6. 作者在三步里能做的

### 6.1 确认

`POST /jobs/{job_id}/piece`（沿用第二包的接口）在三步里只接受：

- `{"action": "confirm"}`：先 `live_state`，再进下一步；大纲确认后进 `finalize`。
- `{"action": "delegate"}`：同确认（「交给编辑部定」）。
- `{"action": "revise", "feedback": "…", "flips": [...]}`：见下面 6.2。
- 其他 `action`：422。

### 6.2 提意见和换决定

| 这一步 | 怎么处理 |
|---|---|
| 定调 | 和第二包一样：重写定调（`revision` 带上意见和换掉的决定），保存，回到这一步的确认。底牌那一条被作者改过的不覆盖。 |
| 设定库 | **不整库重写**。意见先走任务 2 的「群聊找目标」那一套（`library_route`）：找到目标就按它的模式改一处（给几个写法就出候选，照作者的意思改就直接换进去）；不是改某一处的，调 `library_review`，`scope` 写「按作者的意见查一遍：{意见}」，结果进待处理的建议。换掉的决定，每一条按「作者把「{话题}」改成了「{选择}」，查一遍哪些设定要跟着改。」同样查一遍。处理完回到这一步的确认，`pending` 里带上最新的 `summary`。 |
| 大纲 | 见 5.6。 |

意见和换掉的决定照第二包的做法记成作者要求。

### 6.3 回头改前面

- 作者在设定库或大纲这一步，回到定调页直接改了定调的一段话（任务 1 的 `PATCH /books/{id}` 或任务 2 的改一处）：之后调一次 `library_review`，`scope` 写：

  ```
  定调改了。
  改之前：{旧的一段话}
  改之后：{新的一段话}
  查设定库和大纲里哪些地方要跟着改。
  ```

  结果进待处理的建议（`kind = 'concept'`）。这一条写在定调改动的接口里，不在流程图里；只在设定库已经建过以后才调。
- 回头改设定库，照常走任务 1、2 的接口和连带建议，流程图不动。

### 6.4 开写

大纲确认后，`finalize`：书的状态改为 `ready`，`setup_progress` 三块都记为已确认，主编在群聊说「开书方案定好了，可以开写了。」。开写仍然走现有的 `POST /books/{id}/write`；页面上「确认，开写」按钮在任务 3 的简版页面和任务 4 的正式页面里，都是先确认大纲、等开书任务结束，再自动调开写接口。
