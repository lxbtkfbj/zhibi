# 第三包：定调、设定库、大纲

产品规则以 `docs/设计说明.md` 第 13 节为准（讨论过程见 `docs/开书构思讨论.md`，纸上演练见 `docs/开书演练-玄幻修仙.md`）。本目录是交给 Codex 的实施任务：按顺序做，一次一个任务，前一个做完并提交后再开下一个。

一句话概括这一包：开书从第二包的五步改成「定调 → 设定库 → 大纲」三步；设定库是一个按类别管理、能让 AI 只改一处的编辑器；大纲是一棵树（全书 → 篇 → 卷 → 单元 → 章），写作中往下展开。

每个任务要发给 Codex 的话，写在 [给Codex的话.md](给Codex的话.md)，整段复制即可。

## 共同约定（每个任务都适用）

1. **先读后做**：先读 `docs/设计说明.md` 第 13 节、本文件和任务文件。任务文件和设计说明有冲突时，以设计说明为准，并在完成说明里指出冲突。
2. **语言**：界面文字、提示词、schema 字段描述一律用简体中文。界面上不出现「点杀」这类内部说法。
3. **schema 描述就是提示词**：`app/agents/schemas.py` 里的 `Field(description=...)` 会随 schema 发给模型。任务文件里给出的类和描述要逐字照抄，字段顺序也照抄。
4. **提示词由设计方提供**：本目录 `提示词/` 下是写好的模板，任务里写明哪些要用 `git mv -f` 搬进 `backend/app/prompts/`、哪些用 `git rm` 退役。不要改措辞；文字效果以后再调，现在以流程跑通为准。
5. **提示词登记**：新增或改动模板的变量，登记到 `app/prompts/catalog.py`；由程序拼出来再填进模板的文字，逐字照抄任务文件。
6. **内容放在表里**：类别、字段、提示、各题材常建条目写在后端一处配置里，前端从接口读，不在前端再抄一份。
7. **不破坏旧书**：已开完书、写到一半的书，迁移后要能照常续写；迁移前自动备份（第二包已有）。不要升级、重启或改动作者日常的 8000／4320 服务和书库；验收一律用独立的数据库、Redis 库和端口。
8. **演示模式**：`app/llm/demo.py` 补齐所有新增或变化的结构化产出，没有 Key 也能跑通。
9. **检查命令**：开发中只跑相关测试；提交前跑一次全量，全部通过才算完成。
   - 后端（`backend/`）：`uv run ruff check . && uv run ruff format --check . && uv run pytest -q`
   - 前端（`frontend/`）：`npx tsc -b && npm run lint && npm run build && npm run test:workspace`
10. **界面验收**：涉及界面的任务，按验收清单用演示模式在浏览器里跑一遍并截图，结果写进 `docs/第三包验收.md` 对应小节，截图放 `docs/第三包验收/`。
11. **文档同步**：任务完成后，把第 13 节里已实现的内容并入设计说明对应章节，第 13 节开头的状态行写明哪些任务已实现。
12. **分支与提交**：仓库没有远程，直接在当前分支上做。开始前确认工作区干净；不干净就停下来问作者。提交信息以「第三包任务 N：」开头。
13. **完成说明**：做完后用一段中文告诉作者：改了什么、迁移做了什么；搬了和退役了哪些提示词；跑了哪些检查、结果如何；验收写在哪里；有没有没做完、做不到、或和设计说明对不上的地方。

## 名词对照（写代码时用）

| 界面上的叫法 | 代码里 |
|---|---|
| 定调 | 块 `concept`；数据 `books.concept`（一段话、三个短版、底牌引用、基本信息） |
| 设定库 | 块 `settings`；角色卡片在 `characters`，其余类别和自建类别在 `world_entries` |
| 大纲 | 块 `outline`；篇在 `story_nodes.segment`，卷在 `volumes`，单元在 `plot_units`，章纲在 `chapters.outline` |
| 篇 | 第二包的「段」：从一个关键节点走到下一个关键节点 |
| 定下一篇 | 第二包的定下一段：`plan_segment` → `split_segment` → `segment_gate` |
| 改这一句／改这一项 | 改一处：目标是字段、一级等级、选中的文字或整条 |
| 待处理的建议 | 建议收件箱 |
| 锁住 | 第 11 节的铁钉，推广到设定条目和大纲节点 |
