# 新书页装修：照样张一模一样做

作者 2026-10-20 嫌新书页「像水泥毛坯房」，看了五版样张以后定下 `docs/界面原型/装修样张.html`，并且交代：**「记得让 Codex 一模一样的实现，不然我怕我发给他抄的作业很美好，结果他细节的地方抄错就白搭了。」**

所以这一包的要求和以前不一样：不是「照着意思改得好看」，是照着样张抄——样式数值原样搬、页面结构和 class 名照样张、界面上的字照样张；最后用程序逐个元素比样式、逐张截图叠起来比像素、逐页比文字（任务文件第 9 节）。比不过的地方要么修掉，要么一条条说清为什么。

> 状态：**已完成（2026-10-20）**。实现、全量检查和逐页比对结果见 [新书页装修验收](../../新书页装修验收.md)。依赖的拆书第三批任务 1 已先完成；设定页、简介页、角色卡读取第三批写进库里的内容，验收灌数据也复用第三批写库的函数。

## 共同约定（每个任务都适用）

1. **先读后做**：先读本文件、任务文件和样张（`docs/界面原型/装修样张.html`，九页都在浏览器里点一遍）。样张、任务文件、设计说明三者冲突时，以样张为准，其次任务文件，并在完成说明里指出冲突。
2. **开工前工作区要干净**：`git status` 不干净就停下来问作者，不要动、也不要替别人提交没提交的改动。
3. **语言**：界面文字一律用简体中文，照样张逐字抄，不要自己换词、加标点。
4. **不改提示词、不调模型**：这个任务只改样子和加两个只读接口，不碰 `backend/app/prompts/`，不调真实模型。
5. **一模一样**：样式、结构、字照样张抄，规矩在任务文件第 2 节；对得上对不上由第 9 节的程序说了算，不靠眼看。
6. **作者自己的书**：样子跟着换（任务文件第 5.1 条），功能、按钮、能手改的地方一个不少，行为不变。
7. **数据**：验收用作者书库的只读副本加试整理的设定（任务文件第 9.1 条），不用演示模式造数据。
8. **不碰作者的服务和书库**：不要升级、重启或改动作者日常的 8000／4320 服务、日常 worker 和书库，不要对日常环境运行 `start.ps1`／`stop.ps1`。验收一律用独立的数据库、Redis 库、端口和 worker。这个任务不调真实模型。
9. **检查命令**：开发中只跑相关测试；提交前跑一次全量，全部通过才算完成。
   - 后端（`backend/`）：`uv run ruff check . && uv run ruff format --check . && uv run pytest -q`
   - 前端（`frontend/`）：`npx tsc -b && npm run lint && npm run build && npm run test:workspace`
10. **验收**：照任务文件最后一节做，结果写进 `docs/新书页装修验收.md` 对应小节，截图放 `docs/新书页装修验收/`（少而准）。数据用任务文件第 9.1 条备的那一份，不用桌面上的 TXT 重新导入。
11. **文档同步**：任务完成后，在设计说明第 9.12 节后面补一小段「新书页装修（照装修样张）」：样式文件在哪、缩放的算法、新加的两个接口、和样张不一样的地方。
12. **分支与提交**：直接在当前分支（feat/setup-interview-spine）上做，不推送。提交信息以「新书页装修：」开头。
13. **完成说明**：做完后用一段中文告诉作者：改了什么、迁移做了什么；样式比对和截图比对的结果（每页差多少、还有哪些不一样、为什么）；跑了哪些检查、结果如何；验收写在哪里；有没有没做完、做不到、或和设计说明对不上的地方。
