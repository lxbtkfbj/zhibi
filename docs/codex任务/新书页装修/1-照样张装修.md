# 任务：新书页照样张装修

规格是 `docs/界面原型/装修样张.html`（作者 2026-10-20 看过五版后定的）。作者的原话：「记得让 Codex 一模一样的实现，不然……细节的地方抄错就白搭了。」所以这次不是「照着意思改」，是**照着抄**：样式数值原样搬、页面结构和 class 名照样张、界面上的字照样张，最后用程序逐个元素比、逐张截图叠起来比（第 9 节）。比不过不算完成。

## 1. 规格在哪

- `docs/界面原型/装修样张.html`：`<style>` 是全部样式；`<script>` 里的 `tocSettings`、`tocOutline`、`tocManuscript`（左边一栏）和 `V['…']`（各页）是页面结构；`fit()` 是缩放；`more()`、`.clampable` 那几段是「字多」的处理；地址后面加 `#简介`、`#设定`、`#茉莉`、`#卷`、`#单元`、`#章`、`#章-没拆`、`#正文`、`#读` 打开各页。
- `docs/界面原型/装修样张-数据.js`：样张上每个字的来源，由 `docs/界面原型/取样张数据.py` 从作者书库和试整理结果原样生成。取法（人名怎么数、主角怎么认）就是第 6 节接口的规矩。
- `docs/界面原型/装修样张/v-*.png`：2560×1312 的截图；`docs/界面原型/截样张.mjs` 是截图脚本。
- 样张和这份任务文件冲突，以样张为准，在完成说明里写出来；样张里没有的，照第 5 节；还拿不准，停下来问作者，不要自己补设计。

## 2. 怎么做到一模一样（硬规矩）

1. **样式原样搬**：把样张 `<style>` 整段搬进 `frontend/src/styles/desk-v2.css`，在新书页最外层加 class `desk-v2`。搬的时候只做这几处机械的改动，数值和顺序一个不改：
   - `:root { … }` 里的变量改挂在 `.desk-v2 { … }` 上；`body { … }` 那一条的背景（底色＋纸纹）、字体、字色挂在 `.desk-v2` 上（`display`、`overflow`、`height` 那几项由第 2.5 条的缩放管）；
   - 其余每个选择器前面加 `.desk-v2 `（例：`.row.on` → `.desk-v2 .row.on`，`h1` → `.desk-v2 h1`，`*` → `.desk-v2 *`，`a` → `.desk-v2 a`）；
   - 滚动条写成 `.desk-v2 ::-webkit-scrollbar…`，`@supports` 那条里的 `*` 也加前缀；`@media (max-width: 1500px)` 里的规则同样加前缀。
   - 不翻译成 Tailwind 类，不和 `index.css` 里的现有样式合并；`index.css` 的主题变量别的页面还在用，不删。新书页里原来的 Tailwind 类，凡是和 `desk-v2.css` 管的元素冲突的，去掉。
2. **结构照抄**：每一页、左边一栏、顶栏、右边一栏，都照样张模板的 DOM 写成 React 组件：标签名、层级、class 名、先后顺序一样。React 需要多包一层的，那一层不带样式（不加 class，或者 `style={{ display: 'contents' }}`）。模板里用 `data-go` 的地方是点了去哪，换成新书页现有的跳转。
3. **字照抄**：界面上固定的字（页名、小标题、小字说明、按钮、「还有 N 条，展开」「展开」「立住了：」「还没归单元」……）逐字照样张模板；内容（书名、章纲、人名、数字）照数据填。
4. **字体**：`main.tsx` 和 `index.css` 加 `@fontsource/noto-serif-sc/600.css`（样张用 400、600、700 三种粗细）。
5. **缩放**：现在 `index.css` 的 `.desk-zoom`（按宽度 1.1、1.2、1.25、1.5 四档）换成样张 `fit()` 的算法：`z = min(1.5, max(1, 窗口宽 / 1700), max(1, 窗口高 / 800))`，再乘外观里的「界面大小」（`--desk-scale`）；章那一页另有 `--s = clamp(0.9, (书桌高 − 48) / 650, 1.2)`，别的页 `--s = 1`。窗口变大小时重算。弹窗（存档、本书设置、拆书小窗）用同一个 `z`。
6. **字多字少**（照样张实现，数字不要改）：
   - 整页不滚：顶栏、左边一栏、右边一栏都不跟着动；纸（`.page`）和右边一栏（`.rail`）各自在里面滚。
   - 截断：卷页单元卡片那段话三行（`.ucard p`）；简介「主要人物」一人一行（`.plist.one .ds`）；树和表里的章名、单元名一行省略号（`.ell`），鼠标放上去看全名（`title`）。
   - 「还有 N 条，展开」（样张 `more()`，点了就地展开）：设定总览每类最多 8 个名字、往事秘密 3 条；单元页右边「这一单元的人」6 人、「读者在等的事」4 条、「新冒出来的」10 样；章页右边「这一章出场的人」3 人。
   - 折起来（`.clampable`，超过行数才出「展开」）：「这本书好在哪」每条 7 行，角色卡每栏 4 行。
   - 框里滚（`.scrollbox`，最高 340）：卷页「主角这一卷怎么变的」。
   - 空的：没有值的栏不显示（包括旧数据里写着「（记录里没有）」的）；右边一栏里没内容的那一块不显示；整栏都没内容就不出现，纸变宽；现状用一行字说（`.state`，或者 meta 里那一截）。
7. **数据只读、不改字**：页面上不许为了好看删字、改字、挑一部分；要截就照第 6 条的规矩截。

## 6. 后台：右边一栏要的汇总（只读，新接口）

算法和 `docs/界面原型/取样张数据.py` 一字不差（验收时样张就是用它取的数）。

1. `GET /api/books/{id}/teardown/digest?unit={单元 id}` 或 `?volume={卷 id}`：

   ```json
   {"people": [{"name": "萧澈", "chapters": 9, "first": 2}],
    "things": [{"chapter": 1, "kind": "地方", "name": "沧云大陆", "note": "…", "belongs": "", "secret": ""}],
    "waits": [{"chapter": 2, "action": "立下", "what": "…"}],
    "hero": "萧澈",
    "changes": [{"chapter": 2, "change": "…"}]}
   ```

   - 范围：这个单元／这一卷里有记录（`read_version` 有值）的章。
   - `people`：每章 `teardown.read.people` 的 `name`（去首尾空白，套 `books.teardown.names`），一章里同一个名字算一次；按章数从多到少，一样多的按第一次出场先后。
   - `things`：（`kind`，`name`）第一次出现的那一条，按章号、记录里的先后。
   - `waits`：全部，按章号、先后。
   - `hero`：全书有记录的各章里，照 `people` 的排法排第一的人；`changes`：这个范围里，`name` 是他、`also_called` 里有他、或者 `was` 是他的那几条记录的 `change`（不空的），按章号。
   - 不是拆的书：各个列表是 `[]`，`hero` 是 `null`。
2. `GET /api/books/{id}/teardown/appearances?character={角色 id}`：`{"chapters": [12, 41, …]}`。拿这个角色的名字和别称，去有记录的各章里找：`people` 里 `name` 或 `was` 对上，或者 `also_called` 和它们有一个相同，这一章就算出场。
3. **验收用的数据**（只往独立库里灌，不进日常库）：`backend/scripts/seed_teardown_trial.py --book <书 id>`：把 `data/拆书试验/逆天邪神前五十章/整理设定/` 的 `cards.json`、`world.json`、`merits.json` 当成模型的回答，交给拆书第三批任务 1 写库的那几个函数写进这本书（不调模型）。试整理的格式比第三批旧，照下面换：卡里的 `relation` 写进「一句话」（`one_line`），`power` 当 `now.power`，「（记录里没有）」当空，定位：主角（第 6.1 条的 `hero`）写「主角」，其余写「配角」；`merits` 照写，`settings.upto` 写 50。只写这三个文件里有的（不另外按名单补「一句话」的人）。连的是日常库（库名 `zhibi`）就拒绝。

## 6½. 顺手修两处（拆书第三批复核时查出来的，后台）

1. **角色卡的别名只用模型写回的**：第三批第 3.5 条写库时把名单上的别称也并了进去，结果模型已经筛掉的「姐夫」「爷爷」「少爷」「前辈」又被带回来。改成：别名只写模型写回的 `aliases`（模型照提示词筛过），不再并名单上的别称；`books.teardown.names` 照旧。样张上的别名也是这样取的。
2. **名场面去掉重复的「立住了」**：拼「第 N 章：做了什么——立住了什么」时，`shows` 开头已经是「立住了」「立住」（后面可能跟「：」）的，先去掉再拼，免得出现「立住了立住了」。

两处都补测试；已经整理过的书不用回填，下次收尾或重跑 `settings` 时就对了。

## 9. 验收：逐个比、逐张叠

1. **备数据**（独立环境，照前几批的办法）：把作者日常库只读复制一份到独立的 PostgreSQL（第二批任务 2 用过的办法），起独立的后台、拆书 worker、前端；用第 6.3 条的脚本给《逆天邪神》那本灌试整理的设定；然后用独立后台的地址重新生成样张数据：`python docs/界面原型/取样张数据.py --api http://127.0.0.1:{独立端口}/api --book {那本书的 id}`。这样样张和页面用的是同一份数据。
2. **比样式**：写 `frontend/tests/desk-v2-parity.browser.mjs`：在 2560×1312 和 1600×900 两个尺寸下，分别打开样张（`file://…/装修样张.html#{页}`）和新书页对应那一页（读到哪先写成第 2 章，和样张一样）。样张这一页里出现的**每一个 class**，在新书页同一页里找带同一个 class 的第一个元素，比这些计算出来的样式：`font-family`、`font-size`、`font-weight`、`line-height`、`letter-spacing`、`color`、`background-color`、`background-image`、四边 `border-*-width/style/color`、四角 `border-*-radius`、四边 `padding-*`、四边 `margin-*`、`box-shadow`、`width`、`height`、`display`、`gap`、`grid-template-columns`。长度差 0.5px 以内算一样，颜色要完全一样。样张里有、新书页里找不到的 class 也算不对。`.skel`、`.placeholder-note` 两个不比（读一章用真正文）。结果每页一张表（class、属性、样张的值、新书页的值）写进验收；**不一样的必须修到一样**，修不了的每一条写清原因（只允许是真数据和样张的数据不同造成的）。
3. **叠截图**：同样两个尺寸、九页，各截一张样张的、一张新书页的，用 `pixelmatch`（加成开发依赖，连 `pngjs`）比，阈值 0.1，出一张标红的差异图；遮掉这几块再算：读一章的正文区域、存档那一行的「N 分钟前存过」、编辑部小球。差的像素要在 0.5% 以内；超过的，在验收里放三张图（样张、新书页、差异图）并说清差在哪、为什么。
4. **字一样**：九页各把纸和右边一栏的全部文字（`innerText`）取出来，和样张同一页比，要一字不差（读一章的正文除外）。
5. 三张对比图（样张、新书页、差异图）每页一组放进 `docs/新书页装修验收/`，表格和结论写进 `docs/新书页装修验收.md`。
6. 另外截给作者看：作者自己的书（独立库里那几本）的简介、设定、大纲（卷、单元、章）、正文首页；暗色下拆的书的章页和简介；编辑部窗口、存档弹窗、本书设置弹窗、系统设置、书房各一张。
7. 日常 8000／4320 服务、日常 worker 和书库不动；验收全在独立环境。
