# 拆书第五批：整本书（篇、全书结局、读者在等的事）＋「接着拆」那个对话框

## 0. 这次做什么

作者拆别人的书，最想学的是整本书怎么布局：中间分几大段、结局怎么收、一路上拿什么吊着读者。现在只拆到卷，这次补上三样：

1. **篇**：卷上面再归一层。照第 14 节原来的设计，篇存成终点节点的 `segment`，和自己写的书同一种存法。
2. **全书结局**：拆到最后一章时，看原书完没完结；完结了就写结局，放在大纲的「全书」那一页。
3. **读者在等的事**：各章记下的「立下／提起／兑现」连成一本账，存进现成的伏笔台账表 `foreshadowings`。每件事记哪章立下、哪几章提起、哪章兑现、吊了读者多少章。

另外一起改：「接着拆」对话框，说清现在拆到哪、能不能只整理；拆完了的书也能把这次新加的整理补上。

作者要省时间，这几件合成一个任务、一次全量检查。三样都放在拆书收尾时做，用同一套「什么时候能只整理」的规矩，页面也都在大纲那一栏，合在一起反而少改一遍。

不改：逐章记、归单元、归卷这三步和它们的提示词；设定、好在哪的写法；写书那边的流程。

## 2. 收尾整理的顺序

`teardown_runner.Runner.finish()` 里现在是 `not author_stop and reason in (None, "upto")` 时整理设定。改成在同一个条件下依次做：

1. 归篇（第 3 节）
2. 全书结局（第 4 节，只在 `reason is None`，也就是全书都读了、都归好了）
3. 整理设定和好在哪（现有的 `collect_settings`，不改）
4. 读者在等的事（第 5 节）

每一步自己出错只记下来，不影响后面几步。出错的话加进 `stop_note`，群聊最后那句也带上（和现在 `settings_error` 一样）。几句话分别是：

- 「归篇没做完（{原因}），」
- 「写全书结局没做完（{原因}），」
- 「整理读者在等的事没做完（{原因}），」

后面统一接「点「{按钮}」再试一次。」。`{按钮}` 在 stage 是 done 时写「补上整理」，否则写「接着拆」。作者点停下（`JobCancelled`）照现在的处理。

群聊最后那句，在现有的话后面按顺序加上：

- 这次收尾后有篇：「归成了 {k} 篇。」
- 结局写了：「写了全书结局，在大纲的「全书」那一页。」
- 判断没完结：「主编看了最后几章，原书到第 {N} 章还没收住全书，没写结局。」
- 读者在等的事：「读者在等的事整理到第 {upto} 章：一共 {total} 件，还吊着 {open} 件。」

进度（`runner.progress`）加三种 `doing`：

- `arcs`
- `ending`
- `waits`：带 `waits: {first, last}`

页面上怎么写见第 9.6 节。

## 3. 篇

### 3.1 存法

- 一篇一个 `StoryNode`：
  - `kind="milestone"`，`title` 是篇名（截到 100 字），`event=""`；
  - `segment={"title": 篇名, "text": 那段话}`，只有这两个键；
  - `status="pencil"`，`origin="ai"`，`position` 从 1 往后编。
- 卷用现有的 `volumes.target_node_id` 挂到篇上。没归篇的卷，`target_node_id` 为空。
- 整理状态记在 `books.teardown["arcs"] = {"inputs", "final", "rows", "at"}`：
  - `rows` 按顺序记每篇 `{"node": id, "volumes": [卷 id], "hash": 程序写进去的篇名＋那段话的 sha1}`。

### 3.2 什么时候归

- **收住的卷**：
  - 主编归卷的书：不是 `open_volume_id` 那一卷、并且那段话不空的卷。
  - 原书分卷的书：那段话不空的卷。
  - 从第 1 卷起按卷号取连着的一段；中间碰到没收住的就停。
- **不到 3 卷**：不归篇。已有的拆书篇节点（`kind="milestone"`）全删，卷的 `target_node_id` 清空，清掉 `books.teardown["arcs"]`。结局节点不动。
- **3 卷以上**：每次收尾都拿全部收住的卷**从头归一遍**。
  - `final = reason is None`。
  - 发给模型的 user 的 sha1 和 `final` 跟上次一样，就不调，只检查卷都挂对了。

### 3.3 调用

模板 `teardown_arcs`，`purpose="拆书：归篇"`，用拆书那个模型。values：

- `title`：书名。
- `volumes`：收住的卷，一卷一行：「第 {卷号} 卷「{卷名}」（第 {a}–{b} 章）：{那段话}」。章号从这一卷的章算。
- `first`：第一个收住的卷号。
- `max_arcs`：收住的卷数除以 2，有余数往上取。
- `tail_rule`：
  - `final` 时：「这是全书最后几卷：全部归完，open_from 写 null。」
  - 否则：「后面还有没拆的章：最后几卷要是还没收在一个大阶段的结尾（主角还没离开这个舞台），就先不归，open_from 写从第几卷起还没收住。」

schema 见第 12 节 `TeardownArcs`。

检查用现有的 `check_groups`，起止是第一个和最后一个收住的卷号，`close=final`。另外再查两条：

- 篇数不能超过「实际归进篇的卷数除以 2，往上取」。超了写「分了 {n} 篇，最多 {max} 篇」。
- 篇名不能空。

`validated()` 改成也认 `arcs` 这个字段。三次都对不上，按第 2 节记「归篇没做完」。

### 3.4 落库

在一个事务里，持书锁：

1. 现有的拆书篇节点按 `position` 排好，第 i 篇**复用**第 i 个节点，不够的新建、多的删。这样篇数不变时节点 id 不变，作者正看着的那一页不会没。
2. **作者改过的不盖**：复用的节点满足下面两条，就保留节点上现在的篇名和那段话，只重挂卷：
   - 上次 `rows[i].volumes` 和这次这篇的卷完全一样；
   - 节点现在的篇名＋那段话的 sha1 不等于 `rows[i].hash`。
3. 归进篇的卷挂上 `target_node_id`；没归进去的（`open_from` 以后的、还没收住的、「还没收尾」那一卷）清空。
4. 有结局节点（第 4 节）的话，把它的 `position` 挪到最后。
5. 写 `books.teardown["arcs"]`。

## 4. 全书结局

### 4.1 存法

- 一个单独的 `StoryNode`：
  - `kind="ending"`，`segment=None`，`title="结局"`，`event` 是结局那段话；
  - `position` 排在所有篇后面，`status="pencil"`，`origin="ai"`。
  - 它**不当篇**，不挂卷。
- 状态 `books.teardown["ending"] = {"upto": 总章数, "ended": bool, "inputs": sha1, "hint": 认出的字样或 ""}`。

### 4.2 什么时候写

收尾时 `reason is None`，在归篇以后。发给模型的 user 的 sha1 和上次一样，就不调。

### 4.3 原书完没完：先看字样

程序先找完结字样，给模型一个提示：

- **看哪里**：
  - 最后一个不是番外的章（`chapters.teardown.flags` 里没有「番外」）的章名、原标题和正文最后 300 字；
  - 最后三章的章名；
  - `books.teardown.excluded` 里排除的章名。
- **找什么**：`大结局|终章|尾声|全书完|全文完|全剧终|完本|完结|（完）|【完】|\(完\)`。
- **`hint` 怎么写**：
  - 找到了：「文件最后有「{字样}」，原书应该在这里完结。」
  - 没找到：「文件最后没看到「大结局」「全书完」「完本」这类字样，原书可能还没写完。」

### 4.4 调用和落库

模板 `teardown_ending`，`purpose="拆书：全书结局"`。values：

- `title`：书名。
- `last`：总章数。
- `hint`：第 4.3 节那句。
- `outline`：
  - 有篇时先列篇，一篇一行：「第 {n} 篇「{篇名}」（第 {a}–{b} 卷）：{那段话}」；
  - 再列全部的卷，格式同第 3.3 节。
- `units`：最后一卷的单元，一个一行：「第 {a}–{b} 章「{单元名}」：{那段话}」。
- `chapters`：最后 10 章，一章一行：「第 {n} 章「{章名}」：{发生什么}｜{结尾钩子}」。

schema `TeardownEnding`。检查：`ended` 为真时 `text` 不能空。最多三次。

落库：

- **`ended` 为真**：新建或更新结局节点。`inputs` 变了才会走到这里，所以直接覆盖。
- **`ended` 为假**：有结局节点就删掉。
- 两种都写 `books.teardown["ending"]`。

## 5. 读者在等的事

### 5.1 存法

一件事一行 `foreshadowings`：

| 字段 | 写什么 |
|---|---|
| `seq` | 这本书现有最大的加 1 |
| `kind` | 「期待」或「伏笔」 |
| `description` | 这件事 |
| `status` | 还吊着 `planted`，了结了 `resolved` |
| `planted_chapter` | 第几章立下 |
| `hint_chapters` | 提起的章号，去重、从小到大 |
| `resolved_chapter` | 第几章了结，没了结为空 |
| `plant_plan` | 「第 {a} 章」 |
| `payoff_plan` | 了结了写「第 {b} 章：{how}」，没了结写空 |
| `plant_volume`、`payoff_volume` | 那一章所在卷的卷号 |
| `span` | 见第 5.4 节 |
| `node_id` | 空 |

编号照聊天工具 `foreshadow_code` 的规矩：期待是 `E{seq}`，伏笔是 `F{seq}`。

整理状态记在 `books.teardown["waits"] = {"upto", "total", "open", "at"}`。

### 5.2 分段

从 `waits.upto` 后面一章，到读过的最后一章。只要有逐章记录的章；没读成的章跳过。按章号连着切，一段最多 80 章，并且「读者在等的事」记录加起来最多 150 条（先到哪个算哪个，至少一章）。一段一次调用，按顺序一段一段做。

### 5.3 调用和检查

模板 `teardown_waits`，`purpose="拆书：读者在等的事"`。values：

- `title`：书名。
- `first`、`last`：这一段的起止章号。
- `open`：
  - 现在还吊着的事，取最近有动静（立下或提起）的 400 件，再按立下的章排；
  - 一件一行：「{编号}｜{期待或伏笔}｜第 {a} 章立下｜{这件事}｜最近提起：第 {h} 章」，没提起过的最后一栏写「还没提起过」；
  - 一件都没有写「（还没有）」。
- `chapters`：这一段每一章：
  - 先一行「第 {n} 章：{发生什么}」；
  - 下面每条记录一行「  {立下／提起／兑现}：{那件事}」，前面两个空格。

schema `TeardownWaitLedger`。下面任何一条对不上，就把问题写成一句加在 user 后面重来，最多三次：

- `new` 里的 `ref` 是 `N` 加数字，不重复；`chapter` 在这一段里；`what` 1–40 字。
- `hinted`、`resolved` 的 `code` 是还吊着的编号（不分大小写），或者这次 `new` 里的 `ref`。
- `hinted`、`resolved` 的章号在这一段里，并且不早于那件事立下的章。
- 同一个 `code` 只能了结一次。

三次都不行：这一段不落库，`waits.upto` 停在这一段前面，后面的段也不做了，按第 2 节记「整理读者在等的事没做完」。

### 5.4 落库

一段一个事务：

1. 新建 `new` 里的行，`seq` 按出现顺序往后编。
2. 把提起的章号并进 `hint_chapters`。
3. 了结的行：状态改 `resolved`，写 `resolved_chapter`、`payoff_plan`、`payoff_volume`。
4. 重算这本书全部行的 `span`。终点是了结的那章，还吊着的取读过的最后一章：
   - 立下那章和终点在同一个单元：「短」；
   - 同一卷：「中」；
   - 其余：「长」。
5. 更新 `books.teardown["waits"]`。

这一步不碰作者的东西：拆的书里没有写书流程，`foreshadowings` 里全是这里写的。

## 6. 什么时候能「只整理」

在 `teardown_info` 加一个函数 `needs_closing(meta, last, total)`，`last` 是读过的最后一章。按顺序判断：

1. `last == 0`：假。
2. `settings.upto < last`：真（`settings` 为空时当 0）。
3. `waits.upto < last`：真（`waits` 为空时当 0）。
4. `last == total`，并且 stage 不是 `done`：真。这时全书都读过了，但收尾没做完。
5. stage 是 `done`，并且 `ending.upto != total`：真。
6. `books.teardown["arcs"]["failed"]` 为真：真。归篇三次都对不上时记 `failed: true`；归篇成功、或者收住的卷不到 3 卷不用归时，清掉这个标记。只有归篇失败、别的都做好了，也要能点「补上整理」或「只整理」重试。（Codex 开工时问出来、作者 2026-10-20 定的。）
7. 以上都不是：假。

用在三处：

- `teardown_jobs._validate_start` 里原来的 `needs_settings`，全部换成它。
- `start()` 里算只整理不读的那一句：`target == last and not retry and needs_closing(...)`。job 参数名 `settings_only` 不改，免得排队中的旧任务认不出来。
- 书的摘要（第 8 节）。

**只整理的那一次要先把单元和卷归完**。这是现在的一个坑，顺手修掉：

- 现在只整理时不读原文、也不归单元，直接 `finish()`。
- 全书都读完以后，最后一次归单元或归卷出了错（「归了三次都对不上，停下了」），或者作者恰好在这时点了停下，作者再点「接着拆」，就走到只整理这条路，没归完的章永远归不上。`finish()` 每次都判「还有章或卷没有归完」，卡死了。

改成：只整理的那一次也照读完以后的收尾那样跑一遍归单元、归卷（`reading_done = True`，等于 final），不读原文；没有要归的就什么都不做。然后进 `finish()`，按第 2 节做。

全书都读过、都归好的书，`reason` 算出来是 `None`，所以也会归篇、写结局。要测：全书读完、最后几章还没归单元的书，点只整理以后能归完、能拆完。

## 7. 补章节要跟着改的

`teardown_append.plan` 的 `reopen` 加一种 `{"kind": "ending"}`：有结局节点，或者 `books.teardown["ending"]` 不空时加。确认页这一条写：

「全书结局会删掉：补上以后拆到最后一章，再看原书完没完」

补上（`/append/import`）时：

- 删掉结局节点，去掉 `books.teardown["ending"]`。
- 这次打开的那一卷要从篇里拿出来，`target_node_id` 清空。「打开」指：清了那段话的（`summary`）、重新当「还没收尾」的（`volume`）。篇本身先不动，下次收尾时从头归（第 3.2 节）。

前端 `teardownAppend.ts` 认这个新的 `kind`。

## 8. 接口

**大纲树**（`outline_tree.py`，只改拆的书，自己写的书一点不变）：

- `kind="ending"` 并且 `segment` 为空的节点不进 `arcs`，只放在 `ending` 里。
- `segmented` 为真时，`target_node_id` 为空的卷放进最后一个虚的篇：

  ```
  {"node_id": null, "virtual": true, "title": "还没归篇", "text": "", "status": "done", "locked": true, "planned": true, "end": null, "volumes": [...]}
  ```

  `frontend/src/lib/outlineTree.ts` 的类型加 `virtual?: boolean`。

**右栏汇总** `GET /api/books/{id}/teardown/digest`：

- 加参数 `arc`（篇的节点 id）。`unit`、`volume`、`arc` 三个必须给一个且只能给一个。
- 范围是挂在这一篇上的卷里的章。
- 找不到返回 404「篇不存在」。

**读者在等的事** `GET /api/books/{id}/teardown/waits`（新接口，放在 `teardown_digest`）：

- 返回：

  ```
  {"upto", "last", "items": [{"code", "kind", "what", "planted", "hints", "resolved", "how"}]}
  ```

- `last` 是读过的最后一章。
- `how` 从 `payoff_plan` 去掉开头的「第 {resolved} 章：」。
- `items` 按立下的章、再按 `seq` 排。
- 不是拆的书：返回 `{"upto": null, "last": 0, "items": []}`。

**书的摘要**（`TeardownSummary`，后端 schema 和 `frontend/src/api/types.ts`）加：

| 字段 | 内容 |
|---|---|
| `last_read` | 读过的最后一章 |
| `needs_closing` | 第 6 节 |
| `arcs` | 篇数 |
| `ending` | `{"upto", "ended"}` 或 null |
| `waits` | `{"upto", "total", "open"}` 或 null |

`list_books` 里读过几章和最后一章用同一次分组查询查出来，不要一本书查一次。

## 9. 页面

都只改拆的书。第 9.3 节节奏那句小字，自己写的书也跟着改（那是原来写错了）。

### 9.1 大纲那一栏的目录

- 篇那几行照现有的显示。`fromApi.ts` 把虚的篇转成：`kind: '篇'`、`virtual: true`、`id: 'a:unassigned'`、`title: '还没归篇'`，没有 `ref`，不算「下一篇」。目录里这一行加 `virtual` 类（`.row.virtual` 已有）。
- 「全书」那一行下面紧跟一行：
  - `className="row top1"`，选中时加 `on`；
  - 字写「读者在等的事」，后面 `<span className="n">`：有账写「{open} 件还吊着」，没账写「还没整理」；
  - 点了打开第 9.5 节那一页，选中 id 用 `waits`。

### 9.2 全书那一页

照单元页的结构写，从上往下：

1. `kicker`：「全书」。
2. `h1`：「全书」，不能改。
3. `meta`：「{总章数} 章 · {篇数} 篇 · {卷数} 卷 · {单元数} 个单元」。没有篇时去掉「· {篇数} 篇」。
4. `rule1`。
5. **结局**：
   - 有结局节点：
     - 一个 `sec`，`label` 写「结局」，后面 `<span className="n">` 写「原书在第 {总章数} 章完结」。
     - 那段话按「；」能分成四段时，照单元页用 `beats4` 摆四格。四格标题依次是「主线怎么了结」「主角最后到了哪」「各人的去向」「停在什么画面」，能改，存进结局节点的 `event`（现有的改法：全书带 segment ref 时改 `/nodes/{id}` 的 `event`）。
     - 分不成四段，就整段用 `lead` 摆。
   - 没有结局节点：一行 `.state`，按情况写：

| 情况 | 写 |
|---|---|
| 一章都没读 | 还没开拆。拆到最后一章以后，这里写全书结局。 |
| `ending.upto` 等于总章数并且 `ended` 为假 | 主编看了最后几章：原书到第 {总章数} 章还没收住全书，所以没写结局。补上后面的章节、拆到最后一章以后再看。 |
| stage 是 done，但还没判断过 | 全书都拆过了，结局还没写：点右上角「补上整理」。 |
| 其余 | 拆到最后一章以后，这里写全书结局：主线怎么了结、主角最后到了哪、各人的去向、停在什么画面。现在拆到第 {last_read} 章，一共 {总章数} 章。 |

6. **节奏**：`label` 写「节奏」，`n` 写「一格一篇，宽窄是章数」（有篇时）或「一格一卷，宽窄是章数」（没有篇时）。
   - 有篇：一篇一格，「还没归篇」用 `.wait` 那种格，`title` 写「第 {a}–{b} 卷还没归篇」。
   - 没有篇：一卷一格。
   - 点了都打开那一页。
7. **卡片**：`label` 写「篇」或「卷」，`n` 写「那段话只显示前三行，点进去看全部」。用 `ugrid`／`ucard`，和卷页的单元卡片一样。
   - 篇卡的小字：「第 {a}–{b} 章 · {n} 章 · {k} 卷」；卷卡的小字：「第 {a}–{b} 章 · {n} 章」。
   - 「还没归篇」不出卡片。

右边一栏：读者在等的事有账（`total > 0`）才出，`aside.rail` 里一个 `rb`：

- `h3`：「读者在等的事」，`n` 写「整理到第 {upto} 章」。
- 一行 `.small`：「一共 {total} 件：兑现了 {resolved} 件，还吊着 {open} 件。下面是吊得最久的。」
- `ul.tl` 列 5 件：了结的和还吊着的放在一起，按吊了几章从多到少排。
  - 每件：`<b>` 写「第 {a} 章 → 第 {b} 章」，还吊着的写「第 {a} 章 → 还吊着」，点了打开立下那章；
  - 后面写「{这件事}（{吊了几章} 章）」。
- 最后一个 `<a className="more">`：「全部 {total} 件 ›」，打开第 9.5 节那一页。

### 9.3 篇那一页（现有的通用页面，改三处）

1. `meta` 写「{n} 章 · 第 {a}–{b} 章 · {k} 卷」。
2. 节奏那一行的小字，按格子是什么写：
   - 卷：「一格一卷，宽窄是章数」；
   - 单元：「一格一个单元，宽窄是章数」；
   - 篇：「一格一篇，宽窄是章数」。
3. 拆的书右边一栏用 `DigestRail`，接口带 `arc=`。两个标题写「这一篇的人」「主角这一篇怎么变的」，其余照卷页。

### 9.4 还没归篇那一页

- `kicker`：「全书」，`h1`：「还没归篇」，`meta` 同第 9.3 节。
- `rule1` 下面一行 `.state`：「这几卷还没归篇：拆到后面、凑够一个大阶段，收尾时主编再把它们归成篇。」
- 节奏和卷卡片照第 9.3 节。
- 不出右边一栏。

### 9.5 读者在等的事那一页

1. `kicker`：「全书」；`h1`：「读者在等的事」。
2. `meta`：「整理到第 {upto} 章 · 一共 {total} 件 · 兑现了 {resolved} 件 · 还吊着 {open} 件」。
3. 下面一行 `.small`：「期待：读者知道会发生，等着看怎么发生；伏笔：读者不知道答案，等着揭开。从立下到兑现隔了几章，就是读者被吊了多久。」
4. `rule1`。
5. 「还吊着的」：一个 `sec`，`label` 写「还吊着的」，`n` 写「{open} 件，按立下先后」。用 `ul.tl`，`More` 先列 30 件。每件：
   - `<b>` 写「第 {a} 章立下」，点了打开那一章；
   - 一个 `chip`：期待用 `ochre`，伏笔用 `indigo`；
   - 这件事；
   - `<span className="small">`：「（吊了 {last−a} 章）」，有提起的写成「（吊了 {last−a} 章，中间提起 {h} 次）」。
6. 「兑现了的」：`label` 写「兑现了的」，`n` 写「{resolved} 件，吊得久的在前」。每件：
   - `<b>` 写「第 {a} 章 → 第 {b} 章」，点了打开立下那章；
   - `chip`；
   - 「{这件事}：{how}」；
   - `<span className="small">`：「（吊了 {b−a} 章）」，有提起的同上。
7. 还没有账时，`rule1` 下面只一行 `.state`：

| 情况 | 写 |
|---|---|
| 一章都没读 | 还没开拆。拆过的章会把读者在等的事连起来：哪章立下、哪章兑现、吊了读者多久。 |
| 正在拆 | 拆书收尾时整理，到时这里就有了。 |
| stage 是 done | 还没整理：点右上角「补上整理」，不重读原文。 |
| 其余 | 还没整理：点右上角「接着拆」，选「只整理前 {last_read} 章」，不重读原文。 |

不出右边一栏。

### 9.6 顶栏

**正在拆时那行字**（`teardownProgress.ts`）：

- `arcs`：「主编在归篇」
- `ending`：「主编在写全书结局」
- `waits`：「主编在理读者在等的事：第 {first}–{last} 章」

`settings` 照旧是「设定师在整理设定」。

**按钮**（`Chrome.tsx`）：

- stage 是 `imported`：「开始拆」。
- stage 是 `done`：`needs_closing` 为真时写「补上整理」，否则不出按钮。
- 其余：「接着拆」。

### 9.7 「开始拆」对话框（`TeardownStart.tsx`、`BookDesk.tsx`）

对话框多拿三样：`last`（`last_read`）、`needsClosing`、stage。

**全书都读过（`last >= total`）**：

- 标题：「补上整理《{书名}》」。
- 正文一段：「全书 {total} 章都读过了。这次不重读原文，只把收尾补上：没归完的单元和卷、篇、全书结局、设定、读者在等的事，做好了的不重做。」
- 下面照旧是费用提醒那一段，不出「拆到第几章」那一栏。
- 按钮：「先不整理」（ghost）、「开始整理」（primary，`onStart(null)`）。

**其余**：

- 标题照旧是「开始拆《{书名}》」。
- `last > 0` 时，最上面一行：「已经拆到第 {last} 章，一共 {total} 章。」
- 下面照旧是 `TeardownOptions`。
- 按钮从左到右：
  - 「先不拆」（ghost）；
  - `needsClosing` 并且 `last > 0` 时，多一个「只整理前 {last} 章」（outline），`onStart(last)`；
  - 「开始拆」（primary）。

**「拆到第几章」预填**：上次定的目标还没拆到（`upto > last`）就预填它，否则留空（留空就是拆到最后）。补章节那次加的 `stop_reason === 'added'` 特判删掉，被这条盖住了。

### 9.8 设定页空着时那句（`settingsData.ts`）

- stopped／queued 并且读过章：「设定还没整理：点右上角「接着拆」，选「只整理前 {last} 章」，不重读原文」
- stage 是 done：「设定还没整理：点右上角「补上整理」，不重读原文」

其余几种照旧。

## 11. 重跑脚本（`teardown_rerun.py` 和它的命令行）

加三个步骤：`arcs`、`ending`、`waits`。三个都不接 `--from`／`--to`，都可以 `force`（不看 sha1）。

**`arcs`**：

- 预计 1 次。
- 收住的卷不到 3 卷：422「收住的卷不到 3 卷，不用归篇」。

**`ending`**：

- 预计 1 次。
- 还没全书读完、归完：422「还没拆到最后一章，写不了结局」。

**`waits`**：

- 先删掉这本书的全部 `foreshadowings`，清掉 `books.teardown["waits"]`，再从第 1 章起整本重做。
- 预计次数照第 5.2 节切出来的段数。

都照现有步骤的规矩：持任务锁、先估次数确认、做完存一档。

## 12. 三份提示词对应的 schema

放进 `backend/app/agents/schemas.py`，字段顺序和描述逐字照下面：

```python
class TeardownArc(BaseModel):
    first: int = Field(description="这一篇从第几卷起（卷号）")
    last: int = Field(description="到第几卷止（卷号）")
    title: str = Field(description="篇名，4–8 个字")
    text: str = Field(description="这一篇的那段话，150 字以内，四句，用分号隔开")


class TeardownArcs(BaseModel):
    arcs: list[TeardownArc] = Field(description="从第一个收住的卷起，一篇挨一篇")
    open_from: int | None = Field(None, description="从第几卷起还没收住、先不归；全部归完写 null")


class TeardownEnding(BaseModel):
    ended: bool = Field(description="原书是不是在最后一章完结了")
    text: str = Field("", description="全书结局，200 字以内，四句，用分号隔开；没完结写空")


class TeardownWaitNew(BaseModel):
    ref: str = Field(description="新起的编号：N1、N2……")
    chapter: int = Field(description="第一次立下的那一章")
    kind: Literal["期待", "伏笔"]
    what: str = Field(description="这件事，20 字以内")


class TeardownWaitHint(BaseModel):
    code: str = Field(description="编号：还吊着的事里的，或者 new 里的 N 编号")
    chapter: int = Field(description="哪一章又提起")


class TeardownWaitDone(BaseModel):
    code: str = Field(description="编号：还吊着的事里的，或者 new 里的 N 编号")
    chapter: int = Field(description="哪一章了结")
    how: str = Field(description="怎么了结的，30 字以内")


class TeardownWaitLedger(BaseModel):
    new: list[TeardownWaitNew] = Field(default_factory=list, description="这一段新立下的事")
    hinted: list[TeardownWaitHint] = Field(default_factory=list, description="又提起、还没了结的")
    resolved: list[TeardownWaitDone] = Field(default_factory=list, description="了结了的")
```

演示模型（`backend/app/llm/demo_teardown.py`）要能给这三个 schema 出**合规**的结果，下面三条都要能触发：

- **归篇**：按卷连着归，篇数守住上限，非 final 时留最后一卷。
- **结局**：认出字样就写结局，认不出就 `ended=false`。
- **读者在等的事**：
  - 记录里「立下」的进 `new`；
  - 同一件事又出现时，「提起」「兑现」照字面对上已有的编号，进 `hinted`、`resolved`。

## 13. 测试和验收

后台单测，每条都要有：

- **归篇**：
  - 不到 3 卷时删篇；
  - 3 卷以上，`final` 和非 `final` 各一次；
  - `check_groups`、篇数上限、三次不过记错；
  - sha1 一样不调；
  - 复用节点 id；
  - 作者改过、并且卷没变的篇不盖；
  - 卷变了的照新的写；
  - 结局节点排在最后。
- **结局**：
  - 字样认出和认不出；
  - `ended` 为真建节点、为假删节点；
  - sha1 一样不调；
  - 大纲树里结局不进 `arcs`。
- **读者在等的事**：
  - 分段的两个上限；
  - 编号、章号、重复了结、`what` 字数各一条不合规，都重来；
  - 三次不过时 `upto` 停住、后面不做；
  - `span` 三档；
  - `payoff_plan` 和接口里的 `how`；
  - 聊天工具查伏笔能查到拆书记的账。
- **只整理**：
  - `needs_closing` 每条规则；
  - 只整理前 N 章那次不读原文、四步都走；
  - stage 是 done 的书能开始整理，整理完不再能开始。
- **补章节**：有结局时确认页多一条、补上以后结局没了，打开的那一卷离开篇。
- **大纲树**：
  - 拆的书出「还没归篇」；
  - 自己写的书的大纲树输出和改之前完全一样（拿现有测试的书比）。
- **重跑脚本**：三个新步骤各一条。
