# 拆书第三批：拆设定和「这本书好在哪」

产品规则以 `docs/设计说明.md` 第 14 节为准（第一、二批怎么实现的见第 14.4 节后面的「第一批实现」「第二批实现」；试整理设定的脚本和结果见 `docs/拆书/真模型试验/try_settings.py`、`docs/拆书/试验记录.md` 最后两节）。本目录是交给 Codex 的实施任务：按顺序做，一次一个任务，前一个做完并提交后再开下一个。

一句话概括这一批：拆书收尾时，设定师只拿各章记下的东西（不重读原文）整理出设定库——主要人物写全卡（带名场面），金手指、等级、地点、势力、物品功法、往事秘密、特殊规则一类一类整理；主编照程序算好的数字写「这本书好在哪」。接着拆以后只重写有新记录的部分。**篇、全书结局、第几章的小标签不在这一批。**

## 共同约定（每个任务都适用）

1. **先读后做**：先读 `docs/设计说明.md` 第 14 节、本文件和任务文件。任务文件和设计说明有冲突时，以任务文件为准，并在完成说明里指出冲突。
2. **开工前工作区要干净**：`git status` 不干净就停下来问作者，不要动、也不要替别人提交没提交的改动。
3. **语言**：界面文字、提示词、schema 描述一律用简体中文。界面上的说法照任务文件写的抄，不要自己换词。
4. **提示词由设计方提供**：本目录 `提示词/` 下是写好的模板，用 `git mv -f` 搬进 `backend/app/prompts/`：这一批新的是 `teardown_card`、`teardown_world`、`teardown_merits`（`docs/拆书/提示词草稿/` 里同名的是试拆时的旧草稿，以本目录的为准）。不要改措辞；变量登记到 `app/prompts/catalog.py`（分组「拆书」，角色 `teardown`）。由程序拼出来再填进模板的文字，逐字照抄任务文件。
5. **schema 描述就是提示词**：任务文件里给出的类和 `Field(description=...)` 逐字照抄，字段顺序也照抄，放进 `app/agents/schemas.py`。
6. **自己的书不受影响**：凡是加了「是不是拆的书」判断的地方，作者自己的书走原来的路。思考调低、限流等一等只给拆书的调用。
7. **演示模式**：`app/llm/demo.py` 补齐新 schema，没有 Key 也能把一本书从头拆到尾、整理出设定和「这本书好在哪」（章号要在读过的范围里，能过程序检查）。
8. **不碰作者的服务和书库**：不要升级、重启或改动作者日常的 8000／4320 服务、日常 worker 和书库，不要对日常环境运行 `start.ps1`／`stop.ps1`。验收一律用独立的数据库、Redis 库、端口和 worker。真模型只在任务文件写明、作者同意的那一处用，只读取作者日常库里的模型配置，不打印密钥；不要用作者的官方 DeepSeek 配置。
9. **检查命令**：开发中只跑相关测试；提交前跑一次全量，全部通过才算完成。
   - 后端（`backend/`）：`uv run ruff check . && uv run ruff format --check . && uv run pytest -q`
   - 前端（`frontend/`）：`npx tsc -b && npm run lint && npm run build && npm run test:workspace`
10. **验收**：照任务文件最后一节做，结果写进 `docs/拆书第三批验收.md` 对应小节，截图放 `docs/拆书第三批验收/`（少而准）。真书用作者桌面上的 TXT（只读）：`C:\Users\cxc\Desktop\逆天邪神(1-500章).txt`、`C:\Users\cxc\Desktop\都重生了谁考公务员啊.txt`。
11. **文档同步**：任务完成后，在设计说明第 14 节开头的状态行写明哪些已实现；实现时和第 14 节说法不一样的地方，在第 14.4 节后面补一小段「第三批实现」。
12. **分支与提交**：直接在当前分支（feat/setup-interview-spine）上做，不推送。提交信息以「拆书第三批任务 N：」开头。
13. **完成说明**：做完后用一段中文告诉作者：改了什么、迁移做了什么；搬了哪些提示词；跑了哪些检查、结果如何；真模型用了多少（几次调用、多少 token）；验收写在哪里；有没有没做完、做不到、或和设计说明对不上的地方。
