# 任务 1：后台——拆设定和「这本书好在哪」

对应设计说明第 14.2 节第 6、7 条（篇、全书结局不做），第 14.5 节第 3 批（这次只做拆设定和「这本书好在哪」）。这个任务只做后台，不改页面（页面等「装修」做完再出任务 2）。第一、二批的实现见第 14.4 节后面的「第一批实现」「第二批实现」。

一句话：拆书读到作者定的那一章（或者读完全本）收尾时，设定师只拿各章记下的东西（`chapters.teardown.read`，不读原文）整理出设定库——主要人物写全卡（带名场面），其余几类（金手指、等级、地点、势力、物品功法、往事秘密、特殊规则）一类一类整理；最后主编照程序算好的数字写「这本书好在哪」。以后接着拆，只重写有新记录的部分。

## 1. 数据（不用迁移）

1. `library_config.SOURCES` 加 `"teardown": "拆书拆出来的"`；拆书写进设定库的行，`source` 一律记 `teardown`，每行照现有办法记一个版本（`record_version`，来源 `teardown`，说明「拆书整理设定」）。
2. `books.teardown` 加：
   - `settings`：`{"upto": 整理到第几章, "at": 时间, "inputs": {调用键: 这次发给模型的 user 的 sha1}, "rows": {行键: {"id": 行 id, "hash": 程序写进去的那几栏的 sha1}}}`。调用键、行键见下文。
   - `names`：`{名单上的名字: 角色卡上的名字}`（第 3.2 条）。
   - `merits`：`{"upto": 第几章, "at": 时间, "points": [...], "missing": [...]}`（第 5 节）。
3. 拆的书第一次整理设定时，给「角色列表」这一类的卡片栏目（`books.card_layouts`，照第 9.12 节每本书自己定栏目的办法）在正文栏目最后加一栏「名场面」，别的栏目照默认。作者自己改过栏目的不动。

## 2. 什么时候整理

1. **收尾时**：一次拆书读到目标、该归的单元和卷都归完以后（`stop_reason=upto` 或 `stage=done` 之前），进度 `doing` 变成 `settings`，先整理设定（第 3、4 节），再写「这本书好在哪」（第 5 节），然后照第二批的办法停下或拆完。整理设定、写好在哪都失败了，也照常停下／拆完：`stop_note` 后面加一句「整理设定没做完（{一句话原因}），点「接着拆」再试一次。」，不影响已经拆好的大纲。
2. **作者点停下**：不整理，马上停（和第二批一样）。
3. **只整理、不读**：`POST /api/teardown/{id}/start` 现在要求目标大于已读的最后一章（或者有没读成的章）。再加一种能开始的情况：`books.teardown.settings.upto` 小于已读的最后一章（或者还没整理过），这时 `upto` 可以等于已读的最后一章，任务不读原文、不归单元，只做第 2.1 条的收尾。第一、二批已经拆好、还没整理过设定的书（作者现在的《逆天邪神》前 100 章）就靠它补上。
4. 读到哪整理到哪：只用 `index ≤ 已读的最后一章` 的记录。

## 3. 人物

### 3.1 谁写卡

1. 名单照第二批第 4.3 条的办法从各章记录重算（`Roster`），再套上 `books.teardown.names`（第 3.2 条）。每个人数出场章数（他出现在几章的 `people` 里）、名场面场数（`moments` 的 `who` 对上他）。
2. **主角**：出场章数最多的那个人。
3. **全卡**：出场 5 章以上、或者有名场面的人，按出场章数从多到少，最多 40 人，每人调一次 `teardown_card`。
4. **一句话**：出场 2–4 章、没有名场面的人，不调模型：建一行角色，只写姓名、别名、一句话（名单上那句）、第一次出场章；定位「配角」。
5. 只出场 1 章的不进设定库（留在那一章「这一章记下的」里）。
6. 行键：`character:{名单上的名字}`。

### 3.2 名字以角色卡为准

模型写回的 `name` 和名单上的名字不一样时：新名字是名单上这个人的别称、或者名单上的名字出现在模型写回的 `aliases` 里，就认，记进 `books.teardown.names`，以后算名单、写库都用新名字（旧名字放进别名）；新名字和另一个人重名的不认，照旧用名单上的名字，在 `missing` 里记一句「卡上写的名字和 {另一人} 重名，没改」。角色表同一本书不能重名：写库时撞上了作者自己建的同名角色，给新的这一行名字后面加「（第 {第一次出场章} 章起）」。

### 3.3 拼进 `teardown_card` 的字（逐字照抄）

- `title`：书名；`last`：整理到第几章；`name`：名单上的名字；`aliases`：别称用「、」连起来，没有写「无」；`count`：出场章数；`chapters`：出场的章号写成区间（照 `try_settings.py` 的 `spans`，例「1–3、7、9–10」）；`protagonist`：主角名字（写的就是主角本人时也照写）。
- `dossier`：这个人出场的每一章一行 `第 {章} 章：{shown}`，`change` 不空接「（变化：{change}）」；他的名场面每场一行 `第 {章} 章名场面：{what}——立住了{shows}`。按章号排，名场面跟在那一章后面。**太长时截**：整段超过 12,000 字，按这个顺序留，留满为止，再按章号排回去：有名场面的章、有变化的章、头 20 次出场、最后 40 次出场、其余的均匀挑；截过的在最后加一行「（中间有 {N} 章的记录没列出）」。
- 调用键：`card:{名单上的名字}`。

### 3.5 写库

- 照新书页现有的办法按栏目名写（`services/desk.py` 的 `write_value` 那一套）：`role_type`→定位、`belongs`→所属、`gender`→性别、`age`→年龄、`aliases`→别名（并上名单上的别称，去重）、`appearance`→外貌、`personality`→性格与说话方式、`background`→身世、`goal`→想要什么、`weakness`→软肋、`abilities`→能力、`growth`→成长与结局、`now.power`→实力与地位、`now.location`→在哪、`now.condition`→处境、`now.want`→此刻想要、`now.alive`→是否活着；`one_line` 写进一句话；第一次出场章写进 `first_appearance_chapter`。
- 名场面写进「名场面」那一栏，每场一行：`第 {chapter} 章：{what}——立住了{shows}`。
- `ties`：对方是设定库里已有的角色（`who` 先按「/」「、」拆开，拆出来的任何一个对上名字或别名就算）才建关系（`relationships`：`kind` 写 `relation` 的前 50 字、`description` 写 `relation` 全文、`since_chapter`）；同一对人已有拆书建的关系就更新，作者建的不动。对不上的人跳过。
- **作者改过的不动**：写之前算这一行现在那几栏的 hash，和 `settings.rows` 里记的不一样，就说明作者手改过——这一行跳过，记下名字（第 6 节收尾那句话要用）。作者自己新建的角色（不在 `settings.rows` 里）一律不动，重名时照第 3.2 条加区分。
- 一句话的人以后出场多了、要写全卡时，更新同一行（行键不变）。

## 4. 其余几类

### 4.1 收哪些

1. 把读过的各章 `things` 按（`kind`，`name` 去掉首尾空白）合在一起。
2. **出现过几章由程序拿名字去原文里数**：在 `index ≤ 已读最后一章` 的章里，`content` 包含这个名字的章数（照第一批「搜原文」的查法，一次查一个名字；名字不到 2 个字的照记录数）。
3. 收：出现过 2 章以上的；`kind` 是金手指、等级、秘密的一律收；地方被别的地方的 `belongs` 提到的也收（排地点树要用）。
4. 七类各管各的：`kind` → 设定库的类：金手指→金手指、等级→等级体系、地方→地点列表（世界概况也在这一次写）、势力→势力列表、物品功法→物品功法、秘密→往事秘密、规矩→特殊规则。

### 4.2 拼进 `teardown_world` 的字（逐字照抄）

- `title`、`last`、`protagonist` 同第 3.3 条；`kind`：「金手指」「等级」「地方」「势力」「物品功法」「秘密」「规矩」之一。
- `things`：每样东西一行：

  `- {名字}（原文里出现过 {章数} 章，第一次在第 {第一次出现章} 章）：{各章记下的}`

  `{各章记下的}` 是这样东西每次被记下的那几条，`；` 隔开，每条 `第 {章} 章：{note}`，有 `belongs` 接「（属于 {belongs}）」，有 `secret` 接「（{secret}）」；一样东西最多列 6 条（前 3 条和最后 3 条，中间写「……」）。
  一类超过 60 样，按第一次出现的先后每 60 样一次分几次调用，`missing` 合起来。
- `context`：
  - 等级：`主角各章的变化：` 换行，接主角每个 `change` 不空的章一行 `- 第 {章} 章：{change}`，最多 120 行（多了均匀挑）；没有写「主角各章的变化：（没有）」。
  - 势力：`角色卡上写的所属：` 换行，接这次写过全卡、`belongs` 不空的人一行 `- {名字}：{所属}`；没有写「角色卡上写的所属：（没有）」。
  - 其他几类：空字符串。
- `kind_rule`（逐字照抄）：
  - 等级：「等级按高低排，低的在前，一套等级一条（修炼境界、职位、品阶……分开写）；每一级写原文怎么说它；主角第几章到了这一级，看上面主角各章的变化，看不出就留空；怎么往上升、难在哪写进 how_up。」
  - 金手指：「写清是什么、谁知道、能做什么、规矩和限制、代价、来历、第几章出现；后来陆续冒出来的本事，按章写进怎么变强。」
  - 地方：「每个地方写它属于哪里（上一级地方的名字，要是上面列出的另一个地方；最大的留空）、第一次出现在第几章。再写一段世界概况（world）：什么时代，超凡的力量是公开的还是藏着的，普通人知道多少，钱用什么；只写记录里看得出的。」
  - 势力：「写清什么组织、谁领头、地盘在哪、和主角是敌是友、第一次出现在第几章；成员只写上面「角色卡上写的所属」里有的人。」
  - 物品功法：「写清是什么、品阶、有什么用、在谁手里、第一次出现在第几章。」
  - 秘密：「同一个秘密分几次揭开的合成一条：写真相是什么、谁知道、第几章埋下、第几章揭开（还没揭开留空）；揭开不能早于埋下。」
  - 规矩：「写清管什么、怎么运作、有什么限制和代价、第一次出现在第几章。」
- 调用键：`world:{kind}:{第几次}`。
- **先写角色卡、再整理势力**（势力要用卡上的所属）；别的几类和角色卡可以同时写，同时最多 4 个调用。

### 4.4 程序检查和写库

- 章号：`first_chapter`、`planted_chapter`、`revealed_chapter`、`protagonist_chapter` 不在 1 到已读最后一章之间的，置空；秘密的 `revealed_chapter` 早于 `planted_chapter` 的，`revealed_chapter` 置空，`missing` 加一句「{名字}：揭开的章号早于埋下，没写揭开」。
- 写进新书页对应那一类，栏目照现有默认栏目（`services/desk.py` 的 `DEFAULT_FIELDS`）：
  - 金手指：`what`→是什么、`knowers`→谁知道、`can`→能做什么、`rules`→规矩和限制、`cost`→代价、`grows`→怎么变强、`origin`→来历；
  - 等级体系：一套等级一条阶梯，`how_up` 写总说明，`levels` 照现有阶梯的存法，每级的介绍写 `note`，`protagonist_chapter` 有值再接「（主角第 {N} 章到）」；每一级另外多存一个键 `protagonist_chapter`（整数或 null），新书页装修要靠它标出主角到了哪一级；
  - 地点列表：`note`→内容；`parent` 对上这一类里另一个地方（按名字或别名）就挂成它下面一层（`parent_id`），对不上就不挂；`world` 写进「世界概况」那一条（没有就建）；
  - 势力列表：`leader`→领头的、`stance`→对主角、`turf`→地盘、`note`→内容，`members` 不空在内容后面另起一行「成员：{用「、」连起来}」；
  - 物品功法：`grade`→品阶、`holder`→在谁手里、`note`→内容；
  - 往事秘密：`knowers`→谁知道，「打算何时揭开」那一栏写「第 {revealed} 章揭开」，还没揭开写「到第 {已读最后一章} 章还没揭开」；内容写 `truth`，`planted_chapter` 有值再另起一行「第 {N} 章埋下」；
  - 特殊规则：`note`→内容。
  - 别名写进条目的别名，第一次出现的章写进 `created_chapter`。
- 行键：`entry:{类}:{名字}`；作者改过的不动、作者自己建的不动，规则同第 3.5 条。同类里名字撞上作者自己建的条目，新的这一条名字后面加「（拆书）」。
