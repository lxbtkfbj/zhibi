# 拆书架构体检（2026-10-19 晚）

> 作者说「输出质量以后再调，先确定架构没问题」。这份是开做之前的体检：拿设计说明第 14 节（主要是 14.4）一条条对照现在的代码（到 882c145；工作区里别的会话还没提交的改动没算）和 `试验记录.md` 里的结果，写清哪些站得住、哪些要改、哪些还没验。**只分析，没改代码。** 作者定了第五节的几件事，再照第六节改第 14 节，然后开做第一批。

## 一句话结论

地基站得住：拆的书当成一本普通的书来存、拆书单独一个后台程序跑、每章读一次再往上归，这三条主干查下来都不用改。要改的有四处（单元必须属于一卷、角色不能重名、人物名单越带越长、群聊的老办法能改书），另外补一条「每一步能单独重跑」；可以删的有三处（存档只重算改过的、每半小时把自己重新排上、一类上百个时的「其余 N 个」）；有两件最好在第二批开工前各花一块钱左右先验（每章记的东西够不够第三批用、有等级金手指的书记不记得住）。

## 四、还没验的：什么时候验、怎么验、花多少

1. **每章记的东西够不够第三批用**：拿已经拆好的前一百章记录（`data/拆书试验/真书前一百章/`），不读原文，试整理一次设定库：合并人物、写几张带名场面的角色卡、排地点和人物关系、算「这本书好在哪」要的数字。几分钟，一块钱以内。不够就在第二批开工前补记录的栏目。建议第二批之前验。
2. **有等级、金手指的书记不记得住**：拿一本作者熟悉的玄幻／修仙书，前三十章跑一遍逐章记（第三版提示词）。几分钟，一块钱左右。建议第二批之前验（要作者给书，第五节 2）。
3. **人物名单越带越长以后还认不认得准**：第二批整本跑 670 章时看名单长度、每批输入多少、后面的批有没有认错人。不另花钱。
4. **浏览器里大书卡不卡**：第一批导入真书时量，和小书对照。不花钱。
5. **作者别的模型配置**：试拆都用 A 3.8f，拆书也只用它的话不用验；换别的模型时，开拆前三批失败多会停下提示（第 14.2 节第 4 条）。

第 1、2 条只影响第二批的记录格式，第一批不用模型，可以一边做第一批一边验。

**第 1、2 条已验（2026-10-19 晚，模型【Alicia】gemini-3.8-flash，详见 `试验记录.md` 最后两节）**：

- 人物、等级、金手指、秘密：记录够用。16 张角色卡平均一张不到两栏写不出来（多是年龄）；玄幻书的十一级境界排得出来、主角第几章到哪一级对得上；抽查的细节都在原文里，没拿记忆补。
- 地方、势力：不够。①「新冒出来的东西」只在第一次出现时记一次，按记录数不出「出现过几章」，流云城、萧门这种天天出现的反倒被当成只出现一次漏掉 → 程序拿名字去原文里数；②记录里没有「属于哪里」「谁领头」，地点排不成树 → 逐章记加一栏「属于哪里」，势力的成员从角色卡的「所属」反过来填。
- 顺带查出：作者写在章末的「第一卷完结」「第二卷“某某”开启」会被当成卷名；原文缺章、章号打错的地方要在确认页列出来；Gemini 这个中转站不认「思考调低」，不碍事。
- 第 3 条（名单越带越长）还是第二批整本跑时看。

## 五、要作者定的事

### 1. 拆书用哪个模型、在哪选

拆一本 670 章的书要调两百来次模型。试拆用的 A 3.8f 按官方价白天二十块左右，换成贵的模型可能上百块。原计划在系统设置的模型分工里加一行「拆书」，可那一栏下午刚把用不上的「群聊分流」藏掉。

- A（推荐）：确认页上选，默认是设定师用的那个模型，旁边就写这本书预计多少钱、多久。只管这一本，不影响写书，系统设置里不多一行。归单元、归卷也用这一个（试拆时 A 3.8f 三步都做得来）。
- B：模型分工里加一行「拆书」，所有拆的书都用它。
- C：不给选，直接用设定师的模型。最省事，但设定师要是配了贵的模型，拆一本书的钱会多好几倍，想换就得去改设定师（写书也跟着变）。

推荐 A：钱写在选模型的旁边，选之前就看得见；换了只管这一本。

### 2. 第二本书什么时候给

现在试的《都重生了谁考公务员啊》是都市文，没有修炼等级、金手指、宗门。每章记下哪些东西第二批就要定死，之后要加栏目，已经拆过的书得整本重拆。

- A（推荐）：现在给一本作者熟悉的、有等级和金手指的书（玄幻、修仙都行，TXT），拿前三十章验第四节第 2 条。
- B：三批都做完再给，到时候发现记少了，改格式、重拆。

手上没有这类书就先跳过第四节第 2 条，第二批照现在的格式做。

### 3. 拆的时候能不能手改

例：拆到第 300 章时，作者看第 5 章的章纲，觉得「看点」写偏了，想当场改。

- A（推荐）：拆的时候只能看、不能改。要改就点「停下」，改完点「接着拆」，从停的地方往下拆，读过的不重读。和自己的书一个规矩。
- B：拆的时候也能改已经拆好的部分。要多做一套「作者改过的这几处，后面整理时别盖掉」的判断，而且整理设定时正好要用到作者在改的那一章，容易打架。

推荐 A：拆书主要是看，改得少；停下再改只多点两下，规矩和自己的书一样。

### 4. 第二批之前先验第四节第 1、2 条

原计划「原文只读一遍」：第二批每章读一遍就把人物、设定一起记下，第三批整理设定库、写「这本书好在哪」全靠这些记录。记少了，第三批就得把整本书重读一遍（670 章又一小时、二十来块）。

- A（推荐）：先验，两条加起来一两块钱。
- B：不验，第三批做到了再说。

推荐 A：一两块钱换掉以后可能的整本重读。

**作者的答复**（2026-10-19 晚）：

1. 选 B：模型分工里加一行「拆书」，所有拆的书都用它；没选就跟随默认，和别的几行一样。价钱不好估，确认页**不估钱**（也不估时间），只提醒一句「拆书要把整本原文发给模型，书越长调用越多，费用可能不小」；拆起来以后，进度条按实际速度说还要多久。
2. 给了《逆天邪神》前 500 章（`C:\Users\cxc\Desktop\逆天邪神(1-500章).txt`），拿来验第四节第 2 条。
3. 选 A：拆的时候不能改，停下再改。作者说拆到一半自己去改的情况很少，多半是回头再检查；做起来麻烦就直接禁止改。现成的 `ensure_idle` 就是这样挡的，只把挡住时的那句话换成「正在拆，点「停下」才能改」。
